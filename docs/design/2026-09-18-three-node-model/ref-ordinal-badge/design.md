## 1. 原则

1. **顺序是系统给的,不是用户管的**。拉线即编号,零操作;断线自动补位(§2.4)。
2. **序号永远活在「选中目标」的语境里**。它表述的是「这张图是第 N 张入边」,N 只相对于某个 image/video 节点有意义;没有语境就不渲染,绝不臆断(§2.2)。
3. **不靠颜色区分**。常态/高亮的区分 = 位置 + 数字 + 颜色三重编码;默认态 = 元素不存在(§3.4)。

## 2. 交互规范

### 2.1 编号时机
- 用户把一条入边连入 image/video 节点的图片入口时,该源图立即获得序号 = 当前入边数组长度(第 1 条 = 1,第 2 条 = 2,…),**无确认步骤、无悬浮窗操作**。
- 编号是**派生值**:由目标节点的入边数组顺序计算,不落库、不手动编辑。这与「顺序即语义」契约一致,契约口径由 architect 在 R-39 同步。

### 2.2 显示语境(用户裁定)
- **仅当某个 image/video 节点被选中时**,连入它的各源图在其**图片缩略图右上角**显示徽标,数字 = 该图在选中目标入边数组中的序号。
- **未选中任何目标时,画布上不渲染任何徽标** —— 不是隐藏数字,是元素不存在。默认态与选中态的区分是「徽标整体的有无」,无样式渐变,不存在混淆空间。
- 切换选中目标时,徽标数字在新目标的语境下重算并**原位翻转**(150ms,`prefers-reduced-motion` 时直接替换),位置不动。

### 2.3 多目标共享同一源图
- 同一源图连多个目标时,它在不同目标里序号不同 —— 这是事实,不是歧义,因为徽标从不脱离选中目标单独出现。
- 不连当前选中目标的源图保持无标,画布上不会出现「不属于本次语境」的数字。
- 目标节点内的参考图列表文字(「参考图 1 = 款式草图」,现有 `ReferenceImageList` 形态)与源图徽标同源同号,交叉印证。

### 2.4 断线 / 重连 / 删除的序号规则
**结论:自动补位,不留空洞。** 理由:
1. 序号是派生值,语义是「第 N 张」;留空洞(1,3,4)会让「第 3 张」在视觉上不存在,直接违背用户的确认直觉。
2. 提示词正文里的「参考图 N」token 与序号强绑定,空洞会让 token 指向不存在的徽标。
3. 补位成本为零(派生值重算),且断线是高确定性的有意操作,用户预期剩余图重排。
- 断线:剩余入边按原相对顺序重排(1,2,3…)。
- 重连(拖离再落回):视为先断后连,落回时取新位置的序号。
- 源节点删除:其所有出边消失,各目标独立补位。

### 2.5 与提示词正文「参考图 N = …」的对应确认
徽标存在的意义是让用户一眼确认「哪张是面料」。确认路径:
- 提示词正文里的「参考图 N」是可点击 token(现有文字形态,见原型 inner-box)。
- 点击「参考图 N」→ 对应源图徽标进入**确认高亮态**(§3.3)+ 缩略图描边,同时正文 token 同步变色;再次点击或点击别处退出。
- 键盘可达:token 为 button 语义,focus 可见,Enter/Space 触发,Esc 退出;高亮不以 hover 为唯一触发。

## 3. 视觉规范

### 3.1 形态(唯一一种,三主题不变形)
| 参数 | 值 | 来源 |
|---|---|---|
| 尺寸 | 20×20 px 圆形 | 新组件参数(示意,实现时可 ±2) |
| 位置 | 源图缩略图右上角,内缩 6px(top/right) | 用户原话「图片右上角」 |
| 字体 | 11px / 700,`--gc-font-mono` | 现有 token |
| 常态底色 | `rgba(0,0,0,.62)`(`--gc-media-overlay`) | 现有 token |
| 常态文字色 | `#f4f4f4`(`--gc-media-overlay-text`) | 现有 token |
| 描边 | 1.5px `#ffffff` + `0 1px 4px rgba(0,0,0,.35)` | 白描边保证在浅色图上分离;新参数 |
| pointer-events | none(不挡缩略图点击) | — |

**两位数预案**:序号上限受入边容量 8 约束(plan §1.1),个位数常态 20px 足够;若未来放宽到两位数,徽标宽随字数横扩(min-width 20,padding 0 5),高度不变。

### 3.2 三主题一致性
徽标底/字/描边三主题**同值**(media-overlay 系 token 本就不随主题翻转),保证「同形同义」;主题只影响确认高亮态的 accent(§3.3)。三主题实截见 `shots/badge-{obsidian,apple,eye}-*.png`。

### 3.3 确认高亮态
- 徽标底 → `--gc-accent`,字 → `--gc-accent-cta-ink`,描边保持白。
- 同步:源图缩略图 2px `--gc-accent` 描边 + 正文 token 同底色反白。
- 三重编码:位置(哪个徽标)+ 数字(N)+ 颜色(accent),色觉障碍用户靠前两者即可定位。

### 3.4 可访问性
- **不靠颜色区分**:常态与高亮的区分有位置/数字/缩略图描边三个非颜色通道;默认态是元素有无。
- 徽标 `aria-hidden="true"`(装饰性);语义由源图的 `alt` 承载:「参考图 N:{节点名}」(与现有 `ReferenceImageList` 的 alt 口径一致,见 `ReferenceImageList.tsx:74`)。
- 对比度实测(WCAG 2.1,程序预验证 `/tmp/r38_contrast.py`):
  - 常态白字 on 半透明黑底:叠纯白图(最坏)6.19:1,叠浅灰图 7.23:1 —— **过 AA(≥4.5)**。
  - 高亮 accent 底:曜黑 12.1:1、简白 4.7:1、护眼绿 5.41:1 —— **三主题全过 AA**。

### 3.5 与节点卡的关系
徽标属于**图片**,不属于卡片:它渲染在缩略图(`img-slot`)内,跟随图片而非卡框;无图(未上传)时不存在显示对象,自然无标 —— 与「未选中不渲染」同一逻辑:没有语境/没有对象就不出现。

## 4. 待 architect 同步的契约触点(R-39,本规范不覆盖)

- 序号 = 入边数组 index+1 的派生口径,与 `selectActiveEdges` 的顺序语义一致性。
- 「参考图 N」token 的解析与点击事件来源(提示词正文渲染层)。
- `ReferenceImageList` 与画布徽标的同号保证(同一派生函数,避免两处各自重算漂移)。
