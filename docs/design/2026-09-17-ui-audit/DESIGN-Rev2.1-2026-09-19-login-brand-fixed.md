## 1. 裁决内容

**登录页品牌固定，有意不跟随用户主题 —— 有意为之 ✓**

- 登录页（`src/auth/LoginPage.tsx`，V4 分屏）恒为**曜黑 · 荧光绿**品牌外观：`data-theme=null`（即 `:root` 曜黑段 token 生效）、`--gc-accent` 恒 `#B7F35A`、登录卡底恒 `rgb(33,36,42)` 系。
- 用户在简白/护眼绿主题下登出、或携带 `localStorage` 主题偏好访问登录页，看到的仍是曜黑登录页——**这是品牌门面决策，不是主题机制失灵**。品牌外壳在认证之前统一呈现，主题是登录后的工作台个性。
- 裁定选项来源：R-46 首轮验收 README P1-1 提出「① 登录页挂载即应用主题，或 ② 明确裁定登录页恒曜黑并固化」。用户 2026-09-19 裁定为 **②（保持品牌固定）**，原话要点：「**保持品牌固定 —— 有意为之**」。

## 2. 技术机制现状（与裁决自洽）

- `src/lib/theme.ts` 仅被 `CanvasFlow` / `TopBar` 引入，未认证的登录页路径无人设置 `data-theme` → `data-theme=null` → `:root`（曜黑）段生效。**该机理即裁决要的行为，不需要修**。
- 未来若产品决定登录页跟随主题，那是**新需求**（改 `LoginPage` 挂载时 `applyTheme`），不是缺陷修复；届时本补遗作废，需用户重新裁决。

## 3. 给未来审计的提示（重要）

> **登录页 `data-theme=null` / 恒 `#B7F35A` / 三主题截图恒等，不是缺陷，不要再报 ✗。**
> 本裁决（R-56，2026-09-19）之前 R-46 / R-51 两轮独立验收曾先后将其判为 P1，均为「裁定未决」前提下的合理上报；自本补遗起该现象有明文裁决背书，再报即为误报。验收口径：登录页只验**曜黑单主题 × 1024/1280/1440**（对比度、几何、a11y 照常），不再做登录页三主题换肤断言。
