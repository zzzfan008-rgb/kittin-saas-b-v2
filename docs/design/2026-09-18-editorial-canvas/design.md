## 0. 方案一句话

把参考文献的**设计语言**（衬线展示字 + mono 编号系统 + 几何色卡 Plate + 硬投影 + 克制动效 + 透明度灰阶）移植到工作台骨架，**不**移植它的营销页结构。新增第 4 主题 `paper`（浅色）+ `paper-dark`（深色墨变体），现有 `current/white/eye` 三主题零改动。

## 1. 参考文献复核结论（修正 orchestrator 初析）

我逐行复核了 198 行模板源码，初析大体准确，但有三处需要修正/强调：

| 项 | 初析 | 复核裁定 |
|---|---|---|
| italic 衬线 | 全文未提 | `<em class="text-[#5149cf]">record</em>` —— **italic 是点睛强调字的母题**（hero 内嵌斜体单词用强调紫）。本项目 hall­mark 纪律禁斜体标题，裁定：**保留「标题整体 roman，单个强调词可 italic + accent」**这一精确用法，仅用于区块大标题 |
| 灰阶透明度 | /42 /45 /48 /55 /60 | 确认。但实测 `ink/45 on paper = 2.73:1`、`ink/55 = 3.59:1` **均不达 WCAG AA**。裁定：透明度灰阶只允许用于 ① ≥10px mono 大写宽字距的装饰性标签（Large text 3:1 档，仍需 ≥/55 级）② 分隔线/描边。正文次级一律用实体 token `--gc-text-muted`（= ink/62 混合色 4.42:1） |
| 卡片阴影 | 硬投影 `6px 6px 0` | 源码里硬投影只用在 **20×20 logo 方块**一处；大 profile 卡用的其实是 `0_30px_80px_-46px` 柔投影。裁定：**硬投影收缩为装饰性点缀**（每屏至多 1 处），工作台浮层沿用现有软阴影体系 |

## 2. 已定决策（决策 + 理由）

**D1 · 主题接入**：`ThemeId` 增加 `"paper"` 与 `"paper-dark"`，走既有 `data-theme` + `--gc-*` 机制；`THEMES` 数组加两项，浅/深作为**两个独立条目**（与现有三主题平级），不引入 mode 切换器。理由：项目现有机制就是「主题即完整 token 集」，两个 data-theme 段与 white/eye 同构，契约测试模式可直接复制；加 mode 维度是过度工程。

**D2 · 行动色 = 编辑紫**。浅色 `#4a42b8`（在源紫 #5149cf 基础上加深：白字 7.60:1 / 米白底 7.28:1，给 focus 环留余量），深色 `#9c96f2`（6.23:1）。紫不与既有三主题（黄/蓝/绿）撞色，四主题 hue 各占一族。一色一义规则不变：紫只落在主 CTA、选中描边、焦点环、连线、编号高亮。

**D3 · 珊瑚 #ef6b7a 只作装饰**（Plate 色带、硬投影、装饰性状态点），文字场景用其加深变体 `--gc-deco-text`（4.95:1）。理由：珊瑚在米白底 2.85:1，承担文本必然违反 a11y。

**D4 · 深色变体不用纯白节点卡，用米白纸卡**（`--gc-node-main: #fbfaf7`）。理由：① 纯白纸卡是 white/eye/current 三主题的既有语言，米白纸卡让第 4 主题在深色形态也保住「纸」的身份；② 米白底上节点内文字回到浅底紫 `#5149cf`，状态色无需第三套配对。

**D5 · 字体策略：系统栈回退，不引入网络字体**（详见 §5 开放问题——这是本方案最大的待定项，我给出的是推荐解）。Display 栈 `Georgia, "Songti SC", "Noto Serif SC", "STSong", serif`；技术标签沿用现有 `--gc-font-mono`。Georgia 的金属活字气质是 Instrument Serif 在零网络依赖下的最近替身。

**D6 · 衬线的使用边界**：只出现在 ① Inspector/区块级大标题（26–48px，roman + 单强调词 italic）② 统计数字（衬线 oldstyle 数字是编者气质的核心）③ 词标。**节点卡内、表单、页签全部无衬线**——卡内是业务界面，衬线进卡会牺牲小字号可读性。营销页的 `clamp(4.5rem,10vw,9rem)` 巨字不移植（工作台没有 hero）。

**D7 · 编号系统语法统一为 `N-xx`**：节点实例 N-01…；项目页签 `01/02/03`（顺序号，源自参考文献列表行）；区块标题用「名称 · 编号」而非「编号 / 名称」（中文语境下名称前置更可读）。初版原型曾出现「01」在 4 个层级撞车，已修正。

**D8 · 动效**：`transition-colors` + hover `-translate-y-2px`（参考文献是 -1 档/500ms，工作台组件缩小到 2px/180ms 以匹配现有 `--dur-2`），无弹跳无缩放；`prefers-reduced-motion` 全局兜底沿用现有规则。焦点环维持 R-24 的 3px，即时出现、不动画。

**D9 · 状态色浅/深底重配对**（canvas-ui 技能的 re-pair 规则）：queued 浅底用琥珀 `#a16207`（4.72:1，原 #c79002 在米白上只有 2.71:1 被驳回）、unknown 浅底用青 `#0f766e`（5.24:1，与紫 7.28 距离足够）、error 用珊瑚加深变体 `--gc-deco-text` 同值，与主题装饰色同族呼应。

## 4. 不移植清单（明确不做 + 理由）

| 参考文献元素 | 不移植理由 |
|---|---|
| Hero `clamp(4.5–9rem)` 巨字 + `leading-0.78` 极限紧排 | 营销页专属；工作台 56px 顶栏放不下 9rem 字。衬线收缩到 26–48px 区块档 |
| 整段反色带（墨底大区块） | 画布已有明/暗两套底，反色带是第三套底色 = 注意力倒挂（原型 v1 实测：全屏最重色块抢画布视线）。降级为浅色统计带 |
| Aura 外框（卡片外多色渐变光晕） | 工作台卡片密度高，每卡一圈彩虹光晕是视觉噪音；且与「一色一义」冲突 |
| 营销页 `max-w-1240px` 居中阅读栏 + 非对称双栏 `[0.32fr_0.68fr]` | 工作台是全宽三栏工具布局，无阅读流 |
| 外部 Google Fonts（Instrument Serif / IBM Plex Mono） | 项目已定系统栈纪律（2026-09-17-ui-audit）；见 §5 |
| 三栏服务卡 / 项目卡完整行网格 `[4rem_1fr_13rem]` | 节点库是 264px 窄栏，放不下 13rem Plate 列；Plate 收缩为 44×32 微缩图 |
| 装饰标签 `PLATE / 01` 角落编号 | 保留为画布右下**唯一装饰位**（每屏一处），不扩散到节点卡 |

## 5. 开放问题（请三方重点审）

**Q1 · 字体策略（最大待定项）**。三选：
- **A · 系统栈回退（我的推荐）**：Georgia + Songti SC/Noto Serif SC。零成本零风险；代价 = 放弃 Instrument Serif 的独特 italic 气质，Windows 上 Songti 缺失时掉到 Noto Serif SC 或默认衬线，跨平台字形不一致。
- **B · 自托管**：下载 Instrument Serif（仅 400/italic 两字重 ~30KB）+ 中文系统衬线兜底。气质保真度最高；代价 = 引入字体加载策略（font-display:swap 的 FOUT 在 56px 顶栏词标上可见）、构建管线改动、许可证归档（OFL，合规无问题但需流程）。
- **C · Google Fonts CDN**：一行 link 最省事；代价 = 国内可达性 + 违背项目「零外部字体依赖」先例，我不推荐。
IBM Plex Mono 三案都不引入——现有 JetBrains Mono 栈已覆盖技术文本角色，换 mono 是无收益 churn。

**Q2 · 深浅接入形态**。本方案是两个平级主题条目（paper / paper-dark）。备选：paper 单主题 + 跟随系统的 mode 子开关。后者对长时间工作台用户更友好，但给 `theme.ts` 增加第二个维度。请 architect 裁定。

**Q3 · 端口语言**。本主题端口 = 中性底 + 静态紫环，与既有三主题的「径向渐变亮珠」不一致。两个方向：(a) 仅本主题用静态环（主题间视觉差异正当化）；(b) 趁机把三主题端口统一为静态环（改动面大，R-24 刚收过焦点环，不建议本轮做）。请 frontend/ui-qa 评估 (a) 是否会造成主题切换时的端口认知跳跃。

**Q4 · Plate 在真实节点上的语义**。原型里 Plate 只作节点库微缩图与画布装饰。若 P2 想让 Plate 承载真实语义（如「本节点色板」「面料取色结果」），design token 已就位（`--gc-plate-*`），但需要 frontend 确认取色数据来源。本轮默认纯装饰。

## 6. 实现风险点（供 frontend 审）

1. **`theme.ts` 校验白名单**：`getTheme()` 里 `q === "current" || "white" || "eye"` 的硬编码判断要加两个新值，漏一处就是静默回退。契约测试 `theme-contract.test.ts` 的 THEMES 断言与 `coreThemeTokens` 循环都要扩——**测试先行**。
2. **新增 token 进契约**：`--gc-plate-*` ×4、`--gc-deco-text`、`--gc-font-display`、`--gc-font-editorial-meta`、`--gc-tracking-*`、`--gc-elev-hard` 是本主题新增名；若契约测试按「每主题完整 token 集」断言，需同步白名单，否则误报。
3. **深色变体节点卡内文字色跨层**：paper-dark 的 `--gc-node-text: #24231f`（深字）在米白卡上，而 `--gc-text` 是浅字——既有「节点命名空间与壳层解耦」机制正好覆盖，但 frontend 注意不要在卡内误用 `--gc-text`。
4. **意大利斜体强调词的 i18n**：「Coin _AI_」这类内嵌 `<em>` 在中文标题里不存在自然对应（中文无 italic 传统，Songti 伪斜体难看）。中文大标题的强调词建议用 accent 色 + roman，不用 italic——请 ui-qa 在验收时按此口径。
5. **1024 档节点卡宽度**：原型实测画布在 1024 下仅 ~556px 有效宽，节点卡需在 ≤1180px 断点收窄（原型用 220px + 缩略图 88px 验证通过）。React Flow 里节点宽 280px 是写死的（canvas-ui 规则 280–300px），落地时需决定：收侧栏 or 收节点卡。**这是三档验收最可能卡住的点**。
6. **硬投影 token `--gc-elev-hard`** 只许用于空态 CTA 卡 / 画布装饰位，若 frontend 把它扩散到普通弹窗会破坏「每屏一处」纪律——建议 ui-qa 把「硬投影出现次数 ≤1」写进验收脚本。
