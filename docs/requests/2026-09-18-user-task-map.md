# 用户任务地图 —— 从「设计师实际怎么干活」反推三节点模型

- 日期：2026-09-18 · 作者：orchestrator（用户要求：「按用户使用的角度来思考，他需要哪些作用，达成什么目标，应该怎么拉线」）
- 用途：三节点重构（`docs/design/2026-09-18-three-node-model/`）的**产品视角输入**。R-40（悬浮窗口规范）、R-41（功能定义契约）应以本文为对照物。
- 证据来源：6 套内置模板 `data/templates/builtin/*.json`（= 已沉淀的真实任务）+ `src/types/workflow.ts` 的 `NODE_SPECS`（旧 9 节点的用户语义）+ 项目规则 `AGENTS.md` §1（服装设计师的生产工具）。

## 0. 用户是谁、要什么

**服装设计师**（不是通用 AI 用户）。他一天里真正要交付的东西：

1. **效果图** —— 把草图/想法变成能给版房、客户看的图
2. **改款迭代** —— 同一款改领型、袖型、长度、细节，出多版
3. **配色/面料方案** —— 同款换色换料，给客户挑
4. **印花落地** —— 把图案放到服装上、或从图上提取印花
5. **交付级成图** —— 放大到 2K/4K
6. **（新）动态展示** —— 静态款 → 上身动效
7. **（新）把想法说清楚** —— 让 AI 帮他把提示词写好

## 2. 应该怎么拉线（用户的心智模型）

**一句话**：**「用【这个功能】，拿【这几张图】当参考，加工一次，得到新图。」**

画布上的三条规则：

1. **文字从左边的 text 节点进来** —— 写「我要什么」。每个生成节点**必须**有一个（R3 强制，且画布自动补一个空 text 节点 ✓）。多段文字可以拉多条，按顺序拼。
2. **图片从其他 image 节点拉进来** —— 当参考/素材。**顺序即语义**（第 1 张、第 2 张……），序号自动显示在图片右上角、跟随当前选中的目标（用户裁定 ✓）。不区分「款式口/面料口」——是哪张由提示词正文声明（Q3=A ✓）。
3. **产物就在这个节点上** —— 不满意就再往下拉一个 image 节点，换一个功能继续加工。**没有单独的「结果节点」**（Q4=A：产物在节点上 + 结果面板汇总 ✓）。

于是流水线长这样（用户视角）：

```
[文字]──┐
        ├─→ [图片节点：功能=草图渲染] ──→ 效果图 ──┐
[草图]──┘                                        ├─→ [图片节点：功能=换面料] ──→ 换料图
                                    [文字]──┐     │
                                    [面料]──┴─────┘
```

- **视频**：`[文字] + [款式图(首帧)] → [视频节点]`
- **文本**：`[文字] → [文本节点：功能=润色] → 点「采纳」写回正文`（AI 只提案，落笔由人 ✓）

## 3. 逐任务对照：旧形态 → 新形态

| 任务 | 旧形态（9 节点） | 新形态（三节点 + 功能） | 拉线 |
|---|---|---|---|
| T1 草图→效果图 | `image-input` → `sketch-to-render` | text(要求) + image(功能=**草图渲染**)；草图 image → 它 | 1 文 + 1 图 |
| T2 改款 | `ai-modify` | text(改什么) + image(功能=**改款**)；上一版 → 它 | 1 文 + 1 图 |
| T3 换面料/配色 | `fabric-recolor`（双 handle） | text(「参考图 2 = 面料」) + image(功能=**面料替换**)；两张图拉入 | 1 文 + 2 图 |
| T4 放大 | `upscale` | text(可空) + image(功能=**高清放大**) | 1 文 + 1 图 |
| T5 图案迁移 | `ai-modify` + 双 image-input | text(迁移说明) + image(功能=**图案迁移**)；2 图 | 1 文 + 2 图 |
| T6 场景迁移 | `ai-modify` + 双 image-input | text(合成说明) + image(功能=**场景合成**)；2 图 | 1 文 + 2 图 |
| T7 印花提取 | `print-extract` | text + image(功能=**印花提取**) | 1 文 + 1 图 |
| T8 印花变体 | `print-mutate`（1–8 张循环） | text(写变体要求) + image(功能=**印花变体**, batchSize=N) | 1 文 + 1 图 |
| T9 局部修改 | `mask-redraw` | text + image(功能=**局部修改**, needsMask → 出现蒙版编辑) | 1 文 + 1 图 + 蒙版 |
| T10 文生款式 | `sketch-to-render`（纯文本模式） | text(款式描述) + image(功能=**文生图**) | 1 文 |
| T11 上身动效 | （无） | text + video(功能=**图生视频**)；款式图作首帧 | 1 文 + 1 图 |
| T12 提示词打磨 | （无） | text → text(功能=**润色/生成**) → 采纳 | 1 文 |

## 4. 与三节点模型的吻合度检查

- **全覆盖** ✓：12 个任务全部能表达，无「旧能做、新做不了」的项。
- **两处刻意收窄**（用户已裁定 ✓）：
  - 「一色一图」精确循环取消（Q4=A）→ T3/T8 改为「提示词正文写配色/变体要求 + batchSize 控制张数」；牺牲一色一图的精确控制。
  - 无「结果节点」（Q2=A）→ 产物在各节点上 + 结果面板汇总。
- **新增能力**：文本节点可运行（T12）、视频节点（T11）。
- **对「功能（提示词）」的最小要求**（供 R-41 对照）：草图渲染 / 改款 / 面料替换 / 高清放大 / 图案迁移 / 场景合成 / 印花提取 / 印花变体 / 局部修改（needsMask）/ 文生图 / 图生视频 / 文生视频 / 提示词润色 / 提示词生成 —— 共 14 项起步，与旧六族 + 新增一一对应。

## 5. 给 R-40 / R-41 的对照要求

- **R-40（悬浮窗口）**：窗口必须让用户在上面每条流水线上**一眼完成**「选功能 → 调参数 → 选模型 → 运行」；特别是 T3/T5/T6 的**多图参考**场景，用户要能确认「第几张是面料/图案/场景」（靠序号徽标 + 提示词正文回显 ✓）。
- **R-41（功能契约）**：功能清单以本表 §4 的 14 项起步；每条要能回答「它服务哪个任务（T#）、需要几张参考图、是否需要蒙版、适用哪些模型」。
