# 需求：三基础节点模型重构（文本 / 图片 / 视频）

- 状态：**需求已定稿（用户逐项裁定）**，等待架构方案
- 日期：2026-09-18
- 提出人：用户；完善人：orchestrator
- 关联：本文档是 architect 出技术方案的**唯一输入**；UI 主题方案（`docs/design/2026-09-18-editorial-canvas/`）等本重构定稿后再落地

## 1. 目标

把现有 **9 种节点**（`image-input` / `sketch-to-render` / `ai-modify` / `fabric-recolor` / `upscale` / `print-extract` / `print-mutate` / `mask-redraw` / `result`）**收敛为 3 种基础节点**：`text` / `image` / `video`。

核心思想：**功能从「结构」退化为「内容」**——具体功能（改款、换色、扩图、印花提取…）不再由节点类型承载，而是**选择系统提示词**。所有模板都是这 3 种节点的组合；以后加/改功能只改提示词目录，不动节点模型。

## 2. 已确认需求（用户逐项裁定，不得擅自变更）

| # | 项 | 裁定 |
|---|---|---|
| R1 | 节点类型 | `text` / `image` / `video` 三种；**`result` 节点取消** |
| R2 | 提示词承载 | **提示词正文由文本节点承载**（画布上可见、可连线的节点） |
| R3 | 强制约束 | **每个 `image`/`video` 节点必须有上游 `text` 节点提供提示词**（强制，不是可选） |
| R4 | 悬浮窗口职责 | **功能选项（选哪条系统提示词）+ 技术参数 + 模型选择** |
| R5 | 模型参数 | **取消 `modelOptions` 硬校验**；UI **保留默认值/推荐值**（用户可改） |
| R6 | 提示词治理 | **保留**现有评估/发布链（`docs/ai/evaluation` + release registry）——用户选的是**已发布**的功能提示词 |
| R7 | 历史数据 | **不做迁移，直接不兼容**：旧草稿 + 旧模板 + **已保存项目全部清掉**（用户明确接受不可逆） |
| R8 | 输入/输出 | 「图片」节点**同时承担输入（上传）与输出（结果）** |
| R9 | 顺序 | **本次重构优先**；UI 主题方案等本重构定稿后再落地 |
| R10 | 文本/视频模型 | 由 architect **提案**（含 API易 现有可用模型对比）→ **用户确认后**才定 |

## 3. 必须一并解决的既有约束（易漏，请在方案中逐条回应）

1. **CI 门禁口径要改**：现在门禁里有模型参数契约校验（`modelOptions` / model-contracts / `docs:apiyi:check`）；R5 放开后它**不能再当硬校验**，须降级为「推荐值/元数据」，并同步调整门禁与相关测试。
2. **既有测试与 e2e 大量引用旧节点类型**：`tests/workflow-schema.test.ts`、`tests/text-edit-coalescing.test.ts`、`tests/project-tabs.test.ts`、`tests/dag.test.ts`、`e2e/**` 等 → 需给出同步清单。
3. **`result` 节点的能力要归位**：结果汇总、导出、历史、关联证据等 UI/接口，在取消该节点后归到哪里。
4. **多图参考**：原 `image-input` 的参考图列表（多张参考图 + 角色/顺序语义）在新模型下如何表达。
5. **R3 的强制如何落地**：画布层约束 + schema 校验 + 运行前置检查，三处要有统一语义（并说明违反时的用户可见反馈）。
6. **提示词目录的治理**：功能提示词目录将成为新的「功能清单」——谁能新增、如何评审、如何回滚、与 release registry 的关系。
7. **清理方案**：R7 的不可逆操作要说清**范围**（哪些表/哪些行）、**执行方式**、**不可逆提示**，以及是否给用户一次导出机会。
8. **模板格式**：模板 = 3 种节点组合 + 每个 `image`/`video` 节点的上游 text 内容 + 窗口预设（功能/模型/参数）。
