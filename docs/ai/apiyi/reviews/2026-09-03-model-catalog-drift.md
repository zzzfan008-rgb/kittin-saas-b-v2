## 数据质量判定

- **粒度**：单次、已认证、配置令牌/账户范围的模型目录响应。
- **完整性**：对预定六模型的精确覆盖为 5/6；用于六模型发布门禁时不完整，严重程度为阻断。
- **有效性**：HTTP 200 且响应可提取规范化 ID 集合；已保存集合哈希。由于未在仓库保留原始全量导出，无法仅凭脱敏记录定位减少的三个 ID。
- **一致性**：本地 API易 Grok 文档仍声明 `grok-imagine-image`，而配置令牌目录连续两次缺失该精确 ID，属于文档契约与账户级实测冲突。
- **时效性**：本次观测晚于 2026-09-02 证据，并明确显示目录已漂移；它应作为当前最新的账户级线索。
- **置信边界**：对“当前配置令牌没有列出该 ID”置信度高；对“API易全局已移除该模型”或“端点一定不可用”证据不足。

## 决策

1. 保持 `grok-imagine-image` 产品组合为 `unverified` 并继续禁用。
2. `sources.json.modelCatalog.reviewedExportSha256` 继续为 `null`，不得把本次脱敏哈希提升为人工批准基线。
3. 不修改六模型生产契约，不添加别名，不把相似 Grok 文本/代码模型作为图片模型回退。
4. 先向 API易确认当前令牌白名单、账户分组和 `grok-imagine-image` 精确 ID 的可见性；问题解决后重新取得可人工复核的 `/v1/models` 导出。
5. 未获得单独的付费评估授权前，不调用 Grok 或其他模型的图片生成/编辑端点。
