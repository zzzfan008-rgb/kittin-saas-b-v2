# 令牌的按量優先/按次計費有什麼區別？

> 詳細說明API易令牌的5種計費模式、使用場景和最佳實踐

## 快速答案

<Info>
  **推薦設定**：建立令牌時，\*\*計費模式選擇"按量優先"\*\*即可，適用於絕大多數場景。
</Info>

雖然系統提供了 5 種計費型別，但\*\*預設使用"按量優先"\*\*就能覆蓋所有模型的呼叫需求。

## 5 種計費模式詳解

### 1. 按量計費

**定義**：根據輸入和輸出的 **Token 數量**計費，使用多少 Tokens 扣多少費用。

**適用模型**：

* **文本生成模型**：GPT-4、Claude、Gemini、DeepSeek 等
* **多模態理解模型**：支援圖片/音訊輸入的模型
* **特殊圖片模型**：`gpt-image-1`（按 Tokens 計費）

**計費方式**：

```
總費用 = (輸入 Tokens × 輸入價格) + (輸出 Tokens × 輸出價格)
```

**示例**：

* `gpt-4o`：輸入 \$5/百萬 tokens，輸出 \$15/百萬 tokens
* `claude-3-5-sonnet-20241022`：輸入 \$3/百萬 tokens，輸出 \$15/百萬 tokens

<Tip>
  **gpt-image-1 特殊說明**：雖然是圖片生成模型，但按 Tokens 計費。影響 Tokens 的因素包括：

  * 圖片解析度（1024x1024、1792x1024 等）
  * 圖片品質（standard、hd）

  OpenAI 官方提供了詳細的計費表，不同解析度和品質對應不同的 Token 消耗。
</Tip>

***

### 2. 按次計費

**定義**：每次呼叫**固定扣費**，不受輸入和輸出 Tokens 影響。

**適用模型**：

* **圖片生成模型**：DALL-E、Flux、Sora Image 等（除了 gpt-image-1）
* **影片生成模型**：Sora Video、VEO 等

**計費方式**：

```
總費用 = 呼叫次數 × 單次價格
```

**示例**：

* `gemini-3-pro-image-preview`（別名 `nano-banana-pro`）：\$0.09/次
* `sora_video2`：\$0.15/次（10秒影片）
* `flux-1.1-pro`：\$0.04/次

<Note>
  **按次計費的優勢**：

  * 價格透明，每次生成固定費用
  * 無需計算 Token 消耗
  * 適合圖片/影片等固定輸出場景
</Note>

***

### 3. 混合計費

**定義**：同時支援按量和按次兩種計費方式，根據模型自動選擇。

**狀態**：⚠️ **不適用**

<Warning>
  目前 API易 平臺**不推薦使用"混合計費"模式**，該模式可能導致計費混亂。建議使用"按量優先"替代。
</Warning>

***

### 4. 按量優先（推薦）

**定義**：**智慧計費模式**，當模型同時支援按量和按次計費時，**優先使用按量計費**；如果模型只支援按次，則自動切換為按次計費。

**為什麼推薦？**

* ✅ **包含按次計費**：可以呼叫圖片/影片等按次計費模型
* ✅ **包含按量計費**：可以呼叫文本/多模態等按量計費模型
* ✅ **自動適配**：系統自動選擇最合適的計費方式
* ✅ **覆蓋全場景**：400+ 模型全部支援

**計費邏輯**：

```
如果模型支援按量計費 → 使用按量計費
如果模型只支援按次計費 → 使用按次計費
```

**示例場景**：

| 模型                           | 計費方式 | 說明               |
| ---------------------------- | ---- | ---------------- |
| `gpt-4o`                     | 按量計費 | 文本模型，優先按量        |
| `gpt-image-1`                | 按量計費 | 圖片模型但按 Tokens 計費 |
| `gemini-3-pro-image-preview` | 按次計費 | 圖片模型，自動切換為按次     |
| `sora_video2`                | 按次計費 | 影片模型，自動切換為按次     |

<Info>
  **推薦理由**：使用"按量優先"令牌，可以呼叫所有模型，無需為不同模型建立不同計費模式的令牌。
</Info>

***

### 5. 按次優先

**定義**：當模型同時支援按量和按次計費時，**優先使用按次計費**；如果模型只支援按量，則自動切換為按量計費。

**適用場景**：

* 需要固定成本的場景
* 主要使用圖片/影片生成模型

**計費邏輯**：

```
如果模型支援按次計費 → 使用按次計費
如果模型只支援按量計費 → 使用按量計費
```

<Note>
  **使用建議**：除非有明確的成本控制需求，否則建議使用"按量優先"，因為文本模型按量計費通常更划算。
</Note>

***

## 如何選擇計費模式？

### 推薦方案（適合 95％ 使用者）

<Card title="按量優先（預設推薦）" icon="star">
  **適用場景**：

  * 同時使用文本、圖片、影片模型
  * 不想為不同模型建立不同令牌
  * 需要最大靈活性

  **優勢**：

  * 覆蓋所有 400+ 模型
  * 系統自動選擇最優計費方式
  * 無需額外配置
</Card>

### 特殊場景

<Tabs>
  <Tab title="純文本應用">
    **場景**：只使用 GPT、Claude、Gemini 等文本模型

    **推薦計費模式**：按量優先 或 按量計費

    **原因**：文本模型都是按量計費，兩種模式效果相同
  </Tab>

  <Tab title="純圖片/影片應用">
    **場景**：只使用 DALL-E、Flux、Sora 等生成模型

    **推薦計費模式**：按量優先 或 按次優先

    **原因**：圖片/影片模型大多按次計費，但"按量優先"也能自動適配

    **注意**：如果使用 `gpt-image-1`，必須使用"按量優先"或"按量計費"
  </Tab>

  <Tab title="成本控制">
    **場景**：嚴格控制預算，希望每次呼叫成本固定

    **推薦計費模式**：按次計費 或 按次優先

    **原因**：按次計費價格固定，便於成本預測

    **限制**：無法呼叫文本模型（如 GPT-4、Claude）
  </Tab>
</Tabs>

## 常見問題

<AccordionGroup>
  <Accordion title="為什麼 gpt-image-1 需要按量計費令牌？">
    `gpt-image-1` 是 OpenAI 的官方圖片生成模型，雖然是圖片生成，但計費方式與文本模型類似，**按 Tokens 計費**。

    **計費因素**：

    * 圖片解析度（1024x1024 消耗約 5000 tokens，1792x1024 消耗約 8500 tokens）
    * 圖片品質（HD 品質會增加 Token 消耗）

    **解決方案**：

    * 使用"按量優先"或"按量計費"令牌
    * 如果使用"按次計費"令牌，將無法呼叫 `gpt-image-1`
  </Accordion>

  <Accordion title="我已經建立了按次計費令牌，能改成按量優先嗎？">
    **可以修改**。步驟如下：

    1. 登入 [API易令牌管理頁面](https://api.apiyi.com/token)
    2. 找到對應的令牌，點選右側的"編輯"按鈕
    3. 在"計費模式"下拉選單中選擇"按量優先"
    4. 儲存配置

    **注意**：修改後立即生效，不影響已有餘額。
  </Accordion>

  <Accordion title="按量優先和按次優先有什麼區別？">
    **優先順序不同**：

    | 計費模式 | 當模型同時支援按量和按次時 | 適用場景              |
    | ---- | ------------- | ----------------- |
    | 按量優先 | 優先使用按量計費      | 主要使用文本模型，偶爾用圖片/影片 |
    | 按次優先 | 優先使用按次計費      | 主要使用圖片/影片，偶爾用文本模型 |

    **推薦**：大多數情況下使用"按量優先"即可。
  </Accordion>

  <Accordion title="如果選錯計費模式，會呼叫失敗嗎？">
    **不會立即失敗，但可能無法呼叫某些模型**。

    **示例場景**：

    * 如果令牌是"按次計費"，呼叫 `gpt-4o` 會失敗（因為 gpt-4o 只支援按量計費）
    * 如果令牌是"按量計費"，呼叫 `gemini-3-pro-image-preview` 可能失敗（因為該模型只支援按次計費）

    **解決方案**：使用"按量優先"避免這個問題。
  </Accordion>

  <Accordion title="混合計費為什麼不適用？">
    **混合計費**在理論上可以同時支援按量和按次，但在實際使用中可能導致：

    * 計費邏輯不明確
    * 成本難以預測
    * 系統相容性問題

    **替代方案**：使用"按量優先"可以達到相同效果，且更穩定可靠。
  </Accordion>
</AccordionGroup>

</Info>
