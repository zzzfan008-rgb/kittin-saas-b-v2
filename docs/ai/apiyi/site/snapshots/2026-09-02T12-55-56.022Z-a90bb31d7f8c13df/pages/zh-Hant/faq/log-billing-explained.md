# 怎麼看懂日誌裡的計費金額？

> 讀懂後臺日誌的「消費」列：按量計費與按次計費的區別、如何用介面返回的 usage 自己算成本、日誌金額為什麼是折扣前的，以及失敗的呼叫為什麼不出現在日誌裡。

## 簡短回答

後臺[日誌頁面](https://api.apiyi.com/log)的\*\*「消費」列\*\*就是這次呼叫的美元金額。看懂它只需要記住四件事：

1. **按量計費**的模型（絕大部分文本模型，以及 gpt-image-2、SeeDance 2.0 系列等）在**介面響應的 `usage` 欄位裡返回 token 數**，成本可以自己算；
2. **按次計費**的模型接口裡**不返回金額**，但單價固定，成本 = 呼叫次數 × 固定單價，同樣好算；
3. 日誌裡的金額是**折扣前**的，實際成本還要除以你的充值加贈比例（例如加贈 10% 就是 ÷1.1，約 91 折）；
4. **日誌只記錄成功計費的呼叫**——報錯是在接口裡返回的，沒有產生扣費的失敗呼叫不會出現在日誌裡，也不會計費。

<Info>
  **一句話版**：按次計費 = 固定成本；按量計費 = 按 tokens 計算，接口裡有返回。
</Info>

## 日誌各列怎麼讀

| 列  | 含義                                                                        | 注意                          |
| -- | ------------------------------------------------------------------------- | --------------------------- |
| 時間 | 該次呼叫的結算時間戳，按賬戶時區顯示（預設 UTC+0，[建議保持](/zh-Hant/faq/log-timezone-and-export)） | 提工單時報這個時間點最好定位              |
| 模型 | 實際計費所用的模型名                                                                | 帶分組字尾的模型按對應分組倍率計費           |
| 資訊 | 流式/非流式、首位元組耗時等                                                            | 排查慢響應時看首位元組耗時               |
| 提示 | 輸入 tokens                                                                 | 多模態的圖片、音訊會折算成 tokens 計入     |
| 補全 | 輸出 tokens                                                                 | 思考（reasoning）tokens 通常計入這一列 |
| 消費 | 本次呼叫金額（美元，**折扣前**）                                                        | 已含模型分組倍率，未含充值加贈的等效折扣        |

<Note>
  **按次計費的模型**在「提示 / 補全」列也可能顯示 token 數，但**金額不是由這兩列推匯出來的**——判斷方法很簡單：同參數多次呼叫金額恆定、且是 0.030000 這種整齊數字的，基本是按次計費。
</Note>

## 兩種計費方式

<CardGroup cols={2}>
  <Card title="按量計費（按 tokens）" icon="gauge">
    介面響應的 `usage` 欄位直接返回 token 數，成本 = 輸入 tokens × 輸入單價 + 輸出 tokens × 輸出單價。

    **覆蓋範圍**：絕大部分文本模型，以及 **gpt-image-2**、**SeeDance 2.0 系列**等按 token 計價的影像 / 影片模型。
  </Card>

  <Card title="按次計費（固定單價）" icon="hash">
    接口裡**不返回金額**，但每次呼叫價格確定，成本 = 次數 × 固定單價，預算最好估。

    **覆蓋範圍**：多數按張 / 按秒定價的影像、影片模型。單價在後臺「模型價格」頁面查詢。
  </Card>
</CardGroup>

## 介面能直接返回花費金額嗎

**不能返回金額，但成本完全可算**：

* **按量計費**：用響應裡的 `usage` 自己乘單價——這是官方口徑的 token 數，比任何估算都準；
* **按次計費**：單價固定，直接用次數乘即可。

之所以不在響應裡塞金額，是因為同一次呼叫的最終成本還取決於**分組倍率**和**你賬戶的充值加贈比例**，把一個"半成品金額"寫進響應反而容易誤導對賬。

### 用 usage 自己算

按量計費模型的響應裡會帶類似結構：

```json theme={null}
{
  "usage": {
    "prompt_tokens": 905,
    "completion_tokens": 1629,
    "total_tokens": 2534,
    "prompt_tokens_details": {
      "cached_tokens": 512
    }
  }
}
```

對應的成本公式：

```text theme={null}
成本 = (未命中快取的輸入 tokens × 輸入單價)
     + (命中快取的輸入 tokens × 快取命中價)
     + (輸出 tokens × 輸出單價)
```

<Tip>
  命中快取的那部分輸入按**快取命中價**計費（通常是輸入價的 0.1 倍左右），所以長上下文場景下日誌金額可能遠低於按 `prompt_tokens` 全價估算的結果。詳見[快取計費說明](/zh-Hant/faq/cache-billing)。
</Tip>

<Card title="gpt-image-2 的 token 檢視方法" icon="image" href="/zh-Hant/api-capabilities/gpt-image-2/overview">
  影像模型的 token 構成（輸入圖片、輸出圖片分別折算多少）在模型總覽頁的定價章節有實測資料
</Card>

## 為什麼日誌金額是「折扣前」的

日誌記錄的是**按模型價格算出的原始金額**。你的實際成本還要再打一次折——因為充值時拿到了加贈額度：

```text theme={null}
實際成本 = 日誌金額 ÷ (1 + 加贈比例)
```

舉個例子：某次呼叫日誌顯示 \$0.011，你的充值加贈是 10%，那麼實際成本是 `0.011 ÷ 1.1 = 0.01`，相當於打了 91 折。

| 充值加贈比例      | 換算     | 等效折扣       |
| ----------- | ------ | ---------- |
| 10%         | ÷ 1.1  | 約 91 折     |
| 12%         | ÷ 1.12 | 約 89 折     |
| 15%         | ÷ 1.15 | 約 87 折     |
| **20%（上限）** | ÷ 1.2  | **約 83 折** |

<Card title="檢視充值加贈階梯" icon="gift" href="/zh-Hant/faq/recharge-promotions">
  各檔加贈比例、首充加贈與發放規則
</Card>

<Note>
  **分組折扣不用再算一遍**：模型分組的倍率在計費時已經生效，日誌裡的金額就是含倍率的結果。需要另外折算的只有充值加贈這一層。倍率概念見[模型倍率說明](/zh-Hant/faq/model-multiplier)。
</Note>

## 失敗的呼叫會計費嗎

**不會，而且不會出現在消費日誌裡。** 這是理解日誌的關鍵一點：

<Warning>
  **報錯是在接口裡返回的，後臺日誌是記錄成功計費用的。** 所以"日誌裡沒有這條記錄"通常等價於"這次呼叫沒有扣費"。
</Warning>

典型例子：呼叫 **gpt-image-2** 時如果返回

```text theme={null}
400 Your request was rejected by the safety system
```

這類請求會被**直接返回、不做重試**，因此後臺不會產生消費記錄，也不計費。同理，VEO、Sora 2 等影片模型返回 `PUBLIC_` 字首的錯誤時，屬於上游官方內容稽核攔截，同樣不計費，調整提示詞後可直接重試。

<Tip>
  **反過來也成立，這在排查問題時非常有用**：如果日誌裡**有**這條計費記錄，說明請求確實到達了上游併產生了消耗；如果**沒有**，那問題多半發生在到達上游之前（網路、鑑權、引數校驗等）。「有沒有計費記錄」往往是定位斷連類問題最有力的判據。
</Tip>

<Note>
  **預扣額度 ≠ 計費**：請求執行前系統會先凍結一筆預估額度，請求失敗會釋放，最終按實際消耗結算。看到餘額短暫減少又恢復屬於正常現象，詳見[預扣費機制](/zh-Hant/faq/pre-deduction-quota)。
</Note>

## 常見問題

<AccordionGroup>
  <Accordion title="同一個模型，兩次呼叫的金額差很多，正常嗎？">
    正常。按量計費下金額隨用量浮動，常見原因有：

    * **輸入長度不同**：長上下文、多輪歷史、圖片和音訊都會顯著推高輸入 tokens
    * **思考 tokens**：開啟推理的模型會產生額外的輸出 tokens，計入「補全」列
    * **快取命中差異**：命中快取的輸入按更低的快取價計費，同樣的 prompt 第二次可能便宜很多
    * **影像/影片引數**：解析度、時長、張數直接決定 token 數或計費次數
  </Accordion>

  <Accordion title="日誌裡的 token 數和我自己數的對不上？">
    以**介面返回的 `usage`** 和日誌為準，兩者同源。自己統計對不上通常是因為：多模態內容（圖片、音訊）會按官方規則折算成 tokens；系統提示詞、工具定義（tools schema）也計入輸入；思考 tokens 計入輸出但不一定出現在可見文本里。
  </Accordion>

  <Accordion title="按次計費的模型在哪裡查單價？">
    登入後臺在「模型價格」頁面查詢，或檢視站內的[模型價格總覽](/zh-Hant/pricing)。按次計費模型的價格是確定值，乘呼叫次數即為成本。
  </Accordion>

  <Accordion title="呼叫失敗了但好像被扣了費，怎麼辦？">
    先在日誌裡按時間點核對是否真的產生了消費記錄。如果確認存在異常扣費，聯絡客服並提供**日誌中的時間戳和模型名**即可核查處理，我方問題導致的損失會補發額度，詳見 [SLA 保障](/zh-Hant/faq/sla-guarantee)。
  </Accordion>

  <Accordion title="日誌裡能看到我傳送的內容嗎？">
    看不到。出於隱私保護和儲存成本考慮，日誌只保留計費所需的基礎資訊（時間、模型、token 計數、金額），**不記錄具體的輸入輸出內容**。詳見[如何檢視呼叫記錄](/zh-Hant/faq/call-logs)。
  </Accordion>
</AccordionGroup>
