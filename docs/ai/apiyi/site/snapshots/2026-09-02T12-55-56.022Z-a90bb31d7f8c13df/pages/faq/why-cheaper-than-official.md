# 为什么 API易 能比官网价格低？

> 部分模型低于官网标价，来自规模化采购与厂商的渠道分发合作，不是降智或逆向。同时说明价格不是唯一标准，以及如何判断一份过低报价背后的代价。

## 简短回答

**能低是因为「量」和「渠道」，不是因为动了模型本身。**

模型厂商（尤其是国产厂商）需要分发渠道触达开发者，我们作为有稳定用量的渠道方，通过**承诺用量/低消**换到有限的采购折扣，再把这部分让给用户。我们**没有收厂商的广告费或竞价排位费**，价格完全由采购成本决定。

需要说清的是：**并非所有模型都比官网低**。OpenAI、Anthropic、Google 这类海外厂商基本不给转售折扣，这些模型我们与官网**同价**，优惠通过[充值加赠](/faq/official-pricing-advantages)体现。真正能低于官网标价的，主要是国产模型和部分有渠道合作的分组。

</Note>

## 站在模型厂商的视角：Router 的价值

厂商愿意给渠道折扣，不是慈善，而是因为聚合网关（Router）确实承担了他们自己做成本更高的事：

<CardGroup cols={2}>
  <Card title="触达增量开发者" icon="users">
    大量中小团队和个人开发者不会为单一模型单独注册、绑卡、走合规流程。渠道是这批用户唯一的入口
  </Card>

  <Card title="承接一线服务成本" icon="headset">
    集成答疑、参数排错、故障定位由我们承接。厂商不必为分散的长尾用户建中文客服团队
  </Card>

  <Card title="真实问题的反馈闭环" icon="microscope">
    我们对新模型做实测（参数兼容性、计费口径、字段完整性、稳定性），发现问题带回上游，比零散工单更有信息量
  </Card>

  <Card title="结算与合规简化" icon="file-text">
    对厂商而言是一个签约主体、一张账单，替代成千上万笔小额跨境结算
  </Card>

  <Card title="同台竞争的展示位" icon="scale">
    新模型被放在能与主流模型直接比较的位置。被开发者实际选中，是比投放更有效的证明
  </Card>

  <Card title="冷启动期的用量保证" icon="rocket">
    新模型上线初期最缺真实流量，渠道能快速带来可用的负载和反馈样本
  </Card>
</CardGroup>

<Tip>
  换句话说：这份折扣是**合作换来的**，不是靠牺牲模型质量省出来的。同一个模型，我们跑的是同一个上游。
</Tip>

## 价格不是唯一考虑：过低报价的代价

市面上确实存在比我们更低的报价。低价本身不是问题，**关键是低价从哪来**。常见的几种来源和对应风险：

| 低价来源       | 典型表现                         | 潜在代价                     |
| ---------- | ---------------------------- | ------------------------ |
| 逆向 / 网页端封装 | 无正式 usage 字段、不支持缓存计费、部分参数不生效 | 上游一改就断供，无法排障，也拿不到官方口径的账单 |
| 共享或来源不明的账号 | 价格远低于官方成本价，无法说明采购渠道          | 随时封号断供，可能涉及合规问题          |
| 降级替换       | 标称 A 模型，实际跑更小的模型或降低参数        | 效果与预期不符，且难以自证            |
| 数据变现       | 免费或极低价，条款里对日志留存语焉不详          | 请求内容可能被留存或用于训练           |
| 亏本引流       | 明显低于采购成本，强推大额预充值             | 后续涨价、限速，或预充值无法消化         |

<Warning>
  **重点看数据安全**。价格可以谈，数据泄露不可逆。接入前务必确认对方的日志留存策略、是否用于训练、企业能否签署保密条款——尤其在传输代码、客户资料、内部文档时。
</Warning>

### 怎么自己验证一份报价

<Steps>
  <Step title="小额试用，先不谈量">
    用最小金额跑通，不要一上来就大额预充值。
  </Step>

  <Step title="核对 usage 字段与官方口径">
    对比返回的 token 统计、缓存命中字段是否与官方一致。字段缺失或恒为 0，通常说明不是官方直连。
  </Step>

  <Step title="测稳定性，不只测能不能跑通">
    连续压测、观察长文本和高并发下的表现，以及首字延迟和尾部延迟。
  </Step>

  <Step title="问清数据留存策略">
    日志存多久、谁能访问、是否用于训练、能否签保密协议。
  </Step>

  <Step title="看有没有可追责的凭据">
    能否开发票、能否签合同、有没有明确的退款和补偿规则。出问题时这些才是依据。
  </Step>
</Steps>

## 我们更看重的：服务和稳定性

价格只是其中一项。真正决定长期成本的是「出问题时怎么办」：

  <Card title="多渠道容灾" icon="git-branch">

  </Card>

  <Card title="实测与故障复盘" icon="clipboard-check">

## 那 API易 的价格到底怎么定

<AccordionGroup>
  <Accordion title="海外主流模型（OpenAI / Claude / Gemini 等）">
    与官网**同价**。这类厂商不提供转售折扣，同价已经是正常水位，低于官方成本的报价往往意味着非官方来源。优惠通过**充值加赠**实现，部分分组另有折扣且可以叠加。
  </Accordion>

  <Accordion title="国产模型与部分合作分组">
    可以**低于官网标价**，具体幅度取决于当期采购条件，以后台「模型价格」页面显示为准。
  </Accordion>

  <Accordion title="人民币计价">
    按 **1:7 固定汇率**换算，不随实时汇率波动，方便预算和对账。详见[人民币如何换算](/faq/rmb-to-computing-power)。
  </Accordion>

  <Accordion title="我们不承诺「全网最低」">
    我们承诺的是**价格可解释、来源可追溯**：每一个低于官网的价格都能说清折扣从哪来。做不到的低价我们不跟。
  </Accordion>
</AccordionGroup>

## 常见问题

<AccordionGroup>
  <Accordion title="别家报价比你们低，是不是你们没优势？">
    有可能对方拿到了更好的采购条件，这很正常；也有可能来源不同。建议按上面的「怎么自己验证一份报价」核对一遍——重点看 usage 字段是否完整、稳定性如何、数据留存怎么约定。如果对方各项都经得起验证，那是合理的价格差；如果说不清来源，低出来的部分就是风险溢价。
  </Accordion>

  <Accordion title="价格低会不会牺牲模型质量？">
    不会。我们是官方直连转发，不降智、不偷换模型、不降参数。同一模型的输出可以自行做对比验证，详见[企业服务是否值得信任](/faq/enterprise-trust)。
  </Accordion>

  <Accordion title="折扣会不会突然取消？">
    定价随上游采购条件变化会调整，调整会在站内公告。已到账的余额不受影响，也不会出现「充值后单方面涨价把余额吃掉」的情况。
  </Accordion>

  <Accordion title="为什么不干脆所有模型都定得比官网低？">
    因为做不到的部分不会硬撑。海外主流厂商没有转售折扣空间，强行压价只能换渠道来源，代价是稳定性和数据安全。我们宁可在这些模型上保持同价，把优惠放在充值加赠上。
  </Accordion>

  <Accordion title="你们靠什么盈利？">
    靠采购价与售价之间的合理差额，以及规模带来的运营效率。部分模型为了保证供应几乎不盈利，我们接受这种结构——用户的模型选择是完整的，比单点毛利更重要。
  </Accordion>
</AccordionGroup>
