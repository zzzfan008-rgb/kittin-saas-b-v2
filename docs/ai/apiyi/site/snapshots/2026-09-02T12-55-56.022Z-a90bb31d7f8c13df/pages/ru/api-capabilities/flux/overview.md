# Генерация и редактирование изображений FLUX

> Семейство моделей FLUX от Black Forest Labs — от субсекундной FLUX.2 [klein] до флагманской [max] с 4 МП, с поддержкой генерации изображений по тексту, редактирования по нескольким референсам, типографики и точного управления HEX-цветом. Совместимая с OpenAI замена без доработок.

## Обзор

**FLUX** — это флагманское семейство моделей генерации изображений от Black Forest Labs (BFL), базирующейся в Германии. Последнее поколение **FLUX.2** охватывает 5 уровней — от менее чем секунды до флагманского качества 4MP, а также предыдущее поколение **FLUX.1 Kontext** для редактирования изображений — всего 7 активных моделей. Наследуемые модели FLUX.1 \[pro] также по-прежнему доступны для вызова. Шлюз APIYI оборачивает асинхронный polling API BFL в синхронный OpenAI Images API (`/v1/images/generations` и `/v1/images/edits`), так что вы можете подключить OpenAI SDK, изменив только `base_url`.

<Note>
  **🎨 Ключевые особенности**: FLUX.2 \[max] уникально поддерживает **grounding search** для получения актуальных знаний из веба в реальном времени. Нативный вывод 4MP (2048×2048) + до 8 изображений с несколькими референсами + prompt размером до 32K token + точный контроль HEX-цветов + лучшая в классе типографика. **Идеально подходит для флагманского качества, согласованности между несколькими изображениями, точной передачи фирменных цветов и профессиональных макетов** в production.
</Note>

<Info>
  Все API для изображений — **синхронные** — вам не нужно опрашивать task ID, и если ваш клиент отключится, результат будет утерян, при этом запрос всё равно будет тарифицироваться. Установите достаточно большой таймаут для этой модели; см. [Основы и лучшие практики API изображений](/ru/api-capabilities/image-api-best-practices).
</Info>

<Prompt description="Поручите кодирующему агенту интегрировать FLUX text-to-image и редактирование изображений или устранить неполадки. Скопируйте и вставьте в Codex, Claude Code, Cursor и похожие инструменты." icon="bot" actions={["copy"]}>
  Интегрируйте / устраните неполадки в FLUX text-to-image и редактировании изображений в этом проекте.

  Прежде чем трогать код, прочитайте документацию: получите [https://docs.apiyi.com/en/api-capabilities/flux/overview.md](https://docs.apiyi.com/en/api-capabilities/flux/overview.md) как текстовую версию этой страницы. Для более точных сведений о параметрах добавляйте `.md` к страницам text-to-image и редактирования изображений тем же способом.

  Требования:

  1. Таймаут: установите таймаут клиента на 120 секунд, или на 180 секунд, если вы используете `flux-2-flex`. API для изображений синхронны — task ID нет, поэтому если клиент отключится, результат будет потерян, хотя запрос всё равно будет тарифицироваться. Обратные прокси, шлюзы и лимиты serverless-исполнения тоже нужно расширить: любой слой, работающий меньше времени генерации, оборвёт запрос.

  2. Обработка ответа (**самый важный пункт для этой модели**): FLUX **возвращает только URL и никогда не base64** — результат находится в `data[0].url`. Не ищите `b64_json` и не отправляйте `response_format`. Эта подписанная ссылка **действительна лишь около 10 минут**, и **CORS не включён**: получить её напрямую из браузера блокируют правила междоменных запросов (если поместить ссылку в тег image `src`, всё отображается нормально). Поэтому правильный подход такой: **немедленно скачайте URL на стороне сервера и перехостите его в своём объектном хранилище**, а затем передайте на frontend свою постоянную ссылку. Никогда не храните upstream-ссылку в своей базе данных как долговременный адрес. Также учтите, что эта модель не возвращает поле **`usage`**, поэтому не ожидайте количества token в ответе.

  3. Загрузка reference images: multi-image fusion проходит через `/v1/images/generations` с использованием полей JSON `input_image`, `input_image_2` и так далее до `input_image_8`; каждое значение может быть URL изображения или data URL в форме `data:image/...;base64,...`. Эндпоинт `/v1/images/edits` (multipart) **принимает только одно изображение, а поле файла должно называться `image`** — всё остальное возвращает `image is required`. Лимиты на reference images зависят от модели: до 8 для FLUX.2 pro / max / flex, до 4 для klein и только 1 для FLUX.1 Kontext. Сжимайте перед загрузкой — обрабатывайте только файлы больше 1.5MB, уменьшайте длинную сторону до 2048px с сохранением пропорций (никогда не увеличивайте маленькое изображение), перекодируйте с качеством 0.9 и сохраняйте исходный формат; любое отдельное изображение держите меньше 20MB и 20 мегапикселей. Если одно изображение не удаётся сжать, вернитесь к оригиналу и продолжайте.

  4. Параметры размера: используйте либо `size` (например `1024x1024`), либо два целых числа `width` и `height` — обе формы эквивалентны, выберите одну. **Оба измерения должны быть кратны 16**, как минимум 64 на 64 и максимум примерно 4 мегапикселя (рекомендуется 2 мегапикселя или меньше). Учтите, что `1000x1000` недопустимо, потому что это не кратно 16, а `3840x2160` недопустимо, потому что это превышает 4 мегапикселя — проверяйте оба правила перед отправкой, если ваш UI позволяет пользователям вводить размеры. Для редактирования `aspect_ratio` управляет формой, а если его опустить, выходное изображение будет следовать форме первого входного изображения. У этой модели нет параметра **`quality`**; только `flux-2-flex` предоставляет `steps` (по умолчанию 50) и `guidance` (по умолчанию 4.5) как параметры качества. Управляйте стоимостью через выбор модели: klein — самая дешёвая, max — самая дорогая, редактирование стоит столько же, сколько генерация, а дополнительные reference images ничего не добавляют.

  5. Прочее: при вызове через OpenAI SDK параметры FLUX должны помещаться внутрь `extra_body`, чтобы вообще передаваться далее. `prompt_upsampling` по умолчанию выключен и переписывает ваш prompt, так что для брендовых материалов оставляйте его выключенным. `webhook_url` не передаётся далее, так что не рассчитывайте на него.

  6. Читайте ключ из переменной среды `APIYI_API_KEY` и используйте [https://api.apiyi.com/v1](https://api.apiyi.com/v1) как базовый URL. Никогда не зашивайте его в код, никогда не коммитьте его в git.

  7. Когда закончите, реально выполните один вызов text-to-image и один вызов image-edit, а затем покажите мне результаты и стоимость этих двух вызовов.
</Prompt>

## Эндпоинты API

| Эндпоинт                      | Назначение                                                                                                                                                               | Тип содержимого       |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------- |
| `POST /v1/images/generations` | Генерация изображений по тексту + редактирование изображений / слияние нескольких референсов (JSON `input_image` \~ `input_image_8`, **рекомендуется**, все модели FLUX) | `application/json`    |
| `POST /v1/images/edits`       | Совместимое с OpenAI редактирование одного изображения (`client.images.edit()` drop-in; проверено на серии Kontext)                                                      | `multipart/form-data` |

Для слияния нескольких референсов используйте `/generations` (JSON `input_image_N`). Эндпоинт `/edits` принимает только один файл `image` — лучше всего подходит для переноса существующего кода редактирования OpenAI SDK.

<Tip>
  **Варианты домена**: `api.apiyi.com` — основной домен. Альтернативные домены шлюза, такие как `b.apiyi.com` / `vip.apiyi.com`, работают идентично.
</Tip>

## Размер (ширина / высота) в деталях

### Типовые размеры

| Size        | Aspect           | Pixels  | Best For                              |
| ----------- | ---------------- | ------- | ------------------------------------- |
| `1024x1024` | Квадрат 1:1      | \~1MP   | Общие задачи, аватары в соцсетях      |
| `1024x1536` | Портретный 2:3   | \~1.6MP | Постеры, портреты                     |
| `1536x1024` | Альбомный 3:2    | \~1.6MP | Пейзажи, рабочий стол                 |
| `1440x2048` | Портретный \~3:4 | \~2.9MP | Вертикальный кинематографичный формат |
| `1920x1080` | Альбомный 16:9   | \~2MP   | Миниатюры для видео                   |
| `2048x2048` | Квадрат 1:1      | 4MP     | Флагманская печать (лимит FLUX.2)     |

### Ограничения пользовательского размера

FLUX.2 принимает произвольные размеры, если выполняются **все** следующие условия:

1. **ширина / высота должны быть кратны 16**
2. **Минимум 64×64**
3. **Максимум \~4MP** (например, 2048×2048 / 1920×2048 / 2048×1920)
4. **Рекомендуемый итоговый размер ≤ 2MP**, чтобы сбалансировать скорость и стоимость

**Допустимые примеры**: `1280x720`, `1920x1080`, `2048x1024`, `1456x1920`
**Недопустимые примеры**: `1000x1000` (не кратно 16), `3840x2160` (превышает 4MP), `32x32` (ниже 64×64)

<Warning>
  **API: width/height vs OpenAI-compatible size**: BFL нативно использует целые `width` / `height`. APIYI также принимает строку `size: "1024x1024"` в стиле OpenAI. Оба варианта эквивалентны — выберите любой.
</Warning>

## Лучшие практики

<Steps>
  <Step title="Выбирайте модель по сценарию">
    Флагманская финальная версия + нужна информация в реальном времени → `flux-2-max`. Пакетная обработка в production → `flux-2-pro`. Постеры / инфографика с типографикой → `flux-2-flex`. Реальное время с высокой пропускной способностью → `flux-2-klein-9b`. Редактирование изображений → `flux-kontext-max` или `flux-kontext-pro`.
  </Step>

  <Step title="По умолчанию используйте ≤ 2MP">
    Оптимальный баланс скорости и стоимости — 1MP–2MP. К 4MP стоит прибегать только при реальной необходимости (печать, экраны 4K). При высоком разрешении klein заметно увеличивает стоимость каждого вызова.
  </Step>

  <Step title="Указывайте референсные изображения по индексу в prompt">
    Нумерация `input_image` / `input_image_2` / `input_image_3` — это в точности индекс «image 1 / image 2 / image 3» в вашем prompt. Скажите «человек с изображения 1 в сцене изображения 2 с цветовой палитрой изображения 3» — это гораздо надежнее, чем заставлять model угадывать.
  </Step>

  <Step title="Сразу скачивайте URLs результата">
    `data[0].url` **действителен только 10 минут**, размещен на `delivery-eu.bfl.ai` / `delivery-us.bfl.ai`, при отключенном CORS. В production необходимо скачивать их на стороне сервера в свой CDN.
  </Step>

  <Step title="Фиксируйте типографику на flex или max">
    Подписи, постеры, скриншоты UI — отдавайте предпочтение `flux-2-flex` (специалист по типографике) или `flux-2-max` (наивысшее общее качество). Другие модели по-прежнему могут размывать мелкий текст.
  </Step>

  <Step title="Используйте max для grounding-поиска">
    Знания в реальном времени («погода сегодня», «матч прошлой ночи») поддерживаются только на `flux-2-max`. Остальные модели опираются на данные обучения и не могут получать актуальную информацию.
  </Step>

  <Step title="Тайм-аут клиента 60–120s">
    APIYI обрабатывает polling внутри, а pro / max возвращают результат менее чем за 15 s, но с учетом очередей и сетевого jitter установите тайм-аут клиента на 60–120 s. flex может доходить до 180 s.
  </Step>

  <Step title="Фиксируйте seed для воспроизводимости">
    Один и тот же `seed` + одинаковые остальные параметры = стабильные результаты, полезно для A/B-тестов и проверки клиентом. klein не поддерживает `prompt_upsampling`; у pro/max/flex он отключен по умолчанию — включайте при необходимости.
  </Step>
</Steps>

## Коды ошибок и повторные попытки

| Статус  | Значение                                                                                         | Рекомендуемое действие                                                        |
| ------- | ------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------- |
| `400`   | Недопустимые параметры (ширина/высота не кратны 16, превышен лимит 4MP, prompt более 32K tokens) | Проверьте соответствие ограничениям по размеру, особенно правилу кратности 16 |
| `401`   | Недопустимый token                                                                               | Проверьте Bearer token                                                        |
| `403`   | Блокировка модерацией                                                                            | Измените prompt или увеличьте `safety_tolerance` (макс. 6)                    |
| `429`   | Превышен лимит запросов / баланс исчерпан / превышено число активных задач                       | Повтор с экспоненциальной задержкой                                           |
| `5xx`   | Ошибка шлюза / backend                                                                           | Повторите 1–2 раза                                                            |
| Timeout | Длинный хвост                                                                                    | Тайм-аут клиента ≥ **60s** (с возможностью увеличения до 180s)                |

<Info>
  **Рекомендуемая конфигурация клиента**:

  * Тайм-аут запроса **60–120s** (с возможностью увеличения до 180s)
  * Экспоненциальная задержка повторов для 5xx и 429 (рекомендуется 2 повтора)
  * Как только получен `data[0].url`, **сразу скачивайте асинхронно** — не ждите клика пользователя
  * Логируйте заголовок ответа `x-request-id` для поддержки
</Info>

## Часто задаваемые вопросы

<AccordionGroup>
  <Accordion title="Почему поле url истекает через 10 минут?">
    BFL хранит результаты на `delivery-eu.bfl.ai` / `delivery-us.bfl.ai` с подписанными URL, действительными 10 минут, **и CORS отключен**. Производственные сервисы должны на стороне сервера загружать их в ваш собственный OSS / CDN. Не передавайте исходный URL в браузеры и не рассчитывайте, что пользователи смогут открыть его позже.

    APIYI наследует тот же механизм URL — поведение совпадает с официальным каналом.
  </Accordion>

  <Accordion title="Официальный API использует асинхронный опрос — как APIYI делает его синхронным?">
    Шлюз APIYI берет опрос на себя: вы отправляете стандартный запрос OpenAI Images API, шлюз внутри отправляет POST в BFL, опрашивает `polling_url` до `Ready`, затем оборачивает итоговый URL `result.sample` как `data[0].url` и возвращает его. С точки зрения клиента это один запрос-ответ — идентично OpenAI / GPT-Image / Nano Banana.
  </Accordion>

  <Accordion title="Сколько референсных изображений я могу отправить? Как писать prompt?">
    * **FLUX.2 \[pro/max/flex]**: до **8**
    * **FLUX.2 \[klein]**: до **4**
    * **FLUX.1 Kontext \[pro/max]**: один референс (для нескольких изображений нужна склейка на стороне клиента)

    Ссылайтесь на них по индексу («изображение 1 / изображение 2 / изображение 3») в prompt, например: «поместите человека из изображения 1 в сцену из изображения 2, применив цветовую палитру изображения 3». Также работают ссылки на естественном языке — модель хорошо понимает входные изображения.
  </Accordion>

  <Accordion title="Что делает prompt_upsampling? Стоит ли его включать?">
    `prompt_upsampling=true` автоматически расширяет и уточняет ваш prompt (особенно полезно для коротких prompt). Но **это меняет исходный замысел** — держите его выключенным для брендовых задач и включенным для свободного эксперимента.

    **Ограничение**: FLUX.2 \[klein] это не поддерживает (если передать, будет молча проигнорировано).
  </Accordion>

  <Accordion title="Как использовать grounding search?">
    Это поддерживает только `flux-2-max`. **Никаких специальных параметров не нужно** — если вашему prompt нужны знания в реальном времени, модель автоматически выполнит поиск в сети перед генерацией. Пример:

    > «Сгенерируйте новостное фото снежной бури, накрывшей Нью-Йорк 15 декабря 2025 года»

    Отлично подходит для «счета вчерашнего матча», «погоды в реальном времени», «воссоздания исторического события», «последних трендов». Prompt без чувствительного ко времени контента не запустит поиск и будет тарифицироваться как обычная генерация.
  </Accordion>

  <Accordion title="Как эффективнее всего использовать hex-цвета?">
    Пишите hex-коды напрямую в prompt с явными маркерами «color» или «hex»:

    ```
    A vase on a table, the color of the vase is gradient from #02eb3c to #edfa3c, the flowers have color #ff0088
    ```

    Или для брендовых задач с несколькими цветами:

    ```
    Luxury eyeshadow palette with 6 pans: top row #B76E79, #E8D5B7, #8B4789; bottom row #CD7F32, #F8F6F0, #800020
    ```

    Точность на уровне лидеров отрасли — постобработка и коррекция цвета не нужны.
  </Accordion>

  <Accordion title="Что такое структурированный JSON prompting?">
    FLUX.2 поддерживает prompt в формате JSON:

    ```json theme={null}
    {
      "subject": "Mona Lisa painting by Leonardo da Vinci",
      "background": "museum gallery wall, ornate gold frame",
      "lighting": "soft gallery lighting",
      "style": "digital art, high contrast",
      "camera_angle": "eye level view",
      "composition": "centered, portrait orientation"
    }
    ```

    Передавайте JSON-строку в поле `prompt`. Идеально для производственной автоматизации и пакетной генерации по шаблону.
  </Accordion>

  <Accordion title="Какой endpoint мне использовать для редактирования изображений?">
    Два варианта:

    * **Вариант A (рекомендуется)**: JSON + `input_image` (\~ `input_image_8`) в `/v1/images/generations` — работает для всех моделей FLUX и поддерживает слияние нескольких референсов
    * **Вариант B**: `multipart/form-data` в `/v1/images/edits` — имя поля файла должно быть `image` (одно изображение), напрямую совместимо с `client.images.edit()` OpenAI SDK, проверено на серии Kontext

    См. [API редактирования изображений](/ru/api-capabilities/flux/image-edit) для параметров и примеров.

    **Примечание**: FLUX.1 Kontext нативно поддерживает только один референс; FLUX.2 поддерживает до 8 референсов (через Вариант A).
  </Accordion>

  <Accordion title="Могу ли я напрямую использовать официальный SDK OpenAI?">
    Да, без изменения кода. Установите `base_url` в `https://api.apiyi.com/v1`:

    ```python theme={null}
    from openai import OpenAI
    client = OpenAI(api_key="sk-your-key", base_url="https://api.apiyi.com/v1")
    resp = client.images.generate(
        model="flux-2-pro",
        prompt="...",
        size="1024x1024"
    )
    ```

    То же самое для пакета Node.js `openai`. Все модели FLUX используют формат ответа OpenAI Images API с `data[0].url`.
  </Accordion>

  <Accordion title="Могу ли я отменить выполняющуюся задачу?">
    **Не поддерживается**. Если клиент отключится, сервер все равно завершит генерацию и тарифицирует ее как обычно. Задавайте таймауты на стороне клиента и не полагайтесь на «отключение = нет тарификации».
  </Accordion>

  <Accordion title="Каковы лимиты запросов и ограничения на параллельные запросы?">
    BFL ограничивает каждый аккаунт **24 активными задачами**, а `flux-kontext-max` отдельно ограничивает до **6**.

    APIYI агрегирует нагрузку на шлюзе, поэтому корпоративные параллельные запросы не ограничены потолком на уровне аккаунта. Для явных обязательств по SLA / RPM свяжитесь с нашей командой, чтобы получить выделенную квоту.
  </Accordion>

  <Accordion title="Работают ли callback через webhook?">
    BFL нативно поддерживает `webhook_url` + `webhook_secret`, но обертка APIYI, совместимая с OpenAI, ожидает синхронно и **не передает поля webhook** — вам не нужно опрашивать систему, цикл запрос-ответ выполняется за один раз. Если вашему бизнесу действительно нужны webhook, свяжитесь с нами, чтобы включить нативный асинхронный канал.
  </Accordion>

  <Accordion title="Тарифицируются ли неудачные запросы?">
    **Нет**. `400` (ошибка параметра), `403` (блокировка модерацией), `429` (превышен лимит запросов) все возвращают ошибки и не тарифицируются. **Тарифицируются только запросы, которые фактически вошли в генерацию (200 + `data[0].url`)**.
  </Accordion>
</AccordionGroup>
