## Позвольте AI-агенту выполнить интеграцию

<Note>
  Если вы разрабатываете с Codex / Claude Code / Cursor, скопируйте prompt ниже и передайте его своему агенту. Сначала он получает текстовую версию этой страницы (добавьте `.md` к любому docs URL), затем пишет код в собственном стеке вашего проекта — таймаут, защитный разбор `parts`, сжатие при загрузке и параметры разрешения уже заложены в требования.
</Note>

<Prompt description="Поручите coding agent интегрировать или устранить неполадки в Nano Banana Pro для генерации изображений по тексту и редактирования изображений. Скопируйте и вставьте в Codex, Claude Code, Cursor и похожие инструменты." icon="bot" actions={["copy"]}>
  Интегрируйте / устраните неполадки в Nano Banana Pro (`gemini-3-pro-image`) для генерации изображений по тексту и редактирования изображений в этом проекте.

  Прежде чем трогать код, прочитайте документацию: получите [https://docs.apiyi.com/en/api-capabilities/nano-banana-image/overview.md](https://docs.apiyi.com/en/api-capabilities/nano-banana-image/overview.md) в текстовой версии этой страницы. Для более детальной информации о параметрах добавляйте `.md` к страницам text-to-image и image-edit так же, как указано выше.

  Требования:

  1. Таймаут: вызывайте Gemini-native формат по `POST https://api.apiyi.com/v1beta/models/gemini-3-pro-image:generateContent`. Задайте таймаут клиента в зависимости от уровня разрешения: 300 секунд для 1K и 2K и **600 секунд для 4K**. Image API синхронны — task ID нет, поэтому если клиент отключится, результат будет потерян, хотя запрос всё равно тарифицируется. Обратные прокси, шлюзы и лимиты выполнения serverless тоже нужно расширить: любой слой с таймаутом меньше времени генерации оборвёт запрос. В Node обратите внимание, что у undici есть три независимые настройки таймаута, которые опция `timeout` в SDK не покрывает.

  2. Разбор ответа (**самое простое место, где ошибиться**): изображение закодировано в base64, находится под `inlineData.data` внутри `candidates[0].content.parts[]`. Но `parts` — это **гетерогенный массив, длина и порядок которого не гарантированы**: текстовый фрагмент может идти первым, и тогда изображение окажется по индексу 1, а не 0. Поэтому **никогда не хардкодьте `parts[0]` или `parts[1]`**; переключение между ними проблему не решает. Правильный подход: итерируйтесь по `parts`, отфильтруйте каждый элемент, у которого есть `inlineData`, и возьмите **последний** из них (сложные задачи возвращают несколько промежуточных черновиков, и только последний является финальным). Также считывайте `mimeType` из ответа, а не предполагая `image/png`. Затем отобразите изображение и предложите действие сохранения на диск.

  3. Сжатие перед загрузкой: для редактирования вы передаёте референсные изображения в base64 внутри `inlineData`. Сначала сжимайте — обрабатывайте только файлы больше 1.5MB, уменьшайте длинную сторону до 2048px, сохраняя пропорции (никогда не увеличивайте маленькое изображение), повторно кодируйте с качеством 0.9 и сохраняйте исходный формат. Для запросов с несколькими изображениями держите суммарный размер ниже 6MB. Жёсткие ограничения: 7MB на изображение, не более 14 изображений на запрос и менее 100MB всего на одну загрузку; затем base64 увеличивает всё это примерно на треть, поэтому для запаса старайтесь держать каждое изображение ниже 5MB. Если одно изображение не удаётся сжать, используйте исходное и продолжайте. Также учтите: **одна часть может содержать либо `text`, либо `inlineData`, но никогда не оба сразу** — корректная структура это одна текстовая часть плюс N частей с изображениями.

  4. Параметры разрешения: явно передавайте `generationConfig.imageConfig.imageSize` (`1K` / `2K` / `4K`, по умолчанию `1K`) и `aspectRatio` (на этой странице перечислены 10 допустимых соотношений сторон) вместо того, чтобы полагаться на значения по умолчанию. Покажите оба параметра в виде выпадающих списков в вашем UI. Если пользователь выбирает 4K, увеличьте таймаут до 600 секунд. Эта модель **не** поддерживает `thinkingConfig`, а также grounding через Google Search с помощью `tools`, поэтому не передавайте ни то ни другое.

  5. Обработка ошибок: когда модерация контента блокирует запрос, HTTP status всё равно 200, но `candidates[0].content.parts` возвращается пустым. Сначала проверьте, что `candidatesTokenCount` равно 0, затем проверьте, не отличается ли `finishReason` от `STOP`. Блокировки вроде `IMAGE_SAFETY` **не тарифицируются**, а повтор той же самой загрузки один или два раза часто проходит — добавьте автоматический повтор.

  6. Читайте ключ из переменной окружения `APIYI_API_KEY` и передавайте его в заголовке `Authorization` с префиксом `Bearer`. Никогда не хардкодьте его и никогда не коммитьте в git.

  7. Когда закончите, действительно выполните один вызов генерации изображений по тексту и один вызов редактирования изображения, затем покажите мне результаты и сколько стоили эти два вызова.
</Prompt>

Используйте нативный формат Gemini API Google:

```
POST /v1beta/models/gemini-3-pro-image-preview:generateContent
```

  * ✅ 10 соотношений сторон на выбор
  * ✅ Лучший в отрасли рендеринг текста
  * ✅ Продвинутое локальное редактирование

### Неподдерживаемые возможности

<Warning>
  Следующие официальные возможности Google **не поддерживаются** через APIYI и требуют отдельной тарификации:

  * **Grounding с Google Search**: Информация поиска в реальном времени через `tools: [{"google_search": {}}]`
  * **thinkingConfig** (режим рассуждения): Поддерживается только на Nano Banana 2, но не на Nano Banana Pro
  * **Image Search Grounding**: Эксклюзивная функция Nano Banana 2

  Все остальные возможности генерации изображений и редактирования полностью поддерживаются.
</Warning>

## Поддерживаемые разрешения и соотношения сторон

### Выходные разрешения

Nano Banana Pro поддерживает три уровня разрешения — 1K, 2K, 4K (уровень 512px доступен только в Nano Banana 2):

| Разрешение | Описание     | Рекомендуемое применение                      |
| ---------- | ------------ | --------------------------------------------- |
| 1K         | По умолчанию | Социальные сети, отображение в вебе           |
| 2K         | HD           | HD-дисплеи, печатные материалы                |
| 4K         | Ultra HD     | Профессиональный дизайн, коммерческие постеры |

### Размеры вывода для каждого соотношения сторон (пиксели)

| ------------------ | --------- | --------- | --------- |
| **1:1**            | 1024×1024 | 2048×2048 | 4096×4096 |
| **2:3**            | 848×1264  | 1696×2528 | 3392×5056 |

| **4:5**            | 928×1152  | 1856×2304 | 3712×4608 |

<Info>

</Info>

## FAQ

<AccordionGroup>
  <Accordion title="Стоит ли выбирать Nano Banana 2 или Pro?">
    **Для лучшего соотношения цены и качества** выбирайте **Nano Banana 2** (`gemini-3.1-flash-image-preview`):

    * Качество уровня Pro + скорость уровня Flash
    * Оплата по мере использования, всего от \$0.025/изображение
    * 14 соотношений сторон (на 4 больше, чем у Pro)
    * Эксклюзивно: thinking mode, Image Search Grounding

    **Для максимального качества** выбирайте **Nano Banana Pro** (`gemini-3-pro-image-preview`):

    * Наивысшая точность
    * \$0.09/запрос

    Подробнее см. в [документации Nano Banana 2](/ru/api-capabilities/nano-banana-2-image/overview).
  </Accordion>

  <Accordion title="Стоит ли выбирать версию Pro или устаревшую версию?">
    **Рекомендуется для новых проектов: Nano Banana Pro** (`gemini-3-pro-image-preview`)

    ✅ **Преимущества версии Pro**:

    * Поддержка сверхвысокого разрешения 4K (1K, 2K, 4K)
    * Лучшая в отрасли качество рендеринга текста
    * Расширенные функции локального редактирования
    * Всего \~38-67% от официальной тарификации

    ⚡ **Устаревшая версия** (`gemini-2.5-flash-image`) подходит для:

    * Сценариев с чувствительностью к бюджету (\~\$0.025/изображение против \$0.09/изображение)
    * Необходимости быстрой генерации (10s против 20s)
    * Миграции существующих проектов
  </Accordion>

  <Accordion title="Как переключиться с других моделей изображений на Nano Banana?">
    Просто измените имя модели с `gpt-4o-image` или `sora_image` на `gemini-3-pro-image-preview` (рекомендуемая Pro) или `gemini-2.5-flash-image` (устаревшая), оставив остальные параметры без изменений.
  </Accordion>

  <Accordion title="В каком формате возвращаются сгенерированные изображения?">
    Модель возвращает данные изображения в формате base64, обычно в PNG или JPEG. Код автоматически определяет формат и сохраняет его в соответствующий тип файла.
  </Accordion>

  <Accordion title="Поддерживаются ли функции редактирования изображений?">
    Да, Nano Banana Pro поддерживает как генерацию изображений, так и редактирование. См. [Справочник API по редактированию изображений](/ru/api-capabilities/nano-banana-image/image-edit).
  </Accordion>

  <Accordion title="Почему я получаю connection reset by peer / write_response_body_failed (500)?">
    Полная ошибка выглядит так:

    ```text theme={null}
    [&{{write tcp ip:port->ip:port: write: connection reset by peer Unknown error shell_api_error  write_response_body_failed} 500 }]
    ```

    Обычно это **вызвано слишком большими загрузками изображений — тело запроса становится слишком большим, и соединение обрывается**. Следуйте этим рекомендациям:

    * **Ограничьте количество изображений**: соблюдайте официальные правила (максимум 14 изображений на prompt) — не добавляйте слишком много референсных изображений.
    * **Ограничьте размер одного изображения**: держите размер каждого изображения меньше 5MB — официальный лимит на одно изображение составляет 7MB, а кодирование base64 увеличивает размер примерно на 1/3, поэтому оставляйте запас.
    * **Сжимайте на frontend перед загрузкой**: сжимайте изображения на frontend (или через серверный relay) перед отправкой в API — обычно ограничивают длинную сторону, конвертируют в JPEG/WebP и подбирают параметр качества.
    * **Переключитесь на ввод через URL**: нативный формат Gemini поддерживает передачу URL изображения через `fileData.fileUri`, полностью обходя слишком большие тела запросов base64 — см. [Руководство разработчика Nano Banana](/ru/api-capabilities/nano-banana-dev-guide).
  </Accordion>
</AccordionGroup>
