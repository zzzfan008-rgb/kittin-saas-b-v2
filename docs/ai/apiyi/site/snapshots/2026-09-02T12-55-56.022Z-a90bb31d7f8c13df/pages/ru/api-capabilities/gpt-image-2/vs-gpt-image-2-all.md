# GPT-image-2 Официальный vs реверс

> Сравните gpt-image-2 (официальный) с сестринскими моделями, полученными методом реверс-инжиниринга, gpt-image-2-all и gpt-image-2-vip: тип канала, цены, эндпоинты, форматы загрузки и вывода, позиционирование по скорости и качеству, соответствие prompt — выберите подходящую модель.

## Кратко

| Если вам нужно                                                                                                                                           | Выберите                                              |
| -------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| **`quality` регулятор / inpainting по маске / произвольные пользовательские размеры (за пределами 30 пресетов) / строгое соответствие полей OpenAI API** | `gpt-image-2` (Официальный, с тарификацией по token)  |
| **Предсказуемая фиксированная \$0.03/image + быстрый результат (скорость — преимущество)**                                                               | `gpt-image-2-all` (Reverse, линия ChatGPT-web, \~90s) |
| **Предсказуемая фиксированная \$0.03/image + фиксированные размеры (30 пресетов, включая 4K) + иногда более высокое качество (если не спешите)**         | `gpt-image-2-vip` (Reverse, линия Codex, \~120–200s)  |

Все три модели **в основе построены на OpenAI gpt-image-2**. Различия — в характере канала (официальный прямой vs с обратной инженерией), модели тарификации и детализации параметров.

<Note>
  **Два обратных варианта (-all / -vip)**: Столбец «Reverse» на этой странице охватывает **и `gpt-image-2-all`, и `gpt-image-2-vip`** — у них одинаковый формат вызова (`-vip` дополнительно поддерживает поле `size`) и одна и та же фиксированная цена \$0.03/image. Сейчас разница — в **скорости vs качестве + фиксации размеров**:

  * `gpt-image-2-all`: линия ChatGPT web, **\~90s** генерация — **скорость — преимущество**
  * `gpt-image-2-vip`: линия Codex, **\~120–200s** генерация — медленнее, но **иногда более высокое качество**, и она **поддерживает фиксацию `size` (30 пресетов, включая 4K, восстановлено с 2026-07-22)**
  * Оба: без `quality`, без `n`, без inpainting по маске

  Для `quality` tiers, inpainting по маске или произвольных пользовательских размеров за пределами 30 пресетов используйте официальный `gpt-image-2`.
</Note>

<Tip>
  **О текущих скоростях**: генерация `-all` / `-vip` **медленнее, чем на запуске**, из-за **колебаний вычислительных мощностей на стороне OpenAI upstream** — это затрагивает всех пользователей reverse-канала, а не только APIYI; наш пул аккаунтов и операции в порядке. Установите таймауты клиента на 300s+ и закладывайте больший запас по времени для сложных prompt.
</Tip>

## Подробные ключевые различия

### 1. Подводный камень формата b64\_json (ловушка при миграции!)

Как было подтверждено в июле 2026 года, обе модели теперь возвращают **необработанный base64 (без префикса `data:`)** — но `gpt-image-2-all` раньше включал префикс, поэтому в общем коде безопаснее сначала проверять его наличие:

```python theme={null}
# Universal pattern: detect the prefix before processing — works for both models
b64 = resp["data"][0]["b64_json"]
if b64.startswith("data:"):          # handles historical prefixed responses
    b64 = b64.split(",", 1)[1]
with open("out.png", "wb") as f:
    f.write(base64.b64decode(b64))   # ✅ write file
img_tag = f'<img src="data:image/png;base64,{b64}">'  # ✅ browser render
```

<Warning>
  При переключении между ними **код обработки `b64_json` должен измениться**, иначе вы получите повреждённый data URL или ошибку декодирования.
</Warning>

### 2. Управление разрешением

**gpt-image-2-all** (в prompt):

```
"Landscape 16:9 cinematic, old lighthouse at sunset"   → ~1672×941
"Portrait 9:16 phone wallpaper, cyberpunk city"        → ~941×1672
"1024×1024 square logo, minimalist cat line art"        → ~1254×1254
```

**gpt-image-2-vip** (`size` восстановлен, начиная с 2026-07-22):

Поддерживает **30 предустановленных размеров** (10 соотношений × 1K/2K/4K) — передавайте `size: "WIDTHxHEIGHT"` напрямую (должно быть одним из 30 пресетов; полный список в [таблице 30 размеров](/ru/api-capabilities/gpt-image-2-vip/overview#supported-sizes-full-30-size-table)):

```python theme={null}
client.images.generate(
    model="gpt-image-2-vip",
    prompt="...",
    size="3840x2160"    # ✅ one of the 30 presets; images endpoints only (not chat)
)
```

**gpt-image-2** (`size` строгая проверка параметра + `quality` уровни):

```python theme={null}
client.images.generate(
    model="gpt-image-2",
    prompt="...",
    size="2048x1152",   # ✅ output exactly this
    quality="high"      # official-only
)
```

### 3. Различия в формате загрузки / вывода

| Операция                           | gpt-image-2-all                                                                                                                                         | gpt-image-2                                                     |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| **Загрузка референса**             | multipart `image` поле file (эндпоинт edits)                                                                                                            | multipart `image[]` поле file                                   |
| **Скачивание результата**          | По умолчанию `b64_json` (необработанный base64, проверено 2026-07); явный `response_format: "url"` возвращает ссылку R2 CDN (**действительна 24 часа**) | `b64_json` (**необработанный base64**, требуется декодирование) |
| **Слияние нескольких изображений** | Повторяйте поле `image` в эндпоинте edits                                                                                                               | массив `image[]`, **максимум 16**                               |

### 4. Примерная стоимость

| Сценарий                                        | gpt-image-2-all / -vip                                                    | gpt-image-2                                                   |
| ----------------------------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 1024×1024 эскиз                                 | \$0.03                                                                    | \~\$0.006 (низкое)                                            |
| 1024×1024 среднее качество                      | \$0.03                                                                    | \~\$0.053 (среднее)                                           |
| 1024×1024 высокое качество                      | \$0.03                                                                    | \~\$0.211 (высокое)                                           |
| 2048×1152 высокое качество                      | \$0.03                                                                    | \~\$0.20+ (тарификация по token)                              |
| 3840×2160 4K высокое качество                   | \$0.03 (`-vip` уровень 4K Detail, без доплаты; `-all` не поддерживает 4K) | Тарификация по token, **значительно выше, чем 1K**            |
| Редактирование / слияние нескольких изображений | \$0.03                                                                    | Входные tokens быстро растут, один вызов может достичь \$0.1+ |

<Info>
  **Итог**: Для пакетных / низкокачественных нагрузок обратный канал не всегда дешевле (1K low на самом деле дешевле на официальном тарифе). Диапазон **среднего и высокого качества** — это оптимальная зона \$0.03 для обратного канала. Выбирайте официальный (с тарификацией по token), когда вам нужны **`quality` уровни / mask inpainting / фиксированные размеры, 4K / строгое соответствие полей OpenAI API**.
</Info>

## Настройки клиента

| Параметр                        | gpt-image-2-all / -vip                                                   | gpt-image-2                                                              |
| ------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| **Таймаут (консервативный)**    | `-all`: **300s** (обычно \~90s)<br />`-vip`: **300s** (обычно 120–200s)  | **360s** (для 4K в высоком качестве на практике это 3–5 минут)           |
| **Стратегия повторных попыток** | Экспоненциальный backoff при 5xx / timeout, максимум 2 повторные попытки | То же самое                                                              |
| **Параллельные запросы**        | 1 изображение на вызов — для нескольких отправляйте параллельные запросы | 1 изображение на вызов — для нескольких отправляйте параллельные запросы |
| **ID запроса**                  | `request-id` заголовок ответа                                            | `x-request-id` заголовок ответа                                          |

<Tip>
  **Общее для всех трёх моделей: для редактирования изображений / слияния нескольких изображений сжимайте каждое входное изображение до менее чем 1.5MB** (качество JPEG 80-90 / уменьшенное разрешение). Спорадические `shell_api_error` / `Unknown error` ответы чаще всего вызываются слишком большими входными данными — сжатие заметно повышает вероятность успеха и снижает задержку. **Разрешение вывода не зависит от размера входных данных** — качество задаётся на стороне вывода (`size` + `quality` для официального релея; уровень `size` для `-vip`; формулировка prompt для `-all`), а не размером входного файла.
</Tip>

    **Да, настоятельно рекомендуется.** Для всех трёх моделей сжимайте каждое входное изображение до **менее 1.5MB** (JPEG quality 80-90 / уменьшенное разрешение): спорадические ответы `shell_api_error` / `Unknown error` чаще всего вызываются слишком большими входными данными, а сжатие заметно повышает вероятность успеха и снижает задержку.

    **Не беспокойтесь, что сжатие ухудшит качество** — выходное разрешение не зависит от размера входного файла. Управление на «выходной» стороне различается у всех трёх:

    * `gpt-image-2-all`: управляется формулировкой композиции в prompt (см. таблицу проверенных формулировок на [странице обзора -all](/ru/api-capabilities/gpt-image-2-all/overview)) — `4K` / `8K` в prompt не учитываются
    * `gpt-image-2-vip`: управляется полем `size` (30 предустановленных размеров, включая 4K, восстановлено с 2026-07-22) — `4K` / `8K` в prompt тоже не учитываются
    * `gpt-image-2`: управляется `size` + `quality` (любой допустимый размер)

    Итог: уменьшение входных данных лишь ускоряет работу — качество определяется конфигурацией на стороне вывода, а не размером входного файла.
  </Accordion>

  <Accordion title="Может ли один и тот же API Key вызывать все три модели?">
    Да. Все три работают на канале Default — один и тот же API Key вызывает их без дополнительной настройки. Примечание: вызов `gpt-image-2` (официальный) требует token типа «Token-priority»; `-all` / `-vip` принимают любой тип token.
  </Accordion>

  <Accordion title="Какие endpoint'ы мне использовать в обратном канале?">
    **Используйте OpenAI Images API** (`/v1/images/generations` для text-to-image + `/v1/images/edits` для редактирования) по двум причинам:

    1. **Более стабильно**: upstream-обеспечение ресурсов для канала Images API более обильное, поэтому вероятность успешного вызова выше
    2. **Совместимо с официальным релеем для простого переключения**: метод вызова и формат параметров полностью совместимы с official-relay `gpt-image-2` — если на обратном канале возникнут риски из-за контроля, **просто замените имя `model`, чтобы переключиться на официальный релей без каких-либо изменений в коде**

    Есть также chat-based endpoint (`/v1/chat/completions`, **больше не рекомендуется**), полезный только для многоходового итеративного редактирования или прямой передачи онлайн image URLs. Учтите: когда намерение в отношении изображения неоднозначно, он может вернуть обычный текст вместо изображения (добавьте в начало фиксированный префикс вроде «Generate an image:», чтобы усилить это). Полные параметры см. в [справке API на основе chat для -all](/en/api-capabilities/gpt-image-2-all/chat-completions) / [справке API на основе chat для -vip](/en/api-capabilities/gpt-image-2-vip/chat-completions).
  </Accordion>

  <Accordion title="В обратном канале — -all или -vip: что выбрать?">
    Оба варианта — реверс-инжиниринговые каналы по одной и той же фиксированной цене (\$0.03/image), с одинаковым форматом вызова (`-vip` дополнительно поддерживает блокировку `size`). Разница — в **скорости, качестве и фиксации размера**:

    * **Время генерации**: `-all` \~90s — **преимущество в скорости**; `-vip` \~120–200s. Сейчас медленнее, чем на запуске, из-за колебаний вычислительных ресурсов upstream OpenAI
    * **Качество**: у `-vip` (линейка Codex) проработка деталей **иногда выше** — для демонстрационных изображений, когда вы не торопитесь
    * **Фиксация размера**: `-vip` поддерживает 30 предустановленных значений `size` (включая 4K); `-all` отклоняет `size` — композиция задаётся в prompt

    Выбор: нужен быстрый результат → `-all`; приоритет — качество или нужны фиксированные размеры / 4K → `-vip`; нужны пользовательские размеры за пределами 30 preset, `quality` tiers или mask → официальный `gpt-image-2`. Подробности см. в [Обзоре GPT-Image-2-VIP](/ru/api-capabilities/gpt-image-2-vip/overview).
  </Accordion>

  <Accordion title="Мне нужны фиксированные размеры / 4K — что теперь?">
    Начните с `gpt-image-2-vip`: его параметр `size` был восстановлен 2026-07-22 и поддерживает **30 предустановленных размеров (10 соотношений сторон × 1K/2K/4K)** по фиксированной цене \$0.03/image без доплаты за 4K. Учтите, что `size` работает только на эндпоинтах изображений и должен быть одним из 30 предустановленных значений.

    Переходите на официальный релей (`gpt-image-2`, тарификация по token), когда вам нужен **любой допустимый размер за пределами 30 preset**, **уровни `quality`** (low/medium/high/auto), **инпейнтинг по маске** (alpha-channel mask) или **строгое соответствие полей OpenAI API** (миграция без изменений для существующего кода OpenAI SDK).
  </Accordion>

  <Accordion title="Мигрируете с 1.5 — что выбрать?">
    * **Остаетесь на OpenAI SDK / нужно полное совпадение с официальным OpenAI, либо нужны пользовательские размеры за пределами 30 preset**: выбирайте `gpt-image-2` (официальный). Уберите `input_fidelity` и оставьте остальное без изменений (`background: transparent` продолжит работать).
    * **Снизить стоимость, нужен быстрый результат**: выбирайте `gpt-image-2-all` (обратный, \~90s).
    * **Снизить стоимость, приоритет — качество или нужны фиксированные размеры / 4K**: выбирайте `gpt-image-2-vip` (обратный, \~120–200s, 30 предустановленных размеров, включая 4K).
  </Accordion>

  <Accordion title="Могу ли я развернуть несколько моделей для резервного переключения?">
    Да. Типичный вариант: **основной `-all` или `-vip`** (предсказуемая стоимость — выбирайте по предпочтению к скорости / качеству), **резервный `gpt-image-2`** (переключайтесь, когда вам нужны уровни `quality`, mask или пользовательские размеры за пределами 30 preset). Форматы ответов у обратного и официального вариантов различаются — нормализуйте их на уровне бизнес-логики.
  </Accordion>
