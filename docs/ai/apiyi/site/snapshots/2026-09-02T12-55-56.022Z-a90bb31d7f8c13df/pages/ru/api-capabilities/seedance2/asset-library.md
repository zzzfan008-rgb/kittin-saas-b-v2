# Библиотека ассетов Seedance 2.0 (видео с сохранением персонажа)

> Используйте открытый API библиотеки ассетов icover.ai (продукт APIYI), чтобы загружать изображения и получать asset:// ID, а затем генерировать видео с сохранением персонажа через шлюз APIYI. Поддерживается веб-работа без кода и пакетная интеграция через REST API, и это бесплатно с Seedance 2.0 API — без ежегодной платы.

<Info>
  **icover.ai** — это субпродукт APIYI, онлайн-инструмент для тестирования генерации видео с помощью AI. Эта библиотека ресурсов и ее API помогают разработчикам и клиентам реализовывать функции «видео с единообразными персонажами».
</Info>

<Note>
  **Библиотека ресурсов на APIYI бесплатна — без ежегодной платы.** Официально эта возможность является отдельно приобретаемым дополнением: годовой контракт на сумму в сотни тысяч юаней для клиентов без рамочного соглашения (Volcengine также продает его напрямую). Мы ценим долгосрочных пользователей, поэтому она уже включена в цену API [Seedance 2.0](/ru/api-capabilities/seedance2/overview). Для клиентов, которые используют API SD2 в обычном режиме, при стандартных объемах бизнеса дополнительная плата не взимается.
</Note>

## Зачем нужна библиотека активов

При генерации видео с согласованными характеристиками персонажа Seedance 2.0 **не принимает изображения с человеческими лицами напрямую** (фильтрация anti-deepfake). Сначала необходимо загрузить изображение как доверенный актив, получить `asset://xxx` идентификатор актива и указать этот идентификатор в запросе на генерацию видео.

Этот сервис выполняет загрузку за вас: просто **загрузите изображение → получите идентификатор актива → сгенерируйте видео**. Использовать сервис можно двумя способами, при этом данные полностью общие для обоих способов:

| Способ            | Лучше всего подходит                                         | Требования                                   |
| ----------------- | ------------------------------------------------------------ | -------------------------------------------- |
| **Веб-интерфейс** | Всем, без написания кода                                     | Просто зарегистрируйтесь и войдите в систему |
| **API**           | Разработчикам, которым нужна программная пакетная интеграция | Один «KEY библиотеки активов»                |

<Tip>
  **Общие данные**: для одной и той же учётной записи активы, загруженные через веб-интерфейс и через API, находятся в одной библиотеке — активы, созданные через API, отображаются в веб-списке активов / архиве и в средстве выбора референсных изображений генератора видео, а активы, созданные через веб-интерфейс, можно получить через API.

  **Библиотека активов привязана к вашей учётной записи icover.ai, а не к KEY**: все KEY библиотеки активов, созданные в рамках одной учётной записи, эквивалентны и получают доступ к одной и той же библиотеке — KEY является только учётными данными для вызова и не обеспечивает изоляцию. Активы изолированы на уровне учётной записи; вы можете просматривать и использовать только собственные активы. Варианты изоляции и совместного использования между командами описаны в разделе [часто задаваемых вопросов](#faq) ниже.
</Tip>

<Warning>
  **Два разных ключа — не перепутайте их**:

  * **KEY библиотеки активов** (создаётся на icover.ai, `sk-...`): используется только для эндпоинтов библиотеки активов на этой странице (загрузка / импорт / запрос / удаление).
  * **Видео token APIYI Seedance** (создаётся на api.apiyi.com, `sk-...`, с включённой группой `SeeDance2`, общей для семейств 2.5 и 2.0): используется только для эндпоинта генерации видео.
</Warning>

## Способ 1: Web UI (рекомендуется для новичков)

<Steps>
  <Step title="Зарегистрируйтесь и войдите">
    Откройте [страницу библиотеки ресурсов icover.ai](https://icover.ai/en/seedance-official/asset-library) и зарегистрируйтесь / войдите.
  </Step>

  <Step title="Загрузите и выполните ingest">
    На вкладке «Загрузка виртуального аватара»: выберите изображения (поддерживается множественный выбор) → нажмите «Upload & Ingest».

    * Группа ресурсов необязательна; система автоматически использует вашу группу по умолчанию. Сначала создайте группу, если хотите организовать resources по персонажам.
    * Требования к изображениям: jpeg / png / webp / bmp / tiff / gif / heic; соотношение сторон 0.4–2.5; длина стороны 300–6000 px; размер каждого файла не более 30 MB.
  </Step>

  <Step title="Скопируйте ID ресурса">
    Подождите около десяти с лишним секунд; когда статус станет «Active», скопируйте `asset://xxx` ID ресурса.
  </Step>

  <Step title="Сгенерируйте видео">
    Перейдите в [icover.ai video generator](https://icover.ai/en/seedance-official): переключитесь в режим «Multimodal», задайте тип опорного изображения «Ресурс», выберите ваш ресурс и в prompt указывайте персонажа как «Изображение 1».
  </Step>
</Steps>

**Ресурсы реального человека (веб-версия)**: три шага на вкладке «Проверка реального человека» — 1) нажмите «Generate verification link», пусть актер отсканирует QR-код / откроет ссылку на телефоне, войдет в свою учетную запись Volcengine и пройдет проверку на живость; 2) нажмите «Query verification result», чтобы получить выделенную для актера группу ресурсов реального человека; 3) выберите эту группу и загрузите ресурсы (изображения / video / audio) — они пройдут проверку на согласованность лица, и вы получите ID `asset://`. Для одного и того же актера в разных образах используется та же группа, повторная проверка не нужна.

## Метод 2: API (разработчиков)

### Шаг 0: Создайте ключ Asset Library

После входа в icover.ai перейдите в Настройки → Asset Library KEY (`icover.ai/en/settings/apikeys`) и создайте KEY в формате `sk-...`.

<Frame caption="Settings → Asset Library KEY: click the create button and copy the generated sk-... key (note this is separate from the APIYI Token entry in the sidebar)">
  <img src="https://mintcdn.com/apiyillc/KMuJVpzJvYYPxQax/images/seedance2-asset-library-key-create.png?fit=max&auto=format&n=KMuJVpzJvYYPxQax&q=85&s=b7aef248abd888990cc0890de84d93cc" alt="The Asset Library KEY management page in icover.ai settings, with a create button and a list of existing keys" width="1600" height="679" data-path="images/seedance2-asset-library-key-create.png" />
</Frame>

Включайте его в каждый запрос к asset-library:

```
Authorization: Bearer sk-your-asset-library-KEY
```

### Шаг 1: Загрузите файл и получите публичный URL

Файл ресурса (изображение; ресурсы с реальными людьми также поддерживают видео / аудио) сначала должен быть доступен по публичному URL. Выберите любой из вариантов:

**A. У вас уже есть публичный URL** (ваш CDN / хостинг файлов) → перейдите к Шагу 2.

**B. Загрузите в наше хранилище** (два вызова: запросите предварительно подписанный URL для загрузки → PUT файл):

```bash theme={null}
# 1. Request a presigned upload URL
curl -X POST https://icover.ai/api/storage/presign \
  -H "Authorization: Bearer sk-your-asset-library-KEY" \
  -H "Content-Type: application/json" \
  -d '{"ext":"jpg","contentType":"image/jpeg"}'
# → { "code":0, "data": { "uploadUrl":"...", "publicUrl":"https://cdn.icover.ai/..." } }

# 2. PUT the file to uploadUrl (Content-Type must match the presign request)
curl -X PUT "the-uploadUrl-you-just-received" \
  -H "Content-Type: image/jpeg" \
  --data-binary @portrait.jpg
# Once it succeeds, publicUrl is your file's public address
# Same for video/audio: swap ext/contentType to mp4/video/mp4, mp3/audio/mpeg, etc.
```

### Шаг 2: Загрузите asset

```bash theme={null}
curl -X POST https://icover.ai/api/asset-library/assets \
  -H "Authorization: Bearer sk-your-asset-library-KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "imageUrl": "https://cdn.icover.ai/uploads/seedance/xxx.jpg",
    "label": "actor-A-front"
  }'
# → Raw Volcengine response: { ..., "Result": { "Id": "asset-20260702xxxx-xxxxx" } }
```

* `groupId` необязателен: будет использована или автоматически создана ваша группа по умолчанию. Чтобы организовать по character: сначала `POST /api/asset-library/groups {"name":"actor-A"}`, чтобы получить ID группы, затем укажите `"groupId":"group-xxx"` здесь.
* `label` необязателен; он помогает вам идентифицировать asset в веб-интерфейсе.

### Шаг 3: Опрос до состояния Active

Ingest выполняется асинхронно (около 13 секунд на изображение, без SLA). Выполняйте опрос по возвращённому Id:

```bash theme={null}
curl https://icover.ai/api/asset-library/assets/asset-20260702xxxx-xxxxx \
  -H "Authorization: Bearer sk-your-asset-library-KEY"
# → Result.Status == "Active" means ready; "Failed" means re-upload
```

Рекомендуем выполнять опрос каждые 3 секунды; считайте 90 секунд без `Active` тайм-аутом, требующим проверки.

### Шаг 4: Сгенерируйте видео с идентификатором ресурса (через APIYI)

Укажите идентификатор ресурса как `asset://<Id>` и вызовите APIYI, используя **свой собственный APIYI-токен для видео Seedance** (а не KEY библиотеки ресурсов):

```bash theme={null}
curl -X POST https://api.apiyi.com/seedance/api/v3/contents/generations/tasks \
  -H "Authorization: Bearer sk-your-APIYI-token" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "doubao-seedance-2-0-260128",
    "content": [
      {"type":"text","text":"The character in Image 1 smiles at the camera, slow push-in, natural light"},
      {"type":"image_url","image_url":{"url":"asset://asset-20260702xxxx-xxxxx"},"role":"reference_image"}
    ],
    "ratio":"16:9","duration":5,"resolution":"720p"
  }'
# Returns a task id; poll GET .../tasks/{id} until status=succeeded, then read content.video_url
```

<Warning>
  В промпте ссылайтесь на ресурс как на «Image 1» — **не указывайте в промпте необработанный идентификатор ресурса**.
</Warning>

Таблицы выбора модели, цен и разрешений см. в разделе [Обзор Seedance 2.0](/ru/api-capabilities/seedance2/overview); все параметры генерации см. в разделе [API генерации видео](/ru/api-capabilities/seedance2/video-generation). Полный готовый к запуску сквозной скрипт (загрузка → приём → генерация → скачивание) см. в разделе [Руководство по ссылкам на ресурсы](/ru/api-capabilities/seedance2/asset-reference).

### Полный справочник эндпоинтов

| Эндпоинт                                       | Метод                 | Описание                                                                                                                                                                                                                                                                            |
| ---------------------------------------------- | --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/api/storage/presign`                         | POST                  | Запросить заранее подписанный URL для загрузки файла `{ext?, contentType?}`                                                                                                                                                                                                         |
| `/api/asset-library/groups`                    | POST / GET            | Создать группу `{name, description?}` / получить список ваших групп (включая группы реальных людей)                                                                                                                                                                                 |
| `/api/asset-library/assets`                    | POST / GET            | Импортировать `{groupId?, imageUrl, label?, assetType?}` (assetType необязателен: `Image` / `Video` / `Audio`, по умолчанию Image) / список ассетов (`?groupId=`, `?pageNumber=`, `?pageSize=` все необязательны; по умолчанию страница 1, 100 на страницу, pageSize ограничен 100) |
| `/api/asset-library/assets/{id}`               | GET / DELETE / PATCH  | Проверить статус / удалить / обновить метку `{label}`                                                                                                                                                                                                                               |
| `/api/asset-library/real-person/sessions`      | POST / GET            | Запустить верификацию реального человека `{name?}` → возвращает ссылку H5 для верификации и учётные данные для запроса / список ваших сессий верификации                                                                                                                            |
| `/api/asset-library/real-person/sessions/{id}` | POST / PATCH / DELETE | Запросить результат верификации (при успехе возвращает GroupId группы ассетов реального человека) / переименовать `{name}` / удалить запись                                                                                                                                         |
| `/api/asset-library/records`                   | GET                   | Ваши ассеты + архив верификации реального человека (источник данных веб-интерфейса)                                                                                                                                                                                                 |

**Соглашения по ответам**:

* **Эндпоинты для одного объекта** (создать группу / импортировать / получить статус / удалить) передают необработанный JSON Volcengine без изменений как при успехе, так и при ошибке.
* **Списковые эндпоинты** (`GET` на `groups` / `assets`) объединяются и фильтруются по вашим собственным ассетам, поэтому это не побайтный вывод upstream: сохраняется каждое исходное поле Volcengine, а также несколько наших собственных полей метаданных с префиксом `_` (например, `_library`). **Игнорируйте неизвестные поля с префиксом `_` при разборе** — добавление новых таких полей не нарушает обратную совместимость.
* Наши собственные ошибки — это обычный текст с префиксом `[client] ` (400/401/403/404/502).
* `records`, GET/PATCH/DELETE для `real-person/sessions` и ассет `PATCH` возвращают JSON `{code, message, data}` (код 0 = успех).

## Активы реального человека (полностью автоматизированный API)

Портреты реальных людей требуют, чтобы человек, которого снимают (актёр), один раз прошел **проверку живости**, закрепляя права на портрет на уровне источника. Весь процесс теперь полностью управляется через API; вкладка веб-интерфейса «Проверка реального человека» — это тот же процесс с интерфейсом:

### Шаг 1: Запустите сеанс верификации и получите ссылку H5

```bash theme={null}
curl -X POST https://icover.ai/api/asset-library/real-person/sessions \
  -H "Authorization: Bearer sk-your-asset-library-KEY" \
  -H "Content-Type: application/json" \
  -d '{"name":"actor-A"}'
# → Raw Volcengine response: { "Result": { "BytedToken":"2026...", "H5Link":"https://ark.volcengine.com/..." } }
```

* Отправьте `H5Link` актёру, чтобы он **открыл её на телефоне** (или преобразуйте её в QR-код для сканирования). Он войдет в свою личную учетную запись Volcengine и завершит проверку живости. Освещение / угол камеры могут привести к неудачной попытке — просто повторите.
* `BytedToken` — это учетные данные для запроса; мы сохраняем их вместе с сеансом. `GET /api/asset-library/real-person/sessions` позволяет в любой момент просмотреть ваши сеансы (включая id / status / h5Link).

### Шаг 2: Получите результат после завершения актером

```bash theme={null}
curl -X POST https://icover.ai/api/asset-library/real-person/sessions/{session-id} \
  -H "Authorization: Bearer sk-your-asset-library-KEY"
# Verified → { "Result": { "GroupId": "group-xxxx" } }  ← the actor's dedicated real-person asset group
# Not yet  → 404 NotFound.<token> (raw Volcengine text; this is normal — query again after verification)
```

После получения `GroupId` статус сеанса становится `authorized`, а группа активов реального человека автоматически архивируется в вашей учетной записи (она также отображается в группе активов веб-интерфейса). **Примечание**: для ожидающей верификации возвращается тот же `NotFound`, что и для истекших учетных данных — различить эти два случая невозможно. Ссылка, долго остававшаяся без использования, может истечь; просто создайте новый сеанс.

### Шаг 3: Отправьте активы в группу реального человека

Тот же endpoint для загрузки, что и для виртуальных аватаров — просто передайте `groupId` группы реального человека. Поддерживаются изображения, видео и аудио:

```bash theme={null}
curl -X POST https://icover.ai/api/asset-library/assets \
  -H "Authorization: Bearer sk-your-asset-library-KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "groupId": "group-xxxx",
    "imageUrl": "https://cdn.icover.ai/uploads/seedance/xxx.jpg",
    "label": "actor-A-front-full-body",
    "assetType": "Image"
  }'
```

Затем опрашивайте до `Active` как обычно и создавайте видео с помощью `asset://<Id>` (Шаг 4 без изменений).

**Правила и форматы активов реального человека**:

* Одна группа реального человека содержит **только одного человека**; тот же актёр в разном стиле повторно использует ту же группу — повторная верификация не нужна.
* Каждая загрузка проходит **проверку согласованности лица** (видео сэмплируются каждую секунду, и каждый выбранный кадр должен пройти проверку). Профильный ракурс, несколько людей или размытый материал приведут к ошибке — используйте четкий фронтальный материал.
* Изображения до 30MB; видео mp4 / mov, 2–15 секунд, ≤50MB, соотношение сторон 0.4–2.5; аудио mp3 / wav, 2–15 секунд, ≤15MB.

## Примечания

<Warning>
  **Считайте asset:// ID секретами**: assets изолированы на уровне этого service layer (защищены от просмотра списка и удаления), но Volcengine не может авторизовать доступ по ID — если ID утечет, другие вызывающие на том же канале смогут ссылаться на него в запросах на генерацию. См. [Часто задаваемые вопросы](#faq) ниже для полного описания модели владения и изоляции.
</Warning>

* **Срок действия Image URL**: preview URLs, возвращаемые query / list endpoints, — это временные адреса, действительные примерно 12 часов; не кэшируйте их надолго, сам asset ID является постоянным.
* **Лимиты запросов** (на уровне аккаунта Volcengine): status query — 100 QPS, ingest и другие операции — около 10 QPS. Управляйте concurrency и выполняйте повторные попытки при сбое.
* **Синхронизация статуса в Web UI**: после ingest через API, если статус ни разу не запрашивался, в web archive может отображаться «processing»; откройте страницу списка assets и нажмите «Refresh List», чтобы синхронизировать фактический статус.

Официальные материалы Volcengine (скопируйте в браузер): руководство по private asset library `volcengine.com/docs/82379/2333565`, onboarding assets реальных людей `volcengine.com/docs/82379/2315856`.

## FAQ

<AccordionGroup>
  <Accordion title="Чем библиотека ресурсов отличается от прямой передачи референсного изображения?">
    Прямые референсные изображения не могут содержать фотореалистичные человеческие лица (антидипфейк-фильтр отклоняет их). После добавления портрета в качестве доверенного ресурса его `asset://` ID можно повторно использовать в любом количестве задач генерации, сохраняя единообразие лица и одежды персонажа в разных эпизодах и кадрах — это идеально подходит для сериализованного контента, например анимационных драм, коротких драм и персонажей интеллектуальной собственности. Реальные люди также могут появляться в кадре: достаточно пройти описанную выше процедуру верификации реального человека.
  </Accordion>

  <Accordion title="Взимается ли дополнительная плата за библиотеку ресурсов? Чем это отличается от самостоятельного официального подключения?">
    На APIYI это **бесплатно** — просто используйте библиотеку вместе с API Seedance 2.0. Никакой ежегодной платы и отдельного договора.

    Официально частная библиотека ресурсов **оплачивается отдельно для клиентов без рамочного соглашения**: годовая закупка стоимостью в несколько сотен тысяч юаней (Volcengine также продаёт её напрямую). Иными словами, самостоятельное подключение означает ежегодную плату сверх стоимости использования модели и обычно требует прохождения процедур подтверждения статуса корпоративного клиента и закупки. При использовании APIYI достаточно одного видеотокена Seedance — библиотека ресурсов работает сразу после подключения.

    Мы ценим долгосрочных пользователей, поэтому эта стоимость уже включена в цену нашего API; для клиентов, использующих SD2 в обычном режиме, дополнительная плата при стандартных объёмах бизнеса не взимается.
  </Accordion>

  <Accordion title="Привязана ли библиотека ресурсов к аккаунту или к ключу? Как реализована изоляция ресурсов?">
    Одной строкой: **icover.ai изолирует ресурсы, а APIYI обеспечивает унифицированный вызов — сторона генерации проверяет только ID ресурса, и для его использования достаточно иметь этот ID.**

    Она привязана к **аккаунту**. Архитектура устроена следующим образом: все пользователи icover.ai используют единый общий аккаунт APIYI Volcengine, которому принадлежит библиотека ресурсов; icover.ai добавляет на уровне сервиса **изоляцию по аккаунтам** — каждый аккаунт может просматривать, запрашивать и удалять только собственные ресурсы и не может видеть ID ресурсов других пользователей.

    Ключи не обеспечивают изоляцию: несколько ключей библиотеки ресурсов в одном аккаунте эквивалентны и получают доступ к одной и той же библиотеке. Если вам нужна изоляция ресурсов (например, для разделения данных между клиентами или направлениями бизнеса), **зарегистрируйте отдельный аккаунт icover.ai для каждой стороны** и создайте ключи в каждом из них — создание нового ключа в том же аккаунте ничего не изолирует.

    Учитывайте границу безопасности: эта изоляция распространяется на просмотр, запрос и удаление, но Volcengine не может выполнять авторизацию по ID — если `asset://` ID утечёт, другие вызывающие стороны в том же канале смогут указать его в запросах на генерацию. Считайте ID ресурсов конфиденциальными данными.
  </Accordion>

  <Accordion title="Хранятся ли ресурсы на собственных серверах APIYI / icover.ai?">
    Это зависит от способа передачи файла:

    * **Вы указываете общедоступный URL** (собственный CDN / хостинг изображений): исходный файл **никогда не проходит через нас** — мы только передаём этот URL в Volcengine.
    * **Вы загружаете файл через `/api/storage/presign`**: сначала файл сохраняется в нашем объектном хранилище (`cdn.icover.ai`) для получения общедоступного URL, который затем передаётся в Volcengine. **Исходный файл остаётся в нашем хранилище.**

    В обоих случаях сам ресурс в итоге обрабатывается на стороне Volcengine, который возвращает `asset://` ID. **Наша собственная база данных хранит только этот ID и сведения о принадлежности аккаунту** (используемые для описанной выше изоляции по аккаунтам); содержимое ресурса мы не сохраняем.

    Для ресурсов с реальными лицами действует дополнительное обязательное требование: фотографируемый человек должен лично пройти **проверку лица в реальном времени** (войти в собственный аккаунт Volcengine и пройти распознавание лица), что закрепляет права на портрет непосредственно в источнике — никто другой не может пройти эту проверку от его имени. Полное описание процедуры приведено выше в разделе «Ресурсы с реальными лицами».
  </Accordion>

  <Accordion title="Как несколько отделов или команд внутри компании могут совместно использовать библиотеку ресурсов или изолировать её?">
    **Использовать одну библиотеку (рекомендуется, самый простой вариант)**: достаточно одного аккаунта и одного ключа. Управляйте ID ресурсов централизованно в собственной системе и передавайте `asset://` ID каждому отделу — для указания ресурса в запросе на генерацию видео достаточно иметь его ID (для генерации видео используется собственный видеотокен APIYI Seedance каждого отдела, не связанный с ключом библиотеки ресурсов). Также можно создать несколько ключей в одном аккаунте и передать их разным отделам (это удобно для ротации и отзыва учётных данных) — такие ключи всё равно получают доступ к одной и той же библиотеке.

    **Изолировать отделы друг от друга**: зарегистрируйте отдельный аккаунт icover.ai для каждого отдела, используя собственные ключи для каждого аккаунта. Обратите внимание: изоляция распространяется на просмотр, запрос и удаление — утёкший ID ресурса всё равно можно использовать, поэтому не следует без необходимости распространять ID даже между отделами.
  </Accordion>

Фотореалистичный портрет, созданный ИИ и не имеющий соответствия в реальном мире (например, персонаж, созданный с помощью модели вроде Nano Banana), является **виртуальным аватаром** — он сразу проходит процедуру добавления виртуального аватара без этапа авторизации. Реальным лицом считается только фотография **реального существующего человека** — для таких изображений загрузка НЕ означает наличие разрешения; канал добавления виртуальных аватаров отклоняет их, а фотографируемый человек должен пройти проверку живого присутствия (см. раздел о реальных лицах выше).

  <Accordion title="Требуют ли реалистичные цифровые люди (виртуальные аватары) проверки?">
    Нет. Добавление виртуального аватара полностью автоматизировано — ручная проверка и этап авторизации не требуются: после загрузки система автоматически предварительно обрабатывает изображение, примерно через 13 секунд статус меняется на Active, а `asset://` ID сразу становится доступен для генерации видео. Только ресурсы с **реальными лицами** требуют, чтобы фотографируемый человек прошёл проверку живого присутствия (см. раздел о реальных лицах выше).

  <Accordion title="Можно ли перенести ресурсы, уже добавленные в библиотеку или верифицированные у другого провайдера?">
    Их нельзя повторно использовать напрямую. И библиотека ресурсов Volcengine, и верификация реального человека **привязаны к исходному аккаунту**: `asset://` ID, полученный через другого провайдера, принадлежит аккаунту Volcengine этого провайдера, а обращение к нему через канал APIYI возвращает `asset not found`. Ресурсы необходимо повторно добавить с помощью этого сервиса.

    * **Ресурсы виртуальных аватаров**: их можно программно перенести массово — напишите скрипт, который повторно загрузит исходные изображения через API на этой странице, а затем замените старые ID в своей системе на новые `asset://` ID. Мы рекомендуем хранить слой сопоставления ID ресурсов в собственной системе: бизнес-данные будут содержать только ваши внутренние ID, поэтому при последующей смене провайдера достаточно обновить сопоставление.
    * **Ресурсы, верифицированные для реальных людей**: верификация реального человека также привязана к аккаунту и **не может быть перенесена — требуется повторная верификация**: фотографируемый человек должен снова пройти проверку живого присутствия (см. раздел о реальных лицах выше).
    * **Рекомендации для продуктов, ориентированных на потребителей**: если у вас уже есть большое количество ресурсов, перенесите виртуальные ресурсы незаметно с помощью фоновой задачи на серверной стороне — пользователи этого не заметят; для ресурсов с верифицированными реальными людьми предложите пользователям повторно пройти проверку во время обновления системы или выпуска новой версии — это будет восприниматься гораздо естественнее.
  </Accordion>
