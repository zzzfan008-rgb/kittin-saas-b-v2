# Генерация видео Wan (Alibaba Cloud Tongyi Wanxiang)

> Полное руководство по генерации видео Alibaba Cloud Tongyi Wanxiang Wan2.7: text-to-video / image-to-video (с управлением по аудио) / reference-to-video / редактирование видео. Единый асинхронный эндпоинт DashScope, 720P / 1080P, длительность 2–15 секунд.

## Обзор

**Wan (Tongyi Wanxiang)** — это серия моделей генерации видео от Alibaba Cloud. APIYI напрямую подключается к Alibaba Cloud Model Studio через **сквозной канал DashScope**, поэтому один ключ APIYI (начинающийся с `sk-`) открывает доступ ко всем возможностям видео Wan без отдельного аккаунта Alibaba Cloud. Текущий флагман — **Wan2.7**, охватывающий четыре основных сценария использования:

| Сценарий использования   | ID модели          | Ваш ввод                                                           | Результат                                                                                         |
| ------------------------ | ------------------ | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| **Текст-в-видео**        | `wan2.7-t2v`       | Текстовый prompt                                                   | Короткое видео длительностью 5-15 секунд                                                          |
| **Изображение-в-видео**  | `wan2.7-i2v`       | Первый кадр + prompt (необязательное управляющее аудио)            | Оживляет статичное изображение; добавляет аудио для синхронизации губ / рэпа                      |
| **Референс-в-видео**     | `wan2.7-r2v`       | 1-5 референсных изображений/видео + prompt                         | Видео с одним или несколькими персонажами, сохраняющее объекты референсов, с голосовым референсом |
| **Редактирование видео** | `wan2.7-videoedit` | Видео + 1-5 референсных изображений + инструкция по редактированию | Отредактированное видео: замена одежды, замена фона и т. д.                                       |

<Note>
  **🎬 Ключевая особенность**: все четыре возможности используют один и тот же асинхронный эндпоинт и одну и ту же структуру запроса. **Переключайте сценарии использования, изменяя только поле `model`.** Нативная поддержка разрешений 720P / 1080P и целочисленной длительности от 2 до 15 секунд; `wan2.7-i2v` также поддерживает управляющее аудио для синхронизации губ. Идеально подходит для производства коротких видео, материалов для e-commerce, озвучивания цифровых аватаров и креативного маркетинга.
</Note>

<Prompt description="Пусть coding-агент интегрирует или поможет устранить неполадки в Wan2.7 text-to-video, image-to-video, reference-to-video и video editing. Скопируйте и вставьте это в Codex, Claude Code, Cursor и аналогичные инструменты." icon="bot" actions={["copy"]}>
  Интегрируйте / устраните неполадки в генерации видео Wan2.7 (text-to-video, image-to-video, reference-to-video, video editing) в этом проекте.

  Прочитайте docs, прежде чем трогать code: получите [https://docs.apiyi.com/en/api-capabilities/wan/overview.md](https://docs.apiyi.com/en/api-capabilities/wan/overview.md) для текстовой версии этой страницы. У каждой из четырёх capabilities есть своя страница (text-to-video, image-to-video, reference-to-video, video-edit) — с тем же суффиксом `.md`.

  Требования:

  1. Endpoint и async header (**две вещи, которые с наибольшей вероятностью сразу вас заблокируют**): отправки должны идти на `POST /wan/api/v1/services/aigc/video-generation/video-synthesis` и **должны содержать header `X-DashScope-Async: enable`**, иначе upstream отвечает `current user api does not support synchronous calls`. **Никогда не используйте `/v1/videos`** — этот маршрут отбрасывает поле `media`, и затем upstream сообщает `[InvalidParameter] Field required: input.media`. Опрос использует **другой префикс**: `GET /v1/tasks/{task_id}` (async header при опросе не нужен).

  2. Опрос и статус: task ID находится в **`output.task_id`** в submit response. Опрос выполняйте каждые 5–10 секунд и **никогда не чаще чем раз в 3 секунды**, иначе получите лимит запросов; задайте клиенту общий предел в 20 минут. Статусы — `submitted`, `in_progress`, `completed` и `failed`, а **success — это `completed`**. Значение `progress`, застрявшее на 30 процентах надолго, — это нормально: upstream сообщает только 0, 10, 30 и 100, поэтому не считайте это зависанием. Сам task ID можно запрашивать только в течение **24 часов**, после чего вы получите `UNKNOWN`.

  3. Получение video: адрес находится на верхнем уровне в **`result_url`**, это signed link Aliyun OSS, который **истекает через 24 часа**. **Скачайте его на стороне сервера немедленно и пере-разместите в своём object storage или CDN**; никогда не храните его как долгосрочный адрес. При скачивании **не отправляйте header `Authorization`** — это вернёт 403 с `SignatureDoesNotMatch`.

  4. Структура body и типы: body — это вложенная форма DashScope, `{ model, input: { prompt, media[] }, parameters: { ... } }`, а не плоский object. Две ловушки типов: **`duration` должен быть целым числом `5`, никогда не строкой `"5"`** (иначе вы получите `cannot unmarshal string into Go struct field ... of type int`), и **`resolution` должен быть в верхнем регистре `720P` или `1080P`** — у этой модели **нет tier 480P**.

  5. Ключевые параметры: `duration` — это integer от 2 до 15, по умолчанию 5 (и **не должен превышать 10, когда присутствует reference video**). `ratio` — это одно из `16:9`, `9:16`, `1:1`, `4:3` или `3:4`, по умолчанию `16:9`, но **`ratio` автоматически игнорируется всякий раз, когда задано изображение первого кадра**. `prompt_extend` по умолчанию равно `true` и настоятельно рекомендуется включить. **Обратите внимание, что `wan2.7-r2v` по умолчанию `resolution` в `1080P`, а не в `720P`** — а поскольку тарификация зависит от разрешения, оставляя это неявным, вы молча покупаете более дорогой tier, поэтому всегда задавайте это явно. Для `wan2.7-videoedit` длина output следует за исходным video, и `duration` не влияет (и обратите внимание, что в названии модели **нет дефиса в `videoedit`** — не пишите `video-edit`).

  6. Медиа-inputs: они находятся в `input.media[]`, каждая запись имеет форму `{"type": ..., "url": ...}`, где согласно документированному контракту `url` должен быть **публично GET-аемой https ссылкой**. Типы и количества по capabilities: `first_frame` — не более 1 (i2v и r2v); `reference_image` плюс `reference_video` **в сумме не более 5** в r2v; `driving_audio` **поддерживается только в i2v**; а для video editing требуется 1 `video` плюс 1–5 записей `reference_image`. В prompts для reference-to-video обращайтесь к input по позиции как image 1, image 2, video 1, video 2, следуя порядку массива `media`, считая images и videos отдельно.

  7. Тарификация и idempotency: **тарификация поминутная, с градацией по разрешению**, при этом 1080P заметно дороже 720P. Task, который завершился `failed`, **не тарифицируется**, но **повторная отправка того же task тарифицируется снова** — для idempotency ведите сопоставление от вашего business ID к `task_id`, а не слепо выполняйте auto-retry. Ошибки приходят в две стадии: отклонение при отправке (HTTP 4xx/5xx с `type`, например `task_error` или `parse_request_failed`) означает, что body запроса неверен, поэтому исправьте его, а не повторяйте; failure во время выполнения отображается как task `failed`, у которого `error.message` содержит префикс в скобках, где `[InvalidImageUrl]` может быть просто временно недоступной media-ссылкой и заслуживает retry, тогда как `[InvalidParameter]` или отклонение по sensitive-word **нельзя повторять**. Используйте exponential backoff (1s, 4s, 16s) для 5xx и network errors.

  8. Требования к token: этой модели нужен token, несущий группу `Wan&HappyHorse` с режимом тарификации **pay-as-you-go или PAYG-priority** — **token per call не может направить его к ней** и выдаёт ошибку о том, что доступный channel отсутствует.

  9. Прочитайте ключ из environment variable `APIYI_API_KEY`. Никогда не хардкодьте его и никогда не коммитьте в git.

  10. Когда закончите, реально выполните один вызов text-to-video и один вызов image-to-video, затем покажите мне video и стоимость этих двух вызовов. Учтите, что весь flow занимает несколько минут, поэтому если вы работаете в ограниченной execution environment, увеличьте timeout команды выше 600 секунд или запустите её в background.
</Prompt>

## ⚠️ Выбор эндпоинта (самое важное)

APIYI монтирует два пути, но **только endpoint с проксированием DashScope полностью поддерживает все возможности Wan**:

| Path                                                         | Protocol style                   | i2v / r2v availability     | Verdict                    |
| ------------------------------------------------------------ | -------------------------------- | -------------------------- | -------------------------- |
| `/v1/videos`                                                 | OpenAI flat style                | ❌ Поля media отбрасываются | **Не используйте**         |
| `/wan/api/v1/services/aigc/video-generation/video-synthesis` | Нативное проксирование DashScope | ✅ Полностью поддерживается | **Всегда используйте это** |

<Warning>
  Если в какой-либо документации или примере вам предлагают отправлять задачи видео Wan через `/v1/videos`, **игнорируйте это**. Адаптация этого пути для полей i2v / r2v `media` неполная и вызывает upstream-ошибку `[InvalidParameter] Field required: input.media`. Все запросы на создание видео Wan отправляются в `/wan/api/v1/...video-synthesis`.
</Warning>

## Поток асинхронных вызовов

Весь процесс состоит из трёх асинхронных шагов: **создание задачи → опрос статуса → скачивание видео**.

<Steps>
  <Step title="Создайте задачу">
    `POST /wan/api/v1/services/aigc/video-generation/video-synthesis` с заголовком `X-DashScope-Async: enable`. Он сразу возвращает `task_id`.
  </Step>

  <Step title="Опросите статус">
    `GET /v1/tasks/{task_id}` (с `Authorization`) каждые 5-10 секунд (**не реже чем раз в 3 секунды**), пока `status` не станет `completed`.
  </Step>

  <Step title="Скачайте видео">
    Получите mp4 напрямую из `result_url` ответа. **Не отправляйте заголовок `Authorization`** (это подписанная OSS прямая ссылка; добавление Auth приводит к 403).
  </Step>
</Steps>

### Справка по статусам задачи

Верхнеуровневое поле `status` ответа `GET /v1/tasks/{task_id}` (уже нормализовано APIYI):

| Статус        | Значение              | Следующий шаг                                                                                       |
| ------------- | --------------------- | --------------------------------------------------------------------------------------------------- |
| `submitted`   | Отправлено, в очереди | Продолжайте опрос                                                                                   |
| `in_progress` | Генерация             | Продолжайте опрос (прогресс часто замирает на 30%; это грубое отображение upstream, а не зависание) |
| `completed`   | Успешно               | Скачайте по `result_url`                                                                            |
| `failed`      | Сбой                  | Проверьте `error.message` / `fail_reason`                                                           |

### Полный Python-клиент

```python theme={null}
import json, time, urllib.request

BASE = "https://api.apiyi.com"
KEY  = "sk-your-api-key"   # your APIYI Key

def post(path, body):
    h = {"Authorization": f"Bearer {KEY}", "Content-Type": "application/json",
         "X-DashScope-Async": "enable"}
    req = urllib.request.Request(BASE + path, data=json.dumps(body).encode(), headers=h, method="POST")
    return json.loads(urllib.request.urlopen(req).read())

def get(path):
    req = urllib.request.Request(BASE + path, headers={"Authorization": f"Bearer {KEY}"})
    return json.loads(urllib.request.urlopen(req).read())

# 1. Create the task (switch use cases by changing only model and media)
r = post("/wan/api/v1/services/aigc/video-generation/video-synthesis", {
    "model": "wan2.7-t2v",
    "input": {"prompt": "A lighthouse on the seashore at dusk, the camera slowly pushing in, waves gently lapping the rocks, seabirds calling"},
    "parameters": {"resolution": "720P", "duration": 5, "prompt_extend": True, "watermark": True}
})
task_id = r["output"]["task_id"]
print("task_id:", task_id)

# 2. Poll (every 5-10 seconds)
while True:
    info = get(f"/v1/tasks/{task_id}")
    status = info["status"]
    print("status:", status, "progress:", info.get("progress"))
    if status == "completed":
        url = info["result_url"]
        break
    if status == "failed":
        raise RuntimeError(info.get("error") or info.get("fail_reason"))
    time.sleep(10)

# 3. Download (do not send Authorization! result_url is an OSS signed direct link)
urllib.request.urlretrieve(url, "out.mp4")
print("saved out.mp4")
```

## Объяснение ключевых параметров

При отправке тело запроса использует вложенную структуру DashScope: `{ model, input: { prompt, media[] }, parameters: {...} }`.

### Поля `input`

| Поле              | Тип    | Обязательность               | Примечания                                                                                              |
| ----------------- | ------ | ---------------------------- | ------------------------------------------------------------------------------------------------------- |
| `prompt`          | string | ✓                            | Описание на естественном языке; wan2.7-r2v поддерживает маркеры "image 1 / video 1" для ссылки на медиа |
| `negative_prompt` | string |                              | Negative prompt, ≤500 символов                                                                          |
| `media`           | array  | Обязательно для i2v/r2v/edit | Массив медиа-объектов, см. ниже                                                                         |

### Типы `media[]`

| `type`            | Назначение                                                  | Применимые модели |
| ----------------- | ----------------------------------------------------------- | ----------------- |
| `first_frame`     | Изображение первого кадра (≤1)                              | i2v, r2v          |
| `reference_image` | Референсное изображение (сохранение объекта/сцены)          | r2v, videoedit    |
| `reference_video` | Референсное видео (референс объекта/голоса)                 | r2v               |
| `driving_audio`   | Управляющее аудио (синхронизация губ)                       | **только i2v**    |
| `video`           | Входное видео                                               | videoedit         |
| `reference_voice` | Голосовой референс (прикрепляется к reference\_image/video) | r2v               |

Каждому медиа-объекту нужны как минимум `type` + `url`. `url` должен быть общедоступной ссылкой https, которую можно напрямую получить через GET (сначала загрузите локальные файлы в OSS / CDN).

### Поля `parameters`

| Поле            | Тип    | Значения                                | Примечания                                                                      |
| --------------- | ------ | --------------------------------------- | ------------------------------------------------------------------------------- |
| `resolution`    | string | `720P` / `1080P`                        | В верхнем регистре; рекомендуется задавать явно                                 |
| `ratio`         | string | `16:9` / `9:16` / `1:1` / `4:3` / `3:4` | Соотношение сторон; автоматически игнорируется при указании первого кадра       |
| `duration`      | int    | 2-15                                    | Секунды (целое число), обычно 5 / 10; ограничено 10 при наличии reference video |
| `prompt_extend` | bool   | `true` / `false`                        | Умная переработка prompt, **настоятельно рекомендуется `true`**                 |
| `watermark`     | bool   | `true` / `false`                        | Водяной знак «сгенерировано ИИ» в правом нижнем углу                            |
| `seed`          | int    | 0-2147483647                            | Фиксация этого значения улучшает воспроизводимость                              |

<Tip>
  `duration` должен быть **целым числом** `5`, а не строкой `"5"`, иначе вы получите `cannot unmarshal string into Go struct field ... of type int`. Запись `resolution` в **верхнем регистре** (`720P`) надежнее.
</Tip>

## Выбор между Wan и HappyHorse

Wan и [HappyHorse](/ru/api-capabilities/happyhorse/overview) — это обе видеомодели Alibaba, и они используют один и тот же эндпоинт и схему (переключайтесь между ними, меняя только имя `model`), но их сильные стороны различаются:

| Dimension                                 | Wan2.7                                                  | HappyHorse-1.1                                                                                |
| ----------------------------------------- | ------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Синхронизация губ под аудио (i2v)         | ✅ `wan2.7-i2v` поддерживает `driving_audio`             | ❌ Не поддерживается, i2v принимает только первый кадр                                         |
| Лимит изображений для reference-to-video  | reference image + reference video, максимум 5 всего     | до 9 reference images                                                                         |
| Reference images для редактирования видео | ≤5                                                      | ≤5                                                                                            |
| Стиль согласованности объекта             | Взаимодействие нескольких объектов, голосовой reference | Склоняется к «точному воспроизведению динамичного материала», сохраняет стабильность объектов |

<Tip>
  **Нужны lip-sync / rap / озвучка digital-human** → выберите `wan2.7-i2v` (единственный вариант с audio drive).
  **Нужно много reference images, чтобы сохранить согласованность объекта** → рассмотрите [HappyHorse r2v (до 9 изображений)](/ru/api-capabilities/happyhorse/reference-to-video).
</Tip>

## Лучшие практики

<Steps>
  <Step title="Сначала тестируйте на 720P / 5 секунд">
    В процессе разработки быстро проверяйте prompt и направление камеры на коротких клипах низкого разрешения, а после завершения переходите к 720P / 1080P и более длительным роликам, чтобы сократить затраты и время ожидания.
  </Step>

  <Step title="Всегда включайте prompt_extend">
    `prompt_extend: true` заметно улучшает качество для коротких prompt, ценой лишь нескольких дополнительных секунд генерации.
  </Step>

  <Step title="Опрос каждые 5-10 секунд">
    Никогда не делайте интервал меньше 3 секунд (иначе вы упретесь в лимит запросов) и не блокируйте выполнение на длительных задачах бесконечно. 720P / 5 секунд обычно занимает 70-140 секунд; 1080P / более длинные клипы могут превышать 5 минут.
  </Step>

  <Step title="Установите клиентский timeout на 20 минут как запасной предел">
    1080P или клипы длиннее 10 секунд заметно медленнее; задайте для цикла опроса запасной timeout на 20 минут.
  </Step>

  <Step title="Скачивайте сразу после получения result_url">
    `result_url` по умолчанию **истекает через 24 часа** и представляет собой подписанную прямую ссылку OSS, поэтому при скачивании **не отправляйте заголовок Authorization**. В production всегда пересохраняйте его в своем OSS / CDN.
  </Step>

  <Step title="Делайте отправки идемпотентными">
    Неудачные задачи не тарифицируются, но повторная отправка той же задачи тарифицируется снова. Поддерживайте сопоставление «ID бизнеса → task\_id» на уровне приложения, чтобы избежать случайных списаний.
  </Step>
</Steps>

## Коды ошибок и повторные попытки

Ошибки возникают на двух этапах и обрабатываются по-разному:

| Источник                                               | Сигнатура                                                                                                                        | Обработка                                                                                                  |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| **Этап создания (отклонено APIYI)**                    | HTTP 4xx/5xx, `type` — это `task_error` / `parse_request_failed` / `build_request_failed`                                        | Исправьте body и повторите попытку (обычно неверный тип поля, отсутствует media или неправильный endpoint) |
| **Этап выполнения (отклонено upstream Alibaba Cloud)** | Задача завершается как `status=failed`, `error.message` с префиксом `[InvalidParameter]` / `[InvalidImageUrl]` и т. д. в скобках | Прочитайте подсказку в скобках; обычно это недоступный media URL или чувствительный prompt                 |

<Info>
  **Рекомендуемое поведение клиента**: повтор с экспоненциальным backoff при HTTP 5xx / network errors (1s / 4s / 16s); сразу показывайте HTTP 4xx без повтора; задачу `failed` с `[InvalidImageUrl]` можно повторить (возможно, временная проблема сети), а `[InvalidParameter]` / чувствительные слова не следует повторять.
</Info>

## FAQ

<AccordionGroup>
  <Accordion title="Почему я не могу использовать /v1/videos для отправки задач Wan?">
    `/v1/videos` — это эндпоинт OpenAI плоского формата с неполной поддержкой i2v / r2v для Wan: поля media, например `media`, отбрасываются, а upstream Alibaba Cloud возвращает `[InvalidParameter] Field required: input.media`. **Все запросы на создание видео Wan отправляются в `/wan/api/v1/services/aigc/video-generation/video-synthesis`**, а запросы на получение всегда идут в `/v1/tasks/{task_id}`.
  </Accordion>

  <Accordion title="Что делает заголовок X-DashScope-Async: enable? Он обязателен?">
    Он сообщает endpoint, что «это асинхронная задача, сразу верните task\_id и не блокируйте выполнение». **Он обязателен для каждого запроса на создание**; если его опустить, возвращается `current user api does not support synchronous calls`. Запрос на получение (GET) этот заголовок не требует.
  </Accordion>

  <Accordion title="Почему опрос идет через /v1/tasks/{id}, а не через /wan/api/v1/tasks/{id}?">
    APIYI нормализует все запросы на опрос видео-задач к `/v1/tasks/{task_id}`. Независимо от того, какой путь вы использовали для создания задачи, вы опрашиваете ее через этот единственный endpoint, а поля верхнего уровня ответа `status` / `progress` / `result_url` / `error` остаются согласованными.
  </Accordion>

  <Accordion title="загрузка result_url возвращает 403 / SignatureDoesNotMatch, что делать?">
    Уберите заголовок `Authorization`. `result_url` уже является предварительно подписанной прямой ссылкой Alibaba Cloud OSS; если добавить APIYI Key, OSS отклонит ее:

    ```bash theme={null}
    curl -L -o out.mp4 "$RESULT_URL"          # ✅ correct
    curl -L -H "Authorization: Bearer $KEY" -o out.mp4 "$RESULT_URL"   # ❌ wrong
    ```
  </Accordion>

  <Accordion title="Что если срок действия result_url истек?">
    По умолчанию ссылка действительна **24 часа**. После истечения срока снова выполните GET `/v1/tasks/{task_id}`, и обычно вы получите свежую `result_url`, но срок действия опроса по самому task\_id тоже составляет 24 часа (после этого возвращается `UNKNOWN`). Для долгосрочного хранения как можно скорее загрузите файл в свое хранилище.
  </Accordion>

  <Accordion title="прогресс завис на 30% — он завис?">
    Нет. Прогресс, который сообщает upstream Alibaba Cloud, имеет грубую градацию (только уровни 0% / 10% / 30% / 100%). **Пока `status` все еще `in_progress`, продолжайте ждать**; обычно он сразу прыгает с 30% до 100%.
  </Accordion>

  <Accordion title="Сколько задач один Key может выполнять параллельно?">
    На практике вы можете отправить 4-8 задач одновременно без упора в лимит запросов. В production держите одновременно активные задачи ≤10; все, что выше, уходит в очередь. У query API довольно высокий RPS по умолчанию, но интервал опроса в 5-10 секунд все равно рекомендуется.
  </Accordion>

  <Accordion title="Тарифицируются ли неудачные задачи?">
    `status=failed` не тарифицируется. Но учтите: повторная отправка той же задачи тарифицируется снова, поэтому сделайте ее идемпотентной. Во время тестирования можно отключить `prompt_extend` и использовать 720P / 5 seconds / short prompts, чтобы снизить стоимость за единицу.
  </Accordion>

  <Accordion title="Wan2.6 по-прежнему можно использовать?">
    Да. Серия Wan2.6 (включая `wan2.6-r2v-flash`) по-прежнему есть в списке доступных вызовов, с тем же протоколом, что и Wan2.7; достаточно изменить имя `model`. См. [Исторические версии](/ru/api-capabilities/wan/historical-versions).
  </Accordion>
</AccordionGroup>

## Настройка группы

Серии Wan и [HappyHorse](/ru/api-capabilities/happyhorse/overview) **используют одну группу `Wan&HappyHorse`** — один Token может вызывать обе серии. Видео-модели тарифицируются **за секунду**, поэтому Token должен соответствовать двум условиям, чтобы маршрутизация прошла успешно:

1. **Модель тарификации**: выберите **Pay-as-you-go Priority** или **Pay-as-you-go** — видео тарифицируется за секунду, поэтому **Token с Pay-per-request не может маршрутизироваться**
2. **Группа**: выберите группу, которая включает `Wan&HappyHorse`

## Тарификация

### Цена по умолчанию = 98％ от официальной цены Alibaba (легко вычислить)

В консоли группа `Wan&HappyHorse` показывает коэффициент **0.14x**, который выражается во встроенной единице тарификации **RMB**. Поскольку APIYI ведет тарификацию в **USD** по фиксированному курсу 1:7, фактический пересчет такой:

```
0.14 (RMB pricing unit) × 7 (fixed exchange rate) = 0.98
```

Иными словами, **цена по умолчанию = 98% от официальной цены Alibaba** — дешевле, чем покупать напрямую у Alibaba, и без необходимости самостоятельно выстраивать зарубежный канал.

> Пересчет: **цена в USD за секунду = официальная цена в RMB × 0.14** (то есть `× 0.98 ÷ 7`). Например, официальная цена 1080P в ¥1.0/s → \$0.14/s, то есть ровно `0.14x`, который отображается в консоли.

### Подробности цены (цена по умолчанию, тарификация по секундам)

Wan2.7 text-to-video / image-to-video / reference-to-video тарифицируются одинаково, с двумя уровнями — `720P` / `1080P` (480P не поддерживается):

| Разрешение | Официальная цена | Наша цена по умолчанию /s | 5 s    | 10 s   | 12 s   |
| ---------- | ---------------- | ------------------------- | ------ | ------ | ------ |
| `720P`     | ¥0.6/s           | \$0.084/s                 | \$0.42 | \$0.84 | \$1.01 |
| `1080P`    | ¥1.0/s           | \$0.14/s                  | \$0.70 | \$1.40 | \$1.68 |

<Info>
  * `wan2.7-r2v` по умолчанию равен `1080P`, а длительность ограничена 10 секундами, если в reference media есть видео.
  * `wan2.7-videoedit` (редактирование видео) формирует выходную длительность по исходному видео и тарифицируется по фактическим секундам результата, а не по `duration`.
  * Указанные цены — это **цена по умолчанию (98% от официальной)**; с максимальным бонусом за пополнение эффективная цена примерно равна значению из таблицы **÷ 1.2** (например, 1080P 5 s \$0.70 → примерно \$0.58).
</Info>

### Ступенчатые бонусы за пополнение для еще более низкой эффективной цены

После подключения к [программе бонусов за пополнение](/ru/faq/recharge-promotions) зачисленный баланс можно увеличить примерно до \~1.2x, еще сильнее снижая эффективную цену:

```
0.98 ÷ 1.2 ≈ 0.816
```

Таким образом, крупные клиенты могут снизить цену вплоть до **\~81.6% от официальной цены**.

| Уровень                                                       | Эффективная цена (по сравнению с официальной ценой Alibaba) | Формула                                                |
| ------------------------------------------------------------- | ----------------------------------------------------------- | ------------------------------------------------------ |
| По умолчанию                                                  | **98%**                                                     | коэффициент тарифа 0.14x × фиксированный курс обмена 7 |
| С бонусами за пополнение (макс. уровень для крупных клиентов) | **\~81.6%**                                                 | 0.98 ÷ 1.2                                             |

<Info>
  * Единица тарификации = **уровень разрешения × длительность (секунды)**; неудачные задачи не тарифицируются.
  * 1:7 — это **фиксированный расчетный курс обмена** (не льготный); он единообразно применяется ко всем пополнениям в USD.
  * Для самых высоких уровней бонусов и подходящих каналов см. [бонусы за пополнение](/ru/faq/recharge-promotions). Актуальный курс является приоритетным в [консоли](https://api.apiyi.com/token).
</Info>
