# Генерация и редактирование изображений Seedream

> Полное руководство по моделям генерации изображений ByteDance BytePlus ModelArk Seedream — три активные версии (5.0 / 4.5 / 4.0), вывод 4K, объединение нескольких изображений, пакетная генерация последовательностей, редактирование по эталонному изображению — все на одном endpoint.

## Обзор

**Seedream** — флагманская серия моделей генерации изображений от ByteDance BytePlus ModelArk с **единой архитектурой генерации и редактирования**: text-to-image, редактирование одного изображения, слияние нескольких изображений и пакетная генерация последовательностей — всё работает через один `/v1/images/generations` эндпоинт, отличаются только параметры. APIYI имеет стратегическое партнёрство с BytePlus и интегрирует каждую активную версию с первого дня.

<Note>
  **🎨 Основные преимущества**: три активные версии (5.0 / 4.5 / 4.0) с единой тарификацией + вывод 4K + до 10 референсных изображений для слияния + пакетная обработка (ввод + вывод ≤ 15) + лучшее отображение текста. **Идеально для главных изображений в e-commerce, рекламных постеров, фотографий товаров и создания контента** — везде, где важны высокое качество и читаемый текст.
</Note>

<Info>
  Все Image API — **синхронные**: нет task ID для опроса, и если ваш клиент отключится, результат будет потерян, хотя запрос всё равно будет тарифицирован. Задайте для этой модели достаточно большой timeout; см. [Основы Image API и лучшие практики](/ru/api-capabilities/image-api-best-practices).
</Info>

<Note>
  **Какая это версия Seedream?** APIYI предоставляет Seedream на **официальных зарубежных BytePlus (international) ресурсах** — не на материковой версии Doubao / Volcengine. International-версия применяет сравнительно более мягкую политику модерации контента, чем domestic-версия, предоставляя вам больше творческой свободы — это реальное преимущество этой платформы, но **это не означает отсутствие модерации**: BytePlus по-прежнему выполняет встроенные проверки безопасности контента, а нарушающие prompt или референсные изображения отклоняются с 400/403 (отклонённые запросы не тарифицируются). Используйте в рамках правил.
</Note>

## Пусть AI-агент выполнит интеграцию

<Note>
  Если вы разрабатываете с Codex / Claude Code / Cursor, скопируйте prompt ниже и передайте его вашему агенту. Сначала он получает текстовую версию этой страницы (добавьте `.md` к любому docs URL), затем пишет код в стеке вашего проекта — таймаут, немедленное размещение результатов URL заново, редактирование через массив URL вместо multipart, и параметры, которые `seedream-5-0-pro` отклоняет, уже заложены в требования.

<Prompt description="Пусть кодирующий агент интегрирует или устранит неполадки в Seedream text-to-image и редактировании изображений. Скопируйте и вставьте в Codex, Claude Code, Cursor и аналогичные инструменты." icon="bot" actions={["copy"]}>
  Интегрируйте / устраните неполадки в Seedream text-to-image и редактировании изображений в этом проекте.

  Прежде чем трогать код, получите [https://docs.apiyi.com/en/api-capabilities/seedream-image/overview.md](https://docs.apiyi.com/en/api-capabilities/seedream-image/overview.md) как текстовую версию этой страницы. Для более точных сведений о параметрах добавьте `.md` к страницам text-to-image и image-edit тем же способом.

  Требования:

  1. Таймаут: настройте таймаут клиента по модели — начните с 60 секунд для серии 4.x, увеличьте его до 120 секунд для `seedream-5-0`, и **увеличьте его до 240 секунд для `seedream-5-0-pro`, где обработка занимает примерно 2 минуты на изображение**. Image APIs синхронны — task ID нет, поэтому если клиент отключится, результат будет потерян, хотя запрос уже будет оплачен. Reverse proxies, gateways и лимиты serverless-исполнения тоже нужно расширить.

  2. Обработка ответа: значение по умолчанию — `url` — временная подписанная ссылка BytePlus TOS, срок действия которой истекает примерно через 24 часа, — и вы можете передать `response_format`, установив `b64_json`, чтобы получить plain base64 вместо этого (без префикса `data:`). Если вы берете URL, **немедленно скачайте его и разместите заново в своем object storage**; никогда не храните upstream-ссылку в своей базе данных как долгоживущий адрес. Если вы берете base64, отрисуйте его и предложите действие сохранения на диск. Явно передавайте `response_format`, а не полагайтесь на значение по умолчанию.

  3. Загрузка эталонных изображений (**самое большое отличие от других image models**): Seedream использует унифицированную архитектуру генерации и редактирования, поэтому **нет endpoint `/v1/images/edits`** — и генерация, и редактирование обращаются к `/v1/images/generations` как к `application/json`. Эталонные изображения передаются в поле `image`, которое представляет собой **массив URL** — не multipart-загрузку файлов и не повторяющееся поле `image[]`. Элементы массива могут быть URL изображений или data URL в форме `data:image/jpeg;base64,...`, и их можно смешивать. Допускается до 10 эталонных изображений, и **входные изображения вместе с выходными не должны превышать 15**. Поля `mask` нет. Для больших локальных файлов сначала загрузите их в свое object storage и передайте URL; если вы используете data URL, сначала сжимайте — обрабатывайте только файлы больше 1.5MB, уменьшайте длинную сторону до 2048px с сохранением пропорций (никогда не увеличивайте маленькое изображение), перекодируйте с quality 0.9 и держите общий размер ниже 6MB для запросов с несколькими изображениями. Если одно изображение не удается сжать, вернитесь к оригиналу и продолжайте.

  4. Жесткие ограничения по параметрам: у этой модели **нет параметра `quality`** — точность определяется версией модели и `size`. `size` принимает либо уровень (`1K` / `2K` / `3K` / `4K`, по умолчанию `2K`), либо точные пиксели; обратите внимание, что `seedream-5-0-pro` ограничивается примерно 4,19 миллиона пикселей при 2048 × 2048 и не имеет уровня 3K или 4K. `n` **молча игнорируется** (вы все равно получаете одно изображение и платите за одно), поэтому для нескольких результатов используйте `sequential_image_generation`; `seed` не влияет на 4.x или 5.x. Для коммерческого использования **всегда передавайте `watermark` со значением false**, потому что значение по умолчанию зависит от версии. `output_format` поддерживает png только в 5.0 и 5.0-pro; 4.5 и 4.0 возвращают только jpeg, без альфа-канала.

  5. Два жестких запрета для `seedream-5-0-pro`: **не передавайте `sequential_image_generation` вообще — любое значение, включая `"disabled"`, возвращает 400** — и **не передавайте `stream`** (тоже 400). Если вы переносите код с 5.0 или 4.x, полностью удалите оба поля.

  6. Считывайте ключ из переменной окружения `APIYI_API_KEY` и используйте [https://api.apiyi.com/v1](https://api.apiyi.com/v1) как base URL. Никогда не задавайте его жестко в коде, никогда не добавляйте его в git. При вызове через OpenAI SDK параметры `image`, `sequential_image_generation`, `watermark` и `output_format` должны находиться внутри `extra_body`, чтобы они были переданы дальше.

  7. Когда закончите, действительно выполните один вызов генерации изображения по тексту и один вызов редактирования изображения, затем покажите мне результаты и стоимость этих двух вызовов.
</Prompt>

Тарификация за каждое изображение, **та же цена, что у официального BytePlus**. Бонусы за пополнение дополнительно снижают эффективную цену за единицу.

<Info>
  **Примечания по тарификации**:

  * Тарификация идет за каждое сгенерированное изображение, независимо от длины prompt или режима fusion
  * `seedream-5-0-pro` тарифицируется по **фиксированной ставке \$0.12 за request** (1 image на request; пакетная последовательность не поддерживается). Официально модель использует два уровня цен за выходные пиксели (одна цена для ≤2.36M px, одна для >2.36M px) плюс плату за изображение для reference images после первого; APIYI упрощает это до фиксированной цены за request — **без уровней, с включенной платой за input-image**. У этой модели **нет никакой официальной скидки**; APIYI устанавливает цену на основе гарантии поставки — фактически без маржи после учета бонусов за пополнение и налоговых расходов — и о любом изменении цены будет объявлено заранее
  * В режиме `sequential_image_generation: "auto"` тарификация идет по фактическому количеству выходных изображений (например, `max_images: 4` outputs 4 → 4 тарифицируется)
  * Неудачные запросы (4xx / заблокированные модерацией) **не тарифицируются**
  * Бесплатный пробный период: 200 бесплатных изображений при первом onboarding (предоставляется BytePlus)
  * Подробнее о бонусах за пополнение: см. [Акции на пополнение](/ru/faq/recharge-promotions)
</Info>

| **Вход + выход одного запроса**       | input ≤ 10, output 1                                                                           | ≤ 15                              | ≤ 15                  | ≤ 15                  |
| **Типичная задержка**                 | \~2 minutes                                                                                    | \~30s                             | 10-20s                | 10-15s                |
| **Поле ответа**                       | то же самое                                                                                    | `data[].url` or `data[].b64_json` | то же самое           | то же самое           |

## Сравнение времени генерации

Измеренная задержка одного запроса по версии (измерено 2026-07, UTC+8; время по часам от запроса до полного ответа — ожидайте обычные колебания между запросами):

| Сценарий                                                           | seedream-4-0 | seedream-4-5 | seedream-5-0 | seedream-5-0-pro                     |
| ------------------------------------------------------------------ | ------------ | ------------ | ------------ | ------------------------------------ |
| Текст-в-изображение (1K/2K)                                        | 7-11s        | 8-13s        | 29-34s       | **110-130s**                         |
| Текст-в-изображение (высший уровень)                               | \~15s (4K)   | \~18s (4K)   | \~37s (3K)   | \~134s (W×H 2720×1530, макс. размер) |
| Редактирование / слияние нескольких изображений                    | \~11s        | 17-21s       | 38-40s       | **115-132s**                         |
| Пакетная последовательность (2 изображения, редактирование + авто) | —            | \~36s        | —            | — (не поддерживается)                |
| **Рекомендуемый тайм-аут клиента**                                 | ≥ 60s        | ≥ 60s        | ≥ 120s       | **≥ 240s**                           |

<Warning>
  **`seedream-5-0-pro`** стабильно занимает около 2 минут на изображение (110-132s измерено в каждом запуске, без исключений). Это ожидаемое поведение для модели изображений с глубоким рассуждением, а не сбой. Перед тем как выбирать pro, убедитесь, что ваш продукт может выдержать такую задержку: интерактивные сценарии (когда пользователь ждёт на экране) подходят плохо — вместо этого используйте 5.0-lite (\~30s); pro лучше подходит для офлайн-пакетной обработки, где важнее всего качество изображений и соблюдение инструкций.
</Warning>

## Ключевые параметры подробно

### `size` (размер вывода)

Две семейства значений — выберите одно:

**Предустановленные уровни** (модель сама выбирает соотношение сторон):

| Уровень | Примерное число пикселей   | Поддерживается в |
| ------- | -------------------------- | ---------------- |
| `1K`    | \~1024×1024                | 4.0 / 5.0-pro    |
| `2K`    | \~2048×2048 (по умолчанию) | все версии       |
| `3K`    | \~3072×3072                | только 5.0       |
| `4K`    | \~4096×4096                | 4.5 / 4.0        |

**Точные пиксели** (настраиваемые):

* Общее число пикселей ∈ \[1280×720, 4096×4096]
* Соотношение сторон ∈ \[1/16, 16]
* По умолчанию: `2048x2048`

**Допустимые примеры**: `1920x1080` (FullHD), `3840x2160` (ландшафтный 4K), `1080x1920` (портретный режим телефона), `2560x1440` (ландшафтный 2K)
**Недопустимые примеры**: `5000x5000` (превышает лимит), `100x1600` (соотношение сторон меньше 1/16)

<Warning>
  Размеры с общим числом пикселей выше 4096×4096 возвращают 400. Экстремальные соотношения сторон (близкие к 1/16 или 16) могут выглядеть неестественно растянутыми — предпочитайте пресеты или распространенные варианты 16:9 / 9:16 / 1:1.

  **Модели серии 5.0 используют другой диапазон точных пикселей, чем 4.x** (более высокий нижний предел, более низкий верхний предел). Размеры вне диапазона возвращают 400 с допустимым диапазоном в сообщении об ошибке. Измеренный ориентир: нижний предел у 5.0-lite — примерно 2560×1440; **5.0-pro ограничен 4.19M общих пикселей (максимум 2048×2048; при 16:9 длинная сторона достигает 2720×1530 ≈ 2.7K, проверено как рабочее) — пресетов 3K/4K нет**.
</Warning>

### `image` и `sequential_image_generation` (переключатели режима)

Эндпоинт `/v1/images/generations` охватывает и text-to-image, и редактирование/слияние. Два параметра вместе выбирают режим:

| Режим                                | `image`                 | `sequential_image_generation`                               | Примечания                                                               |
| ------------------------------------ | ----------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------ |
| Чистый text-to-image                 | не указан               | не указан или `"disabled"`                                  | 1 результат                                                              |
| Редактирование по одному изображению | `["url1"]`              | `"disabled"`                                                | Редактирование на основе 1 эталона                                       |
| Слияние нескольких изображений       | `["url1", "url2", ...]` | `"disabled"`                                                | До 10 эталонов; ссылайтесь как на «изображение 1 / изображение 2»        |
| Пакетная последовательность          | необязательно           | `"auto"` + `sequential_image_generation_options.max_images` | N согласованных результатов, **N ≤ max\_images** и **вход + выход ≤ 15** |

<Warning>
  **`seedream-5-0-pro` не принимает параметр `sequential_image_generation`** — передача любого значения (включая `"disabled"`) возвращает 400. Для редактирования / слияния с моделью pro указывайте только `image` и полностью опускайте параметр; то же самое относится к `stream`.
</Warning>

Полные примеры кода см. в [Text-to-Image](/ru/api-capabilities/seedream-image/text-to-image) и [Image Editing](/ru/api-capabilities/seedream-image/image-edit).

## Лучшие практики

<Steps>
  <Step title="Выбирайте правильную версию">
    * **Лучший общий опыт** → `seedream-5-0-260128` (больше всего функций, но предел 3K)
    * **4K + качественная отрисовка текста** → `seedream-4-5-251128` (4K + прорыв в тексте)
    * **4K + лучшая цена** → `seedream-4-0-250828` (самый дешевый 4K)
    * **Максимальное качество изображения / сложные инструкции (профессиональная работа)** → `seedream-5-0-pro-260628` (\$0.12/запрос, \~2 минуты на изображение, только 1K/2K — не рекомендуется для повседневного использования)
  </Step>

  <Step title="Предпочитайте предустановленные размеры">
    `1K`/`2K`/`3K`/`4K` настроены BytePlus для стабильной скорости и качества. Используйте точные пиксели только когда у вас есть реальное требование к соотношению сторон. Учитывайте различия между версиями в поддерживаемых уровнях.
  </Step>

  <Step title="Явно указывайте изображения">
    При наличии нескольких `image` URLs пишите prompt с явными ссылками — «Поместите человека из изображения 1 в сцену изображения 2, используя цветовую палитру изображения 3» — вместо того чтобы заставлять модель гадать.
  </Step>

  <Step title="Контролируйте стоимость batch-последовательности">
    `sequential_image_generation: "auto"` + `max_images: 4` дают 4 результата — тарификация × 4. Сначала проверьте с `max_images: 1`, затем масштабируйте.
  </Step>

  <Step title="Выбирайте формат вывода по сценарию использования">
    5.0 / 5.0-pro поддерживают `png` и `jpeg`; 4.5 / 4.0 — только `jpeg`. Используйте серию 5.0 + png, когда нужны прозрачные фоны или без потерь деталей, jpeg — для сценариев, чувствительных к размеру.
  </Step>

  <Step title="Установите тайм-аут клиента ≥ 60 секунд">
    Одно изображение занимает \~15 с, но batch-последовательность (4 изображения) или 4K + hd могут занять 30-60 с. **Начните с тайм-аута клиента 60 с** и показывайте в UI индикатор прогресса. **`seedream-5-0-pro` занимает \~2 минуты на изображение — используйте тайм-аут 240 с или больше**.
  </Step>

  <Step title="Отключайте водяной знак при необходимости">
    Установите `watermark: false`, чтобы удалить водяной знак BytePlus (значения по умолчанию зависят от версии, поэтому задавайте его явно). Требуется для коммерческих материалов.
  </Step>
</Steps>

## Коды ошибок и повторные попытки

| Статус  | Значение                                                                                          | Рекомендуемое действие                                                      |
| ------- | ------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `400`   | Недопустимые параметры (размер вне допустимых границ, массив `image` > 10, неподдерживаемый tier) | Проверьте соответствие поддерживаемому tier используемой версии             |
| `401`   | Недопустимый token                                                                                | Проверьте Bearer Token                                                      |
| `403`   | Заблокировано модерацией контента                                                                 | Скорректируйте prompt или замените референсные изображения                  |
| `429`   | Лимит запросов (по умолчанию 500 RPM) или недостаточный баланс                                    | Экспоненциальная задержка; обратитесь в отдел продаж для более высокого RPM |
| `5xx`   | Ошибка шлюза / вышестоящего сервиса                                                               | Повторите 1-2 раза                                                          |
| Timeout | Долгий запрос                                                                                     | Таймаут клиента ≥ **60s** (batch sequence или 4K + hd могут достигать 60s)  |

<Info>
  **Рекомендации для клиента**:

  * Начните с таймаута запроса **60 секунд** (batch sequence или 4K + hd могут занимать до минуты)
  * Применяйте **экспоненциальную задержку** для 5xx и таймаутов (рекомендуется 2 повторные попытки)
  * Логируйте заголовок ответа `x-request-id` для обращений в поддержку
</Info>

## Частые вопросы

<AccordionGroup>
  <Accordion title="5.0 Pro / 5.0 / 4.5 / 4.0 — что выбрать?">
    | Нужно                                                                            | Рекомендуется                                                                                         |
    | -------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
    | Новейшие функции + лучший вариант в целом                                        | `seedream-5-0-260128`                                                                                 |
    | 4K + качественный рендеринг текста (постеры, реклама)                            | `seedream-4-5-251128`                                                                                 |
    | 4K + лучшая цена                                                                 | `seedream-4-0-250828`                                                                                 |
    | Стабильная пакетная генерация для длительных задач                               | `seedream-4-0-250828` (проверенный, самый дешевый, быстрый режим prompt)                              |
    | Максимальное качество изображения / сложные инструкции (профессиональная работа) | `seedream-5-0-pro-260628` (\$0.12/запрос, \~2 мин на изображение — пропустите, если это вам не нужно) |

    См. [Исторические версии](/ru/api-capabilities/seedream-image/historical-versions) для полного сравнения.
  </Accordion>

  <Accordion title="Почему редактирование изображений тоже использует эндпоинт генерации?">
    Seedream использует единую архитектуру генерации и редактирования — **отдельного эндпоинта `/v1/images/edits` нет**. В отличие от gpt-image-2 от OpenAI (multipart upload в `/v1/images/edits`), Seedream использует `application/json` и передает image **URL изображений в виде массива** в поле `image`.

    Преимущества: согласованность протокола, повторное использование параметров, простое переключение режимов. Подробности см. в [Редактировании изображений](/ru/api-capabilities/seedream-image/image-edit).
  </Accordion>

  <Accordion title="Поле image принимает base64?">
    **Да** (проверено тестированием). Используйте data URI: `data:image/<format>;base64,<base64 string>` с `<format>` в нижнем регистре (например, `data:image/jpeg;base64,...`). URL и записи base64 можно смешивать в одном массиве. Для больших локальных изображений по-прежнему лучше загрузить их в image host и передать URL, чтобы тело запроса оставалось небольшим.
  </Accordion>

  <Accordion title="Лимит слияния нескольких изображений? Лимит пакетной последовательности?">
    * **Слияние нескольких изображений** (массив `image`): 4.5 / 5.0-pro явно поддерживают до 10. 5.0 / 4.0 тоже поддерживают работу с несколькими изображениями, хотя явный верхний предел не задокументирован.
    * **Пакетная последовательность** (`max_images`): ограничена общим правилом **input references + output ≤ 15**. При сочетании слияния и последовательности считайте общее количество. Учтите, что **5.0-pro не поддерживает пакетную последовательность** (передача `sequential_image_generation` возвращает 400).
  </Accordion>

  <Accordion title="Требуется ли у b64_json префикс data:image?">
    Зависит от `response_format`:

    * `response_format: "url"` (по умолчанию) → `data[0].url` — это временный подписанный URL, рендерите напрямую с помощью `<img src=...>`
    * `response_format: "b64_json"` → `data[0].b64_json` — это **обычная base64-строка** (без префикса `data:image/...;base64,`). Декодируйте и запишите на диск либо вручную добавьте префикс для отображения в браузере.
  </Accordion>

  <Accordion title="Поддерживается ли потоковая передача вывода?">
    Поддерживается в 5.0 / 4.5 / 4.0 через `stream: true`. Потоковая передача особенно полезна для длинных prompt и изображений высокого разрешения — frontend может постепенно отображать промежуточные результаты. **`seedream-5-0-pro` не поддерживает потоковую передачу** — передача `stream` возвращает 400.
  </Accordion>

  <Accordion title="Лимит запросов?">
    **По умолчанию 500 изображений в минуту** (Max Images per Minute), единый для всех версий. Чтобы получить более высокие квоты, свяжитесь с отделом продаж.
  </Accordion>

  <Accordion title="Тарифицируются ли неудачные запросы?">
    **Нет**. В BytePlus есть встроенная модерация. Отклонения модерации и ошибки параметров возвращают `400` / `403` и не тарифицируются. Другие ошибки без тарификации: `401` (недействительный token), `429` (достигнут лимит запросов). **Тарифицируется только успешная генерация (`200` с корректным ответом)**.
  </Accordion>

  <Accordion title="Можно ли использовать официальный OpenAI SDK?">
    Да, без изменений кода. Укажите `base_url` на `https://api.apiyi.com/v1` и передавайте дополнительные параметры (`image` / `sequential_image_generation` / `watermark` и т. д.) через `extra_body`:

    ```python theme={null}
    from openai import OpenAI

    client = OpenAI(api_key="sk-your-key", base_url="https://api.apiyi.com/v1")
    resp = client.images.generate(
        model="seedream-5-0-260128",
        prompt="...",
        size="2K",
        extra_body={
            "image": ["https://.../ref.png"],
            "sequential_image_generation": "disabled",
            "watermark": False,
        }
    )
    ```
  </Accordion>

  <Accordion title="Кому принадлежат сгенерированные изображения?">
    Сгенерированные изображения можно использовать в коммерческих и некоммерческих целях. Подробности см. в условиях обслуживания BytePlus.
  </Accordion>

  <Accordion title="Поддерживаются ли прозрачные фоны?">
    `seedream-5-0` / `seedream-5-0-pro` поддерживают вывод `png` и могут создавать прозрачный фон при соответствующем запросе («прозрачный фон, альфа-канал»). `seedream-4-5` / `4-0` выводят только `jpeg` и **не поддерживают прозрачность** — удалите фон самостоятельно на этапе постобработки.
  </Accordion>

  <Accordion title="Можно ли отменить генерацию в процессе?">
    **Нет**. `/v1/images/generations` выполняется синхронно. После отправки запрос выполняется до завершения. Сервер все равно завершает выполнение и тарифицирует запрос даже если клиент отключится. Настройте тайм-ауты клиента и не рассчитывайте, что отключение сэкономит расходы.
  </Accordion>
</AccordionGroup>
