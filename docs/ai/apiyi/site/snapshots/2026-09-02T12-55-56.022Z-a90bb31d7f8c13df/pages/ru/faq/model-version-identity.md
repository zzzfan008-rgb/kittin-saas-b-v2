# Почему модели ИИ не знают свою собственную версию?

> Объясняет, почему модели ИИ не могут точно определить свою версию при вызове через API, и в чём разница между веб-приложениями и вызовами через API

## Краткий ответ

<Info>
  **Это совершенно нормально и не влияет на возможности модели.**

  Имя модели назначается после завершения обучения — сама модель никогда не «учила» собственную идентичность. Официальные веб-приложения (например, claude.ai или chatgpt.com) могут отвечать правильно, потому что в них встроен системный prompt, который сообщает модели, «кто она». Вызовы API по умолчанию не включают эту информацию, поэтому модель может «ошибиться» в определении своей версии.
</Info>

## Реальный пример

<Warning>
  **Распространенный сценарий**

  При вызове Claude Sonnet 4.5 через API и вопросе «Какую модель вы используете?» он может ответить: «Я Claude 3.5 Sonnet». Это **не означает**, что вы вызвали неправильную модель — модель просто не знает собственного названия.

  То же самое происходит с GPT-4o, Gemini и всеми другими моделями — это универсальная особенность больших языковых моделей, а не проблема, специфичная для APIYI.
</Warning>

## Простая аналогия

<Card title="Аналогия с актёром" icon="drama">
  Представьте себе очень талантливого актёра:

  * Его **навыки** формируются годами обучения (как процесс обучения модели)
  * Его **имя персонажа** ему сообщает режиссёр перед съёмками (как System Prompt)
  * Если никто не говорит ему, какую роль он играет, он по-прежнему талантлив, но **не знает имени своего персонажа**

  Модели AI работают так же: их возможности приходят из обучающих данных, но идентичность «Я — Claude Sonnet 4.5» нужно задавать явно.
</Card>

## Техническое объяснение

<AccordionGroup>
  <Accordion title="Почему модель не знает своего собственного имени?">
    **Назначение имени модели происходит после обучения**

    Процесс разработки большой языковой модели выглядит так:

    1. **Сбор данных** → Подготовка обучающего корпуса
    2. **Обучение модели** → Изучение понимания и генерации языка
    3. **Оценка и дообучение** → Оптимизация производительности модели
    4. **Назначение имени и выпуск** → Присвоение имени (например, "Claude Sonnet 4.5")

    Когда обучение завершается на шаге 2, имени из шага 4 еще не существует. В обучающих данных могут встречаться названия более старых версий модели (например, Claude 3.5 Sonnet), поэтому при ответе модель «угадывает» имя, которое уже видела раньше.

    **Аналогия**: это как если бы человек не мог знать свое имя до рождения — имя дают после рождения.
  </Accordion>

  <Accordion title="Почему официальные веб-приложения могут отвечать правильно?">
    **Роль встроенных System Prompt**

    Когда вы общаетесь на claude.ai или chatgpt.com, официальное веб-приложение автоматически вставляет скрытый System Prompt в начало каждого разговора, примерно такой:

    ```
    You are Claude, developed by Anthropic. Your model version is Claude Sonnet 4.5...
    ```

    Этот prompt невидим для пользователей, но модель его «читает» и поэтому знает, кто она.

    **Итак**: модель не знает своего имени по умолчанию — официальное веб-приложение каждый раз «напоминает» ей об этом.
  </Accordion>

  <Accordion title="Почему API работает иначе?">
    **API-запросы по умолчанию не включают информацию об идентичности**

    При вызове модели через API вы отправляете только:

    * Параметр `model` (указывает серверу, какую модель использовать)
    * Массив `messages` (содержимое вашего разговора)
    * Необязательный параметр `system` (ваш собственный System Prompt)

    Параметр `model` — это информация маршрутизации для **сервера** — сама модель не может прочитать это поле. Если вы не укажете идентичность модели в prompt `system`, она сможет только «угадать» ее на основе обучающих данных.

    **Это относится ко всем платформам API** — будь то официальный API, APIYI или любой другой провайдер, поведение будет абсолютно одинаковым.
  </Accordion>
</AccordionGroup>

## Как проверить модель, которую вы фактически вызываете

<CardGroup cols={2}>
  <Card title="Проверьте журналы вызовов" icon="file-text" href="/ru/faq/call-logs">
    В консоли APIYI в разделе **журналов вызовов** вы можете увидеть фактическое имя модели, использованное для каждого запроса — это самый точный способ проверки.
  </Card>

  <Card title="Проверьте ответ API" icon="code">
    Каждый JSON-ответ API включает поле `model`, которое однозначно определяет фактическую версию вызванной модели.

    ```json theme={null}
    {
      "model": "claude-sonnet-4-5-20250514",
      "choices": [...]
    }
    ```
  </Card>
</CardGroup>

## Гарантия сервиса APIYI

<Tip>
  **APIYI перенаправляет запросы через официальные каналы — качество модели идентично исходному.**

  * APIYI напрямую перенаправляет запросы к официальным API от OpenAI, Anthropic, Google и т. д.
  * Незнание моделью собственной идентичности — это универсальное явление на всех API-платформах
  * Вы можете проверить фактическую вызванную модель через журналы вызовов и поле `model` в ответах API
  * Если у вас есть какие-либо сомнения, пожалуйста, свяжитесь с нашей технической командой для проверки
</Tip>

## Как заставить модели корректно определять себя

Просто добавьте параметр `system` в ваш API-вызов, чтобы указать модели ее идентичность:

```python theme={null}
from openai import OpenAI

client = OpenAI(
    api_key="your-api-key",
    base_url="https://vip.apiyi.com/v1"
)

response = client.chat.completions.create(
    model="claude-sonnet-4-5-20250514",
    messages=[
        {
            "role": "system",
            "content": "You are Claude Sonnet 4.5, an AI assistant developed by Anthropic."
        },
        {
            "role": "user",
            "content": "What model are you?"
        }
    ]
)

print(response.choices[0].message.content)
# Output: I am Claude Sonnet 4.5, developed by Anthropic.
```

<Info>
  **Подсказка**: Это работает точно так же, как в официальных веб-приложениях, — через System Prompt вы сообщаете модели ее идентичность. После этого модель сможет корректно отвечать на вопрос «кто я».
</Info>
