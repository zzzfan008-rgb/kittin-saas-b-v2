# Нужно ли задавать доступные модели для token?

> Подробное объяснение механизма доступных моделей для token API.YI, рекомендации по использованию и типичные сценарии

## Общий случай: настраивать не нужно

<Info>
  **Рекомендуемая практика**: при создании token **не нужно задавать доступные модели**, что позволяет вам использовать все модели на сайте.
</Info>

Доступные модели используют **механизм белого списка**:

* **Не задано**: token может вызывать все 400+ моделей на сайте
* **Задано**: token может вызывать только указанные модели и не может использовать другие

Если ваши бизнес-сценарии разнообразны, задание доступных моделей ограничит область использования token и повлияет на гибкость.

## Почему не рекомендуется задавать такую настройку?

### 1. Ограничивает диапазон вызовов

Предположим, вы зададите доступные модели как `gpt-4o`, `claude-3-5-sonnet-20241022`, тогда:

* ✅ Можно вызывать: `gpt-4o`, `claude-3-5-sonnet-20241022`
* ❌ Нельзя вызывать: `gemini-2.5-pro`, `deepseek-v3`, и еще 400+ моделей

Это серьезно ограничит гибкость вашего бизнеса.

### 2. Проблемы с alias моделей

<Warning>
  **Ловушка alias моделей**: у некоторых моделей есть aliases, из-за чего при задании доступных моделей легко допустить ошибку.

  **Пример**:

  * **Alias**: `nano-banana-pro` (дружественный псевдоним)
  * **Официальное имя**: `gemini-3-pro-image-preview` (официальное API-имя)

  Если вы зададите доступные модели как `nano-banana-pro`, но в коде вызовете `gemini-3-pro-image-preview`, вы получите ошибку:

  ```
  {
    "error": {
      "message": "Model not allowed for this API key",
      "type": "invalid_request_error"
    }
  }
  ```
</Warning>

### 3. Изменения бизнес-сценариев

По мере развития вашего бизнеса вам может понадобиться тестировать или переключаться между разными моделями:

* Переключиться с GPT-4 на Claude 3.5
* Тестировать отечественные модели, такие как DeepSeek, Qwen
* Попробовать недавно выпущенный Gemini 2.5

Если вы заранее зададите доступные модели, вам придется каждый раз изменять список разрешенных моделей, что очень неудобно.

## Когда следует это настраивать?

Хотя это не рекомендуется, вы можете рассмотреть настройку доступных моделей в следующих сценариях:

### Сценарий 1: Обмен токенами с другими

<Card title="Совместная работа в команде/обмен с друзьями" icon="users">
  Если вы делитесь token KEY с коллегами или друзьями и хотите, чтобы они **использовали только определенные модели** (например, `gpt-3.5-turbo`), чтобы не расходовать ваш баланс на дорогие модели, вы можете задать доступные модели.

  **Пример**:

  * Ваш баланс ограничен, вы хотите, чтобы коллеги использовали только `gpt-3.5-turbo`, `gpt-4o-mini`
  * После задания доступных моделей, даже если коллеги попытаются вызвать `o3`, им будет отказано
</Card>

### Сценарий 2: Контроль бюджета

<Card title="Строгое управление затратами" icon="dollar-sign">
  Если вы устанавливаете строгий бюджет для проекта и разрешаете использовать только недорогие модели, вы можете ограничить это через белый список доступных моделей:

  **Пример**:

  * Бюджет проекта ограничен, разрешено использовать только `deepseek-v3` (\$0.07/million tokens)
  * Запретите использование `o3` (\$20/million tokens), чтобы избежать перерасхода
</Card>

### Сценарий 3: Соответствие требованиям безопасности

<Card title="Корпоративная политика безопасности" icon="shield">
  У некоторых предприятий действуют строгие правила использования AI-моделей, разрешающие только одобренные модели.

  **Пример**:

  * Компания разрешает использовать только официальные модели OpenAI
  * Задайте доступные модели `gpt-4o`, `gpt-4.1`, запретите использование моделей других поставщиков
</Card>

## Как настроить доступные модели?

Если вам действительно нужно настроить доступные модели, выполните следующие шаги:

1. Войдите на [страницу управления token API.YI](https://api.apiyi.com/token)
2. Нажмите «Add New KEY» или отредактируйте существующий token
3. Выберите разрешенные модели в поле «Available Models»
4. Сохраните конфигурацию

<Tip>
  **Используйте официальные названия**: при настройке доступных моделей рекомендуется использовать **официальные названия** моделей (например, `gemini-3-pro-image-preview`), а не алиасы (например, `nano-banana-pro`), чтобы избежать сбоев при вызове.

  Вы можете посмотреть все официальные названия моделей на [странице списка моделей](/ru/api-capabilities/model-info).
</Tip>
