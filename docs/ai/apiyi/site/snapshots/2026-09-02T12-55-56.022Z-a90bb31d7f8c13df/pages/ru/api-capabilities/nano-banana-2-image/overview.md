# Nano Banana 2 Генерация/редактирование изображений

> Последняя модель генерации изображений Google Nano Banana 2 (gemini-3.1-flash-image-preview) — качество уровня Pro при скорости уровня Flash, вывод 4K, 14 соотношений сторон, привязка к поиску изображений, $0.055 за изображение за вызов, на основе token — от $0.025 за изображение.

## Обзор

**Nano Banana 2** (кодовое имя) — это новейшая модель генерации изображений Google, выпущенная 26 февраля 2026 года, с ID модели `gemini-3.1-flash-image-preview`. Она переосмысливает экономическую эффективность генерации изображений, обеспечивая **качество уровня Pro при скорости и стоимости уровня Flash**, что делает её новейшим флагманом серии Nano Banana.

<Prompt description="Пусть coding agent выполнит интеграцию или отладку Nano Banana 2 для генерации изображений по тексту и редактирования изображений. Скопируйте и вставьте это в Codex, Claude Code, Cursor и аналогичные инструменты." icon="bot" actions={["copy"]}>
  Интегрируйте / отладьте Nano Banana 2 (`gemini-3.1-flash-image`) для генерации изображений по тексту и редактирования изображений в этом проекте.

  Прочитайте документацию, прежде чем трогать код: получите [https://docs.apiyi.com/en/api-capabilities/nano-banana-2-image/overview.md](https://docs.apiyi.com/en/api-capabilities/nano-banana-2-image/overview.md) как plain-text версию этой страницы. Для более точных сведений по параметрам добавьте `.md` к страницам text-to-image и image-edit таким же образом.

  Требования:

  1. Тайм-аут: вызывайте нативный для Gemini формат по `POST https://api.apiyi.com/v1beta/models/gemini-3.1-flash-image:generateContent` и увеличьте тайм-аут клиента до 360 секунд. Image API синхронны — task ID нет, поэтому если клиент отключится, результат будет потерян, хотя запрос всё равно будет тарифицироваться. Обратные прокси, шлюзы и лимиты выполнения serverless тоже нужно расширить: любой слой, который короче времени генерации, обрежет запрос. В Node обратите внимание, что у undici есть три независимых настройки тайм-аута, которые опция SDK `timeout` не покрывает.

  2. Разбор ответа (**самая простая вещь, в которой чаще всего ошибаются**): изображение — это base64, оно находится под `inlineData.data` внутри `candidates[0].content.parts[]`. Но `parts` — это **гетерогенный массив, длина и порядок которого не гарантированы** — текстовая часть может идти первой, из-за чего изображение окажется в индексе 1 вместо 0. Эта модель особенно склонна к этому, потому что может возвращать свой текст рассуждения. Поэтому **никогда не хардкодьте `parts[0]` или `parts[1]`**; переключение между ними не решает проблему. Правильный подход: переберите `parts`, отфильтруйте каждую запись, у которой есть `inlineData`, и возьмите **последнюю** из них (сложные задачи возвращают несколько промежуточных черновиков, и только последний является финальным). Читайте `mimeType` тоже из ответа, а не предполагая `image/png`. Затем отрендерьте изображение и предложите действие сохранения на диск.

  3. Сжимайте перед загрузкой: для редактирования вы передаёте reference images как base64 внутри `inlineData`. Сначала сжимайте — обрабатывайте только файлы больше 1.5MB, уменьшайте длинную сторону до 2048px с сохранением пропорций (никогда не увеличивайте маленькое изображение), повторно кодируйте с качеством 0.9 и сохраняйте исходный формат. Держите суммарный размер ниже 6MB для многoизображенческих запросов. Жёсткие ограничения: 7MB на изображение и не более 14 изображений на запрос; затем base64-кодирование увеличивает это примерно на треть, поэтому старайтесь держать каждое изображение ниже 5MB с запасом. Если одно изображение не удаётся сжать, откатитесь к исходному и продолжайте. Также учтите: **одна часть может содержать либо `text`, либо `inlineData`, но никогда не оба** — правильная структура это одна текстовая часть плюс N частей с изображениями.

  4. Параметры разрешения: **всегда отправляйте** `generationConfig.imageConfig.imageSize` (`512` / `1K` / `2K` / `4K`, по умолчанию `1K`) и `aspectRatio` (на этой странице перечислены 14 допустимых соотношений сторон). При тарификации pay-as-you-go **разрешение напрямую задаёт цену за единицу**, поэтому полагаться на значение по умолчанию опасно для прогнозирования стоимости. Сделайте оба параметра выпадающими списками в интерфейсе. Также: в коде всегда используйте имя модели `gemini-3.1-flash-image` и **не вариант с суффиксом `-4k`** (он существует для чат-клиентов); чтобы получить 4K, просто задайте `imageSize` соответствующим образом. Эта модель не поддерживает grounding Google Search через `tools`, поэтому не отправляйте его.

  5. Обработка ошибок: когда модерация контента блокирует запрос, HTTP-статус всё равно 200, но `candidates[0].content.parts` возвращается пустым. Сначала проверьте `candidatesTokenCount` на 0, затем проверьте, отличается ли `finishReason` от `STOP`. Такие блокировки, как `IMAGE_SAFETY`, **не тарифицируются**, а повторная отправка того же самого ввода один или два раза часто срабатывает — добавьте автоматический повтор.

  6. Читайте ключ из переменной окружения `APIYI_API_KEY` и передавайте его в заголовке `Authorization` с префиксом `Bearer`. Никогда не хардкодьте его и никогда не коммитьте в git.

  7. Когда закончите, реально выполните один вызов генерации изображений по тексту и один вызов редактирования изображений, затем покажите мне результаты и стоимость этих двух вызовов.
</Prompt>

## Три параметра, влияющих на тарификацию

Их влияние на ваш счёт различается на два порядка, поэтому оптимизируйте в указанном порядке.

| `responseModalities`           | −2.8%, статистически незначимо                  | ❌ Не даёт экономии            |

### thinkingLevel: значение по умолчанию уже минимальное, а high стоит ещё на половину дороже

`gemini-3.1-flash-image` поддерживает управление уровнем thinking (Pro — нет). Один и тот же prompt, по 20 прогонов на каждое значение:

| Параметр                 | Среднее число output tokens | `thoughtsTokenCount` | Стоимость за вызов | Медианная задержка |
| ------------------------ | --------------------------- | -------------------- | ------------------ | ------------------ |
| Не указан (по умолчанию) | 1548.7                      | поле отсутствует     | \$0.0335           | 13.3s              |
| `minimal`                | 1546.0                      | поле отсутствует     | \$0.0334           | 13.6s              |
| `high`                   | 1557.5                      | медиана 784.5        | **\$0.0516**       | 20.7s              |

* **Значение по умолчанию идентично `minimal`** — статистически неотличимо (p=0.64), так что явная передача `minimal` ничего не даёт.
* Только при `high` `thoughtsTokenCount` появляется как отдельное поле, и оно **включается в `completion_tokens` и тарифицируется по тарифу генерации изображений**.
* **Сложные prompt'ы начинают стоить дороже только после включения `high`**: на уровне по умолчанию prompt из 3 tokens и prompt с рассуждением из 98 tokens не показали значимой разницы в числе output tokens (p=0.37); с `high` prompt с рассуждением использовал **на 126% больше** thinking tokens и стоил **на 38% дороже** за вызов.

<Tip>
  Оставьте этот параметр без изменений для повседневной генерации. Включайте `high` только если у вас жёсткие требования к логике композиции, размещению текста в изображении или точности пропорций диаграммы — ценой +54% расходов и +55% задержки.
</Tip>

### Привязка Google Search: работает, но тарифицируется за каждый поисковый запрос

Для изображений, которым нужна актуальная информация для корректности (карточки погоды, рыночные графики, афиши событий), подключите инструмент `googleSearch`. Привязка сработала во всех 12/12 прогонах.

```json theme={null}
{
  "contents": [{ "parts": [{ "text": "A weather card poster for Tokyo today" }] }],
  "tools": [{ "googleSearch": {} }]
}
```

**Output tokens почти не меняются** (−2.1% по сравнению с контрольной группой без инструмента после вычета стоимости поиска, статистически незначимо); вся стоимость приходится на сами поисковые вызовы — по **\$0.014 за каждый**.

| Условие            | Привязка сработала | Медианное число запросов | Стоимость за вызов |
| ------------------ | ------------------ | ------------------------ | ------------------ |
| Без инструмента    | 0/12               | 0                        | \$0.036            |
| `googleSearch: {}` | 12/12              | 2                        | **\$0.062 (+73%)** |

<Warning>
  **Модель сама решает, сколько поисков выполнять; заранее задать это нельзя.** В тестах один запрос на изображение сам по себе отправлял 1–3 запроса, поэтому при включении этого инструмента стоимость одного вызова — это диапазон **\$0.050–\$0.078**, а не фиксированное число. Планируйте бюджет по верхней границе.
</Warning>

### Привязка Image Search: доступна только в Nano Banana 2, и пока бесплатно

`searchTypes.imageSearch` позволяет модели извлекать визуальные референсы из Google Image Search — полезно для сценариев «сделайте коллаж из реальных фотографий» или «нарисуйте это по реальному объекту».

```json theme={null}
{
  "tools": [{ "googleSearch": { "searchTypes": { "imageSearch": {} } } }]
}
```

| Условие              | Привязка сработала | Взималась плата за поиск | Стоимость за вызов |
| -------------------- | ------------------ | ------------------------ | ------------------ |
| Без инструмента      | 0/12               | 0/12                     | \$0.036            |
| Только `imageSearch` | 7/12               | **0/12**                 | **\$0.032**        |

* Подтверждается тем, что `imageSearchQueries` появляется в `groundingMetadata`, со значениями вроде `["current weather in Tokyo"]`.
* **Пока дополнительная плата не взимается** — стоимость одного вызова даже оказалась немного ниже, чем в контрольной группе без инструмента.
* Срабатывало в 7 из 12 прогонов: **модель сама решает, искать или нет**, она не делает запрос каждый раз.
* Веб-поиск и поиск изображений **можно включить одновременно**, но модель сама выбирает, что использовать, поэтому стоимость становится непредсказуемой.

<Warning>
  **`searchTypes` должен быть объектом, а не массивом.**

  ✅ `{"searchTypes": {"imageSearch": {}}}` — работает

  ❌ `{"searchTypes": ["imageSearch"]}` — **ошибки нет, возвращается 200, и вы всё равно получаете изображение, но поиск изображений не срабатывает ни разу.** В теле ответа это никак не видно. Ошибка upstream для формы массива — `Proto field is not repeating, cannot start list`.
</Warning>

### responseModalities: ничего не экономит, но убирает нежелательный текст

`responseModalities: ["IMAGE"]` указывает, что вам нужны только изображения. По 20 прогонов на каждое значение:

| Параметр                 | Среднее число output tokens | Стоимость за вызов |
| ------------------------ | --------------------------- | ------------------ |
| Не указан (по умолчанию) | 1548.7                      | \$0.0335           |
| `["IMAGE"]`              | 1535.0                      | \$0.0332           |
| `["TEXT","IMAGE"]`       | 1542.8                      | \$0.0333           |

* **Все три значения отличаются менее чем на 1%**, а `["TEXT","IMAGE"]` полностью эквивалентен отсутствию поля (p=0.90).
* При обычных prompt'ах для генерации **60/60 ответов уже содержали одну часть изображения и вообще не содержали текста**, так что переключателю модальностей просто нечего делать. Только в reasoning prompt'ах (инфографика, data charts) примерно в трети случаев добавляется сводный абзац; здесь `["IMAGE"]` подавляет его и экономит около **2.8%** (p=0.09, статистически незначимо).

<Info>
  **Почему экономить нечего**: output tokens — это не «изображение + текст», а **1120 для изображения плюс примерно 400 tokens невидимого накладного расхода**. Этот накладной расход не отображается ни в одном поле `candidatesTokensDetails`, но **тарифицируется по полному тарифу и составляет 28% стоимости одного вызова**, причём не зависит от длины prompt. На его фоне текст почти ничего не значит.

  Поэтому оценка стоимости одного изображения по 1120 tokens **занижает её примерно на 28%** — вместо этого сверяйте с `candidatesTokenCount` или `totalTokenCount`.
</Info>

## Настройка групп

Nano Banana 2 поставляется с двумя группами на APIYI. Переключите в панели управления → **Настройки Token**:

| Группа                 | Коэффициент тарифа | Когда использовать                                                                                                                                       |
| ---------------------- | ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Default`              | 1.0x               | Базовый канал, соответствует таблице цен; рекомендуемый вариант по умолчанию                                                                             |
| `NanoBananaEnterprise` | 1.4x               | Резервный канал — переключайте вручную, когда у варианта по умолчанию не хватает мощности или резко растут таймауты; с приоритетом по доступной мощности |

**Почему 1.4x?** Даже при 1.4x цена всё ещё составляет около 50% от прайс-листа Google — значительно ниже официальной тарификации. Это резервный канал для нагрузок с высокой параллельностью запросов и неожиданных событий risk-control на стороне upstream, обеспечивающий гарантии высокой доступности для корпоративных клиентов. Когда группа по умолчанию перегружена, переключите ваш Token на `NanoBananaEnterprise`, чтобы переждать всплеск.

**Рекомендуемая модель тарификации**: выберите `Pay-as-you-go Priority` — подходит и для тарификации Nano Banana 2 на основе token, и для тарификации Nano Banana Pro за вызов, **один Token на всю серию**.

## Часто задаваемые вопросы

<AccordionGroup>
  <Accordion title="В чем разница между Nano Banana 2 и Nano Banana Pro?">
    **Nano Banana 2** (`gemini-3.1-flash-image-preview`) основан на Gemini 3.1 Flash, а **Nano Banana Pro** (`gemini-3-pro-image-preview`) — на Gemini 3 Pro. Ключевые различия:

    * ✅ **Скорость**: Nano Banana 2 быстрее (скорость уровня Flash)
    * ✅ **Цена**: тарификация по token у Nano Banana 2 дешевле (от \$0.025 против \$0.09)
    * ✅ **Соотношения сторон**: Nano Banana 2 поддерживает 14 (на 4 больше)
    * ✅ **Привязка к поиску изображений**: эксклюзивно для Nano Banana 2
    * ⚠️ **Максимальное качество**: Nano Banana Pro по-прежнему немного лучше
  </Accordion>

  <Accordion title="Стоит ли переходить с Nano Banana Pro на Nano Banana 2?">
    **Рекомендуем!** Nano Banana 2 обеспечивает качество почти уровня Pro при более низкой цене и более высокой скорости. Если у вас нет экстремальных требований к качеству, Nano Banana 2 — лучший выбор.

    Просто измените имя модели с `gemini-3-pro-image-preview` на `gemini-3.1-flash-image-preview`.
  </Accordion>

  <Accordion title="Стоит ли использовать gemini-3.1-flash-image-preview или версию с суффиксом -4k?">
    **Для кода / вызовов API мы рекомендуем всегда использовать общее имя модели `gemini-3.1-flash-image-preview` (без суффикса `-4k`), а не `gemini-3.1-flash-image-preview-4k`.**

    * **Официальное название не содержит `-4k`**: официальное имя модели Google — `gemini-3.1-flash-image-preview`. Это также основной канал, на поддержание которого мы вкладываем больше всего ресурсов, поэтому он обеспечивает лучшую стабильность и совместимость.
    * **Откуда взялось `-4k`**: `gemini-3.1-flash-image-preview-4k` изначально было конфигурацией, подготовленной для сценариев «chat-to-image» в клиентских приложениях для общения вроде Chatbox — генерации изображений прямо через чат в интерфейсе сообщений.
    * **При работе через код + нативный формат Gemini лучше использовать общее имя**: если вы вызываете через код, используя нативный формат Gemini (`/v1beta/models/.../generateContent`), обычное имя модели `gemini-3.1-flash-image-preview` стабильнее.

    Когда вам нужен вывод 4K, нет необходимости полагаться на имя модели `-4k` — просто укажите разрешение 4K в параметрах запроса (см. выше «Поддерживаемые разрешения и соотношения сторон»).
  </Accordion>

  <Accordion title="Что такое Image Search Grounding?">
    Image Search Grounding — эксклюзивная функция Nano Banana 2. Она извлекает визуальный контекст из Google Image Search, чтобы генерировать изображения, которые лучше соответствуют реальным объектам. Например, при генерации изображений реальных достопримечательностей она может использовать результаты поиска для повышения точности.
  </Accordion>

  <Accordion title="Что делает Thinking Mode?">
    Thinking Mode позволяет модели рассуждать и анализировать перед генерацией изображений, повышая точность для сложных prompt. Установка значения `high` дает наилучшие результаты, но немного увеличивает время генерации. Лучше всего подходит для задач, требующих точной композиции, отрисовки текста или сложных сцен.
  </Accordion>

  <Accordion title="Сколько времени занимает генерация изображения?">
    Время генерации зависит от разрешения и режима рассуждения:

    * **1K resolution**: \~5-10 секунд
    * **2K resolution**: \~10-15 секунд
    * **4K resolution**: \~15-25 секунд
    * Включение высокого режима рассуждения добавляет еще несколько секунд

    Рекомендуем установить более длительный таймаут (как минимум 360 секунд) на случай редких задержек и пиковых нагрузок.
  </Accordion>

  <Accordion title="Есть ли лимит параллельных запросов? API обрабатывает запросы последовательно? Что делать, если мне нужно, чтобы 20 пользователей обратились одновременно?">
    **У API нет лимита параллельных запросов, и он не обрабатывает запросы последовательно.** Вы можете безопасно отправлять параллельные запросы сами — запросы не выстраиваются в очередь и не блокируют друг друга. Если 20 пользователей обращаются одновременно, просто отправьте 20 параллельных запросов; никакого дополнительного запроса на квоту или троттлинга не требуется.

    В отличие от Google AI Studio, канал APIYI не имеет жестких лимитов RPM/RPD, поэтому пакетная генерация для enterprise и пиковый трафик масштабируются линейно.

    **Что на самом деле важно, так это `timeout`**: генерация изображений (особенно 4K или в период пиковых нагрузок) может занимать некоторое время на каждый запрос, поэтому **установите таймаут клиента на 360 секунд**, чтобы не обрывать запросы, которые нормально обрабатываются.

    <Tip>
      Если иногда вы получаете 429 (ограничение из-за высокой параллельности), добавьте `NanoBananaEnterprise` в качестве резервной группы для вашего token (см. выше «Настройка группы»). Когда основная группа перегружена, происходит автоматический переход на резервную, что дополнительно повышает успешность при высокой параллельности запросов.
    </Tip>
  </Accordion>

  <Accordion title="Какие форматы входных изображений поддерживаются?">
    Поддерживаются форматы `image/png` и `image/jpeg`. Загрузка возможна через кодировку base64 или API для файлов.
  </Accordion>

  <Accordion title="Есть ли на выходных изображениях водяные знаки?">
    Все выходные изображения содержат невидимые цифровые водяные знаки SynthID (технология Google для идентификации контента, созданного AI) — они невидимы невооруженным глазом и не влияют на использование.
  </Accordion>

  <Accordion title="Почему я получаю connection reset by peer / write_response_body_failed (500)?">
    Полная ошибка выглядит так:

    ```text theme={null}
    [&{{write tcp ip:port->ip:port: write: connection reset by peer Unknown error shell_api_error  write_response_body_failed} 500 }]
    ```

    Обычно это вызвано слишком большими загрузками изображений — тело запроса становится слишком большим, и соединение обрывается. Следуйте этим рекомендациям:

    * **Ограничьте количество изображений**: соблюдайте официальные правила (максимум 14 изображений на prompt) — не добавляйте слишком много референсных изображений.
    * **Ограничьте размер каждого изображения**: держите каждое изображение меньше 5MB — официальный лимит на одно изображение составляет 7MB, а кодирование base64 увеличивает размер примерно на 1/3, поэтому оставляйте запас.
    * **Сжимайте на frontend перед загрузкой**: сжимайте изображения на frontend (или на сервере-посреднике) перед отправкой в API — обычная практика заключается в ограничении длинной стороны, конвертации в JPEG/WebP и настройке параметра качества.
    * **Перейдите на ввод через URL**: нативный формат Gemini поддерживает передачу URL изображения через `fileData.fileUri`, полностью обходя слишком большие тела запросов base64 — см. [Руководство разработчика Nano Banana](/ru/api-capabilities/nano-banana-dev-guide).
  </Accordion>
</AccordionGroup>
