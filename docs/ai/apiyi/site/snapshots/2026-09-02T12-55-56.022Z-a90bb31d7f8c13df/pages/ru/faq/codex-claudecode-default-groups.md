# Чем отличаются группы CodexReverse, ClaudeCode и по умолчанию?

> Объясняет исходный источник, протокол и рекомендуемые сценарии разработки для групп token CodexReverse, ClaudeCode и по умолчанию.

## Краткий ответ

Три группы в основном различаются своим **upstream-источником, протоколом запросов и предназначенными инструментами**:

* **CodexReverse**: реверс-инжинирированный канал ресурсов Codex для повседневной разработки Codex, с обычным уровнем удобства использования и высокой частотой попадания в кэш
* **ClaudeCode**: выделенная группа для Claude Code и сред, использующих нативный протокол Anthropic `/v1/messages`
* **Default**: общая группа официального релея для смешанного доступа к GPT, Claude, Gemini, DeepSeek и другим моделям

## Какую группу мне следует использовать?

| Группа         | Основные характеристики                                                                                 | Рекомендуемое использование                                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `CodexReverse` | Экономичный реверс-инжиниринговый канал Codex с источником, отличным от ресурсов официального API-релея | Codex CLI, задачи кодирования в Codex и разработка, чувствительная к стоимости                                                 |
| `ClaudeCode`   | Агрегирует модели, совместимые с нативным протоколом Anthropic `/v1/messages`                           | Claude Code, нативные клиенты Anthropic и совместимые модели для кодирования, используемые внутри Claude Code                  |
| `Default`      | Общие ресурсы официального релея с широким покрытием моделей                                            | Смешанная разработка, production-нагрузки, где приоритетом является стабильность, и один token для нескольких семейств моделей |

<Info>
  **«Официальный релей» и «реверс-инжиниринговый» описывают разные источники upstream-ресурсов.** `Default` использует ресурсы официального API-релея, а `CodexReverse` использует реверс-инжиниринговые ресурсы Codex. Оба могут работать нормально, но стабильность в production, тарификация, поведение кэша и доступность моделей могут отличаться.
</Info>

## Рекомендуемая настройка для ежедневной разработки

Если вы используете и Codex, и Claude Code, разумная схема — хранить два отдельных token:

* Используйте token `CodexReverse` в Codex
* Используйте token `ClaudeCode` в Claude Code
* Храните дополнительный token `Default`, если другим приложениям нужен смешанный доступ к нескольким поставщикам моделей

Это позволяет не смешивать протоколы и маршруты, а также проще просматривать журналы использования и затраты.

<Warning>
  Группы влияют на доступность моделей, маршрутизацию и коэффициенты тарифа. `CodexReverse` — это не то же самое, что официальный ресурс API-релея. Для production-нагрузок со строгими требованиями к стабильности или соответствию источнику предпочитайте группу `Default` официального релея и проверяйте её на вашей реальной нагрузке.
</Warning>
