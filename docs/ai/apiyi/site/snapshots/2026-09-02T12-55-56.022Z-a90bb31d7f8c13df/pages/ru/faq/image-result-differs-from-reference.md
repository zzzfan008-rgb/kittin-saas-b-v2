# Почему сгенерированное изображение сильно отличается от референса?

> Gemini-3-Pro-Image и модели серии Banana требуют референсные изображения в формате base64, а не URL в формате OpenAI. Ниже перечислены распространенные проверки.

## Краткий ответ

Если вы используете `gemini-3-pro-image`, Banana Pro или Banana 2, значительные отличия между сгенерированным изображением и референсом обычно вызваны несоответствием формата загрузки референсного изображения:

* Эти модели **не поддерживают загрузку референсных изображений в формате OpenAI**
* Референсы нужно загружать как **base64-строки**
* Проблема связана с методом интеграции, а не с самой моделью

## Шаги по устранению неполадок

Выполните следующие проверки по порядку:

<Steps>
  <Step title="Проверьте модель в веб-консоли">
    Откройте `imagen.apiyi.com` и прогоните тот же reference через веб-интерфейс.

    Если результат в веб-интерфейсе совпадает с reference, модель работает корректно, а проблема находится в вашей интеграции. Если результат в веб-интерфейсе тоже отличается, переходите к следующим проверкам.
  </Step>

  <Step title="Проверьте группу token">
    В консоли APIYI подтвердите, что ваш token включает `gemini-3-pro-image` или группу моделей серии Banana.

    Если модель не включена, вызов может перейти к поведению по умолчанию и дать неожиданные результаты.
  </Step>

  <Step title="Подтвердите режим тарификации">
    В настройках token проверьте режим тарификации:

    * **Сначала оплата по мере использования**: используются и квота по мере использования, и квота по подписке
    * **Только оплата по мере использования**: доступна только квота по мере использования

    Несоответствие между режимом тарификации и группой модели может приводить к ошибкам вызова или неожиданным результатам.
  </Step>

  <Step title="Проверьте способ интеграции">
    Сверьте свой запрос с официальной документацией модели.

    Для Banana 2:
    `docs.apiyi.com/api-capabilities/nano-banana-2-image/image-edit`

    Обратите внимание на:

    * Поле reference ожидает **base64 string**, а не URL
    * MIME type должен соответствовать фактическому формату изображения
    * Структура параметра должна соответствовать тому, что поддерживает эта модель
  </Step>
</Steps>

## Распространенные причины

| Симптом                                         | Вероятная причина                                            |
| ----------------------------------------------- | ------------------------------------------------------------ |
| Web UI работает, результат API отличается       | Несоответствие формата интеграции (чаще всего)               |
| Все вызовы дают неверный результат              | Изображение-референс не загружено или загрузка не удалась    |
| Иногда возникают различия                       | Описание prompt слишком краткое или слишком много референсов |
| Группа модели включена, но вызов не выполняется | Несоответствие режима тарификации                            |

<Tip>
  **Самая частая причина**: размещение URL изображения в поле `image_url`, совместимом с OpenAI. Для моделей, которые не поддерживают референсы в формате OpenAI, закодируйте изображение как строку base64 и поместите его в правильное поле.
</Tip>
