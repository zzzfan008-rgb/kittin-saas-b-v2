# Загружает ли Seedance 2.0 автоматически референсы лиц в библиотеку ассетов? Срабатывает ли при этом фильтр deepfake?

> Seedance 2.0 не может напрямую принимать reference images с реалистичными человеческими лицами — сначала их нужно загрузить в библиотеку ассетов, чтобы получить asset:// ID. На этой странице описаны правильный рабочий процесс и обходной путь для фильтра deepfake.

## Краткий ответ

Два вопроса, два ответа:

1. **Нет, автоматической загрузки не происходит.** Референсные изображения НЕ отправляются автоматически в библиотеку ассетов при вызове Seedance 2.0. Вам нужно отдельно загрузить их через API библиотеки ассетов, чтобы получить ID `asset://`, а затем указать его в запросе на генерацию видео.
2. **Да, фильтр deepfake срабатывает.** Референсные изображения с реалистичными человеческими лицами, переданные напрямую, будут заблокированы вышестоящей системой проверки контента. Отправка фотографий реальных людей для генерации видео завершится ошибкой.

Выберите правильный рабочий процесс в зависимости от типа персонажа:

* **Виртуальный аватар** (реалистичный человек, сгенерированный ИИ, без реального прототипа): используйте путь «ингест виртуального аватара» → получите ID `asset://` → укажите его
* **Реальное человеческое лицо** (знаменитость, модель, фото конечного пользователя): сначала выполните сканирование на живость → выполните ingest с `groupId`, специфичным для человека → получите ID `asset://` → укажите его
* **Результат из Seedance за последние 30 дней**: можно использовать как референс для воссоздания (разрешённый платформой путь)

## Подробное объяснение

### Почему нельзя напрямую передавать изображения лиц?

Seedance 2.0 **не может напрямую принимать эталонные изображения с реалистичными человеческими лицами** (фильтр дипфейков). Это ограничение безопасности контента на стороне вышестоящего сервиса, а не политика apiyi.

### Правильный рабочий процесс

<Steps>
  <Step title="Определите тип ресурса">
    Определите, к какой категории относится ваше изображение:

    * **Аниме / стилизованные персонажи**: реалистичное лицо отсутствует, **регистрация не требуется** — напрямую передайте общедоступный URL или base64
    * **Виртуальные аватары** (реалистичные люди, созданные с помощью ИИ): пройдите «Регистрацию виртуального аватара» — полностью автоматически, без проверки
    * **Реальные человеческие лица** (знаменитость, модель, конечный пользователь): сначала требуется проверка присутствия человека
  </Step>

  <Step title="Загрузите изображение в библиотеку ресурсов, чтобы получить идентификатор asset://">
    * Веб-интерфейс: загрузите изображение в [библиотеке ресурсов icover.ai](https://icover.ai/zh/seedance-official/asset-library), дождитесь смены статуса на «Доступно» и скопируйте `asset://xxx`
    * API: используйте `presign` + `POST /api/asset-library/assets` для полного пути выполнения кода — см. [Полный сценарий работы с ресурсами](/ru/api-capabilities/seedance2/asset-reference)
  </Step>

  <Step title="Укажите идентификатор ресурса в запросе на генерацию видео">
    В `content` запроса Seedance 2.0 поместите `asset://<Id>` в `image_url`, а в промпте используйте «image 1», чтобы сослаться на персонажа. См. [API генерации видео Seedance 2.0](/ru/api-capabilities/seedance2/video-generation).
  </Step>
</Steps>

<Info>
  **Два ключа — не перепутайте их**:

  * **КЛЮЧ библиотеки ресурсов** (создаётся на icover.ai): только для загрузки / регистрации / просмотра списка / удаления
  * **Токен видео Seedance APIYI** (создаётся на api.apiyi.com, с включённой группой `SeeDance2`, общей для 2.5 и семейства 2.0): только для эндпоинта генерации видео

  Подробности см. в разделе [Библиотека ресурсов](/ru/api-capabilities/seedance2/asset-library).
</Info>

### Особый процесс для ресурсов с реальными людьми

Фотографии реальных людей нельзя защитить от фильтра дипфейков, «просто загрузив их в библиотеку» — **сам человек на изображении** должен пройти проверку присутствия (войти в свой аккаунт Volcano и пройти распознавание лица). Это обеспечивает защиту прав на изображение непосредственно на исходном этапе; передача этой процедуры доверенному лицу не допускается.

<Steps>
  <Step title="Сгенерируйте ссылку для проверки присутствия">
    Попросите человека отсканировать QR-код / открыть ссылку на телефоне и пройти проверку присутствия через свой аккаунт Volcano
  </Step>

  <Step title="Запросите результат проверки присутствия">
    Получите группу ресурсов для конкретного реального человека `groupId`
  </Step>

  <Step title="Зарегистрируйте ресурс с помощью groupId">
    Загрузите ресурс с помощью `groupId` этой группы. После успешного прохождения проверки соответствия лица вы получите идентификатор `asset://`. Один и тот же человек может повторно использовать одну и ту же группу для разных образов — повторная проверка не требуется
  </Step>
</Steps>

<Warning>
  **Реальный человек ≠ реалистичный человек, созданный с помощью ИИ.** Реалистично выглядящие люди, созданные с помощью ИИ и не имеющие реального аналога (например, созданные с помощью Nano Banana), являются «виртуальными аватарами» — напрямую пройдите «Регистрацию виртуального аватара», этап авторизации не требуется. К «реальным человеческим лицам» относятся только фотографии **реальных людей** — загрузка такой фотографии не равнозначна авторизации; человек на изображении должен пройти проверку присутствия.
</Warning>

## Вопросы и ответы

<AccordionGroup>
  <Accordion title="Срок действия asset IDs истекает?">
    Нет. `asset://` asset IDs являются постоянными — ingest выполняется один раз, ссылка остается навсегда. Однако `content.video_url`, возвращаемый после успешной генерации, — это подписанный URL со сроком действия 24 часа — **скачайте и сразу разместите у себя после успешного завершения задачи**.
  </Accordion>

  <Accordion title="Если проверка соответствия лица для одного изображения не пройдена, можно ли заменить его другим?">
    Да. Вы можете загрузить несколько изображений в одну и ту же группу активов (боковые ракурсы, несколько лиц, размытые изображения могут не пройти — рекомендуются четкие фронтальные ракурсы). `asset://` ID находится на уровне группы активов, а не отдельного изображения — все изображения в одной группе используют один и тот же ID.
  </Accordion>

  <Accordion title="Тарифицируется ли библиотека активов отдельно?">
    Нет. ingest виртуального аватара, верификация реального человека и другие функции частной библиотеки активов включены в Seedance 2.0 API без дополнительной годовой платы.
  </Accordion>

  <Accordion title="Почему при прямой передаче изображения лица возвращается 400?">
    Фильтр upstream по безопасности контента блокирует это. 400 не списывает баланс, но запрос отклоняется — сначала завершите ingest библиотеки активов, затем укажите `asset://` ID.
  </Accordion>
</AccordionGroup>
