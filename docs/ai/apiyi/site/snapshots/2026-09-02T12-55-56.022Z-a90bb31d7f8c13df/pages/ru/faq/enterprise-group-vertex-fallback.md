# Что такое Enterprise-группа? Когда следует ее использовать?

> В APIYI Enterprise-группа — **для каждой модели отдельно**, а не одна универсальная группа: gpt-image-2 использует image2Enterprise (1.2x), Nano Banana использует NanoBananaEnterprise (1.4x) или NanoBananaReverse (0.8x). В этой статье кратко изложены различия, коэффициенты тарифа и сценарии использования Enterprise-группы каждой модели.

## Краткий ответ

**В APIYI «Enterprise group» — это не одна универсальная группа: у каждой модели есть свой выделенный enterprise-канал резервного переключения.** Обычно он немного дороже группы по умолчанию, но продолжает выполнять генерацию изображений даже при перегрузке группы по умолчанию — поэтому это вариант резервного использования для рабочих нагрузок с высоким процентом успешных результатов.

<Info>
  В этой статье перечислены только факты, которые можно проверить по официальной документации или записям текущего статуса. SLA, лимиты параллельных запросов и другие неопубликованные данные следует запрашивать через службу поддержки.
</Info>

## Enterprise-группы по модели

В отличие от универсальных групп `ClaudeCode`, `Sora2Official` и т. д., Enterprise-группы именуются для каждой модели:

| Модель              | Название Enterprise-группы | Коэффициент тарифа | Тип канала                                                                                                                             |
| ------------------- | -------------------------- | ------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| gpt-image-2         | `image2Enterprise`         | 1.2x               | **OpenAI upstream** резервный вариант Enterprise (см. [Живое обновление · 2026-05-13](/en/live/2026-05/gpt-image-2-default-saturated)) |
| Nano Banana Pro / 2 | `NanoBananaEnterprise`     | 1.4x               | резервный вариант Google с высокой доступностью (см. [Модели изображений и видео](/ru/api-capabilities/image-video-models))            |
| Nano Banana Pro / 2 | `NanoBananaReverse`        | 0.8x               | **Канал Vertex, полученный путем реверс-инжиниринга** (см. [Живое обновление · 2026-06](/en/live/2026-06/nanobanana-reverse))          |

<Tip>
  **Важное уточнение**: Enterprise-группы **НЕ являются синонимом резервного варианта Vertex**. `image2Enterprise` — это резервный вариант OpenAI upstream, не связанный с Google Vertex; `NanoBananaReverse` — это канал, который фактически проходит через Vertex (посредством реверс-инжиниринга); `NanoBananaEnterprise` — резервный вариант с высокой доступностью, состав канала которого явно не задокументирован.
</Tip>

## Когда группа по умолчанию была насыщена, корпоративные группы все еще работали

Практический пример для `gpt-image-2`:

* **2026-05-13 14:29–14:31** журналы вызовов: 9 непотоковых вызовов **все были направлены в группу `image2Enterprise`**, с задержкой до первого байта от 35 до 293 секунд при коэффициенте тарифа 1.2x — и все же успешно генерировали изображения (см. [Живое обновление · 2026-05](/en/live/2026-05/gpt-image-2-default-saturated)).
* Когда группа `gpt-image-2` по умолчанию была насыщена, "**некоторые запросы из группы по умолчанию были направлены через запасной путь в корпоративную группу**" — что подтверждает задумку проекта о том, что корпоративные группы служат запасным вариантом (то же живое обновление).

Задумка проекта `NanoBananaReverse` (см. [Живое обновление · 2026-06](/en/live/2026-06/nanobanana-reverse)):

> Чтобы снизить влияние на официальный direct Nano Banana Pro / 2 в часы пик, мы добавили реверс-инженеренную Vertex группу `NanoBananaReverse` по цене 80% от цены группы по умолчанию (коэффициент тарифа 0.8x), с тарификацией за каждый вызов независимо от разрешения.

<Warning>
  **Нет гарантии «корпоративная группа = всегда стабильна».** Официальная документация прямо указывает: корпоративная группа `gpt-image-2` (официальный OpenAI API) также сталкивалась с ошибками "The server had an error while processing your request." 2026-05-07, и первопричиной был сбой на upstream OpenAI (см. [Живое обновление · 2026-05](/en/live/2026-05/gpt-image-2-upstream-error)). Корпоративные группы **снижают** влияние перегрузки группы по умолчанию, но не гарантируют постоянную стабильность upstream.
</Warning>

## Как переключиться на корпоративную группу?

Корпоративные группы настраиваются **на уровне token**:

1. Откройте [https://api.apiyi.com/token](https://api.apiyi.com/token)
2. Найдите нужный token → нажмите «Управление (значок гаечного ключа)» в столбце действий → «Редактировать token»
3. В разделе «Выберите группу» выберите соответствующую корпоративную группу (например, `image2Enterprise`, `NanoBananaEnterprise`, `NanoBananaReverse`)
4. Сохраните

Изменения кода не нужны. Подробный разбор в [Живое обновление · 2026-04 · image2-enterprise](/en/live/2026-04/image2-enterprise-stable) (пример для gpt-image-2; путь тот же и для других моделей).

<Tip>
  **Область NanoBananaReverse**: Поддерживает только `gemini-3-pro-image` (Nano Banana Pro) и `gemini-3.1-flash-image` (Nano Banana 2), **только тарификация за вызов**. Если у вашего token Nano Banana Pro используется тарификация по использованию, эта группа не применяется.
</Tip>

## ЧЗВ

<AccordionGroup>
  <Accordion title="Enterprise — это то же самое, что и Vertex?">
    **Не обязательно** — это зависит от enterprise-группы конкретной модели:

    * `image2Enterprise` (для gpt-image-2) — **НЕ Vertex**, это резервный enterprise-вариант upstream OpenAI
    * `NanoBananaEnterprise` (для Nano Banana) — документация прямо не говорит, использует ли он Vertex
    * `NanoBananaReverse` (для Nano Banana Pro / 2) — **определенно использует Vertex, полученный обратной разработкой**

    Не приравнивайте «enterprise group» к «Vertex fallback».
  </Accordion>

  <Accordion title="Какие модели имеют enterprise group?">
    По доступной документации / живым обновлениям:

    * gpt-image-2: `image2Enterprise` (1.2x)
    * Nano Banana Pro / 2: `NanoBananaEnterprise` (1.4x), `NanoBananaReverse` (0.8x)
    * Nano Banana OSS (вывод URL): `NB-OSS` (1x, но это beta — вам нужно обратиться в службу поддержки, чтобы включить видимость группы; см. [Группа Nano Banana OSS](/ru/api-capabilities/nano-banana-oss-group))

    Доступные группы **полностью соответствуют тому, что показывает ваша консоль** — платформа может со временем добавлять или переименовывать группы.
  </Accordion>

  <Accordion title="Когда мне следует переключиться на enterprise group?">
    Типичные сценарии из зафиксированных инцидентов:

    * Группа по умолчанию постоянно перегружена / стоит в очереди / ловит таймауты (например, gpt-image-2 около 2026-05)
    * Вашему бизнесу важна успешность, и вы не хотите, чтобы сбои в группе по умолчанию тянули вас вниз
    * У Nano Banana Pro / 2 на пиковых часах качество работы низкое — рассмотрите `NanoBananaReverse` (за вызов, 0.8x, дешевле)

    И наоборот, **если группа по умолчанию хорошо обеспечена ресурсами, не стоит переключаться на enterprise group**: 2026-05-23 после пополнения группы gpt-image-2 по умолчанию было сказано: «вызывайте напрямую — не нужно специально переключаться на image2Enterprise» (см. [Живое обновление · 2026-05](/en/live/2026-05/gpt-image-2-default-restocked-0523-2142)).
  </Accordion>

  <Accordion title="Всегда ли enterprise group дороже группы по умолчанию?">
    Не обязательно. Коэффициенты по зафиксированным данным бывают и выше, и ниже:

    * `image2Enterprise`: 1.2x (примерно на 20% дороже, чем по умолчанию)
    * `NanoBananaEnterprise`: 1.4x (примерно на 40% дороже, чем по умолчанию)
    * `NanoBananaReverse`: **0.8x** (примерно на **20% дешевле**, чем по умолчанию)

    Так что «enterprise» не означает «дороже» — коэффициент тарифа зависит от конкретной модели и группы.
  </Accordion>

  <Accordion title="Могу ли я настроить Default + Enterprise как fallback?">
    Да. token поддерживает **1 группу по умолчанию + до 2 резервных групп** (см. [token и группы](/ru/faq/token-and-groups)). Когда основная группа перегружена, вызовы автоматически переключаются на резервный канал. Это рекомендуемый шаблон для нагрузок с «высокой успешностью».
  </Accordion>
</AccordionGroup>
