# 백엔드에서 문제 해결을 위해 상세 로그를 볼 수 있습니까?

> 관리자가 문제 해결을 돕기 위해 상세 로깅을 활성화하는 방법을 알아봅니다

## 기본 개인정보 보호 정책

개인정보 및 보안을 위해, APIYI는 기본적으로 고객의 입력 및 출력 내용을 **저장하지 않습니다**. 저희는 요청을 전달하는 투명한 프록시로만 동작합니다.

즉, 다음과 같습니다:

* ✅ 데이터 개인정보가 최대한 보호됩니다
* ✅ 데이터 저장 비용이 줄어듭니다
* ✅ 데이터 보안 모범 사례를 준수합니다
* ❌ 관리자 백엔드에서는 구체적인 대화 내용을 볼 수 없습니다

## 배치 처리 시나리오의 과제

많은 고객이 배치 프로세스를 실행할 때 다음과 같은 불편을 겪습니다:

<Warning>
  **일반적인 문제 시나리오**

  “백엔드에 사용자 입력을 포함할 수 있습니까? 그렇지 않으면 배치 처리 중에 어떤 호출이 어떤 작업에 해당하는지 구분할 방법이 없습니다!”

  배치 처리에서는 상세한 입력/출력 기록이 없으면, 어떤 특정 작업에서 문제가 발생했는지 추적하기가 실제로 어렵습니다.
</Warning>

## 관리자 지원 문제 해결

기술 지원의 도움이 필요한 문제가 발생한 경우, 관리자가 문제를 진단할 수 있도록 세부 로깅을 **일시적으로 활성화**할 수 있습니다.

<Info>
  **중요 안내**

  * 이 기능은 **관리자 백엔드**에서만 활성화되며 고객은 제어할 수 없습니다
  * 세부 로그 내용은 **관리자에게만 표시**되며 고객에게는 노출되지 않습니다
  * 이 기능은 일반적인 사용이 아니라 문제 해결을 위한 지원 기능입니다
</Info>

### 활성화 요청 방법

<Steps>
  <Step title="문제 세부 정보와 함께 지원팀에 문의">
    고객 서비스 채널(Telegram, 이메일 등)을 통해 문제를 자세히 설명하고 문제 해결 지원을 요청하십시오
  </Step>

  <Step title="관리자 검토">
    기술 지원 담당자가 문제 진단에 세부 로깅이 필요한지 평가합니다
  </Step>

  <Step title="임시 활성화">
    관리자가 백엔드에서 고객 계정에 대한 로그 세부 기록을 일시적으로 활성화합니다
  </Step>

  <Step title="지원 기반 문제 해결">
    관리자가 세부 로그를 검토하여 문제의 위치를 파악하고 해결하는 데 도움을 줍니다
  </Step>

  <Step title="기능 비활성화">
    문제가 해결된 후 관리자가 즉시 세부 로깅을 비활성화합니다
  </Step>
</Steps>

  * 필요한 경우에만 이 기능을 활성화합니다
  * 기술 지원 목적으로만 사용합니다
  * 문제 해결 후 즉시 비활성화합니다
  * 고객님의 데이터 개인정보를 엄격하게 보호합니다
</Warning>

## 적용 가능한 시나리오

### 권장 요청 시나리오

다음 상황에서는 지원팀에 문의하여 관리자 지원을 요청하십시오.

* 🔍 **API 오류**: 명확한 원인 없이 오류가 자주 발생하는 경우
* 📊 **배치 작업 이상**: 일부 배치 작업이 실패하며, 특정 문제 요청을 추적해야 하는 경우
* 🧪 **출력 품질 문제**: 모델 출력이 비정상적이며, 특정 입력/출력 내용을 분석해야 하는 경우
* 📈 **성능 문제**: 호출 지연 시간이 비정상적으로 길며, 병목을 분석하기 위해 상세 로그가 필요한 경우
* 🐛 **의심되는 버그**: 시스템 문제를 의심하며, 기술팀에 상세 정보를 제공해야 하는 경우

### 활성화가 필요하지 않은 경우

다음 시나리오에서는 일반적으로 상세 로깅이 필요하지 않습니다.

* ✅ **정상 사용**: API 호출이 이상 없이 정상적으로 동작하는 경우
* ✅ **일반적인 문제**: 기본 로그(token 통계, 오류 유형)만으로 진단이 충분한 경우
* ✅ **민감한 개인정보**: 매우 민감한 데이터를 처리하므로 누구도 보지 않기를 원하는 경우

## 데이터 보안 공지

<Info>
  **중요 공지**

  세부 로깅이 일시적으로 활성화되어 있어도, 다음을 수행합니다:

  * ✅ 암호화된 저장소를 사용하여 데이터를 보호합니다
  * ✅ 로그 접근 권한을 엄격하게 제한합니다(승인된 관리자만 가능)
  * ✅ 문제 해결 직후 기능을 즉시 비활성화합니다
  * ✅ 만료된 로그 데이터를 정기적으로 자동 정리합니다
  * ✅ 관련 데이터 보호 규정을 준수합니다
  * ✅ 세부 로그는 어떠한 제3자에게도 공개하지 않습니다
</Info>

## FAQ

### 이 기능을 백엔드에서 직접 활성화할 수 있습니까?

아니요. 이 기능은 관리자 백엔드에서만 활성화되며 고객은 조작할 수 없습니다. 문제 해결에 도움이 필요하시면 지원팀에 문의해 주십시오.

### 활성화 후 상세 로그를 볼 수 있습니까?

아니요. 상세 로그 내용은 기술 지원 목적으로만 관리자에게 표시됩니다. 고객은 기본 호출 기록(token 통계, 오류 유형 등)만 확인할 수 있습니다.

### 상세 로깅을 활성화하면 성능에 영향을 줍니까?

영향은 최소 수준입니다. 주로 소량의 로그 기록 시간이 추가될 뿐이며(일반적으로 10ms 미만), 정상적인 사용에는 영향을 주지 않습니다.

### 로그는 얼마나 오래 보관됩니까?

상세 로그는 기본적으로 7-30일 동안 보관됩니다. 관리자는 문제 해결 후 즉시 기록을 비활성화합니다.

### 관리자가 내 요청 내용을 모두 볼 수 있습니까?

상세 로깅 기간 동안의 요청만 기록됩니다. 관리자는 문제 해결을 지원할 때 관련 로그만 확인하며, 기밀 유지 계약을 엄격히 준수합니다.

### 특정 시간대에만 로그를 기록할 수 있습니까?

네. 예를 들어 문제를 재현할 때만 일시적으로 활성화하는 등, 지원팀과 특정 활성화 시간대를 협의하실 수 있습니다.
