# 통화 로그는 얼마나 보관되며, 언제 삭제됩니까?

> APIYI는 과금에 필요한 것만 저장합니다. 사용자 입력이나 출력은 절대 저장하지 않습니다. 로그는 대략 최근 두 달에 해당하는 롤링 윈도우로 보관되며, 매월 5일, 15일, 25일에 정리 작업이 실행되어 두 달이 지난 모든 항목을 삭제합니다. 장기 보관이 필요하면 직접 내보내십시오.

## 짧은 답변

<CardGroup cols={3}>
  <Card title="과금 데이터만" icon="receipt">
    로그에는 타임스탬프, 모델, token 수 및 금액이 포함됩니다. 이는 billing에 필요한 필드입니다. **입력과 출력은 절대로 저장되지 않습니다.**
  </Card>

  <Card title="최근 2개월만 유지" icon="calendar">
    정리는 매월 **5일, 15일, 25일**에 실행되며, 매번 **2개월보다 오래된** 데이터를 삭제합니다. 예: **8월 15일에는 6월 15일 이전의 모든 데이터가 삭제됩니다.**
  </Card>

  <Card title="장기 기록용 내보내기" icon="download">
    콘솔의 **로그** 섹션에서 **비동기 내보내기**를 사용하고, 대사 및 감사용으로 파일을 직접 보관하십시오.
  </Card>
</CardGroup>

<Warning>
  **정리는 되돌릴 수 없습니다.** 삭제된 로그는 복구할 수 없습니다. 대사, 감사 또는 경비 청구에 필요하시면 정리 날짜 전에 내보내십시오.
</Warning>

## 로그에 포함되는 내용

| 기록됨                | 기록되지 않음            |
| ------------------ | ------------------ |
| 호출 타임스탬프           | prompt 텍스트 / 대화 내용 |
| 모델 이름 및 그룹         | 모델의 출력 텍스트         |
| 입력 / 출력 token 수    | 생성된 이미지 및 동영상 파일   |
| 호출에 청구된 금액         | 업로드된 파일 및 이미지 내용   |
| 상태, 지연 시간 및 유사한 필드 | 개인 식별 정보           |

우리는 과금과 문제 해결에 필요한 것만 보관합니다. 이는 개인정보 최소화 원칙이기도 하고, 데이터 유출 가능 범위를 직접적으로 줄이는 방법이기도 합니다. 각 열의 의미는 [로그에서 과금 금액을 읽는 방법](/ko/faq/log-billing-explained)을 참조합니다.

## 콘솔에서 생성된 이미지와 동영상을 볼 수 있습니까?

이것은 가장 흔한 후속 질문이며, 답은 호출이 어떻게 이루어졌는지에 따라 달라집니다:

<CardGroup cols={2}>
  <Card title="동기 호출: 아니오" icon="eye-off">
    동기 텍스트 및 이미지 엔드포인트의 결과는 **프로그램으로 바로 반환되며 절대 저장되지 않습니다**. 콘솔에는 prompt도 생성된 이미지도 표시되지 않습니다.
  </Card>

  <Card title="비동기 작업: 예, 하지만 링크는 빠르게 만료됩니다" icon="clock-alert">
    동영상 및 기타 **비동기 작업**은 제출 후 조회 모델로 동작하므로, 조회 가능해야 하므로 결과를 일시적으로 보관해야 합니다. 즉, 산출물이 표시됩니다.
  </Card>
</CardGroup>

<Warning>
  **비동기 작업 산출물용 OSS 링크는 약 하루 동안 유지됩니다.** 동영상 및 이미지 다운로드 URL은 약 24시간 후 만료되며 이후에는 가져올 수 없습니다. **결과를 받는 즉시 자체 스토리지로 옮기십시오** — 이러한 임시 링크를 프로덕션에서 사용하거나 최종 사용자에게 전달하지 마십시오.
</Warning>

## 정리 일정

로그는 **롤링 윈도우**로 보관되며, 규칙은 간단합니다. **정리는 매월 5일, 15일, 25일에 실행되고, 각 실행 때마다 두 달보다 오래된 데이터가 삭제됩니다** — 한 달에 세 번 실행되므로, 어느 시점에서든 대략 **최근 두 달**을 조회할 수 있습니다.

| 정리 날짜  | 삭제되는 데이터          | 이후 조회 가능 범위     |
| ------ | ----------------- | --------------- |
| 8월 15일 | 6월 15일 이전의 모든 데이터 | 6월 15일 — 8월 15일 |
| 8월 25일 | 6월 25일 이전의 모든 데이터 | 6월 25일 — 8월 25일 |
| 9월 5일  | 7월 5일 이전의 모든 데이터  | 7월 5일 — 9월 5일   |

<Note>
  실행은 열흘마다 이루어지고, 한 달 단위가 아니라 날짜 기준으로 잘라내기 때문에 사용 가능 범위는 **두 달**과 **두 달 열흘** 사이에서 조금씩 이동합니다 — 가장 짧을 때는 실행 직후이고, 가장 길 때는 다음 실행 직전입니다.
</Note>

<Info>
  **이 페이지가 공지이며, 개별 실행은 별도로 안내되지 않습니다.** 정리는 위의 고정된 일정에 따라 자동으로 실행되며, 각 실행 전에 별도 공지는 없습니다 — 이 페이지의 규칙과 표를 기준으로 삼으십시오.
</Info>

<Accordion title="왜 한 달에 세 번 정리합니까?">
  로그 테이블은 빠르게 커지며, **한 번에 한 달치를 통째로 삭제하면 데이터베이스 속도가 저하되고 실시간 호출에 영향을 줄 만큼 규모가 커집니다**. 열흘마다 더 작은 배치로 실행하면 운영 부하와 실시간 트래픽에 대한 영향을 모두 낮게 유지할 수 있습니다. 그래서 2026년 8월 15일부터 일정이 매월 한 번의 전체 월 정리에서 매월 세 번의 롤링 정리로 변경되었습니다.
</Accordion>

<Info>
  **정리는 호출 로그 상세만 삭제하며, 계정 잔액에는 영향을 주지 않습니다.** 충전 및 정산에 대한 장기 기록도 필요하다면, 해당 데이터도 내보내서 보관하시기 바랍니다.
</Info>

## 로그를 더 오래 보관하기

<Steps>
  <Step title="로그 페이지를 엽니다">
    `https://api.apiyi.com/log`로 이동하거나 상단 내비게이션에서 **로그**를 클릭합니다.
  </Step>

  <Step title="먼저 필터링합니다">
    시간 범위, 모델 또는 상태로 범위를 좁혀 실제로 보관하려는 기록만 내보냅니다.
  </Step>

  <Step title="비동기 내보내기를 사용합니다">
    작업을 시작하려면 **async export**를 클릭합니다. 백그라운드에서 실행되므로 대용량 내보내기에서도 페이지에 머무를 필요가 없습니다.
  </Step>

  <Step title="다운로드하여 보관합니다">
    작업이 완료되면 파일을 다운로드하여 자체 시스템이나 재무 워크플로에 저장합니다.
  </Step>
</Steps>

<Tip>
  **월별 내보내기를 습관으로 만드십시오**: 매달 초에 지난달 자료를 보관하면 정리 날짜는 더 이상 중요하지 않습니다. 이는 대사, 경비 청구 또는 감사 요구사항이 있는 팀에 특히 유용합니다.
</Tip>

## 일반적인 질문

<AccordionGroup>
  <Accordion title="왜 로그를 무기한 보관하지 않습니까?">
    이유는 두 가지입니다. **프라이버시 최소화** — 보관하는 양이 적을수록 노출 위험도 작아집니다. 그리고 **스토리지 비용** — 트래픽이 많은 플랫폼에서는 로그 حجم이 빠르게 늘어나며, 모든 것을 영구 보관하면 결국 가격에 반영됩니다. 저희는 정산에 충분한 기간만 보관하고, 더 오래 보관해야 한다면 직접 보관할 수 있도록 내보내기 도구를 제공합니다.
  </Accordion>

  <Accordion title="삭제된 로그를 복원할 수 있습니까?">
    불가능합니다. 정리는 복구 경로가 없는 물리적 삭제이며, 지원팀도 복원할 수 없습니다. 정리 날짜 전에 내보내십시오.
  </Accordion>

  <Accordion title="정리가 제 잔액이나 충전 기록에 영향을 주습니까?">
    아닙니다. 정리 대상은 호출 로그 세부 정보이며, 계정 잔액에는 영향을 주지 않습니다. 비용 청구나 감사용으로 충전 및 사용 내역의 장기 증빙이 필요하다면, 그것도 내보내서 보관하시기 바랍니다.
  </Accordion>

  <Accordion title="로그가 문제 해결에 충분히 상세하지 않으면 어떻게 합니까?">
    보관 기간 내에는 **로그의 타임스탬프와 모델 이름**만으로도 대부분의 문제를 찾을 수 있습니다. 정말로 더 많은 세부 정보가 필요하다면 지원팀에 문의해 주십시오. 관리자가 **일시적으로 활성화**하여 상세 로깅을 켤 수 있습니다. 자세한 내용은 [백엔드에서 상세 로그를 볼 수 있습니까](/ko/faq/user-logs-control)를 참조하십시오.
  </Accordion>

  <Accordion title="내보낸 파일에 제 입력과 출력이 포함됩니까?">
    아닙니다. 내보내기에는 콘솔에 표시되는 것과 동일한 필드인 시간, 모델, token 수, 금액, 상태만 포함되며, prompt나 모델 출력은 전혀 포함되지 않습니다.
  </Accordion>

  <Accordion title="기업 고객은 보관 기간을 연장할 수 있습니까?">
    특정 보관 또는 컴플라이언스 요구사항이 있는 기업 고객은 영업팀과 논의할 수 있습니다. 표준 권장 사항은 여전히 정기적인 내보내기입니다. [기업 사용자와 개인 사용자의 차이](/ko/faq/enterprise-vs-individual)를 참조하십시오.
  </Accordion>
</AccordionGroup>
