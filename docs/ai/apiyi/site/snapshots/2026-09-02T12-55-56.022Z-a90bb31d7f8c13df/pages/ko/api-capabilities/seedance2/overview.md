# Seedance 2.0 / 2.5 동영상 생성

> 공식 Volcengine 리소스를 통한 바이트댄스 Seedance: 새로운 2.5와 2.0 표준 / 빠른 처리 / 미니 버전을 동시에 제공합니다 — 텍스트-투-비디오, 첫 프레임+마지막 프레임/첫 프레임, 멀티모달 참조, 동영상 편집 및 확장을 지원합니다. 모든 가로세로 비율은 각 등급에서 동일한 가격으로 제공되며, 오디오는 기본적으로 동기화됩니다. 2.5는 30초 클립, 참조 이미지 30개 및 mov 출력을 추가로 지원하며, 2.0 제품군과 동일한 SeeDance2 그룹으로 과금됩니다.

## 개요

**doubao-seedance-2-5-260628** (2.5), **doubao-seedance-2-0-260128** (표준), **doubao-seedance-2-0-fast-260128** (빠른), **doubao-seedance-2-0-mini-260615** (미니/라이트)는 ByteDance의 최신 동영상 생성 모델 제품군입니다. 네 모델이 병렬로 실행되며, APIYI를 통해 **공식 Volcengine 중국 본토 리소스**(BytePlus 국제 버전이 아님)에서 제공되고 상위 공급자의 콘텐츠 안전성 기능이 내장되어 있습니다. 텍스트-투-동영상, 첫 프레임+마지막 프레임/첫 프레임 이미지-투-동영상, 멀티모달 참조-투-동영상을 지원하며, 영상과 동기화된 음성, 음향 효과, 배경 음악을 생성할 수 있습니다.

**2.5는 가장 높은 성능의 등급입니다**: 최대 길이가 15초에서 **30초**로 늘었고, 참조 이미지 수가 9개에서 **30개**로 증가했으며, 오디오를 단독 참조로 사용할 수 있습니다. 또한 **mov** 출력과 명시적인 동영상 편집/확장 작업 유형이 추가되었습니다. **비용도 더 높습니다** — 2.0 표준 모델보다 약 1.5배 높으며(720p/5초 기준 약 \$1.35 대 \$0.91), 이는 Volcengine 자체 목록 가격에서 두 세대 간 차이와 일치합니다. 2.0 제품군은 계속 사용할 수 있으며 단종되지 않습니다. 15초 미만의 일반적인 클립에서는 표준 모델이 더 저렴하고 **1080p도 지원**합니다. 미니는 대량 제작에 적합한 선택입니다(**표준 모델 단가의 약 절반이며 생성 속도가 더 빠름**). 단, 최대 해상도는 720p입니다. 빠른 모델은 이 둘의 중간에 해당합니다.

**2.5는 2.0 제품군과 동일한 `SeeDance2` 그룹에서 실행됩니다**(0.18x). 하나의 token으로 네 모델을 모두 사용할 수 있습니다. 아래의 “그룹 설정”을 참조하십시오.

<Note>
  **🎬 주요 특징**: 2.5는 **4\~30초**, 2.0 제품군은 4\~15초를 지원합니다(두 제품군 모두 `-1`을 허용하며, 이 경우 모델이 길이를 선택합니다). 세 가지 해상도 등급(480p/720p/1080p이며, **1080p는 2.5와 2.0 표준 모델로 제한됨**), 6가지 화면 비율과 적응형 비율을 제공합니다. **동기화된 오디오는 기본적으로 활성화**되어 있으며, 다국어 prompt를 지원합니다. **숏폼 동영상 제작, 이커머스 에셋, 모션 디자인, 가상 인간 콘텐츠**를 대규모로 제작할 수 있도록 설계되었습니다.
</Note>

<Info>
  **🔥 기간 한정 할인 — 2026-09-07 23:59 (UTC+8)까지**: 새로운 단일 모델 그룹 두 개, `SD2Mini` (0.10x)와 `SD2Fast` (0.15x)가 요율을 **`mini`에서 44.4%, `fast`에서 16.7% 인하**합니다. 새 Token 하나로 교체하면 적용되며, 코드를 변경할 필요가 없습니다. 아래의 “기간 한정 할인 그룹” 및 “그룹 설정”을 참조하십시오.
</Info>

<Warning>
  2.5를 호출하는 **Token에는 `SeeDance2` 그룹이 필요합니다**(요율 0.18x). 2.0 제품군과 동일한 그룹입니다. Default 그룹 또는 다른 동영상 그룹의 Token으로 `doubao-seedance-2-5-260628`을 호출하면 **“이 모델에 사용 가능한 채널이 없습니다”** 오류가 발생합니다.

  **`SeeDance2`이 활성화된 Token 하나로 네 모델을 모두 사용할 수 있습니다** — 2.5와 2.0 제품군은 동일한 그룹과 요율을 공유하므로 코드에서는 `model` 필드만 변경하면 됩니다.
</Warning>

<Prompt description="코딩 에이전트가 Seedance 2.5 / 2.0 동영상 생성을 통합하거나 문제를 해결하도록 합니다. Codex, Claude Code, Cursor 및 유사한 도구에 복사하여 붙여넣습니다." icon="bot" actions={["copy"]}>
  이 프로젝트에 Seedance 2.5 / 2.0 동영상 생성(텍스트-동영상, 첫 프레임/마지막 프레임, 멀티모달 참조, 동영상 편집, 동영상 확장)을 통합하거나 문제를 해결합니다.

  코드를 수정하기 전에 문서를 읽습니다. 이 페이지의 일반 텍스트 버전을 가져오려면 [https://docs.apiyi.com/en/api-capabilities/seedance2/overview.md](https://docs.apiyi.com/en/api-capabilities/seedance2/overview.md) 를 가져옵니다. 엔드포인트 세부 정보는 동영상 생성 페이지에서 확인하고, 자산 규칙은 자산 라이브러리 및 자산 참조 페이지에서 확인합니다. 모두 동일한 `.md` 접미사를 사용합니다.

  요구 사항:

  1. 동기식 대기가 아닌 3단계 비동기 흐름을 사용합니다. `POST /seedance/api/v3/contents/generations/tasks`으로 제출하여 작업 ID를 받고, `GET /seedance/api/v3/contents/generations/tasks/{id}`을 폴링한 다음, 성공하면 동영상을 다운로드합니다. 다음 세 가지는 쉽게 잘못 처리할 수 있습니다. **경로 접두사는 `/seedance/api/v3`입니다. `/api`을 제거하지 말고 `/v1/videos`를 사용하지 않습니다**. 작업 ID는 최상위 **`id`** 필드이며 `task_id`이 아닙니다. 또한 **성공 상태는 `succeeded`이며 `completed`이 아닙니다**(시스템은 먼저 `queued`, 그다음 `running`, 이후 `succeeded` / `failed` / `expired` 상태가 됩니다). 폴링 주기: 제출 후 첫 번째 쿼리 전에 20~~30초를 기다린 다음, 10~~20초마다 폴링하며 전체 제한 시간은 15분으로 설정합니다.

  2. 동영상 가져오기: 주소는 \*\*`content.video_url`\*\*에 있으며 `content` 내부에 중첩되어 있고 최상위 수준에는 없습니다.  **24시간 후 만료되는** 서명된 링크이므로 **즉시 서버 측에서 다운로드한 다음 자체 오브젝트 스토리지 또는 CDN에 다시 호스팅합니다**. 장기 주소로 데이터베이스에 저장하지 않습니다. 해당 링크를 가져올 때 `Authorization` 헤더를 전송하지 **마십시오**. 작업 ID 자체는 7일 동안 쿼리할 수 있습니다.

  3. Python requests를 사용하는 경우 **`Accept-Encoding: identity` 헤더를 전송합니다**. 게이트웨이는 응답을 `content-encoding: gzip`로 표시하지만 본문은 실제로 압축되어 있지 않습니다. 따라서 해당 헤더가 없으면 무작위 `ContentDecodingError` 오류, 잘린 JSON(예를 들어 선행 `{"`이 사라짐) 또는 설명할 수 없는 400 오류가 발생합니다. curl과 브라우저 fetch에는 영향이 없습니다. requests와 같이 자동으로 압축을 해제하는 클라이언트만 이 문제의 영향을 받습니다.

  4. 주요 파라미터: 먼저 모델을 선택합니다. `doubao-seedance-2-5-260628`(2.5, 권장) 또는 `doubao-seedance-2-0-260128` / `-fast-260128` / `-mini-260615`입니다. `resolution`는 **소문자** `480p` / `720p` / `1080p` 중 하나이며 기본값은 `720p`입니다. **2.5와 2.0 standard만 `1080p`을 지원**합니다(fast와 mini는 이에 대해 400을 반환함). 또한 **이 제품군의 어떤 모델도 `4k`을 지원하지 않습니다**. `ratio`는 7개 값(`16:9`, `4:3`, `1:1`, `3:4`, `9:16`, `21:9`, `adaptive`) 중 하나이며 기본값은 `adaptive`입니다. 이 집합에 없는 값(예: `2:1`)은 400을 반환합니다. `duration`: **2.5에서는 4\~30의 정수이며 기본값은 `-1`입니다**. 이를 생략하면 모델이 길이를 직접 선택합니다(테스트에서는 10초로 측정되었으며, 5초 클립의 비용이 두 배가 됨). 따라서 **비용이 중요하다면 명시적으로 전달합니다**. 2.0 제품군에서는 4\~15이며 기본값은 5입니다. \*\*`generate_audio`의 기본값은 `true`\*\*이므로 무음 출력을 원하면 `false`을 명시적으로 전달해야 합니다. 마지막으로 `frames` 및 `camera_fixed`은 Seedance 1.x에 속하며 여기서는 지원되지 않습니다. 전달하지 마십시오.

  5. 참조 이미지 및 자산: 이미지는 `content[]` 안에 `{"type":"image_url", ...}` 항목으로 넣습니다. 값은 공개 URL, Base64 data URI 또는 자산 라이브러리 ID(`asset://...`)일 수 있습니다. 모드는 **상호 배타적**입니다. 첫 프레임/마지막 프레임(이미지 2개, 필수 `role`는 `first_frame` 또는 `last_frame`), 첫 프레임만(이미지 1개), 또는 멀티모달 참조(**2.5는 이미지 최대 30개 + 동영상 10개 + 오디오 클립 10개를 지원하며, 오디오만 단독으로 사용할 수도 있음**; 2.0 제품군은 이미지 9개 + 동영상 3개 + 오디오 클립 3개를 지원하며 오디오와 함께 이미지 또는 동영상이 최소 하나 필요함)입니다. 각 이미지는 30MB 미만이어야 하고, 각 변은 300~~6000px이며, 종횡비는 0.4~~2.5여야 합니다. **실제 사람의 얼굴이 포함된 이미지는 업스트림 검토에서 거부됩니다**. 이러한 이미지는 먼저 자산 라이브러리에 등록한 다음 `asset://`로 참조해야 하며, prompt에서는 이미지 1, 이미지 2와 같이 위치를 지정하여 이름을 지정합니다. **prompt에 원시 자산 ID를 직접 작성하지 마십시오.**

  6. **2.5에만 존재하며 위반 시 즉시 400을 반환하는 두 가지 엄격한 제약 조건**: 첫 프레임 / 첫 프레임+마지막 프레임, 동영상 편집 및 동영상 확장 작업에서는 `ratio`이 **반드시 `adaptive`이어야** 합니다. 구체적인 종횡비를 지정하면 거부됩니다. 또한 동영상 편집에서는 `duration`이 **반드시 `-1`이어야** 하며, 원본 동영상 길이는 4\~30초여야 합니다. 편집 또는 확장 작업에서는 `omni_reference_task_type`을 명시적으로 전달하여(`edit` / `extend` / `auto`) 잘못된 파라미터가 몇 분 후 작업 실패로 이어지는 대신 제출 시 `InvalidParameter.TaskTypeConstraint`와 함께 동기식으로 실패하게 합니다. 2.5는 `output_format`도 지원합니다(기본값은 `mp4`이며 `mov`도 가능함). mov는 전문 후반 작업을 위한 높은 색상 충실도의 형식이지만 일부 플레이어에서는 열리지 않을 수 있습니다.

  7. 과금 및 오류: 과금은 token 기반이며 **해상도 영역에 기간을 곱한 값**으로 결정되므로, 동일한 해상도에서는 모든 종횡비의 비용이 같습니다. **동영상 하나는 로그에 두 개의 과금 행을 생성합니다**(제출 시 보류, 완료 시 조정). 이는 정상이며 실제 비용은 두 행의 합계이고 이중 과금이 아닙니다. 파라미터 400 오류는 과금되지 않으며, `PUBLIC_` 접두사로 시작하는 오류는 업스트림 검토 차단이므로 마찬가지로 과금되지 않습니다. 자산 또는 prompt를 조정한 후 재시도할 수 있습니다. 모델에 사용 가능한 채널이 없다는 오류는 token 그룹이 잘못되었다는 의미입니다. **2.5와 2.0 제품군은 모두 `SeeDance2` 그룹을 사용**하며(`mini` / `fast`에는 할인된 `SD2Mini` / `SD2Fast`도 있음), 선불 결제 방식 또는 PAYG-priority 과금 모드를 사용합니다. 검토를 포함하여 생성에 실패한 경우 **동일한 prompt를 반복하여 재시도하지 마십시오**.

  8. `APIYI_API_KEY` 환경 변수에서 키를 읽습니다. 하드코딩하지 말고 git에 커밋하지 마십시오.

  9. 완료되면 실제로 텍스트-동영상 호출 1회와 첫 프레임 이미지-동영상 호출 1회를 실행한 다음, 두 동영상과 각 호출의 비용을 보여 줍니다. 전체 흐름에는 몇 분이 걸리므로, 실행 환경에 제약이 있다면 명령 제한 시간을 600초 이상으로 늘리거나 백그라운드에서 실행합니다.
</Prompt>

## APIYI의 Seedance는 왜 사용합니까?

먼저 포지셔닝에 대해 설명합니다. 이 모델에는 **공식 할인 혜택이 없으며, APIYI는 수익을 목적으로 가격을 책정하지 않습니다**. 이 모델은 **공급을 확보하고 고객에게 서비스를 제공하기 위해** 제공됩니다. APIYI를 이용하는 진정한 가치는 “더 저렴한 가격”이 아니라 액세스와 사용 경험에 있습니다.

## 가격

<Info>
  **한 줄 요약 — 정밀한 token 과금으로, 등급별 가격은 Volcengine 공식 사이트에 맞춰 책정됩니다.** 네 모델은 **가격이 서로 다릅니다**: mini \< fast \< standard \< **2.5** (공식 사이트와 같은 방향이며, mini는 standard 모델 단가의 약 절반이고 2.5는 약 1.5배입니다 — **동일한 가격대가 아닙니다**). Volcengine은 이 시리즈에 **할인을 제공하지 않으며**, 이 채널은 공급 확보를 위해 가격이 책정되므로 명목 요율은 공식 요율보다 약간 높습니다. 하지만 [충전 보너스](/ko/faq/recharge-promotions) (일반 고객 10%, 대규모 예치 고객 최대 20%)를 적용하면 실질 비용은 **공식 사이트와 사실상 동일한 수준**입니다 — 대규모 예치 고객은 약 5%만 더 지불하며, 일부 등급(예: 1080p 대규모 고객 가격)에서는 오히려 더 저렴합니다. 과금은 면적×기간 기준이므로 **±5%의 편차는 정상 범위**입니다 — 언제든지 테스트하고 대조해 보신 후 문의해 주시기 바랍니다.

  한 가지 더 안내드립니다. 캐릭터 일관성을 유지하는 동영상에 필요한 [에셋 라이브러리](/ko/api-capabilities/seedance2/asset-library)는 **APIYI에서 무료로 포함됩니다** (공식적으로는 별도 구매 애드온이며, 프레임워크 계약이 없는 고객의 경우 연간 6자리 CNY 규모의 계약이 필요합니다). 이 가치는 위의 단가 비교에 반영되지 않았습니다.
</Info>

token 기반 과금: `tokens ≈ (input video duration + output duration)(s) × output width × output height × 24 / 1024` (텍스트-/이미지-동영상 변환에서는 입력 동영상 길이가 0이며, 내부 테스트에서 0.1% 이내로 검증되었습니다). 한 등급 내 모든 비율은 동일한 픽셀 면적을 가지므로 **가격은 해상도 등급, 출력 기간, 입력에 동영상이 포함되는지 여부에 따라서만 결정됩니다**.

2.5와 2.0 제품군은 **동일한 `SeeDance2` 그룹과 동일한 0.18x 요율**을 공유합니다. 세대 간 가격 차이는 전적으로 모델 자체의 단가에서 발생합니다. 720p/5초는 2.5에서 \$1.3721, 2.0 표준 모델에서 \$0.9074로, 대략 **1.5배**입니다. 이 차이는 **Volcengine 자체의 정가를 반영한 것**입니다(Volcengine의 2.5 token 요율은 2.0보다 약 52% 높음). APIYI의 마진이 아닙니다. 업그레이드할 가치가 있는지는 실제로 30초 클립, 참조 이미지 30장, mov 출력 또는 동영상 편집/확장이 필요한지에 달려 있습니다. 필요하지 않다면 2.0 표준 모델이 더 저렴하고 **1080p도 지원합니다**.

**① 입력에 동영상이 없는 경우**(텍스트-동영상, 이미지-동영상, 참조 이미지):

| 등급                                       | 백만 tokens당 \$ |
| ---------------------------------------- | ------------- |
| ① 입력에 동영상이 없는 경우(480p / 720p / 1080p 동일) | **\$12.60**   |
| ② 입력에 동영상이 있는 경우                         | **\$7.56**    |

</Warning>

## 그룹 설정

Seedance 2.5와 2.0 제품군은 **전용 그룹**에서 실행되며, 두 가지 **필수 조건**이 있습니다. ① 토큰의 과금 모델이 **종량제 우선**(또는 종량제)이어야 합니다. 요청별 과금 토큰은 라우팅할 수 없습니다. ② 토큰에서 **일치하는 그룹**을 활성화해야 합니다. 기본 그룹 또는 다른 동영상 그룹의 토큰을 사용하면 “**이 모델에 사용 가능한 채널이 없습니다**” 오류가 발생합니다.

현재 그룹은 세 개입니다. **2.5와 2.0 제품군은 `SeeDance2`을 공유**하며, 각각 정확히 하나의 모델만 제공하는 한시적 할인 그룹 두 개가 추가로 있습니다.

| 그룹          | 요율        | 제공 모델                                         | 참고                                                                            |
| ----------- | --------- | --------------------------------------------- | ----------------------------------------------------------------------------- |
| `SeeDance2` | 0.18x     | **네 가지 모델 모두** (2.5 / standard / fast / mini) | 2.5와 standard 모델로 연결되는 유일한 경로이며, 할인이 종료된 후의 대체 경로입니다. 동시 실행 수가 충분하고 대기열이 없습니다 |

  **두 할인 그룹은 단일 모델 채널입니다**: `SD2Mini`은 mini만, `SD2Fast`은 fast만 제공하므로, 이를 통해 다른 모델을 호출하면 동일한 오류가 반환됩니다.

</Note>

<Note>
  **2.5에도 동일한 0.18x가 적용됩니다.** 세대 간 차이는 그룹 요율이 아니라 각 모델의 자체 단가에서 발생합니다(Volcengine은 2.5의 가격을 2.0보다 높게 책정합니다). 따라서 2.5와 2.0 제품군은 정확히 동일한 환산 기준으로 실행됩니다.

  **왜 0.18x인가요?** Seedance에 적용되는 시스템 내장 단가는 Volcengine의 공식 목록 가격과 일치하지만, 해당 목록은 **CNY** 기준인 반면 APIYI 잔액은 **USD** 기준입니다(고정 환율 USD/CNY 1:7). 요율이 1x이면 공식 가격의 7배가 사실상 청구되므로, 통화 환산을 반영하기 위해 그룹 요율을 낮춘 것입니다. **0.18이 나온 이유는 바로 여기에 있습니다. 할인도 아니고 할증도 아닙니다.**

  Volcengine은 이 제품군에 **할인을 제공하지 않으며**, 이 채널은 공급 확보를 위해 가격이 책정됩니다. 기본 명목 청구액은 공식 기준 가격보다 약간 높지만, [충전 보너스](/ko/faq/recharge-promotions)가 이를 대부분 상쇄합니다. **대규모 입금 고객은 약 5%만 더 지불하며**, 일부 등급(예: 1080p)은 공식 가격보다 낮아집니다.

  **다음 사항에 유의하시기 바랍니다**: 과금은 항상 **실제 token 사용량**을 기준으로 하며, token 환산에는 자연스러운 소폭 변동이 있습니다(±5%는 정상 범위입니다). 공식 목록 가격은 요청별 보장 가격이 아니라 **참고 기준**일 뿐입니다. 현재 가격은 공급 우선의 합리적인 구성으로, 항상 **충전 보너스와 함께** 평가하시기 바랍니다. 청구 금액에 이상이 있어 보이면 언제든지 함께 청구 내역을 대조해 드릴 수 있습니다. 그러나 “공식 가격보다 조금 높은 이유”는 협상의 대상이 아니므로 이 점을 염두에 두시고, 우려되는 경우 이 채널을 사용하지 마시기 바랍니다. 반대로 **동시 실행 수가 충분하고 대기열이 없는 것**이 바로 이 채널이 제공하는 장점입니다.

  또한 [에셋 라이브러리](/ko/api-capabilities/seedance2/asset-library)(가상 아바타 가져오기 / 실제 인물 인증)도 **이 채널에서는 무료로 포함**됩니다. 공식적으로는 이를 별도로 구매하려면 연간 CNY 6자리 금액의 계약이 필요합니다. 이 기능 역시 이 채널의 실제 가치를 구성하는 요소입니다.
</Note>

### 토큰 설정 방법

**할인을 이용하지 않는 경우**: `SeeDance2` 그룹을 활성화한 토큰 하나를 생성하면 **네 가지 모델 모두**에 연결할 수 있으므로 아래 표를 건너뛰면 됩니다.

**한시 할인을 이용하려는 경우**: `mini`와 `fast`에는 각각 단일 모델 그룹이 있으므로 아래와 같이 토큰을 나누어 사용합니다.

| 토큰              | 기본 그룹       | 실행 모델                                                      |
| --------------- | ----------- | ---------------------------------------------------------- |
| **A (신규 · 할인)** | `SD2Mini`   | 0.10x 요율로 `doubao-seedance-2-0-mini-260615`만               |
| **B (신규 · 할인)** | `SD2Fast`   | 0.15x 요율로 `doubao-seedance-2-0-fast-260128`만               |
| **C (기존 · 메인)** | `SeeDance2` | 2.5와 2.0 standard 모델. 2.0 제품군 전체는 9월 7일 이후 이 그룹으로 대체 연결됩니다 |

모든 토큰은 종량제 우선(또는 종량제) 과금 모델을 사용해야 합니다. mini만 사용하는 경우 토큰 A 하나면 충분하며, 2.5만 사용하는 경우 토큰 C 하나면 충분합니다. 모든 토큰을 사용할 필요는 없습니다.

<Tip>
  **별도의 할인 토큰을 사용할 가치가 있는 이유**:

  * **기한을 놓치지 않습니다** — 토큰별로 과금이 분리되므로 할인 기간에 사용하고 절약한 금액을 한눈에 확인할 수 있으며, 9월 7일이 다가올 때 배치 작업을 앞당길지 결정하기도 쉽습니다
  * **전환 비용이 없습니다** — 할인이 종료되면 클라이언트를 토큰 C로 다시 지정하면 됩니다. 코드 변경이나 그룹 수정이 필요하지 않습니다
  * **전용 토큰은 어차피 운영 환경에 권장됩니다** — 사업 라인별 쿼터 제어와 알림을 설정할 수 있고, 예상치 못한 사용량 급증을 추적하기도 훨씬 쉽습니다
</Tip>

## 해상도 및 화면 비율 상세 설명

해상도 등급은 짧은 변이 아니라 **픽셀 영역**을 정의합니다. 비율별 실제 출력 크기입니다(공식 값이며, 테스트에서 확인했습니다).

| 비율         | 480p                       | 720p     | 1080p (2.5 / 표준만 해당) |
| ---------- | -------------------------- | -------- | -------------------- |
| `16:9`     | 864×496                    | 1280×720 | 1920×1080            |
| `4:3`      | 752×560                    | 1112×834 | 1664×1248            |
| `1:1`      | 640×640                    | 960×960  | 1440×1440            |
| `3:4`      | 560×752                    | 834×1112 | 1248×1664            |
| `9:16`     | 496×864                    | 720×1280 | 1080×1920            |
| `21:9`     | 992×432                    | 1470×630 | 2206×946             |
| `adaptive` | 입력에 따라 모델이 위 값 중 하나를 선택합니다 | 동일       | 동일                   |

<Note>
  **2.5에서 480p 16:9는 864×496이 아니라 854×480입니다**(측정값). 2.0에서 생성되는 864×496보다 픽셀 영역이 약간 작으므로 동일한 사양에서 비용이 드는 token도 약간 적습니다. 저희가 측정한 다른 모든 등급은 두 세대에서 일치합니다. 480p 1:1 = 640×640, 720p 16:9 = 1280×720, 720p 21:9 = 1470×630, 1080p 16:9 = 1920×1080입니다.

  **이 제품군의 어떤 모델도 `4k`을 지원하지 않습니다**. `"resolution": "4k"`을 전송하면 동기식 400이 반환되며 과금되지 않습니다.
</Note>

### 적응형 작동 방식

1. **텍스트-동영상**: 모델이 prompt에서 가장 적합한 비율을 추론합니다.
2. **첫 프레임+마지막 프레임 / 첫 프레임**: 첫 프레임 이미지의 비율과 일치합니다(비율이 일치하지 않는 이미지는 중앙을 기준으로 잘립니다).
3. **멀티모달 참조-동영상**: prompt의 의도를 따르며, 그렇지 않으면 첫 번째 미디어 항목을 따릅니다(이미지보다 동영상이 우선합니다).
4. **동영상 편집 / 확장(2.5)**: 출력 비율은 편집하거나 확장하는 입력 동영상에 따라 결정됩니다.
5. 실제로 사용된 비율은 작업 응답의 `ratio` 필드에 반환됩니다.

<Warning>
  `ratio`은 위의 7개 enum 값만 허용합니다. 예를 들어 `"2:1"`을 전달하면 `InvalidParameter` 오류가 반환되며(확인됨), 지원 범위를 벗어난 `duration`도 마찬가지입니다(2.5에서는 4~~30, 2.0 제품군에서는 4~~15). 둘 다 과금되지 않습니다.

  **2.5에서는 세 가지 작업 유형에 대해 `ratio: adaptive`도 강제됩니다**: 첫 프레임 / 첫 프레임+마지막 프레임 생성, 동영상 편집, 동영상 확장입니다. 이 경우 구체적인 화면 비율을 전달하면 제출 시점에 `InvalidParameter.TaskTypeConstraint`이 반환됩니다(측정 결과 동기식 400이며, 몇 분 후 실패하는 작업이 아닙니다).
</Warning>

[에셋 우선 워크플로](/ko/api-capabilities/seedance2/asset-first-workflow)를 참조하십시오.
  </Step>

  <Step title="크롭을 방지하려면 적응형을 사용합니다">
    이미지-동영상 변환에서는 모델이 소스 이미지의 비율에 맞추도록 기본값인 `adaptive`을 유지합니다. 대상 플랫폼에서 요구하는 경우에만 `9:16`(세로) 또는 `16:9`(가로)로 고정합니다.
  </Step>

  <Step title="길이를 조절하여 비용을 관리합니다">
    비용은 길이에 따라 엄격하게 증가합니다. 먼저 5초 클립으로 프롬프트를 검증한 다음 길이를 늘립니다(2.5는 최대 30초까지 지원하며, 비용은 5초 클립의 6배입니다). **2.5에서는 항상 `duration`을 명시적으로 전달해야 합니다**. 기본값은 `-1`이므로 생략하면 모델이 선택하며, 테스트에서는 10초를 선택하여 비용이 두 배로 증가했습니다.
  </Step>

  <Step title="필요하지 않다면 오디오를 끕니다">
    `generate_audio`의 기본값은 true입니다. 직접 음악을 입힐 무음 영상에는 `false`을 전달합니다.
  </Step>

  <Step title="더 나은 보이스오버를 위해 대사를 인용합니다">
    프롬프트에서 말하는 대사를 큰따옴표로 묶습니다. 그러면 모델이 자동으로 어울리는 음성을 생성합니다.
  </Step>

  <Step title="HTTP 클라이언트에 Accept-Encoding: identity를 추가합니다">
    게이트웨이는 응답을 `content-encoding: gzip`으로 표시하지만 본문은 압축되지 않은 상태입니다. 따라서 Python requests와 같은 자동 압축 해제 클라이언트에서 `ContentDecodingError`이 발생합니다. `Accept-Encoding: identity` 헤더를 추가하면 이 문제를 방지할 수 있습니다(curl에는 영향을 주지 않습니다).
  </Step>

  <Step title="15~30초마다 폴링하고 즉시 다운로드합니다">
    작업은 일반적으로 2\~5분 내에 완료됩니다. `content.video_url`은 24시간 동안 유효한 서명된 링크이므로 작업이 성공하는 즉시 파일을 자체 스토리지로 복사하십시오.
  </Step>

  <Step title="return_last_frame으로 클립을 연결합니다">
    `return_last_frame: true`을 설정하면 워터마크가 없는 마지막 프레임 PNG를 받을 수 있습니다. 그런 다음 이를 다음 작업의 첫 번째 프레임으로 사용하여 연속적인 여러 클립 동영상을 제작합니다.
  </Step>
</Steps>

| 코드                                                | 의미                                                                                           | 권장 처리                                                                                                               |
| ------------------------------------------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `400`                                             | `InvalidParameter`: 잘못된 해상도/비율/길이(예: fast 또는 mini + 1080p, 모든 모델 + 4k, 2.5 + `duration: 31`) | 메시지에 문제가 있는 매개변수가 표시됩니다. 위 표에 따라 수정하십시오. 과금되지 않습니다.                                                                 |

| `429`                                             | 요청 제한 초과 / 쿼터 부족                                                                             | 지수 백오프를 적용하고 잔액을 확인하십시오.                                                                                            |

| 작업 `expired`                                      | `execution_expires_after` 초과(기본값 48시간)                                                       | 다시 제출하십시오.                                                                                                          |

  * 생성/폴링 호출에는 30\~60초 요청 타임아웃이면 충분합니다(대기는 작업 측에서 수행됩니다).
  * 15\~30초마다 폴링하고 전체 예산을 **15분 이상**으로 설정하십시오(1080p / 15초 작업은 더 길게 설정).
  * 5xx 및 타임아웃에 **지수 백오프**를 적용하십시오(2회 재시도).
  * 문제 해결을 위해 작업 `id` 및 `x-request-id` 응답 헤더를 기록하십시오.
</Info>

## FAQ

<AccordionGroup>
  <Accordion title="이미지나 동영상이 포함된 요청에서 작업 ID가 반환되기까지 너무 오래 걸리거나 시간 초과가 발생하는 이유는 무엇입니까?">
    느린 것은 **생성**이 아니라 **제출**입니다. 미디어가 먼저 APIYI로 업스트림 전송된 다음 Volcengine으로 전달되고, 그곳에서 디코딩 및 검증이 이루어집니다. 이 모든 과정이 끝난 후에야 작업 ID가 반환됩니다. 인라인 Base64나 대용량 이미지 URL을 사용하면 이 단계가 약 1초에서 수십 초로 늘어나며, 60초의 클라이언트 읽기 시간 제한으로도 충분하지 않을 수 있습니다. 생성 자체는 일반적으로 2\~5분이 걸리며, 이는 제공업체의 정상적인 속도로 제출 과정과는 관련이 없습니다.

    실제 해결 방법은 **먼저 미디어를 수집한 후 `asset://` asset ID로 참조하는 것**입니다. 그러면 요청 본문이 메가바이트 단위에서 수십 바이트로 줄어듭니다. 지연 시간 분석, 마이그레이션 단계, 시간 초과 후 작업이 생성되었는지 확인하는 방법은 [Asset-First Workflow](/ko/api-capabilities/seedance2/asset-first-workflow)를 참조하십시오.
  </Accordion>

  <Accordion title="Seedance 2.5와 2.0 중 무엇을 사용해야 합니까?">
    **필요한 기능을 기준으로 선택하십시오. 2.5가 자동으로 기본 선택되는 것은 아닙니다.** 2.0 표준 모델보다 약 1.5배의 비용으로 실행됩니다(720p/5초: \$1.3721 대 \$0.9074). 이는 Volcengine 자체 정가표의 가격 차이와 일치합니다.

    **다음과 같은 경우 2.5를 사용하십시오.** **15초보다 긴** 클립이 필요하거나(2.5는 30초 지원), **참조 이미지가 9개보다 많거나**(2.5는 30개 지원), **mov 출력**이 필요하거나, 제출 시 파라미터 오류가 표시되는 **동영상 편집 / 확장**이 필요한 경우입니다(`omni_reference_task_type`). 또한 2.5는 **오디오만 참조로 사용하는 것**을 허용하지만, 2.0에서는 오디오와 함께 이미지나 동영상도 필요합니다.

    클립이 15초 미만이라면 **2.0 제품군을 계속 사용하십시오.** 표준 모델은 **1080p도 지원**하며 동일한 플래그십 품질 등급에 속합니다. 비용에 민감한 일괄 제작에는 표준 단가의 약 절반 가격이며 생성 속도가 가장 빠른 `mini`를 사용하십시오. 2.0 제품군은 지원 종료되지 않습니다.

    엔드포인트, 인증, 요청 형식은 세대 간에 동일하며, **그룹도 동일합니다.** 전환하려면 필드 하나만 변경하면 됩니다: `model`.
  </Accordion>

  <Accordion title="2.5는 1080p를 지원합니까? 4k는 어떻습니까?">
    **1080p는 정상적으로 작동합니다**(측정 결과: 1920×1080으로 정상 렌더링됨). **4k는 지원되지 않습니다.** `"resolution": "4k"`를 전송하면 동기식 400 오류가 반환됩니다(과금되지 않음).

    쉽게 놓칠 수 있는 차이점이 하나 있습니다. **2.5는 1080p를 H.265(hvc1)로 인코딩**하는 반면, 480p와 720p는 H.264(avc1)를 사용합니다. H.265 파일은 더 작지만 구형 플레이어, 일부 브라우저 및 특정 편집 제품군에서는 H.264보다 안정적으로 처리되지 않을 수 있습니다. 1080p를 배포하기 전에 다운스트림 파이프라인에서 해당 형식을 디코딩할 수 있는지 확인하십시오.
  </Accordion>

  <Accordion title="2.5에서 동영상 편집 및 동영상 확장을 어떻게 실행합니까?">
    두 작업 모두 "옴니 참조" 작업이며, `content`의 참조 동영상과 프롬프트에 표현된 의도로 트리거됩니다. 오류가 조기에 표시되도록 `omni_reference_task_type`를 명시적으로 전달하십시오.

    * **동영상 편집**: `omni_reference_task_type: "edit"`, 최소 하나의 `role: "reference_video"`, **`ratio`는 `adaptive`이어야 하고 `duration`는 `-1`이어야 하며**, 소스 동영상의 길이는 4\~30초여야 합니다. 프롬프트에는 편집 동사(add, remove, delete, change, replace)가 필요합니다. 출력 비율과 길이는 입력 동영상을 따르며, **길이는 소수일 수 있습니다**(측정 실행에서 16.709초가 반환됨).
    * **동영상 확장**: `omni_reference_task_type: "extend"`이며, 다시 참조 동영상과 함께 **`ratio`를 `adaptive`으로 설정**해야 합니다. 프롬프트에는 확장 동사(extend, continue)가 필요합니다.

    프롬프트에서 에셋을 위치 기준으로 참조하십시오(`@video1`, `@image1`). 전달한 순서대로 참조해야 합니다. 잘못된 파라미터는 작업이 몇 분 후 실패하는 대신 **제출 시 400 오류**를 반환합니다(`InvalidParameter.TaskTypeConstraint`).
  </Accordion>

  <Accordion title="2.5의 mov 출력 형식은 어떤 용도입니까?">
    `"output_format": "mov"`를 전달하면 더 높은 색상 및 휘도 충실도를 제공하는 QuickTime 컨테이너(H.264 + yuv444p 크로마 + PCM 오디오)가 반환됩니다. 이는 색보정, 키잉, 합성에 적합하며, 동영상 편집 / 확장 작업에서는 입력과 출력 모두에 공식적으로 권장됩니다. 기본값은 `mp4`이며, 호환성이 가장 넓습니다.

    **mov는 일부 플레이어에서 열 수 없는 전문가용 코덱을 사용한다는 점에 유의하십시오**(VLC, mpv, ffplay 및 macOS의 IINA에서는 모두 처리 가능). 웹이나 모바일에 직접 배포하려면 기본값인 mp4를 계속 사용하십시오.
  </Accordion>

  <Accordion title="'이 모델에 사용 가능한 채널이 없습니다'라는 메시지가 표시되는 이유는 무엇입니까?">
    가장 흔한 Seedance 오류이며, 10번 중 9번은 Token에 잘못된 그룹이 활성화되어 있기 때문입니다. 오류에는 현재 사용 중인 그룹이 표시됩니다. 예를 들면 다음과 같습니다.

    ```
    Current group SeeDance2 has no available channels
    for model doubao-seedance-2-5-260628
    ```

    모델을 해당 그룹에 맞추고 Token Settings에서 활성화하십시오.

    | 호출 중인 모델                          | 활성화할 그룹                  |
    | --------------------------------- | ------------------------ |
    | `doubao-seedance-2-5-260628`      | `SeeDance2`              |
    | `doubao-seedance-2-0-260128`      | `SeeDance2`              |
    | `doubao-seedance-2-0-fast-260128` | `SeeDance2` 또는 `SD2Fast` |
    | `doubao-seedance-2-0-mini-260615` | `SeeDance2` 또는 `SD2Mini` |

    `SeeDance2`이 활성화된 하나의 키로 네 모델 모두에 연결할 수 있습니다. 과금 모델도 Pay-as-you-go Priority 또는 Pay-as-you-go여야 합니다. **Pay-per-request Token은 라우팅할 수 없습니다.**
  </Accordion>

  <Accordion title="Python requests에서 gzip 오류가 발생하거나 잘린 비JSON 본문이 반환됩니다">
    게이트웨이의 `content-encoding: gzip` 헤더가 실제 본문 인코딩과 일치하지 않습니다. 증상으로는 `ContentDecodingError`, 잘린 비JSON 본문(예: 앞부분의 `{"`가 사라지고 `id":"cgt-xxx"}`만 수신됨), 간헐적인 400 오류 등이 있습니다. 요청 헤더에 `"Accept-Encoding": "identity"`를 추가하십시오. curl과 브라우저 fetch에는 영향이 없습니다.
  </Accordion>

  <Accordion title="동영상에 소리가 포함되는 이유는 무엇입니까? 소리를 끄려면 어떻게 합니까?">
    `generate_audio`의 기본값은 `true`입니다(확인됨). 모델이 음성, 효과음 및 배경 음악을 자동으로 추가합니다. 무음 출력을 원하면 `"generate_audio": false`를 명시적으로 전달하십시오.
  </Accordion>

  <Accordion title="동영상 URL은 어디에 있으며, 작동이 중지되는 이유는 무엇입니까?">
    성공 시 URL은 폴링 응답의 `content.video_url`에 있습니다(**최상위 수준이 아님**). 약 24시간 동안 유효한 서명된 링크이므로 즉시 다운로드하여 재호스팅하십시오. task\_id 자체는 7일 동안 계속 조회할 수 있습니다.
  </Accordion>

  <Accordion title="성공 상태 값은 무엇입니까?">
    상태 머신은 `queued → running → succeeded / failed / expired`입니다. 성공 상태는 \*\*`succeeded`\*\*이며, \*\*`completed`\*\*이 아닙니다. 다른 동영상 API에서 마이그레이션할 때 쉽게 발생하는 실수입니다.
  </Accordion>

  <Accordion title="이미지-동영상 변환에 실제 사람의 사진을 업로드할 수 있습니까?">
    아니요. Seedance 2.5와 2.0 제품군 모두 실제 사람의 얼굴이 포함된 참조 이미지/동영상을 허용하지 않습니다(업스트림 콘텐츠 안전 정책). 대안으로는 최근 30일 이내에 Seedance 모델로 생성된 얼굴 포함 출력을 재사용하거나, 플랫폼의 사전 설정 가상 아바타(`asset://` ID)를 사용하거나, 라이선스가 있는 얼굴 에셋을 사용하십시오.
  </Accordion>

  <Accordion title="에셋 라이브러리를 사용하려면 추가 비용이 듭니까?">
    아니요. 가상 아바타 수집, 실제 인물 확인 및 나머지 비공개 에셋 라이브러리는 **APIYI의 Seedance 2.0 API에서 무료이며 연회비도 없습니다.** 공식적으로 이 기능은 별도 구매 애드온입니다. 프레임워크 계약이 없는 고객의 경우 연간 수십만 위안 규모의 CNY 계약이 필요하며, Volcengine에서도 직접 판매합니다. APIYI는 장기 사용자를 중요하게 생각하므로 해당 비용은 이미 API 가격에 포함되어 있습니다. SD2 API를 일반적인 업무 규모로 사용하는 고객에게는 추가 요금이 없습니다. 사용 방법은 [Asset Library](/ko/api-capabilities/seedance2/asset-library)를 참조하십시오.
  </Accordion>

  <Accordion title="실패하거나 거부된 요청에도 과금됩니까?">
    파라미터 거부(HTTP 400)는 **과금되지 않습니다**(확인됨). 제출 시 선결제되고 완료 시 정산되므로 잔액이 잠시 변동될 수 있습니다. 호출 로그를 기준으로 대조하십시오.
  </Accordion>

  <Accordion title="토큰 사용량을 어떻게 추정합니까? 세로 영상이 더 비쌉니까?">
    `tokens ≈ duration(s) × width × height × 24 / 1024`이며, 오차 0.1% 이내로 확인되었습니다. 한 등급 내에서는 모든 비율의 픽셀 면적이 동일합니다(720p 16:9와 9:16 모두 5초당 108,900 token). 따라서 **가로, 세로, 정사각형 모두 비용이 동일합니다.**
  </Accordion>

  <Accordion title="2.0 제품군에서는 표준, fast, mini 중 무엇을 사용해야 합니까?">
    가격과 속도는 mini \< fast \< standard 순입니다(플랫폼 내 720p/5초 기준 가격: 약 ¥3.16 / ¥5.08 / ¥6.35). **일괄 제작 및 비용에 민감한 작업에는 mini를 선택하십시오.** 표준 가격의 약 절반이며 생성 속도가 가장 빠릅니다(2026-07 측정: 720p에서 5초 생성에 약 1.5\~2.5분). 최대 세부 묘사가 필요하면 standard를, 중간 지점을 원하면 fast를 선택하십시오. mini와 fast는 모두 720p로 제한되며, 1080p를 요청하면 400 파라미터 오류가 반환됩니다(과금되지 않음).

    **1080p만 필요하다면 2.0 표준 모델에서 이미 지원합니다.** 이 기능만을 위해 업그레이드할 필요는 없습니다. 30초 클립, 9개를 초과하는 참조 이미지, mov 출력 또는 동영상 편집/확장이 필요하면 **2.5**로 전환하십시오(표준 모델 가격의 약 1.5배이며 2.0 제품군과 동일한 그룹을 사용).
  </Accordion>

  <Accordion title="duration: -1은 어떤 기능을 합니까?">
    모델이 자체적으로 길이를 선택하고(2.5에서는 4~~30초, 2.0 제품군에서는 4~~15초) 실제 출력 길이를 기준으로 과금합니다. 최종 길이는 작업의 `duration` 필드에 반환됩니다.

    **`-1`는 2.5의 기본값입니다**(2.0 제품군의 기본값은 5초). 따라서 `duration`를 생략하면 모델 선택 길이를 사용하게 되며, 측정된 2.5 요청에서 duration을 지정하지 않자 정확히 5초의 두 배 비용인 10초 클립이 반환되었습니다. 비용 예측 가능성이 중요하다면 `duration`를 명시적으로 전달하십시오.
  </Accordion>

  <Accordion title="frames 파라미터는 소수 초를 지원합니까?">
    아니요. `frames`와 `camera_fixed`은 Seedance 1.x 파라미터이며 **Seedance 2.5와 2.0 시리즈 모두에서 지원되지 않습니다.** 대신 초 단위 정수인 `duration`을 사용하십시오.
  </Accordion>

  <Accordion title="첫 프레임+마지막 프레임, 첫 프레임 및 참조 이미지를 혼합할 수 있습니까?">
    아니요. 세 가지 **상호 배타적인** 모드입니다. 첫 프레임+마지막 프레임(`first_frame`/`last_frame` 역할이 필수인 이미지 2개), 첫 프레임(이미지 1개), 멀티모달 참조-동영상 변환(이미지 역할 `reference_image`)입니다. "첫 프레임/마지막 프레임 + 참조"를 근사하려면 참조 모드를 사용하고 프롬프트에서 프레임을 지정하십시오.

    참조 제한은 세대별로 다릅니다. **2.5는 이미지 30개 + 동영상 10개 + 오디오 클립 10개를 지원하며 오디오만 단독으로 사용할 수 있습니다.** 2.0 제품군은 이미지 9개 + 동영상 3개 + 오디오 클립 3개를 지원하며, 오디오를 사용하는 경우 이미지 1개 또는 동영상 1개 이상이 함께 필요합니다.
  </Accordion>

  <Accordion title="동시 실행 수 제한이나 대기열이 있습니까?">
    `SeeDance2` 그룹은 동시 실행 수가 충분하고 대기열이 없습니다(테스트에서 15개의 동시 작업이 모두 즉시 실행됨). 더 큰 규모의 지속적인 작업이 필요하면 영업팀에 문의하십시오.
  </Accordion>

  <Accordion title="프롬프트에 제한이 있습니까?">
    프롬프트는 중국어 약 500자 또는 영어 약 1,000단어 이하로 유지하십시오. 더 긴 프롬프트는 세부 묘사를 희석합니다. 지원 언어는 중국어, 영어, 일본어, 스페인어, 포르투갈어, 인도네시아어입니다. 주제 + 동작 + 카메라 움직임 + 조명/스타일을 설명하십시오.
  </Accordion>
</AccordionGroup>
