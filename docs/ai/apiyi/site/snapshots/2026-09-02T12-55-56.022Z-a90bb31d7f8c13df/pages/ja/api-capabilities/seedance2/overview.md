# Seedance 2.0 / 2.5 動画生成

> 公式 Volcengine リソース経由の ByteDance Seedance：新しい 2.5 と、2.0 の標準 / 高速 / Mini を並行提供 — テキストから動画、最初+最後 / 最初のフレーム、マルチモーダルリファレンス、動画編集と延長に対応。すべてのアスペクト比で各ティアの料金は同一で、音声はデフォルトで同期されます。2.5 では 30 秒クリップ、30 枚のリファレンス画像、mov 出力が追加され、2.0 ファミリーと同じ SeeDance2 グループで課金されます。

## 概要

**doubao-seedance-2-5-260628**（2.5）、**doubao-seedance-2-0-260128**（標準）、**doubao-seedance-2-0-fast-260128**（高速）、**doubao-seedance-2-0-mini-260615**（ミニ／ライト）は、ByteDanceの最新動画生成モデルファミリーです。4つのモデルが並行して稼働し、APIYIを通じて**公式のVolcengine中国本土リソース**（BytePlusの国際版ではありません）で提供され、上流側のコンテンツセーフティを組み込んでいます。テキストから動画、始点＋終点／始点フレームから動画、マルチモーダルな参照から動画に対応し、映像と同期した音声、効果音、BGMも生成できます。

**2.5は最も高性能なティアです**。最大再生時間は15秒から**30秒**に延長され、参照画像は9枚から**30枚**に増加し、音声を単独の参照として使用できるほか、**mov**出力と、動画編集／延長タスクタイプが明示的に追加されています。**その分、料金も高くなります**。720p／5秒の場合、2.0標準モデルの約1.5倍（約\$1.35対約\$0.91）で、Volcengineの公式リスト価格における2世代間の差と一致します。2.0ファミリーも引き続き利用でき、廃止予定はありません。15秒未満の通常のクリップでは標準モデルのほうが安価で、**1080pにも対応**しています。ミニは大量制作向けの選択肢です（**標準モデルの単価の約半分で、生成も高速**ですが、最大720pです）。高速モデルはその中間に位置します。

**2.5は2.0ファミリーと同じ`SeeDance2`グループ**（0.18x）で稼働します。1つのtokenですべての4モデルにアクセスできます。下記の「グループ設定」を参照してください。

<Note>
  **🎬 ハイライト**：2.5は**4～30秒**、2.0ファミリーは4～15秒に対応します（どちらもモデルが長さを選択する`-1`を受け付けます）。解像度は3段階（480p／720p／1080p）で、**1080pは2.5と2.0標準に限定**されます。アスペクト比は6種類に加えてアダプティブに対応し、**同期音声はデフォルトで有効**です。多言語プロンプトにも対応しています。**ショート動画制作、Eコマース素材、モーションデザイン、バーチャルヒューマンコンテンツ**の大規模制作向けに設計されています。
</Note>

<Info>
  **🔥 期間限定割引 — 2026-09-07 23:59 (UTC+8)まで**：2つの新しい単一モデルグループ、`SD2Mini`（0.10x）と`SD2Fast`（0.15x）により、レートが\*\*`mini`では44.4%、`fast`では16.7%\*\*引き下げられます。新しいTokenに差し替えるだけで利用でき、コード変更は不要です。下記の「期間限定割引グループ」と「グループ設定」を参照してください。
</Info>

<Warning>
  **2.5を呼び出すTokenには`SeeDance2`グループが必要です**（レートは0.18x）。2.0ファミリーと同じグループです。Defaultグループまたは別の動画グループのTokenで`doubao-seedance-2-5-260628`を呼び出すと、「**このモデルで利用可能なチャネルがありません**」というエラーになります。

  **`SeeDance2`を有効にした1つのTokenですべての4モデルにアクセスできます**。2.5と2.0ファミリーは同じグループと同じレートを共有するため、コードで変更するのは`model`フィールドだけです。
</Warning>

## AI エージェントに統合を任せる

<Note>
  Codex / Claude Code / Cursor で構築する場合は、以下の prompt をコピーしてエージェントに渡してください。まずこのページのプレーンテキスト版を取得し（任意の docs URL に `.md` を追加）、その後、プロジェクト独自のスタックでコードを作成します。非同期ポーリング、**即時コピーを必須にする24時間のリンク有効期限**、gzip ヘッダーの落とし穴、パラメーターの禁止事項は、すでに要件に組み込まれています。
</Note>

<Prompt description="このプロジェクトに Seedance 2.5 / 2.0 の動画生成を統合またはトラブルシューティングさせます。Codex、Claude Code、Cursor などのツールにコピー＆ペーストしてください。" icon="bot" actions={["copy"]}>
  このプロジェクトに Seedance 2.5 / 2.0 の動画生成（テキストから動画、最初／最後のフレーム、マルチモーダル参照、動画編集、動画延長）を統合またはトラブルシューティングしてください。

  コードに触れる前にドキュメントを読んでください。このページのプレーンテキスト版を取得するには、[https://docs.apiyi.com/en/api-capabilities/seedance2/overview.md](https://docs.apiyi.com/en/api-capabilities/seedance2/overview.md) にアクセスしてください。エンドポイントの詳細については動画生成ページを、アセットのルールについてはアセットライブラリページとアセット参照ページを参照してください。いずれも同じ `.md` サフィックスを使用します。

  要件：

  1. 同期的な待機ではなく、3段階の非同期フローを使用してください。`POST /seedance/api/v3/contents/generations/tasks` に送信してタスク ID を取得し、`GET /seedance/api/v3/contents/generations/tasks/{id}` をポーリングし、成功したら動画をダウンロードします。間違えやすい点は3つあります。**パスのプレフィックスは `/seedance/api/v3` です。`/api` を削除せず、`/v1/videos` も使用しないでください**。タスク ID はトップレベルの **`id`** フィールドであり、`task_id` ではありません。また、**成功ステータスは `succeeded` であり、`completed` ではありません**（マシンの状態は `queued`、続いて `running`、その後 `succeeded` / `failed` / `expired` になります）。ポーリング間隔は、送信後の最初のクエリまで20～30秒待機し、その後は10～20秒ごとにポーリングしてください。全体の予算時間は15分です。

  2. 動画の取得：アドレスは **`content.video_url`** にあります。`content` の内側にネストされており、トップレベルにはありません。これは**24時間で有効期限が切れる**署名付きリンクなので、**サーバー側ですぐにダウンロードし、自分のオブジェクトストレージまたは CDN で再ホスティングしてください**。データベースに長期的なアドレスとして保存しないでください。このリンクを取得する際に `Authorization` ヘッダーを**送信しないでください**。タスク ID 自体は7日間クエリ可能です。

  3. Python requests を使用する場合は、**`Accept-Encoding: identity` ヘッダーを送信してください**。ゲートウェイはレスポンスを `content-encoding: gzip` として示しますが、ボディは実際には圧縮されていません。そのため、このヘッダーがないと、ランダムな `ContentDecodingError` エラー、切り詰められた JSON（先頭の `{"` が欠落する場合など）、または不可解な 400 が発生します。curl とブラウザの fetch には影響ありません。影響を受けるのは、requests のように自動で解凍するクライアントだけです。

  4. 主要パラメーター：まずモデルを選択してください。`doubao-seedance-2-5-260628`（2.5、推奨）または `doubao-seedance-2-0-260128` / `-fast-260128` / `-mini-260615` です。`resolution` は **小文字の** `480p` / `720p` / `1080p` のいずれかで、デフォルトは `720p` です。**`1080p` をサポートするのは 2.5 と 2.0 standard だけです**（fast と mini では 400 が返されます）。また、このファミリーの**どのモデルも `4k` をサポートしていません**。`ratio` は7つの値（`16:9`、`4:3`、`1:1`、`3:4`、`9:16`、`21:9`、`adaptive`）のいずれかで、デフォルトは `adaptive` です。このセット外の値（`2:1` など）を指定すると 400 が返されます。`duration` については、**2.5 では4～30の整数で、デフォルトは `-1` です**。省略するとモデルが長さを自動選択します（テストでは10秒として測定され、5秒のクリップのコストが2倍になるため、**コストが重要な場合は明示的に指定してください**）。2.0 ファミリーでは4～15で、デフォルトは5です。**`generate_audio` のデフォルトは `true`** なので、無音出力にするには `false` を明示的に渡す必要があります。最後に、`frames` と `camera_fixed` は Seedance 1.x に属しており、ここではサポートされていません。送信しないでください。

  5. 参照画像とアセット：画像は `content[]` 内に `{"type":"image_url", ...}` エントリとして配置します。その値にはパブリック URL、Base64 データ URI、またはアセットライブラリ ID（`asset://...`）を指定できます。モードは**相互排他的**です。最初／最後のフレーム（画像2枚、`role` は `first_frame` または `last_frame` が必須）、最初のフレームのみ（画像1枚）、またはマルチモーダル参照（**2.5 は最大30枚の画像 + 10本の動画 + 10個の音声クリップに対応し、音声単独でも使用できます**。2.0 ファミリーは画像9枚 + 動画3本 + 音声クリップ3個に対応し、音声とともに少なくとも1枚の画像または1本の動画が必要です）のいずれかです。各画像は30MB未満で、辺の長さは300～6000px、アスペクト比は0.4～2.5でなければなりません。**実在する人物の顔を含む画像は上流モデレーションで拒否されます**。そのような画像は、まずアセットライブラリに登録し、その後 `asset://` として参照してください。prompt では画像1、画像2のように位置を指定して名前を付けます。**生のアセット ID を prompt に書き込まないでください。**

  6. **2.5 にのみ存在し、違反すると即座に 400 が返される厳格な制約が2つあります**。最初のフレーム／最初 + 最後のフレーム、動画編集、動画延長のタスクでは、`ratio` **は `adaptive` でなければなりません**。具体的なアスペクト比を指定すると拒否されます。また動画編集では、`duration` **は `-1` でなければならず**、ソース動画は4～30秒でなければなりません。編集または延長の処理では、`omni_reference_task_type`（`edit` / `extend` / `auto`）を明示的に渡してください。そうすれば、不正なパラメーターは数分後にタスクが失敗するのではなく、送信時に `InvalidParameter.TaskTypeConstraint` とともに同期的に失敗します。2.5 は `output_format` にも対応しています（デフォルトは `mp4`、または `mov`）。mov はプロフェッショナルなポストプロダクション向けの高い色忠実度を持つ形式ですが、一部のプレーヤーでは開けない場合があります。

  7. 課金とエラー：課金は token ベースで、**解像度の面積に期間を乗じた値**によって決まるため、同じ解像度であればアスペクト比が異なってもコストは同じです。**1本の動画につき、ログには2つの課金行が生成されます**（送信時のホールドと、完了時の精算）。これは正常な動作です。実際のコストは両方の合計であり、二重課金ではありません。パラメーターの 400 は課金されません。また、`PUBLIC_` プレフィックスで始まるエラーは上流モデレーションによるブロックであり、これも課金されません。アセットまたは prompt を調整して再試行できます。モデルに利用可能なチャンネルがないというエラーは、token グループが間違っていることを意味します。**2.5 と 2.0 ファミリーはいずれも `SeeDance2` グループを使用します**（`mini` / `fast` には割引された `SD2Mini` / `SD2Fast` もあります）。課金モードは従量課金または PAYG-priority です。モデレーションの場合を含め、生成に失敗したときは、**同一の prompt を繰り返し再試行しないでください**。

  8. `APIYI_API_KEY` 環境変数からキーを読み込んでください。ハードコードしたり、git にコミットしたりしないでください。

  9. 完了したら、実際にテキストから動画への呼び出しを1回と、最初のフレーム画像から動画への呼び出しを1回実行し、その2つの動画と、それぞれのコストを表示してください。フロー全体に数分かかるため、制限のある実行環境で実行する場合は、コマンドのタイムアウトを600秒より長くするか、バックグラウンドで実行してください。
</Prompt>

## APIYI の Seedance を選ぶ理由

まず位置づけについて補足します。このモデルには**公式割引はなく、APIYI も利益目的で価格設定していません**。**供給を確保し、お客様に提供するため**に提供しています。APIYI を利用する真の価値は「より安い」ことではなく、アクセス性と体験にあります。

## 料金

<Info>
  **料金を一言で言えば — 正確な token 課金で、Volcengine 公式サイトに段階ごとに正確に連動しています。** 4つのモデルは**料金が異なります**：mini \< fast \< standard \< **2.5**（公式サイトと同じ順序です。mini は standard モデルの単価の約半分、2.5 は約1.5倍です — **同じ料金水準ではありません**）。Volcengine はこのシリーズに**割引を提供していません**。また、このチャネルは供給確保を目的に価格設定されているため、表示上の料金は公式料金をわずかに上回ります。ただし、[チャージボーナス](/ja/faq/recharge-promotions)（一般顧客は10%、大口入金顧客は最大20%）を適用すると、実質的なコストは**公式サイトとほぼ同等**です — 大口入金顧客の場合、追加負担は約5%にとどまり、一部のティア（例：1080p の大口顧客向け料金）ではさらに低くなります。課金は面積×時間で計算されるため、**±5%の差異は正常範囲**です — ぜひお試しいただき、照合のうえ、いつでもお問い合わせください。

  もう1点、キャラクターの一貫性を保った動画に必要な[アセットライブラリ](/ja/api-capabilities/seedance2/asset-library)は、**APIYI では無料で含まれています**（公式では別途購入するアドオンであり、フレームワーク契約のない顧客の場合、年間契約額は6桁の人民元に達します）。この価値は、上記の単価比較には反映されていません。
</Info>

token ベースの課金：`tokens ≈ (input video duration + output duration)(s) × output width × output height × 24 / 1024`（テキスト／画像から動画への変換では、入力動画の長さは0です。当社のテストでは誤差0.1%以内で検証済みです）。各ティア内のすべての比率でピクセル面積が同じであるため、**料金は解像度ティア、出力時間、入力に動画が含まれるかどうかだけで決まります**。

<Warning>

  1. \*\*`duration`のデフォルト値は`-1`\*\*です（2.0ファミリーのデフォルト値は5）。これを省略すると、2.5は4～30秒の範囲で独自に長さを選択します。長さを指定しないテストリクエストでは10秒のクリップが返され、5秒の場合のちょうど2倍の料金になりました。**料金が重要な場合は、`duration`を明示的に渡してください。**

<Info>

  * 最終的な料金は、コンソールのモデル料金と呼び出しログに従います
  * **タスクは送信時に前払い請求され、完了時に精算されます**。残高は一時的に変動します。呼び出しログと照合してください。1本の動画では**2件の課金エントリ**が生成されます（下記の「ログで課金を確認する」を参照）

  **ベータ供給に関するお知らせ**：Seedance 2.5および2.0ファミリーは現在ベータ供給フェーズです。実際の課金額が上記の表から大きく乖離する場合は、カスタマーサポートまでお問い合わせください。照合のうえ調整します。価格は、上流ポリシー（例：より低価格な公式バリアントが後日提供された場合）およびAPIYIの供給能力に応じて動的に調整されます。対応能力のあるチャネルパートナーからのご連絡も歓迎します。このモデルの価格は、利益ではなく**供給の確保と顧客への提供**を目的としています。
</Note>

## グループ設定

Seedance 2.5 と 2.0 ファミリーは **専用グループ**で動作し、**必須条件が2つ**あります。①トークンの課金モデルが **従量課金・優先（Pay-as-you-go Priority）**（または従量課金（Pay-as-you-go））であること — リクエスト単位課金のトークンではルーティングできません。②トークンで**対応するグループ**が有効になっていることです。デフォルトグループや他の動画グループのトークンでは、「**このモデルで利用可能なチャネルがありません**」というエラーになります。

現在、グループは3つあります。**2.5 と 2.0 ファミリーは `SeeDance2` を共有**し、さらに、それぞれ1つのモデルだけを提供する期間限定の割引グループが2つあります。

| グループ        | レート       | 対象モデル                                     | 備考                                                            |
| ----------- | --------- | ----------------------------------------- | ------------------------------------------------------------- |
| `SeeDance2` | 0.18x     | **4モデルすべて**（2.5 / standard / fast / mini） | 2.5 と standard モデルへの唯一のルート。オファー終了後のフォールバック — 同時実行数が多く、キュー待ちなし |
| `SD2Mini`   | **0.10x** | `doubao-seedance-2-0-mini-260615` のみ      | 🔥 期間限定。元のレートより**44.4%低い**。2026-09-07 23:59 (UTC+8) まで        |
| `SD2Fast`   | **0.15x** | `doubao-seedance-2-0-fast-260128` のみ      | 🔥 期間限定。元のレートより**16.7%低い**。2026-09-07 23:59 (UTC+8) まで        |

<Note>
  **1つの `SeeDance2` トークンですべての4モデルにアクセスできます**。2.5 と 2.0 ファミリーの3モデルはすべてこのグループにあるため、コードでは `model` フィールドを変更するだけです。

  **2つの割引グループは単一モデル用のチャネルです**。`SD2Mini` は mini のみ、`SD2Fast` は fast のみを提供するため、これらを通じて他のモデルを呼び出すと同じエラーが返されます。

  **オファー終了後も利用停止にはなりません**。2026-09-07 23:59 (UTC+8) の後も、両方の割引グループはオンラインのままレートが0.18xに戻るだけです。トークンやコードの変更は必要ありません。
</Note>

<Note>
  **2.5 も同じ0.18xを使用します。** 世代間の差はグループレートではなく、各モデル固有の単価によるものです（Volcengine は 2.5 を 2.0 より高く設定しています）。そのため、2.5 と 2.0 ファミリーはまったく同じ換算基準で動作します。

  **なぜ0.18xなのか？** Seedance のシステム内蔵単価は Volcengine の公式リスト価格と一致しています。ただし、そのリストは **CNY** 建てである一方、API易 の残高は **USD** 建てです（固定レートは1 USD = 7 CNY）。レートが1xだと、実質的に公式価格の7倍を請求することになるため、通貨換算を吸収できるようグループレートを引き下げています。**0.18の理由はここにあります。割引でも値上げでもありません。**

  Volcengine はこのシリーズに**割引を提供しておらず**、このチャネルは供給確保を目的とした価格設定です。名目上の課金額はデフォルトで公式参考価格をわずかに上回りますが、[チャージボーナス](/ja/faq/recharge-promotions) がその差を大部分吸収します。**大口入金の顧客が支払うのは約5%増にとどまり**、一部のティア（たとえば1080p）では公式価格を下回ります。

  **ご注意ください**。課金は常に**実際のトークン使用量**に基づき、トークン換算には自然な小幅の変動があります（±5%は通常の範囲です）。公式リスト価格はあくまで**基準となる参考値**であり、リクエストごとの保証価格ではありません。現在の価格設定は、供給を優先した妥当な構成です — 必ず**チャージボーナスと合わせて**評価してください。課金額に問題があるように見える場合は、いつでも請求内容を確認・調整します。ただし、「なぜ公式価格を少し上回るのか」という点は議論の対象外です — この点を理解したうえで、懸念がある場合はこのチャネルを選択しないでください。その一方で、**同時実行数が多くキュー待ちがないこと**こそが、このチャネルの提供価値です。

  さらに、[アセットライブラリ](/ja/api-capabilities/seedance2/asset-library)（バーチャルアバターの取り込み / 実在人物の検証）も**このチャネルでは無料で含まれます**。公式には、これを別途購入するには年間6桁のCNY契約が必要です。これも、このチャネルが実際に持つ価値の一部です。
</Note>

### トークンの設定方法

**割引を追求しない場合**：`SeeDance2` グループを有効にしたトークンを1つ作成してください。これですべての**4モデル**にアクセスできるため、下の表は不要です。

**期間限定の割引を利用したい場合**：`mini` と `fast` にはそれぞれ単一モデル用のグループがあるため、以下のようにトークンを分けてください。

| トークン          | プライマリグループ   | 実行対象                                                 |
| ------------- | ----------- | ---------------------------------------------------- |
| **A（新規・割引）**  | `SD2Mini`   | `doubao-seedance-2-0-mini-260615` のみ、0.10x           |
| **B（新規・割引）**  | `SD2Fast`   | `doubao-seedance-2-0-fast-260128` のみ、0.15x           |
| **C（既存・メイン）** | `SeeDance2` | 2.5 と 2.0 standard モデル。2.0 ファミリー全体が9月7日以降にここへフォールバック |

すべてのトークンで、課金モデルに従量課金・優先（Pay-as-you-go Priority）（または従量課金（Pay-as-you-go））を使用する必要があります。mini だけを使用する場合はトークンAが1つあれば十分です。2.5 だけを使用する場合はトークンCが1つあれば十分で、すべてを用意する必要はありません。

<Tip>
  **割引用の別トークンを用意する価値**：

  * **期限を逃しません** — 課金はトークンごとに分かれるため、オファー期間中にどれだけ使用して節約したかを一目で確認できます。また、9月7日が近づいたときに、バッチ処理を前倒しするかどうかも判断しやすくなります
  * **切り替えにコストはかかりません** — オファー終了後はクライアントの接続先をトークンCに戻すだけです。コード変更もグループ編集も必要ありません
  * **専用トークンは本番環境でも推奨されます** — 業務ラインごとのクォータ管理とアラートに対応でき、予期しない使用量の急増もはるかに追跡しやすくなります
</Tip>

<Info>
  **Seedance 2.5 が利用可能になりました**（2026-08-28）。モデル名は `doubao-seedance-2-5-260628` で、2.0 ファミリーと同じ **`SeeDance2` グループ**（0.18x）にあります。エンドポイント、認証、リクエスト形式は 2.0 と同一です — **`model` フィールドを置き換えるだけで、コードはそのまま動作します**。2.0 ファミリーと比較すると、最大再生時間は15秒 → **30秒**、参照画像は9枚 → **30枚**、参照動画/音声は3本 → **10本**、音声を単独で使用可能、さらに **mov** 出力と `omni_reference_task_type` タスクセレクターに対応しています。2.0 standard モデルの約1.5倍の速度で動作します。完全な差分については、下記の「技術仕様」を参照してください。
</Info>

## 解像度とアスペクト比の詳細

解像度ティアは**短辺ではなく、ピクセル面積**を定義します。比率ごとの実際の出力寸法（公式値、テストで検証済み）は次のとおりです。

| 比率         | 480p                  | 720p     | 1080p（2.5 / 標準のみ） |
| ---------- | --------------------- | -------- | ----------------- |
| `16:9`     | 864×496               | 1280×720 | 1920×1080         |
| `4:3`      | 752×560               | 1112×834 | 1664×1248         |
| `1:1`      | 640×640               | 960×960  | 1440×1440         |
| `3:4`      | 560×752               | 834×1112 | 1248×1664         |
| `9:16`     | 496×864               | 720×1280 | 1080×1920         |
| `21:9`     | 992×432               | 1470×630 | 2206×946          |
| `adaptive` | 入力に基づいてモデルが上記のいずれかを選択 | 同じ       | 同じ                |

<Note>
  **2.5では、480p 16:9は864×496ではなく854×480です**（実測値）。864×496は2.0が生成する値で、2.5では面積がわずかに小さいため、同じ仕様でも必要なtokenはわずかに少なくなります。その他の測定したすべてのティアは両世代で一致します。480p 1:1 = 640×640、720p 16:9 = 1280×720、720p 21:9 = 1470×630、1080p 16:9 = 1920×1080です。

  **このファミリーのモデルはいずれも`4k`をサポートしていません**。`"resolution": "4k"`を送信すると同期400が返されます（課金対象外）。
</Note>

### アダプティブ動作の仕組み

1. **テキストから動画**：モデルがpromptから最適な比率を推測します
2. **最初+最後 / 最初のフレーム**：最初のフレーム画像の比率に合わせます（比率が一致しない画像は中央でクロップされます）
3. **マルチモーダル参照から動画**：promptの意図に従い、それ以外の場合は最初のメディア項目に従います（画像より動画が優先されます）
4. **動画編集 / 拡張（2.5）**：出力比率は、編集または拡張する入力動画に従います
5. 実際に使用された比率は、タスクレスポンスの`ratio`フィールドで返されます

<Warning>
  `ratio`が受け付けるのは、上記の7つの列挙値のみです。たとえば`"2:1"`を渡すと`InvalidParameter`エラーが返されます（検証済み）。また、サポート範囲外（2.5では4～30、2.0ファミリーでは4～15）の`duration`でも同様です。いずれも課金対象外です。

  **2.5では、3種類のタスクで`ratio: adaptive`も強制されます**：最初のフレーム / 最初+最後のフレームの生成、動画編集、動画拡張です。そこに具体的なアスペクト比を渡すと、`InvalidParameter.TaskTypeConstraint`が**送信時に**返されます（実測では、数分後に失敗するタスクではなく、同期400でした）。
</Warning>

## ベストプラクティス

<Steps>
  <Step title="出力要件に応じてモデルを選択する">
    **まず、2.5でしか利用できない機能が必要かどうかを確認します**：30秒クリップ、30枚の参照画像、単独の音声参照、mov出力、または明示的な動画編集／延長タスクタイプです。いずれかが必要な場合は、`doubao-seedance-2-5-260628`を選択します（標準モデルの約1.5倍の価格で、2.0ファミリーと同じグループです）。必要ない場合は、2.0ファミリーを使用します：**バッチ生成やコスト重視のワークロードにはLiteモデルを使用します** `doubao-seedance-2-0-mini-260615`（標準モデルの約半額で、生成速度が最も速く、720pまでに制限されます）。1080pまたは最高品質が必要な場合は標準モデルを使用します。`fast`はその中間的な選択肢です。
  </Step>

  <Step title="画像と動画はまずアセット IDに取り込む">
    リクエストにメディアが含まれる場合、タスク作成のレイテンシーは**そのメディアのアップロード**によって大きく左右されます。インライン Base64や大きな画像 URLを使用すると、送信にかかる時間が約1秒から数十秒に延びたり、読み取りタイムアウトが発生したりします。まずメディアを取り込み、`asset://`アセット IDを取得して、それを参照してください。これにより、リクエストボディは数十バイトに縮小され、タスク IDがすぐに返され、コンテンツチェックも取り込み時に実行されます。[アセット優先ワークフロー](/ja/api-capabilities/seedance2/asset-first-workflow)を参照してください。
  </Step>

  <Step title="クロッピングを避けるにはadaptiveを使用する">
    画像から動画への変換では、モデルが元画像の比率に合わせられるよう、デフォルトの`adaptive`を使用してください。`9:16`（縦向き）または`16:9`（横向き）に固定するのは、対象プラットフォームでその指定が必要な場合だけにしてください。
  </Step>

  <Step title="長さでコストを調整する">
    コストは長さに厳密に比例します。まず5秒のクリップでプロンプトを検証し、その後、長さを増やしてください（2.5は最大30秒で、5秒のクリップの6倍のコストがかかります）。**2.5では、必ず`duration`を明示的に指定してください**。デフォルトは`-1`なので、省略するとモデルが選択します。テストでは10秒が選択され、コストが2倍になりました。
  </Step>

  <Step title="不要な場合は音声をオフにする">
    `generate_audio`のデフォルト値はtrueです。自分で音楽を付ける予定の無音映像には、`false`を指定してください。
  </Step>

  <Step title="より自然なボイスオーバーのためにセリフを引用符で囲む">
    プロンプト内で話し言葉を二重引用符で囲んでください。モデルが自動的に一致する音声を生成します。
  </Step>

  <Step title="HTTPクライアントにAccept-Encoding: identityを追加する">
    ゲートウェイはレスポンスに`content-encoding: gzip`というラベルを付けますが、ボディは圧縮されていません。Python requestsなどの自動展開クライアントでは`ContentDecodingError`が発生します。`Accept-Encoding: identity`ヘッダーを追加するとこれを回避できます（curlには影響ありません）。
  </Step>

  <Step title="15～30秒ごとにポーリングし、すぐにダウンロードする">
    タスクは通常2～5分で完了します。`content.video_url`は24時間有効な署名付きリンクです。タスクが成功したら、できるだけ早くファイルを自分のストレージにコピーしてください。
  </Step>

  <Step title="return_last_frameでクリップを連結する">
    `return_last_frame: true`を設定すると、ウォーターマークのない最後のフレームのpngを取得できます。それを次のタスクの最初のフレームとして使用し、複数のクリップから連続した動画を作成します。
  </Step>
</Steps>

<Info>
  **クライアントに関する推奨事項**:

  * 作成／ポーリング呼び出しでは、リクエストタイムアウトは 30～60 秒で十分です（待機はタスク側で発生します）
  * 全体の時間枠を **15 分以上**として、15～30 秒ごとにポーリングしてください（1080p／15 秒タスクではさらに長くしてください）
  * 5xx およびタイムアウト時には **指数バックオフ**を適用してください（2 回リトライ）
  * トラブルシューティングのため、タスク `id` と `x-request-id` レスポンスヘッダーをログに記録してください
</Info>

## FAQ

<AccordionGroup>
  <Accordion title="画像または動画を含むリクエストで、タスク ID の返却に時間がかかったり、タイムアウトしたりするのはなぜですか？">
    遅いのは**生成**ではなく、**送信**です。メディアは上流の APIYI まで送られた後、Volcengine に転送され、そこでデコードと検証が行われます。タスク ID が返るのは、そのすべてが完了してからです。インラインの Base64 や大きな画像 URL を使用すると、この処理は約 1 秒から数十秒に延び、クライアントの 60 秒の読み取りタイムアウトでも足りない場合があります。生成自体は通常 2～5 分かかります。これはプロバイダーの通常の速度であり、送信処理とは無関係です。

    本当の解決策は、**先にメディアを取り込み、`asset://` アセット ID として参照すること**です。これにより、リクエスト本文を数メガバイトから数十バイトに削減できます。レイテンシの内訳、移行手順、タイムアウト後にタスクが作成されたかどうかの確認方法については、[アセット優先ワークフロー](/ja/api-capabilities/seedance2/asset-first-workflow)を参照してください。
  </Accordion>

  <Accordion title="Seedance 2.5 と 2.0 のどちらを使うべきですか？">
    **必要な機能で選択してください。2.5 が自動的なデフォルトというわけではありません。** 2.5 は 2.0 の標準モデルの約 1.5 倍の価格です（720p/5 秒：\$1.3721 対 \$0.9074）。これは Volcengine 独自の表示価格の差とも一致します。

    **次の場合は 2.5 を選択してください**：**15 秒を超える**クリップが必要（2.5 は 30 秒まで対応）、**9 枚を超える参照画像**が必要（2.5 は 30 枚まで対応）、**mov 出力**が必要、または送信時にパラメータエラーを検出できる**動画編集／延長**を行う場合（`omni_reference_task_type`）。2.5 では**音声のみを参照素材にすることも可能**ですが、2.0 では音声とともに画像または動画も必要です。

    クリップが 15 秒未満の場合は、**2.0 ファミリーを使い続けてください**。標準モデルは**1080p にも対応**しており、最高クラスの品質帯に位置します。コスト重視の一括生成には、標準単価の約半額で最速の生成が可能な `mini` を使用してください。2.0 ファミリーは廃止される予定はありません。

    エンドポイント、認証、リクエスト形式は世代間で同一で、**グループも同じ**です。切り替え時に変更するフィールドは 1 つだけです：`model`。
  </Accordion>

  <Accordion title="2.5 は 1080p に対応していますか？4k はどうですか？">
    **1080p は動作します**（実測では 1920×1080 が正常にレンダリングされました）。**4k には対応していません**。`"resolution": "4k"` を送信すると同期 400 が返されます（課金されません）。

    見落としやすい違いが 1 つあります。**2.5 は 1080p を H.265（hvc1）としてエンコード**しますが、480p と 720p では H.264（avc1）が使用されます。H.265 ファイルは小さくなりますが、古いプレーヤー、一部のブラウザー、特定の編集ソフトでは H.264 より安定して扱えない場合があります。1080p を配布する前に、後続のパイプラインでデコードできることを確認してください。
  </Accordion>

  <Accordion title="2.5 で動画編集と動画延長を実行するにはどうすればよいですか？">
    どちらも「オムニ参照」タスクです。`content` に参照動画を指定し、prompt で意図を表現すると実行されます。エラーを早期に検出できるよう、`omni_reference_task_type` を明示的に渡してください。

    * **動画編集**：`omni_reference_task_type: "edit"`、少なくとも 1 つの `role: "reference_video"`、**`ratio` は `adaptive`、`duration` は `-1` である必要があります**。また、元の動画の長さは 4～30 秒でなければなりません。prompt には編集を表す動詞（追加、削除、消去、変更、置換）が必要です。出力のアスペクト比と長さは入力動画に従います。また、**長さには小数を指定できます**（実測では 16.709 秒の結果が返されました）。
    * **動画延長**：`omni_reference_task_type: "extend"`。参照動画を指定し、**`ratio` を `adaptive` に設定**します。prompt には延長を表す動詞（延長、継続）が必要です。

    prompt 内では、アセットを位置で参照してください。`@video1`、`@image1` のように、渡した順序に従います。無効なパラメータの場合は、数分後にタスクが失敗するのではなく、**送信時に 400** が返されます（`InvalidParameter.TaskTypeConstraint`）。
  </Accordion>

  <Accordion title="2.5 の mov 出力形式は何に使用しますか？">
    `"output_format": "mov"` を渡すと、QuickTime コンテナ（H.264 + yuv444p クロマ + PCM オーディオ）が返され、色と輝度の再現性が向上します。これはカラーグレーディング、キーイング、コンポジットに適しており、動画編集／延長では入力と出力の両方に使用することが公式に推奨されています。デフォルトは`mp4`で、最も幅広い互換性があります。

    **mov では、一部のプレーヤーで開けないプロフェッショナル向けコーデックが使用されることに注意してください**（VLC、mpv、ffplay、macOS の IINA はすべて対応しています）。Web やモバイルで直接配信する場合は、デフォルトの mp4 を使用してください。
  </Accordion>

  <Accordion title="「このモデルに利用可能なチャネルがありません」と表示されます。なぜですか？">
    Seedance で最もよくあるエラーで、10 回に 9 回は Token で有効になっているグループが間違っています。エラーには、現在使用しているグループが表示されます。たとえば次のようになります。

    ```
    Current group SeeDance2 has no available channels
    for model doubao-seedance-2-5-260628
    ```

    モデルに対応するグループを確認し、Token 設定で有効にしてください。

    | 呼び出しているモデル                        | 有効にするグループ                 |
    | --------------------------------- | ------------------------- |
    | `doubao-seedance-2-5-260628`      | `SeeDance2`               |
    | `doubao-seedance-2-0-260128`      | `SeeDance2`               |
    | `doubao-seedance-2-0-fast-260128` | `SeeDance2` または `SD2Fast` |
    | `doubao-seedance-2-0-mini-260615` | `SeeDance2` または `SD2Mini` |

    `SeeDance2` を有効にした 1 つのキーですべての 4 モデルにアクセスできます。課金モデルは「従量課金（優先）」または「従量課金」である必要もあります。**リクエストごとの課金 Token ではルーティングできません**。
  </Accordion>

  <Accordion title="Python requests で gzip エラーが発生する／切り詰められた非 JSON 本文が返される">
    ゲートウェイの `content-encoding: gzip` ヘッダーが、実際の本文のエンコーディングと一致していません。症状には、`ContentDecodingError`、切り詰められた非 JSON 本文（例：先頭の `{"` が失われ、`id":"cgt-xxx"}` しか取得できない）、断続的な 400 などがあります。リクエストヘッダーに `"Accept-Encoding": "identity"` を追加してください。curl とブラウザーの fetch には影響ありません。
  </Accordion>

  <Accordion title="動画に音声が付くのはなぜですか？オフにするにはどうすればよいですか？">
    `generate_audio` のデフォルトは `true` です（検証済み）。モデルが音声、効果音、BGM を自動的に追加します。無音の出力にするには、`"generate_audio": false` を明示的に渡してください。
  </Accordion>

  <Accordion title="動画 URL はどこにありますか？また、なぜ使えなくなるのですか？">
    成功時、URL はポーリングレスポンスの `content.video_url` にあります（**トップレベルではありません**）。これは約 24 時間有効な署名付きリンクです。すぐにダウンロードして、自分の環境で再ホストしてください。task\_id 自体は 7 日間クエリ可能です。
  </Accordion>

  <Accordion title="成功ステータスの値は何ですか？">
    状態マシンは `queued → running → succeeded / failed / expired` です。成功状態は **`succeeded`** であり、**`completed`** ではありません。他の動画 API から移行する際によくある間違いです。
  </Accordion>

  <Accordion title="実在する人物の写真を image-to-video にアップロードできますか？">
    いいえ。Seedance 2.5 も 2.0 ファミリーも、実在する人物の顔を含む参照画像／動画は受け付けません（上流のコンテンツ安全対策による制限です）。代替手段として、過去 30 日以内に Seedance モデルで生成された顔を含む出力を再利用する、プラットフォームのプリセット仮想アバター（`asset://` ID）を使用する、またはライセンス済みの顔アセットを使用してください。
  </Accordion>

  <Accordion title="アセットライブラリには追加料金がかかりますか？">
    いいえ。仮想アバターの取り込み、実在人物の検証、その他の非公開アセットライブラリは、**APIYI の Seedance 2.0 API で無料です。年額料金もかかりません**。公式には、この機能は別途購入するアドオンであり、フレームワーク契約のない顧客の場合は年間 6 桁人民元の契約が必要です（Volcengine から直接購入することもできます）。長期利用のお客様を重視しているため、この費用はすでに当社の API 価格に含まれています。SD2 API を通常の範囲で利用するお客様には、通常の業務量で追加料金はかかりません。使用方法については、[アセットライブラリ](/ja/api-capabilities/seedance2/asset-library)を参照してください。
  </Accordion>

  <Accordion title="失敗または拒否されたリクエストにも課金されますか？">
    パラメータ拒否（HTTP 400）は**課金されません**（検証済み）。課金は送信時に仮請求され、完了時に確定するため、残高は一時的に変動します。コールログと照合してください。
  </Accordion>

  <Accordion title="token の使用量を見積もるにはどうすればよいですか？ポートレートは割高ですか？">
    `tokens ≈ duration(s) × width × height × 24 / 1024`です。誤差 0.1% 以内で検証済みです。1 つのティア内では、すべてのアスペクト比でピクセル面積が同じです（720p の 16:9 と 9:16 はどちらも 5 秒あたり 108,900 token）。**横長、縦長、正方形の料金はすべて同じ**です。
  </Accordion>

  <Accordion title="2.0 ファミリーでは、standard、fast、mini のどれを選ぶべきですか？">
    価格と速度は mini ＜ fast ＜ standard の順です（プラットフォーム上の 720p/5 秒の公称価格：約 ¥3.16 / ¥5.08 / ¥6.35）。**一括生成やコスト重視のワークロードには mini を選択してください**。標準価格の約半額で、生成速度も最速です（2026-07 の実測：720p・5 秒で約 1.5～2.5 分）。最大限のディテールが必要な場合は standard、中間の選択肢として fast を選んでください。mini と fast はどちらも 720p が上限です。1080p を要求すると 400 パラメータエラーが返されます（課金されません）。

    **1080p だけが必要な場合、2.0 standard モデルはすでに対応しています**。その目的だけでアップグレードする必要はありません。30 秒のクリップ、9 枚を超える参照画像、mov 出力、動画編集／延長が必要な場合は **2.5** を選択してください（standard モデルの約 1.5 倍の価格で、2.0 ファミリーと同じグループです）。
  </Accordion>

  <Accordion title="duration: -1 は何をしますか？">
    モデルが長さを自動的に選択し（2.5 では 4～30 秒、2.0 ファミリーでは 4～15 秒）、実際の出力長に基づいて課金されます。最終的な長さはタスクの `duration` フィールドに返されます。

    **2.5 では `-1` がデフォルトであることに注意してください**（2.0 ファミリーのデフォルトは 5 秒です）。そのため、`duration` を省略すると、モデルが選択する長さが使用されます。実測では、duration を指定しない 2.5 のリクエストから 10 秒のクリップが返され、5 秒の場合のちょうど 2 倍の料金になりました。料金を予測しやすくしたい場合は、`duration` を明示的に渡してください。
  </Accordion>

  <Accordion title="frames パラメータは小数秒に対応していますか？">
    いいえ。`frames` と `camera_fixed` は Seedance 1.x のパラメータです。**Seedance 2.5 も Seedance 2.0 シリーズも対応していません**。代わりに、秒単位の整数の `duration` を使用してください。
  </Accordion>

  <Accordion title="first+last frame、first frame、参照画像を組み合わせて使用できますか？">
    いいえ。これらは 3 つの**相互排他的な**モードです。first+last（`first_frame`／`last_frame` のロールが必須の 2 枚の画像）、first frame（1 枚の画像）、マルチモーダルの reference-to-video（画像ロール `reference_image`）です。「first/last frame + reference」を近似するには、reference モードを使用し、prompt でフレームを指定してください。

    参照数の上限は世代によって異なります。**2.5 は画像 30 枚、動画 10 本、音声クリップ 10 個に対応し、音声のみでも使用できます**。2.0 ファミリーは画像 9 枚、動画 3 本、音声クリップ 3 個に対応し、音声を使用する場合は少なくとも画像 1 枚または動画 1 本も必要です。
  </Accordion>

  <Accordion title="同時実行数の制限やキューはありますか？">
    `SeeDance2` グループは十分な同時実行数を備えており、キュー待ちはありません（テストでは 15 個のタスクを同時に実行し、すべて即時に開始されました）。より大規模な継続的ワークロードについては、営業にお問い合わせください。
  </Accordion>

  <Accordion title="prompt に制限はありますか？">
    prompt は中国語で約 500 文字、英語で約 1,000 語未満にしてください。長すぎる prompt はディテールを薄めます。対応言語は中国語、英語、日本語、スペイン語、ポルトガル語、インドネシア語です。被写体、動作、カメラの動き、ライティング／スタイルを説明してください。
  </Accordion>
</AccordionGroup>
