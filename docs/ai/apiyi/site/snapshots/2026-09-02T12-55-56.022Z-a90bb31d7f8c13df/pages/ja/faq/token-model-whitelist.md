# トークンに利用可能なモデルを設定する必要はありますか?

> API.YI token の利用可能なモデルの仕組み、利用に関する推奨事項、よくあるシナリオの詳細な説明

## 一般的なケース: 設定不要

<Info>
  **推奨運用**: token を作成する際、**利用可能モデルを設定する必要はありません**。これにより、サイト上のすべてのモデルを利用できます。
</Info>

利用可能モデルは **ホワイトリスト機構** を採用しています:

* **未設定**: token はサイト上の 400 以上のすべてのモデルを呼び出せます
* **設定済み**: token は指定したモデルのみ呼び出せ、他のモデルは利用できません

業務シナリオが多岐にわたる場合、利用可能モデルを設定すると token の利用範囲が制限され、柔軟性に影響します。

## なぜ設定を推奨しないのですか？

### 1. 呼び出し範囲が制限される

利用可能なモデルを `gpt-4o`、`claude-3-5-sonnet-20241022` に設定すると、次のようになります。

* ✅ 呼び出し可能: `gpt-4o`、`claude-3-5-sonnet-20241022`
* ❌ 呼び出し不可: `gemini-2.5-pro`、`deepseek-v3`、その他400以上のモデル

これでは、ビジネスの柔軟性が大きく損なわれます。

### 2. モデルエイリアスの問題

<Warning>
  **モデルエイリアスの落とし穴**: 一部のモデルにはエイリアスがあり、利用可能なモデルを設定する際に簡単にエラーの原因になります。

  **ケーススタディ**:

  * **エイリアス**: `nano-banana-pro`（親しみやすいニックネーム）
  * **正式名称**: `gemini-3-pro-image-preview`（公式API名）

  利用可能なモデルを `nano-banana-pro` に設定しているのに、コード内で `gemini-3-pro-image-preview` を呼び出すと、エラーが発生します。

  ```
  {
    "error": {
      "message": "Model not allowed for this API key",
      "type": "invalid_request_error"
    }
  }
  ```
</Warning>

### 3. ビジネスシナリオの変更

ビジネスの成長に伴い、異なるモデルをテストしたり切り替えたりする必要が出てくる場合があります。

* GPT-4 から Claude 3.5 に切り替える
* DeepSeek、Qwen などの国内モデルをテストする
* 新しくリリースされた Gemini 2.5 を試す

あらかじめ利用可能なモデルを設定していると、そのたびにホワイトリストを変更する必要があり、非常に面倒です。

## いつ設定すべきですか？

おすすめではありませんが、次のようなシナリオでは利用可能なモデルを設定することを検討できます。

### シナリオ 1: 他の人と token を共有する

<Card title="チームでの共同利用/友人との共有" icon="users">
  同僚や友人と token KEY を共有し、**特定のモデルのみを使ってほしい**（たとえば`gpt-3.5-turbo`）場合、高額なモデルで残高を消費しないように、利用可能なモデルを設定できます。

  **例**:

  * 残高が限られているため、同僚には`gpt-3.5-turbo`、`gpt-4o-mini`だけを使ってほしい
  * 利用可能なモデルを設定した後は、同僚が`o3`を呼び出そうとしても拒否されます
</Card>

### シナリオ 2: 予算管理

<Card title="厳格なコスト管理" icon="dollar-sign">
  プロジェクトに厳しい予算を設定し、低コストのモデルだけを使わせたい場合は、利用可能なモデルのホワイトリストで制限できます。

  **例**:

  * プロジェクトの予算が限られているため、`deepseek-v3`（\$0.07/百万 token）のみを許可する
  * 使いすぎを防ぐため、`o3`（\$20/百万 token）の使用を禁止する
</Card>

### シナリオ 3: セキュリティ準拠

<Card title="企業のセキュリティポリシー" icon="shield">
  一部の企業では AI モデルの利用に厳格な規則があり、承認済みのモデルのみの使用を許可しています。

  **例**:

  * 会社では公式 OpenAI モデルのみの使用を許可している
  * 利用可能なモデルを`gpt-4o`、`gpt-4.1`に設定し、他のベンダーのモデルの使用を禁止する
</Card>

## 利用可能なモデルの設定方法

どうしても利用可能なモデルを設定する必要がある場合は、次の手順に従ってください。

1. [API.YI トークン管理ページ](https://api.apiyi.com/token)にログインします
2. 「新しい KEY を追加」をクリックするか、既存のトークンを編集します
3. 「利用可能なモデル」フィールドで許可するモデルを選択します
4. 設定を保存します

<Tip>
  **公式名を使用する**: 利用可能なモデルを設定する際は、呼び出し失敗を避けるため、エイリアス（`nano-banana-pro` のようなもの）ではなく、モデルの**公式名**（`gemini-3-pro-image-preview` のようなもの）を使用することをおすすめします。

  すべてのモデルの公式名は、[モデル一覧ページ](/ja/api-capabilities/model-info)で確認できます。
</Tip>

## 概要

| 設定方法              | 利点                                                                     | 欠点                                                                    | 適用シナリオ                       |
| ----------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------- | ---------------------------- |
| **利用可能モデルを設定しない** | ✅ 400+ のすべてのモデルを使用できます<br />✅ エイリアスの問題を心配する必要がありません<br />✅ ビジネスの柔軟性が高い | ❌ 他者による高価なモデルの利用を制限できません                                              | 個人利用、開発テスト、本番環境（推奨）          |
| **利用可能モデルを設定する**  | ✅ モデルの利用範囲を厳密に管理できます<br />✅ 高価なモデルが残高を消費するのを防げます                       | ❌ 柔軟性が下がります<br />❌ エイリアスの問題が発生する場合があります<br />❌ ホワイトリストを手動で維持する必要があります | 共有 token、予算管理、セキュリティコンプライアンス |

<Info>
  **推奨運用**: 明確な管理要件がない限り、**利用可能モデルを設定せず**、すべてのモデルへのアクセスをそのまま利用してください。
</Info>
