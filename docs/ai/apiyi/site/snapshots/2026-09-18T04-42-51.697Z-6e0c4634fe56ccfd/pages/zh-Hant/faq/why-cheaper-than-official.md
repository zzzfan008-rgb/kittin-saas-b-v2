# 為什麼 API易 能比官網價格低？

> 部分模型低於官網標價，來自規模化採購與廠商的渠道分發合作，不是降智或逆向。同時說明價格不是唯一標準，以及如何判斷一份過低報價背後的代價。

## 簡短回答

**能低是因為「量」和「渠道」，不是因為動了模型本身。**

模型廠商（尤其是國產廠商）需要分發渠道觸達開發者，我們作為有穩定用量的渠道方，通過**承諾用量/低消**換到有限的採購折扣，再把這部分讓給使用者。我們**沒有收廠商的廣告費或競價排位費**，價格完全由採購成本決定。

需要說清的是：**並非所有模型都比官網低**。OpenAI、Anthropic、Google 這類海外廠商基本不給轉售折扣，這些模型我們與官網**同價**，優惠通過[充值加贈](/zh-Hant/faq/official-pricing-advantages)體現。真正能低於官網標價的，主要是國產模型和部分有渠道合作的分組。

  </Card>

  <Card title="聚合攤薄運營成本" icon="layers">

  </Card>

<Note>
  **我們不做付費上榜**：模型能不能上、排在哪，取決於實測結果和使用者需求，不接受廠商付費買位置。這也是價格能保持可解釋的前提。
</Note>

## 站在模型廠商的視角：Router 的價值

廠商願意給渠道折扣，不是慈善，而是因為聚合閘道（Router）確實承擔了他們自己做成本更高的事：

<CardGroup cols={2}>
  <Card title="觸達增量開發者" icon="users">
    大量中小團隊和個人開發者不會為單一模型單獨註冊、綁卡、走合規流程。渠道是這批使用者唯一的入口
  </Card>

  <Card title="承接一線服務成本" icon="headset">
    整合答疑、引數排錯、故障定位由我們承接。廠商不必為分散的長尾使用者建中文客服團隊
  </Card>

  <Card title="真實問題的反饋閉環" icon="microscope">
    我們對新模型做實測（引數相容性、計費口徑、欄位完整性、穩定性），發現問題帶回上游，比零散工單更有資訊量
  </Card>

  <Card title="結算與合規簡化" icon="file-text">
    對廠商而言是一個簽約主體、一張賬單，替代成千上萬筆小額跨境結算
  </Card>

  <Card title="同臺競爭的展示位" icon="scale">
    新模型被放在能與主流模型直接比較的位置。被開發者實際選中，是比投放更有效的證明
  </Card>

  <Card title="冷啟動期的用量保證" icon="rocket">
    新模型上線初期最缺真實流量，渠道能快速帶來可用的負載和反饋樣本
  </Card>
</CardGroup>

<Tip>
  換句話說：這份折扣是**合作換來的**，不是靠犧牲模型品質省出來的。同一個模型，我們跑的是同一個上游。
</Tip>

## 價格不是唯一考慮：過低報價的代價

市面上確實存在比我們更低的報價。低價本身不是問題，**關鍵是低價從哪來**。常見的幾種來源和對應風險：

| 低價來源       | 典型表現                         | 潛在代價                     |
| ---------- | ---------------------------- | ------------------------ |
| 逆向 / 網頁端封裝 | 無正式 usage 欄位、不支援快取計費、部分引數不生效 | 上游一改就斷供，無法排障，也拿不到官方口徑的賬單 |
| 共享或來源不明的賬號 | 價格遠低於官方成本價，無法說明採購渠道          | 隨時封號斷供，可能涉及合規問題          |
| 降級替換       | 標稱 A 模型，實際跑更小的模型或降低引數        | 效果與預期不符，且難以自證            |
| 資料變現       | 免費或極低價，條款裡對日誌留存語焉不詳          | 請求內容可能被留存或用於訓練           |
| 虧本引流       | 明顯低於採購成本，強推大額預充值             | 後續漲價、限速，或預充值無法消化         |

<Warning>
  **重點看資料安全**。價格可以談，資料洩露不可逆。接入前務必確認對方的日誌留存策略、是否用於訓練、企業能否簽署保密條款——尤其在傳輸程式碼、客戶資料、內部文件時。
</Warning>

### 怎麼自己驗證一份報價

<Steps>
  <Step title="小額試用，先不談量">
    用最小金額跑通，不要一上來就大額預充值。
  </Step>

  <Step title="核對 usage 欄位與官方口徑">
    對比返回的 token 統計、快取命中欄位是否與官方一致。欄位缺失或恆為 0，通常說明不是官方直連。
  </Step>

  <Step title="測穩定性，不只測能不能跑通">
    連續壓測、觀察長文本和高併發下的表現，以及首字延遲和尾部延遲。
  </Step>

  <Step title="問清資料留存策略">
    日誌存多久、誰能訪問、是否用於訓練、能否籤保密協議。
  </Step>

  <Step title="看有沒有可追責的憑據">
    能否開發票、能否籤合同、有沒有明確的退款和補償規則。出問題時這些才是依據。
  </Step>
</Steps>

## 我們更看重的：服務和穩定性

價格只是其中一項。真正決定長期成本的是「出問題時怎麼辦」：

<CardGroup cols={2}>
  <Card title="多渠道容災" icon="git-branch">
    同一模型接入多個上游渠道，單一渠道異常時可切換，降低單點斷供風險
  </Card>

  <Card title="實測與故障復盤" icon="clipboard-check">
    新模型上線前做引數與計費實測，故障後給可復現的分析結論，而不是一句「已恢復」
  </Card>

  <Card title="中文人工客服" icon="message-circle">
    工單與微信客服直達技術，不是隻會回覆模板的機器人
  </Card>

  <Card title="計費透明可查" icon="receipt">
    每一次呼叫的日誌和扣費明細可在後臺自查，計費口徑公開
  </Card>

  <Card title="資料最小化留存" icon="shield">
    不將請求內容用於訓練，企業客戶可另行約定留存策略
  </Card>

  <Card title="企業結算與合同" icon="building">
    支援對公轉賬、開具發票、簽署合同與保密協議，可滿足報銷與採購流程
  </Card>
</CardGroup>

<Card title="瞭解 SLA 與補償規則" icon="shield-check" href="/zh-Hant/faq/sla-guarantee">

## 那 API易 的價格到底怎麼定

<AccordionGroup>
  <Accordion title="海外主流模型（OpenAI / Claude / Gemini 等）">
    與官網**同價**。這類廠商不提供轉售折扣，同價已經是正常水位，低於官方成本的報價往往意味著非官方來源。優惠通過**充值加贈**實現，部分分組另有折扣且可以疊加。
  </Accordion>

  <Accordion title="國產模型與部分合作分組">
    可以**低於官網標價**，具體幅度取決於當期採購條件，以後臺「模型價格」頁面顯示為準。
  </Accordion>

  <Accordion title="人民幣計價">
    按 **1:7 固定匯率**換算，不隨即時匯率波動，方便預算和對賬。詳見[人民幣如何換算](/zh-Hant/faq/rmb-to-computing-power)。
  </Accordion>

  <Accordion title="我們不承諾「全網最低」">
    我們承諾的是**價格可解釋、來源可追溯**：每一個低於官網的價格都能說清折扣從哪來。做不到的低價我們不跟。
  </Accordion>
</AccordionGroup>

## 常見問題

<AccordionGroup>
  <Accordion title="別家報價比你們低，是不是你們沒優勢？">
    有可能對方拿到了更好的採購條件，這很正常；也有可能來源不同。建議按上面的「怎麼自己驗證一份報價」核對一遍——重點看 usage 欄位是否完整、穩定性如何、資料留存怎麼約定。如果對方各項都經得起驗證，那是合理的價格差；如果說不清來源，低出來的部分就是風險溢價。
  </Accordion>

  <Accordion title="價格低會不會犧牲模型品質？">
    不會。我們是官方直連轉發，不降智、不偷換模型、不降引數。同一模型的輸出可以自行做對比驗證，詳見[企業服務是否值得信任](/zh-Hant/faq/enterprise-trust)。
  </Accordion>

  <Accordion title="折扣會不會突然取消？">
    定價隨上游採購條件變化會調整，調整會在站內公告。已到賬的餘額不受影響，也不會出現「充值後單方面漲價把餘額吃掉」的情況。
  </Accordion>

  <Accordion title="為什麼不乾脆所有模型都定得比官網低？">
    因為做不到的部分不會硬撐。海外主流廠商沒有轉售折扣空間，強行壓價只能換渠道來源，代價是穩定性和資料安全。我們寧可在這些模型上保持同價，把優惠放在充值加贈上。
  </Accordion>

  <Accordion title="你們靠什麼盈利？">
    靠採購價與售價之間的合理差額，以及規模帶來的運營效率。部分模型為了保證供應幾乎不盈利，我們接受這種結構——使用者的模型選擇是完整的，比單點毛利更重要。
  </Accordion>
</AccordionGroup>
