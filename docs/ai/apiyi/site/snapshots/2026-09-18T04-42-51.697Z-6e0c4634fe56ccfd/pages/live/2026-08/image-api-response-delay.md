# 图片 API 偶发响应收尾延迟已缓解，今日运行正常

> 8 月 4 日晚之前，部分图片生成调用出现偶发的响应收尾延迟：图片数据已完整送达，但连接结束信号迟到，导致耗时被异常拉长，持续分钟级。主要影响以 Base64 接收图片返回的场景，文本接口基本无感知。已对数据库做针对性优化，今日运行正常。

**2026/8/5 12:16 (UTC+8)** · 模型状态

✅ **图片 API 偶发响应收尾延迟已缓解，8 月 5 日运行正常**

8 月 4 日晚之前，部分图片生成调用出现过偶发情况：图片数据已经完整传输到客户端，但连接的「结束信号」迟迟未发出，程序因此继续等待，单次请求耗时被异常拉长，持续时间为分钟级。**主要影响以 Base64 方式接收图片返回的场景**，文本类接口基本无感知，图片数据本身完整无损。

根因是后台日志数据量过大，拖慢了请求的收尾处理。我们已对数据库做针对性优化，并清理、限制了消耗过大的后台统计查询；今天同步补充了官方 Gemini 图片 API 资源。

建议这样自查：对比 **API易后台日志记录的本次请求耗时** 与 **你实际收到完整图片数据的耗时**，正常情况下两者应比较接近。若差距明显（例如后台显示 20 秒、客户端等了 2 分钟），请把对应的请求记录发给我们。

日志层面的治理仍在推进，我们会持续观察。如仍遇到异常，欢迎随时联系我们，会第一时间跟进。
