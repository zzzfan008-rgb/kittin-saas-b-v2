# Могу ли я просматривать подробные логи в backend для устранения неполадок?

> Узнайте, как администраторы могут включить подробное логирование, чтобы помочь в устранении неполадок

## Политика защиты приватности по умолчанию

По соображениям приватности и безопасности APIYI **не хранит** входящий и исходящий контент клиентов по умолчанию — мы выступаем только как прозрачный прокси для пересылки запросов.

Это означает:

* ✅ Ваша приватность данных максимально защищена
* ✅ Снижение затрат на хранение данных
* ✅ Соответствие лучшим практикам безопасности данных
* ❌ Административная backend-панель не может просматривать конкретное содержимое переписки

## Проблемы в сценариях пакетной обработки

Многие клиенты сталкиваются с этой проблемой при запуске пакетных процессов:

<Warning>
  **Типичный сценарий проблемы**

  «Может ли backend включать пользовательский ввод? Иначе во время пакетной обработки невозможно понять, какой вызов соответствует какой задаче!»

  При пакетной обработке без подробных записей ввода/вывода действительно трудно отследить, в какой именно задаче возникли проблемы.
</Warning>

## Устранение неполадок с помощью администратора

Если у вас возникнут проблемы, требующие помощи технической поддержки, мы можем **временно включить** подробное ведение журнала для администраторов, чтобы помочь диагностировать неполадки.

<Info>
  **Важное уведомление**

  * Эта функция включается только в **административном бэкенде** и не может управляться клиентами
  * Подробное содержимое журналов **видно только администраторам** и не отображается клиентам
  * Это функция для помощи в устранении неполадок, а не для обычного использования
</Info>

### Как запросить включение

<Steps>
  <Step title="Свяжитесь со службой поддержки, указав детали проблемы">
    Обратитесь через каналы службы поддержки (Telegram, email и т. д.), чтобы подробно описать проблему и запросить помощь в устранении неполадок
  </Step>

  <Step title="Проверка администратором">
    Сотрудники технической поддержки оценят, нужно ли подробное ведение журнала для диагностики проблемы
  </Step>

  <Step title="Временная активация">
    Администратор временно включит запись подробностей журналов для вашей учетной записи в бэкенде
  </Step>

  <Step title="Помощь в устранении неполадок">
    Администратор просмотрит подробные журналы, чтобы помочь найти и устранить проблему
  </Step>

  <Step title="Отключение функции">
    После устранения проблемы администратор незамедлительно отключит подробное ведение журнала
  </Step>
</Steps>

## Применимые сценарии

### Рекомендуемые сценарии запроса

Свяжитесь со службой поддержки, чтобы запросить помощь администратора в следующих ситуациях:

* 🔍 **Ошибки API**: Частые ошибки, возникающие без ясной причины
* 📊 **Аномалии пакетных задач**: Некоторые пакетные задачи завершаются сбоем, нужно отследить конкретные проблемные запросы
* 🧪 **Проблемы с качеством вывода**: Ненормальные ответы модели, нужно проанализировать конкретное содержимое входных и выходных данных
* 📈 **Проблемы с производительностью**: Необычная задержка вызовов, нужны подробные логи для анализа узких мест
* 🐛 **Предполагаемые ошибки**: Есть подозрение на проблемы системы, нужно предоставить подробную информацию технической команде

### Когда включение не требуется

Подробное ведение журналов обычно не требуется в следующих сценариях:

* ✅ **Обычное использование**: Вызовы API работают нормально, без аномалий
* ✅ **Распространенные проблемы**: Для диагностики достаточно базовых логов (статистика token, типы ошибок)
* ✅ **Чувствительные данные**: Обработка крайне конфиденциальных данных, предпочтительно, чтобы их никто не просматривал

## FAQ

### Могу ли я самостоятельно включить эту функцию в backend?

Нет. Эта функция включается только в административном backend и недоступна для клиентов. Если вам нужна помощь в устранении неполадок, обратитесь в поддержку.

### Могу ли я просматривать подробные логи после включения?

Нет. Подробное содержимое логов доступно только администраторам для технической поддержки. Клиенты могут видеть только базовые записи вызовов (статистика token, типы ошибок и т. д.).

### Влияет ли включение подробного логирования на производительность?

Влияние минимально — в основном добавляется небольшое время на запись логов (обычно \< 10ms), что не влияет на обычное использование.

### Как долго хранятся логи?

По умолчанию подробные логи хранятся 7–30 дней. После устранения проблемы администраторы оперативно отключают запись.

### Увидят ли администраторы все содержимое моих запросов?

Будут записываться только запросы в период подробного логирования. Администраторы просматривают только релевантные логи при помощи в устранении неполадок, строго соблюдая соглашения о конфиденциальности.

### Можно ли записывать логи только за определенные промежутки времени?

Да. Вы можете согласовать с поддержкой конкретные периоды включения, например временно активировать их только при воспроизведении проблем.
