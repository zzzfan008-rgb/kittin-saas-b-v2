# GPT-image-2.5 / 2: официальный или реверс-инжиниринговый

> Сравните официальные gpt-image-2.5-flare / gpt-image-2.5-sunburst / gpt-image-2 с родственными реверс-инжиниринговыми моделями gpt-image-2.5-all, gpt-image-2-all, gpt-image-2.5-vip и gpt-image-2-vip: особенности каналов, цены, эндпоинты, форматы загрузки и вывода, позиционирование по скорости и качеству, соблюдение промптов — выберите подходящий вариант.

## Кратко

| Если вам нужно                                                                                                                                    | Выберите                                                                                                                                                                                        |
| ------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Регулятор `quality` / масочный inpainting / произвольные пользовательские размеры (сверх 30 пресетов) / строгое соответствие полей OpenAI-API** | Официальные, с тарификацией по token: `gpt-image-2.5-flare` (приоритет скорости) / `gpt-image-2.5-sunburst` (приоритет точности редактирования) / `gpt-image-2` (предыдущее поколение)          |
| **Предсказуемая фиксированная цена \$0.03/изображение + быстрый вывод (скорость — преимущество)**                                                 | `gpt-image-2-all` / `gpt-image-2.5-all` (Реверс, линия ChatGPT-web, \~90 с; 2.5-all работает на базе Images 2.5)                                                                                |
| **Предсказуемая фиксированная цена \$0.03/изображение + фиксированные размеры (30 пресетов, включая 4K)**                                         | `gpt-image-2-vip` / `gpt-image-2.5-flare-vip` / `gpt-image-2.5-sunburst-vip` (Реверс, линия Adobe; две модели 2.5 поддерживают все шесть уровней `quality`, `gpt-image-2-vip` вплоть до `high`) |

Все восемь моделей **внутренне построены на OpenAI GPT-Image серий 2.5 / 2**. Различия заключаются в характере канала (официальный прямой или реверс-инжиниринг), модели ценообразования и детализации параметров. Три официальные модели имеют одинаковую цену и параметры; пять реверс-моделей имеют одинаковую цену и формат вызова.

<Note>
  **Три реверс-линейки (-all / 2.5-all / трио -vip)**: Столбец «Реверс» на этой странице охватывает **`gpt-image-2-all`**, **`gpt-image-2.5-all`** и **`gpt-image-2-vip` / `gpt-image-2.5-flare-vip` / `gpt-image-2.5-sunburst-vip`** (псевдоним `gpt-image-2.5-vip` = sunburst-vip). Все они используют фиксированную цену \$0.03/изображение и одинаковый формат вызова (три модели `-vip` дополнительно поддерживают `size`):

  * `gpt-image-2-all` / `gpt-image-2.5-all`: линия ChatGPT web, генерация **\~90 с** — **скорость является преимуществом**; 2.5-all работает на базе Images 2.5
  * `gpt-image-2-vip` и две модели 2.5 -vip: линия Adobe (Firefly), фиксация `size` (30 пресетов, включая 4K); все три принимают `quality` (поведение канала, не обязательство): две модели 2.5 открыли `xhigh` / `max` при повторном тестировании 2026-09-10 и теперь поддерживают все шесть уровней, `gpt-image-2-vip` — вплоть до `high`; все три возвращают прозрачные фоны; flare-vip — самая быстрая с более мягким видом, sunburst-vip визуально близка к `gpt-image-2-vip`
  * Общее: ни одна не поддерживает `n`; `mask` представляет собой полную регенерацию изображения во всех случаях, без гарантии изменения только замаскированной области

  Для точного масочного inpainting, произвольных пользовательских размеров сверх 30 пресетов или `n` > 1 используйте официальные модели (`gpt-image-2.5-flare` / `gpt-image-2.5-sunburst` / `gpt-image-2`).
</Note>

<Tip>
  **О текущих скоростях**: Генерация `-all` / `-vip` **медленнее, чем при запуске**, из-за **колебаний вычислительных мощностей на стороне OpenAI** — это затрагивает всех пользователей реверс-каналов, а не только APIYI; наш пул аккаунтов и операционные процессы в норме. Установите тайм-ауты клиента на 300 с+ и оставляйте больший запас времени для сложных prompt.
</Tip>

## Когда выбирать каждый вариант

### Выбирайте `gpt-image-2-all` / `gpt-image-2.5-all` (реверс), когда

### Выбирайте три модели `-vip` (реверс, с фиксацией размера), когда

Соответствие уровней: 2.5 `high` соответствует только `gpt-image-2-vip` `medium`, а 2.5 `max` соответствует `gpt-image-2-vip` `high`; фиксированная цена \$0.03 не меняется в зависимости от уровня.

Все они медленнее `-all` — `max` при 1024² по измерениям занимает 80–160 с — поэтому выбирайте их, если приемлемо более длительное ожидание.

  </Card>

### Выбирайте официальные модели (`gpt-image-2.5-flare` / `sunburst` / `gpt-image-2`), когда

<CardGroup cols={2}>

    Доступны все шесть уровней `quality` **с официальными обязательствами**, а уровни и количество token стабильны согласно официальной спецификации. ## Подробные ключевые различия

### 1. Особенность формата b64\_json (ловушка при миграции!)

Как подтверждено в июле 2026 года, официальные и реверсные модели возвращают **необработанный base64 (без префикса `data:`)** — однако `gpt-image-2-all` раньше включал этот префикс, поэтому наиболее безопасный общий код сначала проверяет его наличие:

```python theme={null}
# Universal pattern: detect the prefix before processing — works for all official and reverse models
b64 = resp["data"][0]["b64_json"]
if b64.startswith("data:"):          # handles historical prefixed responses
    b64 = b64.split(",", 1)[1]
with open("out.png", "wb") as f:
    f.write(base64.b64decode(b64))   # ✅ write file
img_tag = f'<img src="data:image/png;base64,{b64}">'  # ✅ browser render
```

<Warning>
  При переключении между официальным и реверсным каналами **код обработки `b64_json` должен измениться**, иначе вы получите поврежденный URL данных или ошибку декодирования.
</Warning>

### 2. Управление разрешением

**`gpt-image-2-all` / `gpt-image-2.5-all`** (без поля `size` — композиция задается в промпте; оба имени работают одинаково):

```
"Landscape 16:9 cinematic, old lighthouse at sunset"   → ~1672×941
"Portrait 9:16 phone wallpaper, cyberpunk city"        → ~941×1672
"1024×1024 square logo, minimalist cat line art"        → ~1254×1254
```

**Три модели `-vip`** (`gpt-image-2.5-vip` / `gpt-image-2.5-flare-vip` / `gpt-image-2-vip`; `size` восстановлен с 2026-07-22):

Принимают **30 предустановленных размеров** (10 соотношений × 1K/2K/4K) — передавайте `size: "WIDTHxHEIGHT"` напрямую (должен быть одним из 30 предустановленных размеров; полный список приведен в [таблице 30 размеров](/ru/api-capabilities/gpt-image-2-vip/overview#supported-sizes-full-30-size-table)). Все три также принимают `quality` в тестовом режиме (поведение канала, а не обязательство): две модели 2.5 поддерживают все шесть уровней (`xhigh` / `max` открыты 2026-09-10), `gpt-image-2-vip` — до `high`; выходные token модели 2.5 в `high` равны только `gpt-image-2-vip` `medium`, а их `max` равен ее `high`:

```python theme={null}
client.images.generate(
    model="gpt-image-2.5-vip",   # alias = gpt-image-2.5-sunburst-vip; swap in gpt-image-2.5-flare-vip / gpt-image-2-vip on this line only
    prompt="...",
    size="3840x2160",   # ✅ one of the 30 presets; images endpoints only (not chat)
    quality="max"       # optional; all six tiers on the 2.5 models, gpt-image-2-vip stops at high; flat $0.03 regardless of tier
)
```

**Официальные модели** (`size` строго соблюдается + уровни `quality`; в примере используется `gpt-image-2.5-flare`, замените его на `sunburst` / `gpt-image-2`, изменив только имя модели):

```python theme={null}
client.images.generate(
    model="gpt-image-2.5-flare",
    prompt="...",
    size="2048x1152",   # ✅ output exactly this
    quality="max"       # all six tiers; xhigh / max on the two 2.5 models only; 2.5 high only equals gpt-image-2 medium
)
```

  <Accordion title="Следует ли сжимать входные изображения? Помогает ли указание 4K / 8K в prompt?">

    Итог: уменьшение входных файлов только ускоряет работу — качество задаётся конфигурацией на стороне вывода, а не размером входного файла.

  <Accordion title="Какие эндпоинты следует использовать в обратном канале?">
    **Используйте OpenAI Images API** (`/v1/images/generations` для преобразования текста в изображение + `/v1/images/edits` для редактирования) по двум причинам:

    1. **Более стабильно**: поставки ресурсов upstream для канала Images API обильнее, поэтому вероятность успешных вызовов выше
    2. **Совместимость с официальным реле для простого переключения**: метод вызова и формат параметров полностью совместимы с тремя официальными моделями (`gpt-image-2.5-flare` / `sunburst` / `gpt-image-2`) — если обратный канал столкнётся с проблемами risk-control, **просто замените имя `model`, чтобы переключиться на официальный релей** без каких-либо изменений в коде

Учтите, что при неоднозначном намерении изображения он может вернуть обычный текст вместо изображения (добавьте фиксированный префикс вроде «Сгенерируй изображение:», чтобы усилить указание). Полный список параметров приведён в [справочнике chat-based API -all](/en/api-capabilities/gpt-image-2-all/chat-completions) / [справочнике chat-based API -vip](/en/api-capabilities/gpt-image-2-vip/chat-completions).

Различие состоит в **скорости и качестве + фиксации размера**:

    * **Время генерации**: `-all` / `2.5-all` \~90 с — **скорость является преимуществом**; трио `-vip` \~120–200 с. Сейчас медленнее, чем при запуске, из-за колебаний вычислительных ресурсов upstream OpenAI
    * **Качество**: детализация `-vip` (линейка Adobe) **иногда выше** — для демонстрационных изображений, когда время не критично; в рамках трио sunburst-vip выглядит близко к `gpt-image-2-vip`, а flare-vip мягче

    Решение: нужен быстрый результат → `-all` / `2.5-all`; нужны фиксированные размеры / 4K → трио `-vip`; нужны пользовательские размеры за пределами 30 предустановок или точная маска → официальные модели. Подробнее см. в [обзоре GPT-Image-2.5-VIP](/ru/api-capabilities/gpt-image-2-vip/overview).
