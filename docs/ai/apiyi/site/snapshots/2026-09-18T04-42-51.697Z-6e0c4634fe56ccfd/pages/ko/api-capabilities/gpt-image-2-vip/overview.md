# GPT-Image-2.5-VIP 이미지 생성/편집

> GPT 이미지 생성 리버스 엔지니어링 모델 gpt-image-2-vip(Adobe 라인, Firefly) 및 그 2.5 형제 모델인 gpt-image-2.5-flare-vip / gpt-image-2.5-sunburst-vip입니다. 이미지당 고정 $0.03입니다. 30개의 명시적 크기(비율 10개 × 해상도 단계 3개: 1K / 2K / 4K)를 지원합니다. gpt-image-2-all과 동일한 호출 형식입니다. 이미지당 약 90–150초가 소요되며, 출력 크기를 고정해야 하는 워크로드에 적합합니다.

<Info>
  **`size` 매개변수를 다시 사용할 수 있습니다** (업데이트 2026-07-22): `size`를 명시적으로 전달하면 이제 예상대로 출력 크기가 잠기며, 이 페이지의 30개 크기 참조 표도 다시 적용됩니다. 참고: `size`는 `/v1/images/generations` 및 `/v1/images/edits` 엔드포인트에서만 동작합니다 — **`/v1/chat/completions` 채팅 엔드포인트는 `size` 매개변수를 지원하지 않으므로**, 채팅 기반 이미지 생성에서는 크기를 잠글 수 없습니다. 최신 상태는 [실시간 업데이트](/en/live) 섹션을 참조하십시오.
</Info>

<Info>
  모든 이미지 API는 **동기식**입니다 — 폴링할 작업 ID가 없으며, 클라이언트가 연결을 끊으면 요청은 계속 과금되지만 결과는 사라집니다. 이 모델에는 넉넉한 타임아웃을 설정하십시오. [Image API Essentials & Best Practices](/ko/api-capabilities/image-api-best-practices)를 참조하십시오.
</Info>

## 개요

**gpt-image-2.5-vip**(`gpt-image-2.5-sunburst-vip`의 별칭), **gpt-image-2.5-flare-vip** 및 이전 세대 **gpt-image-2-vip**는 APIYI의 **Adobe 계열(Firefly) GPT 이미지 생성 역설계 모델**입니다. 저품질 업스케일링이 아닌 고품질 GPT-Image 2.5 역설계 라인입니다. [`gpt-image-2.5-all`](/ko/api-capabilities/gpt-image-2-all/overview)과 동일한 고정 **\$0.03/이미지**이며 **요청/응답 형식도 동일**합니다. 유일하게 중요한 차이점은 `vip`가 **`size` 필드를 지원**한다는 점으로, 4K를 포함한 \*\*일반적인 크기 30개(가로세로 비율 10개 × 해상도 등급 3개: 1K 빠른 처리 / 2K 권장 / 4K 디테일)\*\*를 제공합니다.

<Note>
  **🎨 포지셔닝**: 출력 크기를 **고정해야 할 때**(이커머스 히어로 이미지, 포스터 템플릿, 동영상 썸네일, 4K 배경화면 등) `gpt-image-2.5-vip`을 사용합니다. `model` 필드를 `gpt-image-2.5-vip`로 바꾸고 `size` 필드를 추가하기만 하면 됩니다. 나머지 코드는 모두 `gpt-image-2.5-all`과 동일하게 유지됩니다.
</Note>

<Note>
  **세 가지 -vip 모델은 하나의 제품군입니다**: `gpt-image-2.5-vip`(`gpt-image-2.5-sunburst-vip`의 별칭), `gpt-image-2.5-flare-vip` 및 이전 세대 `gpt-image-2-vip`는 동일한 Adobe 역설계 라인을 공유하며, **가격(\$0.03/이미지, 호출당), 그룹(`Default` / `image2_OSS` / `svip`), 엔드포인트 및 호출 형식이 동일**합니다. 전환하려면 `model`만 바꾸면 됩니다. flare-vip는 더 빠르고 부드러운 느낌을 제공하며, sunburst-vip는 더 높은 품질과 편집 정밀도를 제공하고 시각적으로 `gpt-image-2-vip`와 유사합니다. 매개변수 제한과 측정된 차이점은 아래의 "세 가지 -vip 모델 비교" 섹션에 나와 있습니다.
</Note>

## AI Agent에게 통합 작업 맡기기

<Note>
  Codex / Claude Code / Cursor로 개발한다면, 아래 prompt를 복사하여 agent에게 전달하십시오. agent는 먼저 이 페이지의 일반 텍스트 버전을 가져온 다음(모든 문서 URL에 `.md` 추가), 프로젝트 자체 스택으로 코드를 작성합니다. timeout, base64 렌더링, 업로드 압축 및 허용되는 30개의 `size` 값은 이미 요구 사항에 포함되어 있습니다.
</Note>

<Prompt description="코딩 agent에게 gpt-image-2.5-vip 시리즈 텍스트-이미지 변환 및 이미지 편집을 통합하거나 문제를 해결하도록 맡기십시오. Codex, Claude Code, Cursor 및 유사 도구에 복사하여 붙여넣으십시오." icon="bot" actions={["copy"]}>
  이 프로젝트에서 gpt-image-2.5-vip 텍스트-이미지 변환 및 이미지 편집을 통합하거나 문제를 해결하십시오(`gpt-image-2.5-flare-vip` / `gpt-image-2-vip`는 가격과 호출 형식을 공유합니다. 쉽게 전환할 수 있도록 모델 이름을 구성 값으로 만드십시오).

  코드를 수정하기 전에 문서를 읽으십시오. 이 페이지의 일반 텍스트 버전을 위해 [https://docs.apiyi.com/en/api-capabilities/gpt-image-2-vip/overview.md를](https://docs.apiyi.com/en/api-capabilities/gpt-image-2-vip/overview.md를) 가져오십시오. 더 세부적인 파라미터 정보가 필요하면 텍스트-이미지 변환 및 이미지 편집 페이지에도 같은 방식으로 `.md`를 추가하십시오.

  요구 사항:

  1. Timeout: 클라이언트 timeout을 360초로 늘리십시오. 이미지 API는 동기식입니다. task ID가 없으므로 클라이언트 연결이 끊기면 요청이 계속 과금되는 동안 결과가 손실됩니다. 너무 일찍 timeout되지 않도록 기다리십시오. 리버스 프록시, 게이트웨이 및 서버리스 실행 제한도 늘려야 합니다. 생성 시간보다 짧은 모든 계층은 요청을 중단시킵니다.

  2. 응답 렌더링: 기본값은 base64입니다(`b64_json`, `data:` 접두사 없음). 또는 `response_format`를 url로 설정하여 CDN 링크를 받을 수 있습니다. **기본값에 의존하지 말고 항상 `response_format`를 명시적으로 전송하십시오**. 기본 동작은 과거에 그룹 및 부하에 따라 변경되었습니다. base64를 사용하는 경우 렌더링하고 디스크 저장 작업을 제공하십시오. URL을 사용하는 경우 약 24시간 후 만료되므로 즉시 다운로드하여 서버 측에서 다시 호스팅해야 합니다. `data[]`의 각 항목은 두 필드 중 하나만 포함하므로 둘 다 방어적으로 파싱하십시오.

  3. 업로드 전 압축: `/v1/images/edits`(multipart)를 호출하기 전에 각 참조 이미지를 압축하십시오. 1.5MB를 초과하는 파일만 처리하고, 가로세로 비율을 유지하면서 긴 변을 2048px로 축소하며(작은 이미지를 확대하지 마십시오), 품질 0.9로 다시 인코딩하고 원본 형식을 유지하십시오. 여러 이미지 요청의 경우 합산 크기를 6MB 미만으로 유지하고, 단일 이미지는 10MB를 초과하지 않게 하십시오. 한 이미지 압축에 실패하면 원본으로 대체하고 계속 진행하십시오. 압축 실패 때문에 전체 요청을 절대 중단하지 마십시오.

  4. 크기 파라미터: `size`는 **이 페이지에 나열된 30개 값**(1K / 2K / 4K별 각 10개) 중 하나 또는 `auto`여야 하며, 예를 들어 `1536x1024`처럼 소문자 ASCII x로 작성해야 합니다. 전각 곱셈 기호나 대문자 X를 사용하지 마십시오. 표 밖의 크기는 오류가 아니라 재작성됩니다(16의 배수로 정렬되고, 너무 작은 값은 최소 변 크기로 상향 조정됨). 따라서 이미지가 요청과 일치하지 않을 수 있습니다. 사용자가 자유롭게 입력하지 못하도록 UI에서 이 30개 값을 해상도 드롭다운으로 노출하십시오. `quality`는 `low` / `medium` / `high` / `xhigh` / `max`일 수 있습니다(`xhigh` / `max`는 두 2.5 모델에서만 가능하며, `gpt-image-2-vip`는 이를 거부합니다. `auto`에 의존하지 마십시오. 2.5 `high`는 `gpt-image-2-vip` `medium`와만 같고, 2.5 `max`는 해당 `high`와 같습니다). `n` 또는 `aspect_ratio`를 절대 전송하지 마십시오(`n`를 3으로 설정해 전송하면 이미지 3장에 대해 과금되지만 1장만 반환됩니다). 여기서 `mask`는 정밀 인페인팅이 아닙니다. 필요하다면 공식 방식을 사용하십시오. `size`가 필요하면 반드시 `/v1/images/generations` 또는 `/v1/images/edits`를 호출해야 합니다. `/v1/chat/completions` 엔드포인트는 이를 무시합니다.

  5. `APIYI_API_KEY` 환경 변수에서 키를 읽고, 기본 URL로 [https://api.apiyi.com/v1를](https://api.apiyi.com/v1를) 사용하십시오. 절대 하드코딩하거나 git에 커밋하지 마십시오.

  6. 요청 제한: 500 RPM 이내에서는 동시 실행 수 제한이 필요하지 않습니다. 429가 발생하면 먼저 error.message를 읽으십시오. 거부된 파라미터라면 파라미터를 수정해야 하며, 업스트림 포화라면 backoff를 적용해 재시도하거나 [https://docs.apiyi.com/live를](https://docs.apiyi.com/live를) 확인하십시오.

  7. 완료 후 실제로 텍스트-이미지 변환 호출 1회와 이미지 편집 호출 1회를 실행한 다음, 결과와 해당 두 호출의 비용을 보여주십시오.
</Prompt>

## `gpt-image-2-all`와의 주요 차이점

`gpt-image-2-vip`과 [`gpt-image-2-all`](/ko/api-capabilities/gpt-image-2-all/overview)은 모두 리버스 엔지니어링 채널이며, 가격과 호출 코드가 동일합니다. **서로 미러링됩니다** — 동일한 요청에서 `model` 필드만 바꾸면 동작은 대부분 동일합니다. 차이점은 다음과 같습니다.

| 차원                     | `gpt-image-2-all`                                                 | `gpt-image-2-vip`                                                                                                                                                 |
| ---------------------- | ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **채널**                 | 리버스 엔지니어링된 ChatGPT 웹                                              | 리버스 엔지니어링된 Adobe 제품군(Firefly)                                                                                                                                     |
| **가격**                 | \$0.03 / 이미지                                                      | \$0.03 / 이미지(모든 크기에 동일한 정액)                                                                                                                                       |
| **`size` 매개변수**        | ❌ 허용되지 않음(프롬프트에 설명)                                               | ✅ 4K를 포함한 30가지 크기                                                                                                                                                 |
| **4K(예: `3840x2160`)** | ❌                                                                 | ✅ 4K Detail 등급                                                                                                                                                    |
| **생성 시간**              | 약 30\~60초                                                         | 약 90\~150초(공식 `gpt-image-2`과 비슷함)                                                                                                                                 |
| **`quality` 매개변수**     | ❌ 허용되지 않음                                                         | ✅ 측정 결과이며 보장 사항은 아님: 두 2.5 모델은 6개 등급 `auto` / `low` / `medium` / `high` / `xhigh` / `max`을 모두 지원함(`xhigh` / `max`은 2026-09-10에 공개됨), `gpt-image-2-vip`은 최대 `high` |
| **엔드포인트**              | `/images/generations` + `/images/edits`                           | 왼쪽과 동일(완전히 동일함)                                                                                                                                                   |
| **응답 형식**              | `b64_json`(기본값, 원시 base64, 접두사 없음) / `url`(명시적 `response_format`) | 왼쪽과 동일                                                                                                                                                            |
| **적합한 용도**             | 프롬프트 중심, 크기에 민감하지 않은 경우                                           | 출력 크기 고정이 필요한 경우(4K 포함)                                                                                                                                           |

<Tip>
  **한 줄 결론**: **엄격한 크기가 필요하지 않고 가장 빠른 출력을 원하는 경우** → `gpt-image-2-all`; **크기 고정 또는 4K가 필요한 경우** → `gpt-image-2-vip`; **`quality` 조절 기능 또는 엄격한 OpenAI-API 필드 호환성이 필요한 경우** → 공식 [`gpt-image-2`](/ko/api-capabilities/gpt-image-2/overview)을 사용합니다.
</Tip>

## -vip 모델 3종 비교 (2026-09-09 측정)

동일한 채널과 token에서 모델 이름만 변경한 253개 요청의 3군 비교와 26회의 직렬 경계 호출입니다. 계약은 셀 단위까지 동일하며, 아래 행만 다릅니다. `quality` 및 투명 배경은 과거에 `gpt-image-2-vip`에서 거부되었지만 현재는 허용됩니다 — **보장이 아닌 채널 동작이므로 실제 응답을 따르십시오**.

| 항목                          | `gpt-image-2-vip`                                                                                             | `gpt-image-2.5-flare-vip`                                                                              | `gpt-image-2.5-sunburst-vip` (별칭 `gpt-image-2.5-vip`) |

## 그룹 설정

`gpt-image-2-vip`은 `Default` 그룹에 있습니다 — **추가 그룹이 필요하지 않습니다**. 현재 역방향 채널은 안정적인 공급을 제공하므로, 공식 릴레이 `gpt-image-2`과 같은 엔터프라이즈 그룹 폴백 구성이 없습니다.

| 모델                                                                             | 그룹                                | 참고                                                                   |
| ------------------------------------------------------------------------------ | --------------------------------- | -------------------------------------------------------------------- |
| `gpt-image-2-vip`                                                              | `Default`                         | Adobe 역방향 라인(Firefly), 이미지당 고정 \$0.03, 약 90\~150초                    |
| `gpt-image-2-vip`                                                              | `image2_OSS`                      | **1x 요율 배수(추가 요금 없음)**, 결정론적 URL 출력 — 기본 그룹에 부하가 걸려도 base64로 폴백되지 않음 |
| `gpt-image-2.5-flare-vip` / `gpt-image-2.5-sunburst-vip` / `gpt-image-2.5-vip` | `Default` / `image2_OSS` / `svip` | `gpt-image-2-vip`과 정확히 동일한 그룹                                        |

### 결정론적 URL 출력이 필요하신가요? → `image2_OSS` 그룹으로 전환하십시오

2026년 7월 기본 그룹에서 측정한 결과, `gpt-image-2-vip`(및 `gpt-image-2-all`)은 `response_format`이 생략되면 `b64_json`을 반환합니다. 이미지 URL을 받으려면 `response_format: "url"`을 명시적으로 전달하십시오. 기본 그룹의 출력 형식은 **보장되지 않습니다** — 과거에는 기본적으로 `url`을 사용하고 부하가 발생하면 `b64_json`로 폴백했으며, 채널 버전에 따라 변경된 적이 있습니다.

비즈니스가 **URL 출력에 의존하는 경우**(URL을 데이터베이스에 바로 기록하거나, URL로 프런트엔드에서 렌더링하거나, base64를 허용할 수 없는 경우) 토큰의 그룹을 \*\*`image2_OSS`\*\*로 전환하십시오 — 이 그룹은 **결정론적 URL 출력**을 목적으로 설계되었으며 \*\*1x 요율 배수(추가 요금 없음)\*\*가 적용되고, 두 역방향 모델 `gpt-image-2-vip` 및 `gpt-image-2-all` 모두에서 사용할 수 있습니다. 응답에 항상 이미지 URL이 포함되며 base64로 폴백되지 않음을 보장합니다.

<Tip>
  **고급 설정(`gpt-image-2-all` 및 공식 릴레이 `gpt-image-2`도 함께 사용하는 경우)**: 토큰이 세 모델을 모두 지원한다면 토큰의 그룹 우선순위를 다음과 같이 설정하십시오.

  * **첫 번째 우선순위**: `image2Enterprise`(1.2x 엔터프라이즈 그룹, 공식 릴레이 전용 안정적 라인)
  * **기본 폴백**: `Default`(두 역방향 모델이 모두 이곳에 있으며 모델에 따라 라우팅됨)

  결과적으로 공식 릴레이 `gpt-image-2`은 안정성을 위해 엔터프라이즈 라인을 사용하고, 두 역방향 모델은 기본 그룹에 유지됩니다 — 하나의 토큰으로 세 모델을 모두 지원하며 서로 간섭하지 않습니다.
</Tip>

## 엔드포인트

`gpt-image-2-vip`는 `gpt-image-2-all`와 **완전히 동일한** 두 엔드포인트와 호환됩니다. 필요하면 `model` 필드만 바꾸고 `size`를 추가하면 됩니다:

| 엔드포인트                         | 용도            | Content-Type          | 가장 적합한 경우                                                      |
| ----------------------------- | ------------- | --------------------- | -------------------------------------------------------------- |
| `POST /v1/images/generations` | 텍스트-이미지       | `application/json`    | OpenAI Images API 표준 형식 — 동일한 코드로 공식 채널과 리버스 채널 모두를 호출할 수 있습니다 |
| `POST /v1/images/edits`       | 이미지 편집(단일/다중) | `multipart/form-data` | OpenAI Images API 표준 형식 — 동일한 코드로 공식 채널과 리버스 채널 모두를 호출할 수 있습니다 |

<Tip>
  **OpenAI Images API를 사용하십시오** (`/v1/images/generations` + `/v1/images/edits`), 이유는 두 가지입니다:

  1. **더 안정적입니다**: Images API 채널의 상위 리소스 공급이 더 풍부하므로 호출 성공률이 더 높습니다
  2. **공식 릴레이와 호환되어 전환이 쉽습니다**: 호출 방식과 `size` 같은 파라미터가 공식 릴레이 [`gpt-image-2`](/ko/api-capabilities/gpt-image-2/overview)와 완전히 호환됩니다 — 리버스 채널이 리스크 제어에 걸려 불안정해지면 **`model` 이름만 바꾸면** 코드 변경 없이 그대로 사용할 수 있습니다

  채팅 기반 엔드포인트(`/v1/chat/completions`, 더 이상 권장되지 않음)도 있습니다 — 아래 FAQ를 참고하십시오.
</Tip>

<Tip>
  **도메인 옵션**: `api.apiyi.com`이 메인 도메인입니다. `b.apiyi.com` / `vip.apiyi.com` 같은 대체 게이트웨이 도메인도 사용할 수 있습니다. 응답 동작은 동일합니다.
</Tip>

## 모범 사례

<Steps>
  <Step title="입력 이미지를 1.5MB 미만으로 압축합니다(이미지 편집 / 다중 이미지 융합)">
    업로드하는 각 이미지를 **1.5MB 미만**으로 압축합니다(JPEG 품질 80\~90 / 해상도 축소). 다중 이미지 융합에서도 이미지별로 동일한 상한을 적용합니다. 간헐적인 `shell_api_error` / `Unknown error` 응답은 대부분 지나치게 큰 입력으로 인해 발생하므로, 압축하면 성공률과 지연 시간이 눈에 띄게 개선됩니다. **출력 해상도는 입력 크기가 아니라 `size` 필드에 의해 결정됩니다** — 입력 크기를 줄이면 처리 속도만 빨라질 뿐 품질에는 영향을 주지 않습니다. 프롬프트에 `4K` / `8K`을 잔뜩 입력해도 4K 이미지가 생성되지는 않습니다. 해상도는 프롬프트의 불필요한 내용이 아니라 `size`에 의해 설정됩니다.
  </Step>

  <Step title="결과물에 맞게 크기 등급을 선택합니다">
    초안에는 1K 빠른 처리를, 프로덕션에는 2K 권장 등급을, 인쇄물/대형 디스플레이에는 4K 디테일을 사용합니다. 가격은 동일하므로 필요에 따라 선택합니다.
  </Step>

  <Step title="크기에는 소문자 ASCII x를 사용합니다">
    `"size": "1536x1024"`를 전송합니다 — `1536×1024`도, 대문자 `X`도 사용하지 마십시오.
  </Step>

  <Step title="quality는 high까지 지원되며 n은 전달하지 마십시오">
    세 가지 -vip 모델 모두 테스트에서 `quality`를 허용합니다(보장 사항은 아님). 두 2.5 모델은 6개 등급을 모두 지원하며(`xhigh` / `max`는 2026-09-10에 제공 시작), `gpt-image-2-vip`는 최대 `high`까지 지원하고 `xhigh` / `max`은 거부합니다. 2.5 `high`는 `gpt-image-2-vip` `medium`과만 같고, 2.5 `max`는 자체 `high`과 같습니다. `n`는 호출당 이미지 1개만 반환하므로 여러 이미지가 필요한 경우 병렬로 호출합니다.
  </Step>

  <Step title="타임아웃을 300초로 설정합니다">
    일반적인 생성에는 90\~150초가 걸리지만 이미지 업로드/다운로드 시간과 피크 시간대의 꼬리 지연으로 더 길어질 수 있습니다. **보수적인 기준으로 300초를 설정합니다.**
  </Step>

  <Step title="필요에 따라 응답 형식을 선택합니다">
    직접 웹 렌더링에는 `b64_json`를, 서버 측 저장/전달에는 `url`을 사용합니다.
  </Step>

  <Step title="-all을 사용해 코드를 공유합니다">
    동일한 코드가 두 경우 모두 작동합니다. 필요에 따라 `model`를 `gpt-image-2-all`과 `gpt-image-2-vip` 사이에서 전환합니다. 크기가 고정되어야 할 때는 vip를 사용하고, 가장 빠르게 반복 작업을 수행하려면 -all로 다시 전환합니다.
  </Step>
</Steps>

## FAQ

<AccordionGroup>
  <Accordion title="vip와 -all 간에 코드를 공유할 수 있습니까?">
    **예, 거의 동일합니다.** 두 엔드포인트(`/v1/images/generations`, `/v1/images/edits`)는 요청 필드, 응답 필드 및 `b64_json` 접두사 동작을 공유합니다. 차이점은 다음과 같습니다.

    1. `model` 필드: `gpt-image-2-vip` ↔ `gpt-image-2-all`
    2. `size` 필드: vip는 30개 크기 세트를 허용하지만, -all은 `size`를 거부합니다(대신 크기는 prompt에 입력).

    실용적인 패턴은 `if model == 'vip': payload['size'] = ...` 스위치를 사용하여 하나의 코드베이스를 유지하는 것입니다.
  </Accordion>

  <Accordion title="vip는 왜 훨씬 느립니까?">
    `gpt-image-2-vip`는 Adobe 역방향 채널(Firefly)을 사용하므로 **일반적으로 90\~150초**가 걸립니다. 이는 공식 `gpt-image-2`(100~~120초)와 비슷하며 ChatGPT-web-line `gpt-image-2-all`(30~~60초)보다 느립니다. **지연 시간에 민감한** 워크로드에는 `gpt-image-2-all`를 우선 사용하고, **고정된 크기 또는 4K가 필요한** 경우에만 vip로 전환하십시오.
  </Accordion>

  <Accordion title="size는 반드시 표에 있는 값이어야 합니까? 1024x768을 보내면 어떻게 됩니까?">
    **30개 크기 세트를 사용하십시오.** 2026-09-09 테스트 기준으로 목록에 없는 크기도 더 이상 오류가 발생하지 않지만, 생성 전에 다시 작성됩니다. 16의 배수는 그대로 전달되고(`1024x1024` / `1600x1600`), 나머지는 16 단위로 정렬되며(`1920x1080` → 1920×1088), 너무 작은 값은 최소 변의 길이까지 올려집니다(`512x512` → 816×816). 생성된 이미지가 요청과 일치하지 않을 수 있으므로, 정확한 크기가 중요할 때는 항상 30개 프리셋을 사용하십시오.
  </Accordion>

  <Accordion title="4K에서 500이 자주 반환되는 이유는 무엇입니까? 안정적으로 4K를 사용하려면 어떻게 해야 합니까?">
    **증상**: 4K 디테일 등급(예: `3840x2160` / `2880x2880`)에서는 `status_code: 500` 오류가 더 쉽게 발생하며, 업스트림에서 다음을 반환합니다(`invalid_request_error`):

    ```json theme={null}
    {
      "status_code": 500,
      "error": {
        "message": "An error occurred while processing your request. ... Please include the request ID xxxxxxxx in your message.",
        "type": "invalid_request_error",
        "code": null
      }
    }
    ```

    **근본 원인**: **OpenAI 컴퓨팅 변동**이며, 요청 매개변수의 문제가 아닙니다. 동일한 페이로드는 일반적으로 2K에서 정상 처리됩니다. 역방향 채널은 특히 피크 시간대에 4K와 같은 대용량 출력에 더 민감합니다.

    **완화 방법**(비용 대비 효과순):

    1. **2K 권장**을 우선 사용하십시오(예: `2048x1360` / `2048x2048`). 성공률이 크게 높고, **이미지당 \$0.03**으로 동일합니다.
    2. img2img / 다중 이미지 융합에서는 **입력 이미지를 더 적게 보내십시오**. 역방향 채널은 입력 부하가 높을 때 처리에 어려움을 겪어 4K 실패율이 더 높아집니다. 각 입력 이미지를 **1.5MB 미만**으로 미리 압축하는 것도 도움이 됩니다.
    3. **4K를 보장해야 하는 경우** 공식 프록시 [`gpt-image-2`](/ko/api-capabilities/gpt-image-2/overview) + **`image2Enterprise` 그룹**으로 전환하십시오. 공식 프록시의 4K는 더 비싸지만(**이미지당 \~\$0.3 이상**), 훨씬 안정적이므로 4K 제공이 필수 요건일 때 적합합니다.

    📖 현장 참고: [/en/live/2026-05/gpt-image-2-vip-4k-tips](/en/live/2026-05/gpt-image-2-vip-4k-tips)
  </Accordion>

  <Accordion title="입력 이미지를 압축해야 합니까? prompt에 4K / 8K를 작성하면 도움이 됩니까?">
    **예, 강력히 권장합니다.** 각 입력 이미지를 **1.5MB 미만**으로 압축하십시오(JPEG 품질 80\~90 / 해상도 축소). 간헐적인 `shell_api_error` / `Unknown error` 응답은 대부분 지나치게 큰 입력으로 인해 발생하며, 압축하면 성공률과 지연 시간이 측정 가능할 정도로 개선됩니다. 참고로 1.5MB는 안정성과 속도를 위한 **권장 상한**이며, 위 FAQ의 10MB는 게이트웨이의 하드 제한입니다.

    **압축으로 인해 품질이 저하될까 걱정하지 않아도 됩니다**. 출력 해상도는 입력 크기가 아니라 `size` 매개변수에 의해 결정됩니다. 입력을 줄이면 처리 속도만 빨라집니다.

    prompt에 `4K` / `8K`를 억지로 입력해도 실제로 4K 출력이 생성되지는 않습니다. prompt에 `8K ultra HD`라고 작성했지만 `size`을 `1024x1024`로 설정하면 여전히 1K 품질의 이미지를 받습니다. **4K를 사용하려면 `size` 필드에서 설정하십시오**. 1K / 2K / 4K는 30개 크기 세트 전체에서 모두 이미지당 고정 \$0.03으로 동일한 비용이 청구됩니다.

    📖 출처: [/en/live/2026-05/gpt-image-2-vip-unknown-error](/en/live/2026-05/gpt-image-2-vip-unknown-error)
  </Accordion>

  <Accordion title="4K에 정말 추가 요금이 없습니까?">
    **추가 요금은 없습니다.** 4K 디테일 등급(`3840x2160` / `2880x2880` 등)은 1K 및 2K와 동일하게 이미지당 \$0.03입니다.
  </Accordion>

  <Accordion title="n을 지원합니까? n=3을 전달하면 어떻게 됩니까?">
    **지원하지 않습니다.** 이 모델은 호출당 이미지 1개를 반환합니다. 여러 이미지가 필요한 경우 **반복 호출 또는 동시 호출**을 사용하십시오.

    ⚠️ **중요**: 요청에 `n=3`를 전달하면 **과금액은 0.03 × 3 = \$0.09**가 되지만, **실제로 반환되는 이미지는 1개뿐입니다**. 불필요한 과금을 방지하려면 `n` 필드를 제거하십시오.
  </Accordion>

  <Accordion title="콘텐츠가 거부되거나 모델이 '그렇게 할 수 없습니다'라고 응답하면 과금됩니까?">
    이는 **동기식 chat 스타일 응답**을 사용하는 역공학 채널입니다. 결과는 **서로 다른 과금 규칙이 적용되는 두 가지 경우**로 나뉩니다.

    **1) HTTP 5xx 반환 → 과금되지 않음**

    업스트림 콘텐츠 정책이 요청을 강제로 차단하면 다음과 같은 응답을 보게 됩니다.

    ```json theme={null}
    {
      "error": {
        "message": "Image was not generated as expected. Please adjust the prompt and retry (traceid: 0672821c6951af183dbf847130caaf16)",
        "localized_message": "Unknown error",
        "type": "invalid_request_error",
        "param": "",
        "code": null
      }
    }
    ```

    이러한 하드 오류에는 **과금되지 않습니다**. 사용자에게 prompt를 조정한 후 다시 시도하도록 안내하십시오.

    **2) 텍스트 “소프트 거부”와 함께 HTTP 200 반환 → 과금됨**

    모델이 대화 중에 소프트 거부를 수행하는 경우(예: “그렇게 할 수 없습니다”, “죄송하지만 이 요청에는 …이(가) 포함되어 있습니다”), 프로토콜 수준에서는 일반적인 chat completion처럼 보이므로 **과금됩니다**. 역방향 채널은 프로토콜 계층에서 “거부 텍스트”와 “이미지 출력”을 안정적으로 구분할 수 없습니다.

    **소프트 거부를 그냥 면제할 수 없는 이유**

    모든 소프트 거부를 자동으로 면제하면 플랫폼이 실패한 모든 업스트림 호출 비용을 부담하게 됩니다. 더 중요한 점은 **업스트림 콘텐츠 안전 정책을 자주 트리거하면 공급업체 계정이 차단될 위험도 높아진다**는 것입니다. 이는 완전히 제거할 수 없는 실제 공급 측 비용입니다.

    **통합 개발자를 위한 권장 사항**

    * ✅ **사전 필터링 및 사용자 경고**: 프런트엔드 또는 게이트웨이에 키워드/시나리오 필터를 추가하십시오(실존 인물 이름, 저작권이 있는 캐릭터, 민감한 주제). 또한 “유명인 / IP 관련 주제는 실패할 수 있으며 업스트림 정책에 따라 과금될 수 있습니다.”와 같은 UI 안내를 표시하십시오. 이렇게 하면 낭비되는 과금을 크게 줄일 수 있습니다.
    * ✅ **소비자 제품의 월별 환급**: 소비자 대상 제품에서는 사용자 입력을 완전히 제한하기 어렵다는 점을 이해합니다. 월간 지출이 충분히 큰 경우(**월 \$1000 이상**), **로그를 매월 일괄 취합**한 후 지원팀에 문의하여 일회성 수동 크레딧을 요청할 수 있습니다. 호출별 이의 제기를 제출할 필요는 없습니다.

    📖 관련 문서: [500 오류는 일반적으로 콘텐츠 정책 적중입니다(과금되지 않음)](/en/live/2026-04/gpt-image-2-all-500-content-policy)
  </Accordion>

  <Accordion title="b64_json에 data:image/png;base64, 접두사를 추가해야 합니까?">
    **먼저 감지한 후 처리하십시오.** 2026년 7월에 확인한 결과, 반환된 `b64_json`는 **`data:` 접두사가 없는 원시 base64**입니다. 이를 디코딩하여 파일을 작성하거나, 렌더링 전에 직접 접두사를 추가하십시오. **이전 버전에는 접두사가 포함되어 있었습니다**. 코드에 `startsWith('data:')` 검사를 추가하십시오. 접두사가 있으면 값을 그대로 `img src`로 사용하고, 없으면 먼저 디코딩하거나 접두사를 추가하십시오. 이렇게 하면 접두사를 이중으로 추가하거나 접두사가 포함된 문자열을 디코딩하여 이미지가 손상되는 문제를 방지할 수 있습니다.
  </Accordion>

  <Accordion title="참조 이미지의 최대 크기와 지원 형식은 무엇입니까?">
    이미지당 **10MB 이하**를 권장하며, 지원 형식은 `png` / `jpg` / `webp`입니다. 지나치게 큰 이미지는 게이트웨이 제한에 걸릴 수 있습니다. 다중 이미지 융합에서 각 이미지는 이 제한을 충족해야 합니다.
  </Accordion>

  <Accordion title="반환된 이미지 URL은 얼마 동안 유효합니까? 다운로드해야 합니까?">
    `url`-mode 응답의 `url` 필드는 **약 1일(24시간) 후 만료되는 R2 CDN 링크**입니다. 그 이후 요청하면 404가 반환됩니다.

    **강력히 권장합니다**: 생성된 이미지를 생성 직후 자체 객체 스토리지(S3 / OSS / R2), CDN 또는 데이터베이스에 다운로드하여 저장하십시오.
  </Accordion>

  <Accordion title="스트리밍을 지원합니까?">
    지원하지 않습니다. 이 모델은 이미지를 한 번에 반환하며 스트리밍은 지원되지 않습니다. 지연 시간이 중요한 경우 클라이언트 측에 “생성 중...” 진행 표시기를 표시하고 **300초 타임아웃**(보수적 설정)을 구성하십시오.
  </Accordion>

  <Accordion title="공식 OpenAI SDK를 사용할 수 있습니까?">
    예. `base_url`을 `https://api.apiyi.com/v1`로 지정하고 `api_key`을 APIYI token으로 설정하십시오. `client.images.generate(model="gpt-image-2.5-vip", size="2048x1360", prompt=...)`는 직접 작동합니다.
  </Accordion>

  <Accordion title="여전히 /v1/chat/completions를 통해 이미지를 생성할 수 있습니까?">
    예. 엔드포인트는 여전히 작동하지만 **더 이상 권장되지 않습니다**. 대신 `/v1/images/generations` 및 `/v1/images/edits`을 사용하십시오(더 안정적이며 동일한 코드가 공식 릴레이 `gpt-image-2`에서도 작동합니다).

    chat 기반 방식은 두 가지 상황에서만 의미가 있습니다. 다중 턴 반복 편집 또는 온라인 이미지 URL을 직접 전달하는 경우입니다. 이미지 의도가 모호하면 모델이 이미지 대신 일반 텍스트를 반환할 수 있습니다(prompt에 “이미지 생성:”과 같은 고정 접두사를 추가하면 이미지 생성 의도를 강화할 수 있습니다).

    전체 매개변수는 [chat 기반 API 참조](/en/api-capabilities/gpt-image-2-vip/chat-completions)를 확인하십시오.
  </Accordion>

  <Accordion title="공식 gpt-image-2로 전환해야 하는 시점은 언제입니까?">
    **정밀한** 마스크 인페인팅 또는 엄격한 OpenAI-API 필드 호환성이 필요한 경우(공식적으로 보장되는 `quality` 등급 포함) 공식 [`gpt-image-2.5-flare` / `sunburst` / `gpt-image-2`](/ko/api-capabilities/gpt-image-2/overview)을 사용하십시오. [공식 API와 역방향 API 비교](/ko/api-capabilities/gpt-image-2/vs-gpt-image-2-all)를 참조하십시오.
  </Accordion>
</AccordionGroup>
