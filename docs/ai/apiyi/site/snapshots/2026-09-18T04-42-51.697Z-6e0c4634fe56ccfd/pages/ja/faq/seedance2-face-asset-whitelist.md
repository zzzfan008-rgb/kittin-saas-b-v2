# Seedance 2.0 / 2.5で顔アセットがブロックされるのはなぜですか？

> Seedance 2.0および2.5の顔アセット制限と、正しいアセット取り込みおよび実在人物確認のワークフローについて説明します。

## 短い回答

Seedance 2.0 および 2.5 チャネルに含まれる「バーチャル顔ホワイトリスト」は、**プラットフォームのチャネルレベルで有効化される上流機能**です。APIYI の token やアカウントで手動で有効化する必要はなく、また有効化することもできません。ただし、これは顔を含む画像を、公開 URL や Base64 の先頭フレームまたは参照画像として常に直接送信できるという意味ではありません。

AI 生成のバーチャルモデルが「実在の人物を含む可能性がある」と分類された場合は、[Seedance 2.0 / 2.5 アセットライブラリ](https://icover.ai/en/seedance-official/asset-library) にアップロードし、ステータスが `Active` になるまで待ってから、`asset://xxx` ID を取得し、そのアセット ID を動画生成タスクで使用してください。

<Info>
  **チャネルアクセスと信頼済みアセットのステータスは異なる概念です**

  * **バーチャル顔ホワイトリスト**: プラットフォームのチャネルですでに利用可能であり、アカウントや token の個別有効化は不要です
  * **アセット取り込み**: 特定の顔画像を信頼済みアセットとして登録し、動画生成に使用できる `asset://` ID を返します
</Info>

## Seedance 2.0 と 2.5 では顔アセットのルールは同じですか？

顔アセットの審査について、現在のドキュメントでは Seedance 2.0 と 2.5 は同じ扱いとなっています。どちらの生成でも、実在人物の写実的な顔を最初のフレームまたは参照画像として直接使用することはできません。この類似点は顔アセットの審査に限られ、2つのモデル世代の機能やパラメータが完全に同一であることを意味するものではありません。

* AIで生成された写実的なバーチャル人物も、実在人物の可能性があると判定される場合があります
* バーチャル人物の画像は、まず取り込んでから `asset://xxx` IDで参照する必要があります
* 実在人物の顔には、本人によるライブネス認証と、対応する認証済みアセットが必要です

<Note>
  `SeeDance2` はモデルアクセス用のグループであり、顔審査を回避するためのスイッチではありません。Seedance 2.5 と 2.0シリーズのすべてのモデルは **同じ `SeeDance2` グループ**（0.18x）を共有しているため、1つの token で両方の世代を利用でき、追加のグループを選択する必要はありません。
</Note>

## AI生成の顔画像がそれでもブロックされる理由

上流のコンテンツ安全システムは、画像そのものを顔や実在人物の可能性があるコンテンツとして判定します。画像がAIで生成されたという申告だけには依存しません。そのため、非常に写実的なバーチャルモデルは「実在人物が含まれている可能性がある」と分類されることがあり、URL 直指定や Base64 入力でもディープフェイク対策フィルタリングが発動することがあります。

通常、これは APIYI アカウントにホワイトリストがないとか、token の権限を変更する必要があるという意味ではありません。正しい対処法は、まず画像を取り込んで信頼済みアセットにすることです。

<Warning>
  URL を何度も変更したり、画像を再ホスティングまたは圧縮したり、ファイル名を変更したりして顔検出を回避しようとしないでください。これらの操作ではアセットの顔の特性は変わらず、アセットの取り込みや実在人物確認の代わりにはなりません。
</Warning>

## AIバーチャルモデルの正しいワークフロー

<Steps>
  <Step title="アセットライブラリにサインイン">
    [icover.ai Asset Library](https://icover.ai/en/seedance-official/asset-library) を開き、icover.ai アカウントを登録するか、サインインしてください。
  </Step>

  <Step title="バーチャルポートレートをアップロード">
    「Virtual Portrait Ingestion」でAI生成モデルをアップロードします。対応形式は jpeg、png、webp、bmp、tiff、gif、heic です。アスペクト比は 0.4–2.5 で、各辺は 300–6000px、各ファイルは 30MB 未満である必要があります。
  </Step>

  <Step title="アセットがアクティブになるまで待機">
    状態が`Active`になるまで10秒強ほど待ち、その後、`asset://xxx` ID をコピーします。アセットIDは再利用でき、各タスクごとに再生成する必要はありません。
  </Step>

  <Step title="生成方法を選択">
    [icover.ai online generator](https://icover.ai/en/seedance-official) でマルチモーダルモードを選択し、参照画像タイプをアセットに設定します。API リクエストでは、`asset://xxx` を `image_url.url` に設定します。
  </Step>

  <Step title="画像の役割を設定">
    アセットが最初のフレームの場合は `role: "first_frame"` を使用し、キャラクターまたはスタイル参照の場合は `role: "reference_image"` を使用します。プロンプトではアセットを「Image 1」として参照してください。
  </Step>
</Steps>

<Tip>
  キャラクターの一貫性を高めるには、同じバーチャルキャラクターの全身正面画像と、無表情の正面顔アップ画像を1つのアセットグループに入れてください。
</Tip>

## プリセットアセットまたはSeedance生成画像を使用する必要がありますか？

いいえ。以下のソースはいずれも使用できますが、顔アセットは適切なワークフローに従う必要があります。

| アセットのソース                   | サポート対象 | 推奨される扱い                                                 |
| -------------------------- | ------ | ------------------------------------------------------- |
| ご自身で生成したAI生成の仮想モデル         | はい     | アセットライブラリに取り込み、生成された`asset://` IDを使用します                 |
| プラットフォームライブラリ内の既存の仮想キャラクター | はい     | 既存のアセットを選択するか、その`asset://` IDを直接参照します                   |
| Seedanceまたは別のモデルで生成された顔画像  | はい     | 顔参照として再利用する場合は、まず取り込んでください。生成元によって、自動的に検出対象外になることはありません |
| 実在人物の顔画像                   | 条件付き   | 実在人物の生体認証を完了したうえで、その人物の検証済みアセットグループにアップロードします           |

重要なのは、どのモデルが画像を生成したかではなく、**その顔画像が有効な信頼済みアセットになっているかどうか**です。

## アカウントまたは Seedance 2.5 で AI 顔ホワイトリストを有効にできますか？

個別の有効化は必要なく、アカウントにユーザー向けの「AI 顔ホワイトリスト」スイッチもありません。プラットフォームのチャネルには、関連する上流のバーチャル顔機能がすでに含まれています。必要な対応は token 権限の変更ではなく、アセットの取り込みです。

バーチャルポートレートの取り込みに失敗した場合、または有効な `asset://` ID が引き続きブロックされている場合は、サポートに連絡し、アセットの状態または上流での審査結果を調査できるよう、次の情報を提供してください。

* APIYI アカウントまたは登録済みメールアドレス
* 使用したモデル名
* アセット ID（`asset://xxx`）
* 動画タスク ID と完全なエラーメッセージ
* アセット取り込みステータスのスクリーンショット

Seedance 2.5 または 2.0 シリーズのモデルを呼び出す場合は、token で `SeeDance2` グループが選択されていることを確認してください。グループはモデルへのアクセス経路と課金倍率を決定しますが、顔審査のルールは変更しません。

<Warning>
  画像に実在の人物が含まれている場合、またはシステムによって実在人物の承認が必要と判断された場合、通常のバーチャル人物取り込みによって上流の保護ポリシーを回避することはできません。実在人物認証ページで出演者の生体存在確認を完了し、その出演者専用の認証済みアセットグループにアセットをアップロードしてください。
</Warning>

  </Accordion>
</AccordionGroup>
