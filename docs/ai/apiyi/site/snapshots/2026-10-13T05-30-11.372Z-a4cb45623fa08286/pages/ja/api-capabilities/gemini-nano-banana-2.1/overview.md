# Nano Banana 2.1 画像生成/編集

> Google Nano Banana 2.1（gemini-nano-banana-2.1）が一般提供開始：画質、テキストレンダリング、マルチターンの整合性が向上したNano Banana 2のアップグレード版です。1リクエストあたり$0.045（4Kを含む）、または1M tokensあたり入力$0.66 / 出力$13.2のtokenベース課金となります。

## 概要

**Nano Banana 2.1** は、Google が 2026年10月6日にリリースした画像生成モデルです。モデル ID は **`gemini-nano-banana-2.1`** であり、一般提供（GA）としてリリースされました。[Nano Banana 2](/ja/api-capabilities/nano-banana-2-image/overview)（`gemini-3.1-flash-image`）のアップグレード版であり、Flash レベルの速度を維持しながら、画質、画像内テキストレンダリング、マルチターンの編集一貫性を向上させ、前バージョンのタイリングアーティファクトを修正しています。Google はすべての新規プロジェクトにおいて 2.1 を推奨しています。

<Note>
  **🆕 2026年10月6日リリース**: APIYI で利用可能になりました。**リクエスト単位**の課金（1リクエストあたり \$0.045、1K / 2K / 4K で同価格、2026年10月13日以降 \$0.05 から値下げ）と **token ベース**の課金（1M tokens あたり入力 \$0.66 / 出力 \$13.2）の両方に対応しています。Nano Banana 2 も同価格で引き続き利用可能であり、Google からの提供終了日は発表されていません。
</Note>

<Info>
  すべての画像 API は**同期型**です。ポーリングするタスク ID は存在せず、クライアントの接続が切断された場合、リクエストに対して課金されたまま結果が失われます。このモデルには長めのタイムアウトを設定してください。詳細は[画像 API の基本とベストプラクティス](/ja/api-capabilities/image-api-best-practices)を参照してください。
</Info>

<Prompt description="コーディングエージェントにNano Banana 2.1の画像生成および画像編集の統合やデバッグを行わせます。Codex、Claude Code、Cursorなどにコピー＆ペーストしてください。" icon="bot" actions={["copy"]}>
  このプロジェクトにNano Banana 2.1（`gemini-nano-banana-2.1`）の画像生成 + 画像編集を統合（またはデバッグ）してください。

  コードを書く前にドキュメントを読んでください：このページのプレーンテキスト版を取得するには [https://docs.apiyi.com/en/api-capabilities/gemini-nano-banana-2.1/overview.md](https://docs.apiyi.com/en/api-capabilities/gemini-nano-banana-2.1/overview.md) をfetchしてください。詳細なパラメーターについては、画像生成および画像編集のページにも同様に`.md`を追加してください。

  要件：

  1. タイムアウト：Geminiネイティブフォーマットの`POST https://api.apiyi.com/v1beta/models/gemini-nano-banana-2.1:generateContent`を使用し、クライアントのタイムアウトを360秒に設定してください。画像呼び出しはタスクIDのない同期処理です。クライアントが切断されると、結果は失われますがリクエストは課金されます。中間のすべてのレイヤー（リバースプロキシ、ゲートウェイ、サーバーレス実行時間制限）の制限値も引き上げてください。生成時間より短いレイヤーがあるとリクエストが切断されます。Nodeを使用する場合、undiciには3つの独立したタイムアウトがあり、SDKの`timeout`ではそれらをカバーできないことに注意してください。

  2. レスポンスのパース（**最も間違いやすい点**）：画像は`candidates[0].content.parts[]`内の`inlineData.data`にbase64形式で格納されています。ただし、`parts`は**長さや順序が保証されていない異種混在の配列**です。テキストパートが最初に来て、画像がインデックス0ではなく1になる場合があります。そのため、**絶対に`parts[0]`や`parts[1]`をハードコードしないでください**。代わりに`parts`を反復処理し、`inlineData`を持つすべてのパートを収集して、**最後のパート**を取得してください（複雑なタスクでは複数のドラフトが返されることがあり、最後のものが最終版です）。`image/png`をハードコードするのではなく、レスポンスから`mimeType`を読み取ってください。画像をレンダリングし、「ディスクに保存」アクションを提供してください。

  3. アップロードの圧縮：編集の場合、参照画像をbase64として`inlineData`に含めてください。アップロード前に圧縮を行ってください — 1.5MBを超えるファイルのみ、長辺を2048pxに縮小（アップスケールは絶対に行わない）、元のフォーマットで品質0.9で再エンコードし、複数画像のリクエストでは合計サイズを6MB未満に抑えてください。base64エンコードによってサイズは約3分の1増加するため、各画像は5MB未満に保ってください。1つの画像の圧縮に失敗した場合は、リクエスト全体を失敗させるのではなく、元の画像にフォールバックしてください。また、**1つのパートに含めることができるのは`text`または`inlineData`のいずれか一方のみで、両方を含めることはできません** — 正しい構造は1つのテキストパート + N個の画像パートです。

  4. 解像度パラメーター：**常に**`generationConfig.imageConfig.imageSize`（`1K` / `2K` / `4K`、デフォルトは`1K`。**このモデルは`512`をサポートしておらず、渡すと400が返されます**）および`aspectRatio`（有効な14種類のアスペクト比がこのページに記載されています）**を渡してください**。`aspectRatio`がない場合、モデルはコンテンツに基づいてアスペクト比を選択するため、出力の形状が予測できなくなります。tokenベースの課金では、**解像度が価格を直接決定します**。UIには解像度とアスペクト比の両方をドロップダウンとして配置してください。

  5. エラーハンドリング：コンテンツモデレーションによってリクエストがブロックされた場合、HTTPステータスは200のままですが、`candidates[0].content.parts`は空になります。まず`candidatesTokenCount == 0`を確認し、次に`finishReason`が`STOP`でないかどうかを確認してください。`IMAGE_SAFETY`のようなブロックは**課金されず**、同じリクエストを1〜2回再試行すると成功することが多いため、自動的に再試行してください。

  6. キーは環境変数`APIYI_API_KEY`から読み取り、`Authorization: Bearer ...`として送信してください。決してハードコードしたり、Gitにコミットしたりしないでください。

  7. 完了したら、実際に画像生成の呼び出しと画像編集の呼び出しをそれぞれ1回実行し、生成された画像と両方の呼び出しのコストを表示してください。
</Prompt>

<Accordion title="このpromptによって防げる問題">
  | 要件 | 回避できる落とし穴 |
  | - | - |
  | `parts`インデックスをハードコードしない | `parts`の数と順序は保証されていないため、固定インデックスを使用すると断続的に失敗します。[Nano Banana開発者ガイド](/ja/api-capabilities/nano-banana-dev-guide)を参照してください |
  | 最後の画像パートを取得する | 複雑な編集では複数のドラフトが返される場合がありますが、最後のものが最終版です |

  | 常に`imageSize`と`aspectRatio`を渡す | tokenベースの課金では、解像度が価格を決定します。アスペクト比がない場合、モデルが独自に選択するため、同じpromptでも横長または縦長で返される可能性があります |
  | アップロード前に圧縮する | base64によってサイズは約3分の1増加します。[画像の圧縮と出力解像度](/ja/api-capabilities/image-compression-resolution)を参照してください |
  | `IMAGE_SAFETY`を自動再試行する | モデレーションによるブロックは画像なしで200を返し、課金されません。単純な再試行で成功することがよくあります。[Gemini画像エラーハンドリング](/ja/api-capabilities/gemini-image-error-handling)を参照してください |
</Accordion>

<Tip>
  **どちらを使うべきか**:

  * **新規プロジェクト** → Nano Banana 2.1：品質が高く、リクエストあたりのコストも安価です

  * **512px のサムネイルが必要な場合** → Nano Banana 2 をそのまま使い続けるか、[Nano Banana 2 Lite](/ja/api-capabilities/nano-banana-lite-image/overview) をご利用ください

</Tip>

## 料金

<Info>
  **課金モードの選択**：Nano Banana 2.1は2つの課金モードに対応しており、token作成時の「Billing model」設定で選択します：

  * **Pay-as-you-go**または**Pay-as-you-go Priority** → tokenベース課金
  * **Pay-per-request**または**Pay-per-request Priority** → リクエスト課金
  * ⚠️ **Hybrid billingは選択しないでください**
</Info>

### リクエスト課金

| モデル | APIYI価格 | Google価格（4K） | 対Google比 |
| - | - | - | - |
| **Nano Banana 2.1** `gemini-nano-banana-2.1` | **1リクエストあたり\$0.045**（1K / 2K / 4K一律） | 1画像あたり\$0.113 | **約40%** |

<Tip>
  **2026年10月13日より10%値下げ：1リクエストあたり\$0.05 → \$0.045**（1K / 2K / 4K一律）。

  * **値下げの理由**：tokenベース課金では、1K / 2Kの画像がすでに1枚あたりわずか\$0.02〜\$0.04であり、1リクエストあたり\$0.05が割高に見えたため、リクエスト課金の価格も引き下げました。4Kの場合、リクエスト課金はtokenベース課金（\$0.06以上）よりも約30%安くなっています。
  * **tokenベース課金の料金は変更なし**：入力\$0.66 / 出力\$13.2（1M tokensあたり）。
  * **さらにお得に**：10%〜20%のチャージボーナスを適用すると、実質的な1リクエストあたりのコストは約\$0.038〜\$0.041になります。
</Tip>

### tokenベース課金

| 項目 | Google | APIYI | 対Google比 |
| - | - | - | - |
| 入力 | \$1.50 / 1M tokens | \$0.66 / 1M tokens | **44%** |
| 出力（画像、テキスト、思考が一律レート） | 画像 \$30 / 1M、テキストと思考 \$7.50 / 1M | \$13.2 / 1M tokens | 画像料金の**44%** |

<Note>モデル価格は公式サイトに連動しており、変更される場合があります。上記の表は参考用です。最新の確定情報は上部ナビゲーションの**モデル価格**タブをご確認ください：[モデル価格](/en/models/index)。</Note>

### tokenベース課金：本番環境での実際の課金実績

Nano Banana 2.1は**デフォルトで生成前に思考を行います**（デフォルトレベル：medium）。画像tokensに加えて、各画像で約400〜1,300の思考およびその他の出力tokensが生成され、画像と一緒に\$13.2 / 1Mで課金されます。そのため、tokenベース課金における1画像あたりのコストは**固定ではなく、変動します**。以下の表は2026-10-07の実際のtoken課金リクエストから抽出したものです。金額はコンソールでの実際の課金額です（解像度は出力tokensから推定）：

| シナリオ | 入力tokens | 出力tokens | 実際の課金額 |
| - | - | - | - |
| 1K テキストからの画像生成 | 36 | 1,970 | \$0.0260 |
| 1K 単一画像編集 | 1,137 | 2,015 | \$0.0273 |
| 1K 単一画像編集（思考多め） | 1,132 | 2,409 | \$0.0325 |
| 2K テキストからの画像生成 | 13 | 2,623 | \$0.0346 |
| 2K 単一画像編集 | 1,188 | 2,957 | \$0.0398 |
| 2K 参照画像14枚の合成 | 15,735 | 2,827 | \$0.0581 |
| 4K テキストからの画像生成 | 13 | 4,703 | \$0.0621 |
| 4K 複雑なprompt | 72 | 4,933 | \$0.0652 |

当日のtoken課金リクエスト60件の分布：

| 解像度 | リクエスト数 | 最小 | 中央値 | 最大 | リクエスト課金価格 |
| - | - | - | - | - | - |
| 1K | 31 | \$0.021 | \$0.029 | \$0.033 | \$0.045 |
| 2K | 19 | \$0.033 | \$0.036 | \$0.058 | \$0.045 |
| 4K | 10 | \$0.061 | \$0.063 | \$0.067 | \$0.045 |

<Tip>
  **課金モードの選び方**：

  * **1K / 2K → tokenベース課金**：通常1画像あたり\$0.02〜\$0.04で、リクエスト課金の\$0.045を下回ります
  * **4K → リクエスト課金**：tokenベース課金では\$0.06以上かかるのに対し、\$0.045固定です
  * **1リクエストに多数の参照画像がある場合**（10枚以上など）：入力tokensによりtokenベース課金のコストが\$0.045近くまたはそれ以上になるため、この場合もリクエスト課金をご利用ください

  当サービスの[チャージボーナス](/ja/faq/recharge-promotions)と組み合わせることで、実際のコストはさらに抑えられます。
</Tip>

<Info>
  **画像tokensのみではコストを過小評価してしまう理由**：`usageMetadata`内の`thoughtsTokenCount`は`candidatesTokenCount`に含まれていませんが、APIYIのログでは出力tokensとしてカウントされ課金されます。1,120 / 1,680 / 3,780 tokensで見積もると、コストを20%〜40%過小評価することになります。コンソールのログに記録された課金額でご確認ください。
</Info>

## 課金に影響するパラメータ

| パラメータ | リクエストあたりのコストへの影響 | 備考 |
| - | - | - |
| `imageConfig.imageSize` | 1K 約\$0.026 → 4K 約\$0.062（tokenベース） | 最も大きな要因。リクエスト単位の課金には影響なし |
| `thinkingConfig.thinkingLevel` | `high` は約30%多くの thinking tokens を消費し、4K画像で約+6% | 影響は軽微。必要な場合に有効化 |
| `tools: [{"googleSearch": {}}]` | 検索クエリあたり \$0.014。テストでは画像1枚あたり2回のクエリを実行 | リクエストあたりのコストが顕著に増加 |

### thinkingLevel：デフォルトは medium、high でもわずかなコスト増

| 設定 | Thinking tokens（中央値） | 4K画像あたりのコスト（tokenベース） |
| - | - | - |
| 未設定（デフォルトの medium） | 約690 | 約\$0.062 |
| `high` | 約940 | 約\$0.066 |

Nano Banana 2（デフォルトは minimal で、`high` は54%高コスト）とは異なり、2.1 はデフォルトですでに思考を行い、`high` は少し長めに思考するだけです。画像内のテキスト配置やグラフの比率を正確にする必要がある場合は、気兼ねなく有効にしてください。

### Google Search グラウンディング：検索クエリごとに課金

リアルタイム情報を必要とする画像（天気カード、市場チャート、最近のイベントのポスターなど）には、`googleSearch` ツールをアタッチします：

```json theme={null}
{
  "contents": [{ "parts": [{ "text": "A weather card poster for Tokyo today" }] }],
  "tools": [{ "googleSearch": {} }]
}
```

テストではグラウンディングが3回中3回トリガーされ、モデルはリクエストあたり自律的に2回の検索クエリを実行しました。クエリ1回あたりのコストは \$0.014（1,000回あたり \$14）です。**モデルが実行するクエリ数を決定し、事前に上限を設定することはできません**。そのため、リクエストあたり2〜3回のクエリを予算として見込んでおいてください。

<Warning>
  **検索料金はリクエスト単位の課金にも加算されます**：リクエストあたり \$0.045 は画像のみをカバーし、`googleSearch` をアタッチした場合、各検索クエリの料金が上乗せされます。
</Warning>

## グループ

APIYIではNano Banana 2.1を2つのグループで提供しており、token設定で切り替えることができます：

| グループ | レート倍率 | ユースケース |
| - | - | - |
| `Default` | 1.0x | 表示価格通りの標準チャネル。デフォルトとして推奨 |
| `NB-Enterprise` | 1.4x | デフォルトグループの混雑時やタイムアウト時のフォールバックチャネル。安定性を最優先 |

**推奨されるtoken課金モード**: `Pay-as-you-go Priority`を選択してください — Nano Banana 2 / 2.1のtokenベースの課金とNano Banana Proのリクエスト単位の課金の両方に対応しているため、**1つのtokenでシリーズ全体をカバーできます**。`Default`をプライマリグループ、`NB-Enterprise`をフォールバックとして設定してください。プライマリグループが429を返した場合、リクエストは自動的にフォールバックし、生成を継続します。

## 解像度とアスペクト比

### 出力解像度

| 解像度 | 説明 | ユースケース |
| - | - | - |
| 1K | デフォルト | ソーシャルメディア、Web |
| 2K | HD | HDディスプレイ、印刷 |
| 4K | Ultra HD | プロフェッショナルデザイン、商用ポスター |

<Warning>
  **`512` はサポートされていません**: `"imageSize": "512"` は 400 `Image size 512 is not supported for this model` を返します（課金されません）。Nano Banana 2 から移行する際は変更してください。
</Warning>

### サポートされているアスペクト比 (14)

`1:1`, `1:4`, `4:1`, `1:8`, `8:1`, `2:3`, `3:2`, `3:4`, `4:3`, `4:5`, `5:4`, `9:16`, `16:9`, `21:9`

**`aspectRatio` を省略した場合、モデルはコンテンツに基づいてアスペクト比を選択します**: 弊社のテストでは、シーンの prompt はほとんどが 16:9 になり、ポスターの prompt は 2:3 または 3:4 になりました。固定のアスペクト比が必要な場合は、明示的に指定してください。

## FAQ

<AccordionGroup>
  <Accordion title="Nano Banana 2.1 と Nano Banana 2 は同じモデルですか？">
    いいえ、異なります。2.1 は別のモデルID（`gemini-nano-banana-2.1`）であり、品質、テキストレンダリング、マルチターンの整合性が向上しているほか、異なる価格体系が適用されます（入力がより高額、画像出力がより安価、4K画像あたりの token 数が増加）。どちらのモデルも APIYI で利用可能であり、相互に影響することはありません。
  </Accordion>

  <Accordion title="Nano Banana 2 から切り替えるには何を変更すればよいですか？">
    1. モデル名を `gemini-3.1-flash-image`（または `-preview`）から `gemini-nano-banana-2.1` に変更します
    2. `"imageSize": "512"` を使用している場合は、`1K` に変更します
    3. token 数からコストを見積もっている場合は、上記の「画像1枚あたりの実際のコスト」の表と照らし合わせて再確認してください

    リクエスト形式、レスポンス構造、複数画像やマルチターンの編集機能はすべてそのまま維持されます。
  </Accordion>

  <Accordion title="Nano Banana 2 は提供終了になりますか？">
    2026年10月7日現在、Google は `gemini-3.1-flash-image` の提供終了日を発表しておらず、推奨される代替モデルとして 2.1 を案内しているのみです。APIYI 上の Nano Banana 2 は引き続き同価格でご利用いただけます。変更がある場合は事前にお知らせいたします。
  </Accordion>

  <Accordion title="請求額が画像の token 数からの想定より高くなるのはなぜですか？">
    2.1 はデフォルトで思考を行うため、画像1枚あたりおよそ 400〜1,300 の思考およびその他の出力 token が追加され、画像と共に出力レートで課金されます。これらは `thoughtsTokenCount` で確認できます。主に 4K 画像を生成する場合は、リクエストごとの課金（\$0.045）の方がお得です。
  </Accordion>

  <Accordion title="同時実行数の制限はありますか？">
    **同時実行数の制限はありません** — 同時リクエストは自由にお送りいただけます。キューに入ったり互いにブロックしたりすることはありません。重要となるのは `timeout` です。4K やピーク時間帯のリクエストには時間がかかる場合があるため（検証ではほとんどの 4K リクエストに 30〜50 秒、一部は 2 分以上かかりました）、**クライアントのタイムアウトを 360 秒に設定してください**。まれに 429 エラーが発生する場合は、token のフォールバックグループとして `NB-Enterprise` を追加してください。
  </Accordion>

  <Accordion title="出力画像に透かしは入りますか？">
    出力されるすべての画像には、目に見えない SynthID の透かし（AI 生成コンテンツであることを示す Google のマーカー）が付与されます。目に見えるものではなく、利用に影響はありません。
  </Accordion>
</AccordionGroup>
