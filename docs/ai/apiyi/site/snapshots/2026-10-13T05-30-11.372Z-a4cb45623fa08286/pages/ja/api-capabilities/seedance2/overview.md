# Seedance 2.0 / 2.5 動画生成

> 公式 Volcengine リソース経由の ByteDance Seedance：新しい 2.5 と、2.0 の標準 / 高速 / Mini を並行提供 — テキストから動画、最初+最後 / 最初のフレーム、マルチモーダルリファレンス、動画編集と延長に対応。すべてのアスペクト比で各ティアの料金は同一で、音声はデフォルトで同期されます。2.5 では 30 秒クリップ、30 枚のリファレンス画像、mov 出力が追加され、2.0 ファミリーと同じ SeeDance2 グループで課金されます。

## 概要

**doubao-seedance-2-5-260628**（2.5）、**doubao-seedance-2-0-260128**（standard）、**doubao-seedance-2-0-fast-260128**（fast）、および **doubao-seedance-2-0-mini-260615**（mini/lite）は、ByteDanceの最新動画生成モデルファミリーです。4つのモデルが並行して稼働し、APIYIを通じてアップストリームのコンテンツセーフティが組み込まれた**公式Volcengine中国本土リソース**（BytePlus国際版ではありません）から提供されます。テキストからの動画生成（text-to-video）、最初＋最後のフレーム／最初のフレームからの画像・動画生成（image-to-video）、マルチモーダル参照からの動画生成（reference-to-video）をサポートしており、映像と同期した音声、効果音、BGMを生成できます。

**2.5は最も高機能なティアです**：生成時間の制限が15秒から**30秒**に、参照画像数が9枚から**30枚**に拡大され、音声単体を参照として使用できるようになり、**mov**出力や明示的な動画編集・延長タスクタイプが追加されました。**コストも高く**、2.0 standardモデルの約1.5倍（720p/5秒で約\$0.91に対して約\$1.35）となっており、Volcengine自身の定価における2世代間の差と一致しています。2.0ファミリーも引き続き利用可能で、提供終了の予定はありません。15秒以内の日常的なクリップではstandardモデルの方が安価で**1080pもサポート**しています。miniは大量生成向けの選択肢であり（**standardモデルの約半額の単価で、より高速に生成可能**、最大720p）、fastはその中間に位置します。

**2.5は2.0ファミリーと同じ `SeeDance2` グループ（0.18倍）で稼働します**。1つのtokenで4つのモデルすべてにアクセスできます。詳細は以下の「グループ設定」をご覧ください。

<Note>
  **🎬 主な特徴**：2.5は**4〜30秒**、2.0ファミリーは4〜15秒をサポート（いずれもモデルによる自動決定の `-1` を指定可能）。3つの解像度ティア（480p/720p/1080p、**1080pは2.5および2.0 standardに限定**）。6種類のアスペクト比＋適応型。**同期音声がデフォルトで有効**。多言語プロンプトに対応。**ショート動画制作、Eコマース向けアセット、モーションデザイン、バーチャルヒューマンコンテンツ**の大規模な展開向けに構築されています。
</Note>

<Warning>
  **2.5を呼び出すtokenには `SeeDance2` グループ（レート0.18倍）が必要です**。これは2.0ファミリーと同じグループです。デフォルトグループや他の動画グループのtokenで `doubao-seedance-2-5-260628` を呼び出すと、「**no available channel for this model**」というエラーが発生します。

  **`SeeDance2` を有効化した1つのTokenで4つのモデルすべてにアクセスできます** — 2.5と2.0ファミリーは同じグループと同じレートを共有しているため、コード内で変更するのは `model` フィールドのみです。
</Warning>

  Codex / Claude Code / Cursor を使用して構築する場合は、以下の prompt をコピーしてエージェントに渡してください。まずこのページのプレーンテキスト版を取得し（任意のドキュメント URL の末尾に `.md` を追加）、お客様のプロジェクト独自のスタックでコードを記述します。非同期ポーリング、**即時コピーを必須とする24時間のリンク有効期限**、gzip ヘッダーの落とし穴、パラメータの禁止事項はすべて要件に組み込み済みです。

<Prompt description="コーディングエージェントに Seedance 2.5 / 2.0 動画生成の統合やトラブルシューティングを実行させます。Codex、Claude Code、Cursor などのツールにコピー＆ペーストしてください。" icon="bot" actions={["copy"]}>
  このプロジェクトにおいて、Seedance 2.5 / 2.0 動画生成（テキストからの動画生成、先頭/末尾フレーム、マルチモーダル参照、動画編集、動画延長）の統合またはトラブルシューティングを行ってください。

  コードに手を付ける前にドキュメントを読んでください: このページのプレーンテキスト版として [https://docs.apiyi.com/en/api-capabilities/seedance2/overview.md](https://docs.apiyi.com/en/api-capabilities/seedance2/overview.md) を取得してください。エンドポイントの詳細については video-generation ページを、アセットのルールについては asset-library および asset-reference ページを参照してください（いずれも末尾に同様の `.md` が付きます）。

  要件:

  1. 同期的な待機ではなく、3ステップの非同期フローを使用してください。`POST /seedance/api/v3/contents/generations/tasks` に送信してタスク ID を取得し、`GET /seedance/api/v3/contents/generations/tasks/{id}` をポーリングして、成功時に動画をダウンロードします。間違いやすいポイントが3つあります: **パスのプレフィックスは `/seedance/api/v3` です — `/api` を省略したり、汎用の動画エンドポイント `/v1/videos`、`/v1/video/generations`、`/v2/videos/generations` を使用したりしないでください**（理由については「APIエンドポイント」を参照）。タスク ID はトップレベルの **`id`** フィールドであり、`task_id` ではありません。そして**成功ステータスは `completed` ではなく `succeeded` です**（状態遷移は `queued`、次に `running`、その後に `succeeded` / `failed` / `expired` となります）。ポーリング頻度: 送信後、初回問い合わせまで20〜30秒待機し、その後は10〜20秒ごとにポーリングを行い、全体の制限時間は15分としてください。

  2. 動画の取得: アドレスは **`content.video_url`** にあります — トップレベルではなく、`content` の内側にネストされています。これは**24時間で失効する**署名付きリンクであるため、**直ちにサーバー側でダウンロードし、自前のオブジェクトストレージや CDN に再ホストしてください**。長期的なアドレスとしてデータベースに保存してはいけません。そのリンクを取得する際には、`Authorization` ヘッダーを**送信しないでください**。タスク ID 自体は7日間問い合わせ可能です。

  3. Python の requests を使用する場合は、**`Accept-Encoding: identity` ヘッダーを送信してください**。ゲートウェイはレスポンスに `content-encoding: gzip` とラベルを付けますが、本文は実際には圧縮されていないため、このヘッダーがないとランダムな `ContentDecodingError` エラー、切り捨てられた JSON（例えば先頭の `{"` が欠落するなど）、または不可解な 400 エラーが発生します。curl やブラウザの fetch は影響を受けません — requests のように自動解凍を行うクライアントのみが影響を受けます。

  4. 主要パラメータ: まずモデルを選択します — `doubao-seedance-2-5-260628`（2.5、推奨）または `doubao-seedance-2-0-260128` / `-fast-260128` / `-mini-260615`。`resolution` は**小文字の** `480p` / `720p` / `1080p` で、デフォルトは `720p` です。**`1080p` をサポートしているのは 2.5 と 2.0 standard のみです**（fast と mini では 400 が返されます）。また、**このファミリーのモデルはどれも `4k` をサポートしていません**。`ratio` は7つの値（`16:9`、`4:3`、`1:1`、`3:4`、`9:16`、`21:9`、`adaptive`）のいずれかで、デフォルトは `adaptive` です。これら以外の値（`2:1` など）は 400 を返します。`duration`: **2.5 では 4 から 30 までの整数で、デフォルトは `-1` です** — 省略するとモデルが自動で長さを決定します（テストでは 10 秒と測定され、5 秒のクリップの2倍のコストがかかるため、**コストを重視する場合は明示的に渡してください**）。2.0 ファミリーでは 4 から 15 で、デフォルトは 5 です。**`generate_audio` のデフォルトは `true` です**ので、無音で出力する場合は明示的に `false` を渡す必要があります。最後に、`frames` と `camera_fixed` は Seedance 1.x のものであり、ここではサポートされていません — 送信しないでください。

  5. 参照画像とアセット: 画像は `content[]` 内に `{"type":"image_url", ...}` エントリとして配置し、値には公開 URL、Base64 データ URI、またはアセットライブラリ ID（`asset://...`）を指定できます。各モードは**相互排他**です: 先頭/末尾フレーム（画像2枚、`role` は `first_frame` または `last_frame` が必須）、先頭フレームのみ（画像1枚）、またはマルチモーダル参照（**2.5 は最大30枚の画像 + 10本の動画 + 10本の音声クリップを受け付け、音声単体でも使用可能**。2.0 ファミリーは画像9枚 + 動画3本 + 音声クリップ3本を受け付け、音声とともに少なくとも1つの画像または動画が必要です）。各画像は 30MB 未満、短辺・長辺が 300〜6000px、アスペクト比が 0.4〜2.5 の範囲内である必要があります。**実在の人物の顔を含む画像は上流のモデレーションによって拒絶されます** — これらはまずアセットライブラリに登録し、`asset://` として参照した上で、prompt 内で「画像1」「画像2」のように位置で指定する必要があります。**prompt 内に生のアセット ID を直接記述しないでください。**

  6. **2.5 にのみ存在する2つの厳格な制約（違反すると即座に 400 が返されます）**: 先頭フレーム / 先頭＋末尾フレーム、動画編集、動画延長タスクでは、`ratio` は**必ず `adaptive` でなければなりません** — 具体的なアスペクト比を指定すると拒絶されます。また、動画編集タスクでは `duration` は**必ず `-1` でなければならず**、ソース動画は 4〜30 秒である必要があります。編集や延長の処理では、無効なパラメータによって数分後にタスクが失敗するのを防ぎ、送信時に同期的に `InvalidParameter.TaskTypeConstraint` で失敗させるため、`omni_reference_task_type`（`edit` / `extend` / `auto`）を明示的に渡してください。また、2.5 は `output_format`（デフォルトは `mp4`、または `mov`）も受け付けます。mov はプロ向けのポストプロダクション用高色忠実度フォーマットであり、一部のプレーヤーでは開けない場合があります。

  7. 課金とエラー: 課金は token ベースで、**解像度の面積 × 再生時間**によって決定されるため、同じ解像度であればすべてのアスペクト比で同額のコストになります。**1本の動画につきログに2行の課金レコードが生成されます**（送信時の保留（ホールド）、その後の完了時の精算）。これは正常な動作であり、実際のコストはその合計であり、二重課金ではありません。パラメータ起因の 400 エラーは課金されません。また、`PUBLIC_` プレフィックスが付いたエラーは上流のモデレーションによるブロックであり、同様に課金されず、アセットや prompt を調整した後に再試行できます。モデルに対して利用可能なチャネルがない旨のエラーが表示される場合、token グループが間違っていることを意味します — **2.5 と 2.0 ファミリーはいずれも `SeeDance2` グループを使用します**（既存の `SD2Mini` / `SD2Fast` token も引き続き機能し、2026-10-08 より `SeeDance2` と同じ 0.18 倍の価格が設定されています）。課金モードは従量課金または PAYG 優先です。モデレーションを含め生成が失敗した場合は、**まったく同一の prompt を繰り返し再試行しないでください**。

  8. キーは `APIYI_API_KEY` 環境変数から読み取ってください。決してハードコードしたり、git にコミットしたりしないでください。

  9. 完了したら、テキストからの動画生成の呼び出しを1回、先頭フレーム画像からの動画生成の呼び出しを1回実際に実行し、生成された動画とそれら2回の呼び出しのコストを提示してください。全体のフローには数分かかるため、制限のある実行環境で実行する場合は、コマンドのタイムアウトを600秒以上に引き上げるか、バックグラウンドで実行してください。
</Prompt>

## APIYI の Seedance を選ぶ理由

まず位置づけについて補足します。このモデルには**公式割引はなく、APIYI も利益目的で価格設定していません**。**供給を確保し、お客様に提供するため**に提供しています。APIYI を利用する真の価値は「より安い」ことではなく、アクセス性と体験にあります。

## 料金

<Info>
  **料金を一言で言えば — 正確な token 課金で、ティアごとに Volcengine 公式サイトに連動しています。** 4つのモデルは**それぞれ料金が異なります**：mini \< fast \< standard \< **2.5**（公式サイトと同じ順序です。mini は standard モデルの単価の約半分、2.5 は約1.5倍です — **同じ料金水準ではありません**）。Volcengine はこのシリーズに**割引を提供しておらず**、このチャンネルは利益目的ではなく、供給確保のために運用する**純粋な公式リレー**です。料金は「大口入金顧客向け20%ボーナス」基準に設定されています。名目上の課金額は公式料金の1.26倍（レート0.18 × 固定1:7の為替レート）ですが、20%の[チャージボーナス](/ja/faq/recharge-promotions)適用後は**公式料金の約1.05倍**となります。この5%のプレミアムは主に、特別請求書の発行にかかる6%の VAT コストを補填するものです。10%ボーナスが適用される一般顧客の場合は、約1.15倍となります。課金は面積×期間で計算されるため、**±5%の差異は正常です** — ぜひお試しいただき、照合のうえ、いつでもお問い合わせください。

  単価以外にも、このチャンネルでは2つのメリットがあります：**ホワイトリスト登録されたアカウントでは実在の人間の顔を生成できます**（公式ではデフォルトでブロックされています）。また、キャラクターの一貫性を保った動画に必要な[アセットライブラリ](/ja/api-capabilities/seedance2/asset-library)を、**APIYI では無料で利用できます**（公式では別途購入が必要なアドオンであり、フレームワーク契約のない顧客の場合、年間6桁人民元の契約となります）。いずれも、上記の単価比較には反映されていません。
</Info>

token ベースの課金：`tokens ≈ (input video duration + output duration)(s) × output width × output height × 24 / 1024`（テキスト／画像から動画への変換では、入力動画の長さは0です。弊社のテストでは0.1%以内であることを確認しています）。同一ティア内のすべての比率でピクセル面積が同じであるため、**料金は解像度ティア、出力時間、入力に動画が含まれるかどうかだけで決まります**。

### Seedance 2.5 の料金（`SeeDance2` グループ、0.18x）

2.5 と 2.0 ファミリーは**同じ `SeeDance2` グループ、同じ 0.18x レート**を共有しています。世代間の価格差は、純粋にモデル自体の単価の違いによるものです。720p/5秒は 2.0 スタンダードモデルの \$0.9074 に対し、2.5 では \$1.3721 となり、およそ **1.5倍** です。この差は **Volcengine 自身の定価をそのまま反映した**ものであり（2.5 の token レートは 2.0 より約 52% 高額です）、APIYI による上乗せではありません。アップグレードする価値があるかどうかは、30秒のクリップ、30枚のリファレンス画像、mov 出力、または動画編集／延長が実際に必要かどうかによります。これらが不要であれば、2.0 スタンダードモデルの方が安価であり、**1080p もサポートしています**。

<Warning>
  **2.5 で費用を使いすぎてしまいがちな3つの落とし穴**：

  1. **`duration` のデフォルト値は `-1` です**（2.0 ファミリーはデフォルトで 5）。省略した場合、2.5 は 4 〜 30 秒の間で独自に長さを決定します。時間を指定しなかったテストリクエストでは 10 秒のクリップが返され、5 秒のちょうど 2 倍の費用がかかりました。**コストを重視する場合は、明示的に `duration` を渡してください。**
  2. **30 秒は 5 秒の 6 倍の費用がかかります**（720p で ¥57.23 に対し ¥9.60）。費用は長さに厳密に比例するため、長いクリップを生成する前に、まずは 5 秒で prompt を検証してください。
  3. **リファレンス動画の長さも課金対象となります。** `video_url` を使用すると、入力動画の 1 秒ごとに出力解像度に応じた tokens に変換され、出力と一緒に精算されます（2.0 と 2.5 の両方）。事前請求では出力時間のみがカウントされるため、これらのタスクの精算額は**事前請求の数倍になることがよくあります**が、これは正常な動作です。
</Warning>

上記の表および前述の 2.0 の表は**いずれも 0.18x の `SeeDance2` グループ**のものであるため、直接比較できます。

<Info>
  **課金に関する注意事項**：

  * 最終的な請求額は、コンソールのモデル価格および呼び出しログに従います
  * **タスクは送信時に事前請求され、完了時に精算されます** — 残高は一時的に変動します。1 つの動画に対して **2 つ** の請求エントリが生成されるため、呼び出しログと照合してください（後述の「ログにおける請求額の確認方法」を参照）
  * **保留額（ホールド）は解像度に関係なく、時間のみに基づいて計算されます**：2.0 ファミリーは \$0.09/秒、2.5 は \$0.135/秒です。そのため、1080p は通常追加請求で精算され、480p は一部返金されるのが一般的ですが、どちらも正常な挙動です
  * 拒否されたリクエスト（HTTP 400 パラメータエラーなど）は**課金されません**（検証済み）
  * 費用は時間に比例して増加します：15 秒の動画は 5 秒の動画の約 3 倍の費用がかかります
</Info>

</Note>

### タスクIDで1本の動画のコストを調べる：タスクAPIを使用

プログラムによる照合では、**ログエントリを1件ずつ対応付けようとしないでください**。動画の2つのログエントリにはどちらも`task_id`が含まれておらず、決済エントリの`request_id`は空です（これはドキュメント化された`/seedance/api/v3/...`パスでの仕様です）。**タスクAPI**を使用し、[ログ照会API](/ja/api-capabilities/log-query)と同じシステムtokenで認証して、`task_id`を直接クエリしてください。

```bash theme={null}
curl --compressed -s "https://api.apiyi.com/api/task/self?p=1&page_size=1&task_id=cgt-20260915152401-grlz4" \
  -H "Authorization: $APIYI_SYS_TOKEN" | jq '.data.items[0] | {task_id, status, quota, submit_time, finish_time, model_name}'
```

返された\*\*`quota`\*\*は動画の合計コストです（事前チャージ + 決済、÷ 500,000 = USD）。これは2つのログエントリを合計した値と同じであり、「非同期タスク」ページのタスク詳細に表示される同じ`quota`です。`status`に従って解釈してください。

| `status` | `quota`の意味 | 動画の実際のコスト |
| - | - | - |
| `completed` | 最終決済合計 | = `quota` |
| `submitted` / `in_progress` | 送信時に取得された事前チャージのみ | 完了まで待機 |
| `failed` | **事前チャージが引き続き表示されます**（ゼロにはなりません） | **0**：事前チャージは全額返金され、ログ内には対応する負の`type=11`返金エントリがあります |

2つの用語体系は異なります。動画クエリエンドポイント`/seedance/api/v3/.../tasks/{id}`は成功を`succeeded`として報告しますが、タスクAPI`/api/task/self`は成功を`completed`として報告します。

<Warning>
  **タスクAPIのページングパラメータはログ照会APIとは逆です**：ここではsnake\_caseの`page_size`を使用し、ページ番号`p`は**1**から始まります。ログAPIでは`pageSize`を含むcamelCaseを使用し、`p`は0から始まります。誤って指定してもエラーは発生せず、デフォルトページが返されるだけです。検証済みフィルター：`task_id`、`model_name`、`start_timestamp` / `end_timestamp`（Unix秒）。
</Warning>

ログ照会APIで手動クロスチェックを行う必要がある場合：決済エントリのタイムスタンプはタスクの`finish_time`と一致し（1秒以内）、その`completion_tokens`はタスクの`usage.completion_tokens`と等しく、`other.final_quota`はタスクの`quota`と等しく、`other.original_quota`は事前チャージです。複数のタスクが同じ秒に送信されると、その事前チャージエントリは競合するため、これは手動確認にのみ使用でき、自動対応付けには使用できません。完全な手順：[task\_idで動画の実際のコストを調べる方法](/ja/faq/seedance-task-cost-lookup)。

## グループの設定

Seedance 2.5 および 2.0 ファミリーは**専用グループ**で動作し、2 つの**必須要件**があります。① Token の課金モデルが**Pay-as-you-go Priority**（または Pay-as-you-go）である必要があります（Pay-per-request の token はルーティングできません）。② Token で**一致するグループ**が有効になっている必要があります。Default グループやその他の動画グループの Token は、「**no available channel for this model**」というエラーで失敗します。

**2.5 と 2.0 ファミリーは `SeeDance2` を共有します** — 新しい Token に必要なグループはこれだけです。単一モデル向けの 2 つのグループ `SD2Mini` / `SD2Fast` は、以前の期間限定割引の名残です。2026-10-08 12:00 (UTC+8) 以降、これらは `SeeDance2` と同じ 0.18x に戻っています：

| グループ | レート | 対応モデル | 備考 |
| - | - | - | - |
| `SeeDance2` | 0.18x | **4 つのモデルすべて** (2.5 / standard / fast / mini) | **推奨**。2.5 および standard モデルへの唯一のルート — 十分な同時実行数、キュー待ちなし |
| `SD2Mini` | 0.18x | `doubao-seedance-2-0-mini-260615` のみ | `SeeDance2` と同価格。既存の Token を引き続き機能させるためだけに残されています — 新しい Token で有効にする必要はありません |
| `SD2Fast` | 0.18x | `doubao-seedance-2-0-fast-260128` のみ | `SeeDance2` と同価格。既存の Token を引き続き機能させるためだけに残されています — 新しい Token で有効にする必要はありません |

<Note>
  **1 つの `SeeDance2` token で 4 つすべてのモデルを利用できます**: 2.5 および 3 つの 2.0 ファミリーモデルはすべてこのグループに含まれるため、コード側では `model` フィールドを変更するだけで済みます。

  **`SD2Mini` / `SD2Fast` は単一モデル用チャンネルです**: `SD2Mini` は mini のみ、`SD2Fast` は fast のみに対応しているため、これらを通じて他のモデルを呼び出すと同様のエラーが返されます。すでにこのような Token をお持ちの場合はそのまま使い続けて問題ありません — 価格は `SeeDance2` と同じです。1 つの Token ですべてのモデルを利用したい場合は、`SeeDance2` が有効になった Token に切り替えてください。
</Note>

<Note>
  **2.5 も同じ 0.18x を使用します。** 世代間の差はグループレートではなく、モデル自体の単価の違い（Volcengine の価格設定では 2.5 が 2.0 より高価）によるものです。そのため、2.5 と 2.0 ファミリーは完全に同一の換算基準で動作します。

  **なぜ 0.18x なのか？** システムに組み込まれた Seedance の単価は Volcengine の公式定価に一致しています — ただし、その定価は **CNY** 建てであるのに対し、APIYI の残高は **USD** 建て（1:7 の固定 USD/CNY レート）です。レートが 1x だと実質的に公式価格の 7 倍が課金されてしまうため、通貨換算を吸収するためにグループレートが引き下げられています — **0.18 という数値はここに由来しており、割引でも値上げでもありません**。

  Volcengine はこのシリーズに対して**割引を提供しておらず**、本チャンネルは供給を確保するための価格設定となっています。名目上の料金はデフォルトで公式参考価格をわずかに上回っていますが、[チャージボーナス](/ja/faq/recharge-promotions)によってその大部分が相殺されます。**大口チャージのお客様の負担増は約 5% に留まり**、一部の階層（例：1080p）では公式価格を下回ります。

  **ご注意ください**: 課金は常に**実際の token 使用量**に基づいて行われ、token 換算には自然なわずかな変動が伴います（±5% は通常範囲です）。公式定価はあくまで**参考基準**であり、リクエストごとの保証ではありません。現在の価格設定は供給優先の妥当な構成となっています — 必ず**チャージボーナスと合わせて**ご検討ください。請求額に誤りがあると思われる場合は、いつでも請求内容の照合に対応いたします。ただし、「なぜ公式価格よりわずかに高いのか」についての議論には応じかねます — あらかじめご了承いただき、この点が気になる場合は本チャンネルのご利用をお控えください。一方で、**キュー待ちなしの十分な同時実行数**こそが、本チャンネルが確実に提供する価値です。

  さらに、[アセットライブラリ](/ja/api-capabilities/seedance2/asset-library)（バーチャルアバターの取り込み／実人物検証）が**本チャンネルでは無料で含まれています** — 公式では個別に購入する場合、年間 6 桁（CNY）の契約が必要です。これも本チャンネルの真の価値の一部です。
</Note>

### Token の設定方法

`SeeDance2` グループを有効にした Token を 1 つ作成します — これにより **4 つすべてのモデル**が利用可能になり、コード側では `model` フィールドを変更するだけで済みます。課金モデルは Pay-as-you-go Priority（または Pay-as-you-go）である必要があります。本番環境では、クォータの上限設定、アラートの設定、予期しない支出の追跡ができるよう、業務ラインごとに 1 つの Token を運用することを検討してください。

<Info>
  **Seedance 2.5 が利用可能になりました** (2026-08-28): モデル名は `doubao-seedance-2-5-260628` で、2.0 ファミリーと同じ **`SeeDance2` グループ** (0.18x) で提供されます。エンドポイント、認証、リクエスト形式は 2.0 と同一です — **`model` フィールドを差し替えるだけで、既存のコードがそのまま動作します**。2.0 ファミリーとの比較：最大生成時間 15 秒 → **30 秒**、参照画像 9 枚 → **30 枚**、参照動画／音声 3 点 → **10 点**、音声単体での利用が可能になり、さらに **mov** 出力および `omni_reference_task_type` タスクセレクターにも対応しました。2.0 standard モデルの約 1.5 倍のレートで実行されます。完全な差分については、以下の「技術仕様」をご覧ください。
</Info>

## 解像度とアスペクト比の詳細

解像度ティアは**短辺ではなく、ピクセル面積**を定義します。比率ごとの実際の出力寸法（公式値、テストで検証済み）は次のとおりです。

| 比率 | 480p | 720p | 1080p（2.5 / 標準のみ） |
| - | - | - | - |
| `16:9` | 864×496 | 1280×720 | 1920×1080 |
| `4:3` | 752×560 | 1112×834 | 1664×1248 |
| `1:1` | 640×640 | 960×960 | 1440×1440 |
| `3:4` | 560×752 | 834×1112 | 1248×1664 |
| `9:16` | 496×864 | 720×1280 | 1080×1920 |
| `21:9` | 992×432 | 1470×630 | 2206×946 |
| `adaptive` | 入力に基づいてモデルが上記のいずれかを選択 | 同じ | 同じ |

<Note>
  **2.5では、480p 16:9は864×496ではなく854×480です**（実測値）。864×496は2.0が生成する値で、2.5では面積がわずかに小さいため、同じ仕様でも必要なtokenはわずかに少なくなります。その他の測定したすべてのティアは両世代で一致します。480p 1:1 = 640×640、720p 16:9 = 1280×720、720p 21:9 = 1470×630、1080p 16:9 = 1920×1080です。

  **このファミリーのモデルはいずれも`4k`をサポートしていません**。`"resolution": "4k"`を送信すると同期400が返されます（課金対象外）。
</Note>

### アダプティブ動作の仕組み

1. **テキストから動画**：モデルがpromptから最適な比率を推測します
2. **最初+最後 / 最初のフレーム**：最初のフレーム画像の比率に合わせます（比率が一致しない画像は中央でクロップされます）
3. **マルチモーダル参照から動画**：promptの意図に従い、それ以外の場合は最初のメディア項目に従います（画像より動画が優先されます）
4. **動画編集 / 拡張（2.5）**：出力比率は、編集または拡張する入力動画に従います
5. 実際に使用された比率は、タスクレスポンスの`ratio`フィールドで返されます

<Warning>
  `ratio`が受け付けるのは、上記の7つの列挙値のみです。たとえば`"2:1"`を渡すと`InvalidParameter`エラーが返されます（検証済み）。また、サポート範囲外（2.5では4～30、2.0ファミリーでは4～15）の`duration`でも同様です。いずれも課金対象外です。

  **2.5では、3種類のタスクで`ratio: adaptive`も強制されます**：最初のフレーム / 最初+最後のフレームの生成、動画編集、動画拡張です。そこに具体的なアスペクト比を渡すと、`InvalidParameter.TaskTypeConstraint`が**送信時に**返されます（実測では、数分後に失敗するタスクではなく、同期400でした）。
</Warning>

## ベストプラクティス

<Steps>
  <Step title="出力要件に応じてモデルを選択する">
    **まず、2.5でしか利用できない機能が必要かどうかを確認します**：30秒クリップ、30枚の参照画像、単独の音声参照、mov出力、または明示的な動画編集／延長タスクタイプです。いずれかが必要な場合は、`doubao-seedance-2-5-260628`を選択します（標準モデルの約1.5倍の価格で、2.0ファミリーと同じグループです）。必要ない場合は、2.0ファミリーを使用します：**バッチ生成やコスト重視のワークロードにはLiteモデルを使用します** `doubao-seedance-2-0-mini-260615`（標準モデルの約半額で、生成速度が最も速く、720pまでに制限されます）。1080pまたは最高品質が必要な場合は標準モデルを使用します。`fast`はその中間的な選択肢です。
  </Step>

  <Step title="画像と動画はまずアセット IDに取り込む">
    リクエストにメディアが含まれる場合、タスク作成のレイテンシーは**そのメディアのアップロード**によって大きく左右されます。インライン Base64や大きな画像 URLを使用すると、送信にかかる時間が約1秒から数十秒に延びたり、読み取りタイムアウトが発生したりします。まずメディアを取り込み、`asset://`アセット IDを取得して、それを参照してください。これにより、リクエストボディは数十バイトに縮小され、タスク IDがすぐに返され、コンテンツチェックも取り込み時に実行されます。[アセット優先ワークフロー](/ja/api-capabilities/seedance2/asset-first-workflow)を参照してください。
  </Step>

  <Step title="クロッピングを避けるにはadaptiveを使用する">
    画像から動画への変換では、モデルが元画像の比率に合わせられるよう、デフォルトの`adaptive`を使用してください。`9:16`（縦向き）または`16:9`（横向き）に固定するのは、対象プラットフォームでその指定が必要な場合だけにしてください。
  </Step>

  <Step title="長さでコストを調整する">
    コストは長さに厳密に比例します。まず5秒のクリップでプロンプトを検証し、その後、長さを増やしてください（2.5は最大30秒で、5秒のクリップの6倍のコストがかかります）。**2.5では、必ず`duration`を明示的に指定してください**。デフォルトは`-1`なので、省略するとモデルが選択します。テストでは10秒が選択され、コストが2倍になりました。
  </Step>

  <Step title="不要な場合は音声をオフにする">
    `generate_audio`のデフォルト値はtrueです。自分で音楽を付ける予定の無音映像には、`false`を指定してください。
  </Step>

  <Step title="より自然なボイスオーバーのためにセリフを引用符で囲む">
    プロンプト内で話し言葉を二重引用符で囲んでください。モデルが自動的に一致する音声を生成します。
  </Step>

  <Step title="HTTPクライアントにAccept-Encoding: identityを追加する">
    ゲートウェイはレスポンスに`content-encoding: gzip`というラベルを付けますが、ボディは圧縮されていません。Python requestsなどの自動展開クライアントでは`ContentDecodingError`が発生します。`Accept-Encoding: identity`ヘッダーを追加するとこれを回避できます（curlには影響ありません）。
  </Step>

  <Step title="15～30秒ごとにポーリングし、すぐにダウンロードする">
    タスクは通常2～5分で完了します。`content.video_url`は24時間有効な署名付きリンクです。タスクが成功したら、できるだけ早くファイルを自分のストレージにコピーしてください。
  </Step>

  <Step title="return_last_frameでクリップを連結する">
    `return_last_frame: true`を設定すると、ウォーターマークのない最後のフレームのpngを取得できます。それを次のタスクの最初のフレームとして使用し、複数のクリップから連続した動画を作成します。
  </Step>
</Steps>

| - | - | - |
| `400` | `InvalidParameter`: 解像度／アスペクト比／長さが不正（例: fast または mini + 1080p、任意のモデル + 4k、2.5 + `duration: 31`） | メッセージに問題のあるパラメータが示されています。上記の表に従って修正してください。課金されません |
| `400` | `InvalidParameter.TaskTypeConstraint`（**2.5 のみ**）: パラメータがタスクタイプと競合しています | first/last-frame、編集、拡張タスクでは `ratio` を `adaptive` に設定し、編集タスクでは `duration` を `-1` に設定してください。課金されません |
| タスク `failed` + `InvalidParameter.TaskTypeMismatch` | **2.5 のみ**: 宣言された `omni_reference_task_type` が、モデルが prompt から推測したタスクタイプと一致していません | 意図したタスクに合わせて prompt を調整してください（編集: 追加／削除／置換、拡張: 拡張／継続）。または `auto` に切り替えてください |
| `401` | 無効な Token | Bearer Token を確認してください |
| `403` | コンテンツモデレーションによる拒否（実在する顔、ポリシー違反） | アセットまたは prompt を変更してください |
| `429` | レート制限、またはクォータ不足 | 指数バックオフを使用し、残高を確認してください |
| `5xx` | ゲートウェイ／バックエンドエラー | 1～2 回リトライしてください |
| タスク `failed` | 生成に失敗しました | タスクのエラーフィールドを確認し、必要に応じて別のシードでリトライしてください |
| タスク `expired` | `execution_expires_after` を超過しました（デフォルトは 48 時間） | 再送信してください |

<Info>
  **クライアントに関する推奨事項**:

  * create／poll 呼び出しでは、リクエストタイムアウトは 30～60 秒で十分です（待機はタスク側で行われます）
  * 15～30 秒ごとにポーリングし、全体の予算を **15 分以上** に設定してください（1080p／15 秒のタスクでは、さらに長くします）
  * 5xx とタイムアウトには **指数バックオフ** を適用してください（2 回リトライ）
  * トラブルシューティングのため、タスク `id` と `X-Shellapi-Request-Id` レスポンスヘッダー（ログで検索できる APIYI のリクエスト ID。`X-Request-Id` はプロバイダー側のもの）を記録してください
</Info>

## FAQ

<AccordionGroup>
  <Accordion title="画像や動画を含むリクエストでタスクIDが返るまでに時間がかかる、またはタイムアウトするのはなぜですか？">
    遅いのは動画生成ではなく、\*\*送信（提出）\*\*です。メディアデータはアップストリームのAPIYIに送信され、そこからVolcengineに転送されてデコードおよびバリデーションが行われます。タスクIDはこれらすべてが完了した後にのみ返されます。インラインのbase64や大きな画像URLを使用すると、このステップが約1秒から数十秒に延び、クライアントの60秒の読み取りタイムアウトでも不足する場合があります。生成自体には通常2〜5分かかりますが、これはプロバイダーの通常の処理速度であり、送信とは関係ありません。

    本質的な解決策は、**まずメディアを取り込んで`asset://`アセットIDとして参照すること**です。これにより、リクエストボディが数メガバイトから数十バイトに削減されます。レイテンシーの内訳、移行手順、タイムアウト後にタスクが作成されたかどうかの確認方法については、[アセットファーストワークフロー](/ja/api-capabilities/seedance2/asset-first-workflow)を参照してください。
  </Accordion>

  <Accordion title="Seedance 2.5と2.0のどちらを使用すべきですか？">
    **必要な機能に応じて選択してください。2.5が自動的にデフォルトとなるわけではありません。** 2.0標準モデルの約1.5倍のコストがかかり（720p/5秒：\$1.3721 対 \$0.9074）、これはVolcengine自身の定価の差を反映しています。

    **15秒を超える**クリップ（2.5は最大30秒）、**9枚を超える参照画像**（2.5は最大30枚）、**mov出力**、または送信時にパラメータエラーが検知される（`omni_reference_task_type`）**動画編集／動画延長**が必要な場合は、**2.5を選択してください**。また、2.0では音声と併せて画像や動画が必要ですが、2.5では**音声のみを参照とすること**も可能です。

    クリップが15秒未満の場合は、**2.0ファミリーをそのままお使いください**。標準モデルは**1080pにも対応**しており、同じフラッグシップ品質ティアに位置しています。コスト重視のバッチ制作には、標準単価の約半額で最も生成が速い`mini`を使用してください。2.0ファミリーが廃止される予定はありません。

    世代間でエンドポイント、認証、リクエスト形式は同一であり、**グループも同様**です。切り替えは1つのフィールド（`model`）を変更するだけです。
  </Accordion>

  <Accordion title="2.5は1080pに対応していますか？4Kはどうですか？">
    **1080pは対応しています**（実測値：1920×1080が正常にレンダリングされます）。**4Kは非対応です** — `"resolution": "4k"`を送信すると同期的に400が返されます（課金はされません）。

    見落としやすい違いとして、480pと720pはH.264（avc1）を使用するのに対し、**2.5では1080pをH.265（hvc1）としてエンコードします**。H.265ファイルは軽量ですが、古いプレーヤーや一部のブラウザ、特定の編集ソフトではH.264ほど安定して処理できない場合があります。1080pを配信する前に、後続のパイプラインでデコード可能か確認してください。
  </Accordion>

  <Accordion title="2.5で動画編集や動画延長を実行するにはどうすればよいですか？">
    どちらも「全機能参照（omni reference）」タスクであり、`content`内の参照動画とpromptで表現された意図によってトリガーされます。エラーを早期に検知できるよう、明示的に`omni_reference_task_type`を渡してください：

    * **動画編集**：`omni_reference_task_type: "edit"`、少なくとも1つの`role: "reference_video"`、**`ratio`は`adaptive`、`duration`は`-1`である必要があり**、ソース動画は4〜30秒である必要があります。promptには編集用の動詞（add、remove、delete、change、replaceなど）を含める必要があります。出力のアスペクト比と再生時間は入力動画に従います — そして**再生時間は小数になる場合があります**（実測では16.709秒が返されました）。
    * **動画延長**：`omni_reference_task_type: "extend"`。こちらも参照動画を含め、**`ratio`を`adaptive`に設定**します。promptには延長用の動詞（extend、continueなど）を含める必要があります。

    prompt内では、渡した順序に従って位置指定（`@video1`、`@image1`）でアセットを参照してください。無効なパラメータを指定すると、数分後にタスクが失敗するのではなく、**送信時に400**（`InvalidParameter.TaskTypeConstraint`）が返されます。
  </Accordion>

  <Accordion title="2.5のmov出力フォーマットは何のためにありますか？">
    `"output_format": "mov"`を指定すると、色と輝度の忠実度が高いQuickTimeコンテナ（H.264 + yuv444pクロマ + PCM音声）が返されます。カラーグレーディング、キーイング、コンポジットに適しており、動画編集／動画延長作業の入力および出力の両方として公式に推奨されています。デフォルトは`mp4`で、最も幅広い互換性を持っています。

    **movはプロ向けのコーデックを使用しているため、一部のプレーヤーでは開けないことに注意してください**（macOS上のVLC、mpv、ffplay、IINAはすべて対応しています）。Webやモバイルで直接配信する場合は、デフォルトのmp4のままにしてください。
  </Accordion>

  <Accordion title="「no available channel for this model」というエラーが表示されるのはなぜですか？">
    これはSeedanceで最も一般的なエラーであり、原因の9割はTokenで有効になっているグループが正しくないことです。エラーメッセージには、現在設定されているグループ名が表示されます。例：

    ```
    Current group SeeDance2 has no available channels
    for model doubao-seedance-2-5-260628
    ```

    モデルを対応するグループに一致させ、Token設定で有効にしてください：

    | 呼び出すモデル | 有効にするグループ |
    | - | - |
    | `doubao-seedance-2-5-260628` | `SeeDance2` |
    | `doubao-seedance-2-0-260128` | `SeeDance2` |
    | `doubao-seedance-2-0-fast-260128` | `SeeDance2` |
    | `doubao-seedance-2-0-mini-260615` | `SeeDance2` |

    `SeeDance2`を有効にした1つのKeyで4つのモデルすべてにアクセスできます（既存の`SD2Fast`／`SD2Mini` Tokenも引き続き、同じ価格で単一モデルを呼び出すことができます）。また、課金モデルは従量課金優先（Pay-as-you-go Priority）または従量課金（Pay-as-you-go）である必要があります — **リクエスト単位課金（Pay-per-request）のTokenはルーティングできません**。
  </Accordion>

  <Accordion title="Pythonのrequestsがgzipエラーを発生させる／不完全な非JSONボディを返す">
    ゲートウェイの`content-encoding: gzip`ヘッダーが実際のボディエンコーディングと一致していません。症状としては、`ContentDecodingError`、切り捨てられた非JSONボディ（例：先頭の`{"`が失われて`id":"cgt-xxx"}`のみが取得される）、または断続的な400エラーなどがあります。リクエストヘッダーに`"Accept-Encoding": "identity"`を追加してください。curlやブラウザのfetchは影響を受けません。
  </Accordion>

  <Accordion title="動画に音声が含まれているのはなぜですか？消音にするにはどうすればよいですか？">
    `generate_audio`はデフォルトで`true`に設定されています（検証済み）：モデルが音声、効果音、BGMを自動的に追加します。無音で出力するには、明示的に`"generate_audio": false`を渡してください。
  </Accordion>

  <Accordion title="動画のURLはどこにありますか？なぜアクセスできなくなるのですか？">
    成功時、URLはポーリングレスポンスの`content.video_url`に格納されます（**トップレベルではありません**）。これは約24時間有効な署名付きリンクです — すぐにダウンロードして再ホストしてください。task\_id自体は7日間照会可能です。
  </Accordion>

  <Accordion title="成功時のステータス値は何ですか？">
    ステートマシンは`queued → running → succeeded / failed / expired`です。成功ステータスは`completed`ではなく\*\*`succeeded`\*\*です — 他の動画APIから移行する際によくある間違いです。
  </Accordion>

  <Accordion title="画像から動画への生成（image-to-video）で実在の人物の写真をアップロードできますか？">
    いいえ。Seedance 2.5も2.0ファミリーも、実在の人物の顔を含む参照画像／動画を受け付けません（アップストリームのコンテンツセーフティによる制限）。代替案として、過去30日以内にSeedanceモデルで生成された顔を含む出力を再利用する、プラットフォームのプリセット仮想アバター（`asset://` ID）を使用する、またはライセンス取得済みの顔アセットを使用する方法があります。
  </Accordion>

  <Accordion title="アセットライブラリに追加料金はかかりますか？">
    いいえ。仮想アバターの取り込み、実在人物の検証、およびその他のプライベートアセットライブラリ機能は、**APIYIのSeedance 2.0 APIでは無料であり、年会費も不要です**。公式には、この機能は個別購入アドオンとして提供されており、フレームワーク契約のない顧客向けには年間数十万元規模の契約となっています（Volcengineからも直接販売されています）。APIYIでは長期的なユーザーを重視しているため、そのコストはすでにAPI価格に含まれています。通常の業務量でSD2 APIをご利用いただくお客様には、追加料金は一切発生しません。使用方法については、[アセットライブラリ](/ja/api-capabilities/seedance2/asset-library)を参照してください。
  </Accordion>

  <Accordion title="失敗または拒否されたリクエストに対しても課金されますか？">
    パラメータの不正による拒否（HTTP 400）は**課金されません**（検証済み）。課金は送信時に事前引き落としされ、完了時に精算されるため、残高が一時的に変動します — 呼び出しログと照合してください。
  </Accordion>

  <Accordion title="token消費量はどのように見積もればよいですか？縦向きのほうが高いですか？">
    `tokens ≈ duration(s) × width × height × 24 / 1024`（0.1%以内の精度で検証済み）。同じティア内のすべてのアスペクト比は同一のピクセル面積を持ちます（720pの16:9と9:16はいずれも5秒あたり108,900 tokens） — **横向き、縦向き、正方形のいずれも料金は同一です**。
  </Accordion>

  <Accordion title="2.0ファミリー内での選択 — standard vs fast vs mini？">
    価格と速度の関係は mini \< fast \< standard となります（プラットフォーム上の公称720p/5秒：約¥3.16 / ¥5.08 / ¥6.35）。**バッチ制作やコスト重視のワークロードには mini を選択してください** — 標準モデルの約半額で、最も高速に生成されます（実測 2026-07：720p\@5秒で約1.5〜2.5分）。最大限のディテールを求める場合は standard、バランスを重視する場合は fast を選択してください。mini と fast の上限はいずれも 720p であり、1080p をリクエストすると400パラメータエラーが返されます（課金はされません）。

    **1080pのみが必要な場合、2.0 standard モデルで既に対応しています** — そのためだけにアップグレードする必要はありません。30秒のクリップ、9枚を超える参照画像、mov出力、または動画編集／動画延長が必要な場合は、**2.5**を選択してください（standard モデルの約1.5倍の価格、2.0ファミリーと同じグループです）。
  </Accordion>

  <Accordion title="duration: -1 はどのような動作をしますか？">
    モデルが自動的に長さを決定し（2.5では4〜30秒、2.0ファミリーでは4〜15秒）、実際の出力時間に基づいて課金されます。最終的な長さはタスクの`duration`フィールドに返されます。

    **2.5では`-1`がデフォルトである点に注意してください**（2.0ファミリーのデフォルトは5秒です）。そのため、`duration`を省略するとモデルによる自動決定が適用されます。持続時間を指定しない2.5の実測リクエストでは10秒のクリップが返され、5秒のちょうど2倍のコストとなりました。コストの予測可能性を重視する場合は、明示的に`duration`を渡してください。
  </Accordion>

  <Accordion title="1秒未満の指定に frames パラメータは対応していますか？">
    いいえ。`frames`および`camera_fixed`はSeedance 1.xのパラメータであり、**Seedance 2.5および2.0シリーズのいずれも対応していません**。代わりに整数秒単位の`duration`を使用してください。
  </Accordion>

  <Accordion title="最初＋最後のフレーム、最初のフレーム、参照画像を混在させることはできますか？">
    いいえ — これらは**互いに排他的な**3つのモードです：最初＋最後（必須の`first_frame`/`last_frame`ロールを持つ2枚の画像）、最初のフレーム（1枚の画像）、マルチモーダル参照動画生成（画像ロール`reference_image`）。「最初／最後のフレーム＋参照」に近い処理を行うには、参照モードを使用してprompt内でフレームを指定してください。

    参照の上限は世代によって異なります：**2.5では画像30枚＋動画10本＋音声10本に対応し、音声のみの指定も可能です**。2.0ファミリーでは画像9枚＋動画3本＋音声3本に対応し、音声と併せて少なくとも1枚の画像または1本の動画が必要です。
  </Accordion>

  <Accordion title="同時実行数の制限やキュー待ちはありますか？">
    `SeeDance2`グループには十分な同時実行数があり、キュー待ちは発生しません（弊社のテストでは15件の同時タスクがすべて即座に実行されました）。より大規模で継続的なワークロードについては、営業担当にお問い合わせください。
  </Accordion>

  <Accordion title="promptの制限事項はありますか？">
    promptは約500文字の中国語または約1,000単語の英語未満に抑えてください。長すぎるpromptはディテールの精度を低下させます。サポートされている言語：中国語、英語、日本語、スペイン語、ポルトガル語、インドネシア語。「被写体＋動作＋カメラワーク＋照明／スタイル」の形式で記述してください。
  </Accordion>
</AccordionGroup>
