# Seedream 画像生成と編集

> ByteDance BytePlus ModelArk Seedream 画像生成モデルの完全ガイド — 1つの統合で 5.0 Flash / 5.0 Pro / 5.0 / 4.5 / 4.0 に対応、5.0 Flash は1リクエストあたり $0.018、約15〜20秒で生成、4K出力、複数画像合成、バッチシーケンス生成、参照画像編集をすべて単一のエンドポイントで実現します。

## 概要

**Seedream** は、ByteDance BytePlus ModelArk のフラグシップ画像生成モデルシリーズであり、**生成と編集を統合したアーキテクチャ**を備えています。Text-to-Image、単一画像編集、複数画像融合、そしてバッチシーケンス生成のすべてが、パラメータの違いのみで単一の `/v1/images/generations` エンドポイントを通じて実行されます。APIYI は BytePlus と戦略的パートナーシップを結んでおり、提供中のすべてのバージョンを初日から統合しています。

<Note>
  **🎨 ハイライト**: 新登場の **5.0 Flash** は **1リクエストあたり \$0.018** で、約15〜20秒で返答します。大量のアセット制作向けに強力なレイアウトとテキストレンダリングを備えています。シリーズ全体で単一の統合 + 4K出力 + 融合用の参照画像最大10枚 + バッチ（入力 + 出力 ≤ 15） + 業界をリードするテキストレンダリングを共有しています。**Eコマースのメインビジュアル、広告ポスター、商品写真、コンテンツ制作に最適です** — 高品質さと可読性のあるテキストが重視されるあらゆる場面で活躍します。
</Note>

<Info>
  すべての画像 API は**同期型**です — ポーリング用のタスクIDは存在せず、クライアントが切断された場合、リクエストに対して課金が発生したまま結果が失われます。このモデルには十分なタイムアウト値を設定してください。詳細については [画像 API の基本とベストプラクティス](/ja/api-capabilities/image-api-best-practices) を参照してください。
</Info>

<Note>
  **これはどの Seedream ですか？** APIYI は、中国本土の Doubao / Volcengine 版ではなく、**公式の海外 BytePlus（国際）リソース**上で Seedream を提供しています。国際版は国内版と比較してコンテンツモデレーションポリシーが比較的緩やかであり、より高い創造的自由度が得られます — これは本プラットフォームの大きな強みですが、**モデレーションが完全に存在しないという意味ではありません**。BytePlus は引き続き組み込みのコンテンツ安全チェックを実行しており、規約に違反する prompt や参照画像は 400/403 で拒絶されます（拒絶されたリクエストには課金されません）。コンプライアンスを遵守してご利用ください。
</Note>

## AIエージェントに統合を任せる

<Note>
  Codex / Claude Code / Cursorで開発している場合は、以下のpromptをコピーしてエージェントに渡してください。まず本ページのプレーンテキスト版を取得し（任意のドキュメントURLの末尾に`.md`を追加）、その後プロジェクト独自のスタックでコードを記述します。タイムアウト、URL結果の即時再ホスティング、multipartではなくURL配列による編集、`seedream-5-0-pro`が拒否するパラメータなどは、すでに要件に組み込まれています。
</Note>

<Prompt description="コーディングエージェントにSeedreamのテキストからの画像生成および画像編集を統合またはトラブルシューティングさせます。Codex、Claude Code、Cursorなどのツールにコピー＆ペーストしてください。" icon="bot" actions={["copy"]}>
  このプロジェクトでSeedreamのテキストからの画像生成および画像編集を統合 / トラブルシューティングしてください。

  コードに手を付ける前にドキュメントを読んでください：本ページのプレーンテキスト版を取得するには、[https://docs.apiyi.com/en/api-capabilities/seedream-image/overview.md](https://docs.apiyi.com/en/api-capabilities/seedream-image/overview.md) をフェッチしてください。より詳細なパラメータについては、同様にテキストからの画像生成および画像編集ページに`.md`を追加してください。

  要件：

  1. タイムアウト：モデルごとにクライアントのタイムアウトを段階的に設定してください — 4.xシリーズおよび`seedream-5-0-flash`は60秒から開始し（Flashは参照画像10枚で約30秒かかります）、`seedream-5-0`は120秒に引き上げ、**画像1枚あたり約2分を要する`seedream-5-0-pro`は240秒に引き上げてください**。画像APIは同期型です — タスクIDが存在しないため、クライアントが切断されると、リクエストに対して課金されたまま結果が失われます。リバースプロキシ、ゲートウェイ、サーバーレス実行の制限時間もすべて広げる必要があります。

  2. レスポンスの処理：デフォルトは`url`（約24時間で期限切れになるBytePlus TOSの一時的な署名付きリンク）であり、プレーンなbase64（`data:`プレフィックスなし）を取得するために`response_format`を`b64_json`に設定して渡すことも可能です。URLを受け取る場合は、**直ちにダウンロードして独自のオブジェクトストレージに再ホスティングしてください**。アップストリームのリンクを長期的なアドレスとしてデータベースに保存してはいけません。base64を受け取る場合は、それをレンダリングしてディスクへの保存アクションを提供してください。デフォルトに頼るのではなく、明示的に`response_format`を送信してください。

  3. 参照画像のアップロード（**他の画像モデルとの最大の違い**）：Seedreamは生成と編集の統合アーキテクチャを採用しているため、**`/v1/images/edits`エンドポイントは存在しません** — 生成と編集の両方が`application/json`として`/v1/images/generations`にアクセスします。参照画像は`image`フィールドに入り、これはmultipartのファイルアップロードや重複した`image[]`フィールドではなく、**URL配列**です。配列のエントリには画像URLまたは`data:image/jpeg;base64,...`形式のデータURLを使用でき、両者を混在させることも可能です。最大10枚までの参照画像が許可され、**入力画像と出力画像の合計は15枚を超えてはなりません**。`mask`フィールドは存在しません。大容量のローカルファイルの場合は、まず独自のオブジェクトストレージにアップロードしてそのURLを渡してください。データURLを使用する場合は、最初に圧縮してください — 1.5MBを超えるファイルのみを処理し、アスペクト比を維持しながら長辺を2048pxに縮小し（小さい画像をアップスケールしないでください）、品質0.9で再エンコードし、複数画像のリクエストでは合計サイズを6MB未満に抑えてください。1枚の画像の圧縮に失敗した場合は、オリジナルにフォールバックして続行してください。

  4. パラメータのレッドライン：このモデルには\*\*`quality`パラメータがありません\*\* — 忠実度はモデルのバージョンと`size`によって決まります。`size`は階層（`1K` / `2K` / `3K` / `4K`、デフォルトは`2K`）または正確なピクセル数のいずれかを受け入れます。`seedream-5-0-pro`は2048×2048の約419万ピクセルで上限となり、`seedream-5-0-flash`は`1K` / `1.5K` / `2K`のみを提供し、正確なピクセル数の上限は約462万ピクセルであることに注意してください。**いずれにも3Kまたは4Kの階層はありません**。`n`は**警告なく無視されます**（1枚の画像のみが返され、1枚分の料金が請求されます）ので、複数の出力には`sequential_image_generation`を使用してください。`seed`は4.xまたは5.xには影響を与えません。商用利用の場合は、デフォルト値がバージョンによって異なるため（フィールドが省略された場合、`seedream-5-0-flash`は「AI generated」の透かしを追加します）、**常に`watermark`をfalseに設定して送信してください**。`output_format`は5.0シリーズでのみpngをサポートし、4.5および4.0はアルファチャンネルなしのjpegのみを出力します。`seedream-5-0-flash`は直接生成時にアルファチャンネルなしのpngを返します。透明なアセットには`layer_decomposition: true`を使用してください（出力画像ごとに課金され、多くの場合1ダース以上になります）。

  5. `seedream-5-0-pro`および`seedream-5-0-flash`に対する2つの厳格なレッドライン：**`sequential_image_generation`は一切送信しないでください — `"disabled"`を含むいかなる値でも400が返されます** — そして\*\*`stream`も送信しないでください\*\*（同様に400となります）。5.0または4.xからコードを移植する場合は、両方のフィールドを完全に削除してください。

  6. キーは`APIYI_API_KEY`環境変数から読み取り、ベースURLとして [https://api.apiyi.com/v1](https://api.apiyi.com/v1) を使用してください。決してハードコードしたり、gitにコミットしたりしないでください。OpenAI SDK経由で呼び出す場合、`image`、`sequential_image_generation`、`watermark`、`output_format`パラメータは転送されるように`extra_body`内に含める必要があります。

  7. 完了したら、テキストからの画像生成呼び出しと画像編集呼び出しを実際に1回ずつ実行し、結果とそれら2回の呼び出しにかかった費用を示してください。
</Prompt>

## APIYIのSeedreamが選ばれる理由

BytePlus ModelArk公式チャネルのドロップインリプレイスとして機能し、**安定性**、**コスト**、**統合**の3つの軸で本番環境向けに最適化されています：

<CardGroup cols={2}>
  <Card title="戦略的パートナーシップ・安定したリソース" icon="shield-check">
    BytePlus ModelArkへの公認直接接続です。リクエストとレスポンスの挙動はアップストリームと同一であり、**プロトコルのバイパスはありません**。本番環境でも安全にご利用いただけます。
  </Card>

  <Card title="無制限の同時実行数・エンタープライズ対応" icon="infinity">
    バッチ生成、複数画像合成、シーケンス生成向けに線形スケーリングが可能で、Tier形式のアカウント制限はありません。**デフォルトで500 RPM**に対応しており、より高いクォータが必要な場合は営業担当までお問い合わせください。
  </Card>

  <Card title="同等価格 ＋ チャージで最大20%オフ" icon="percent">
    デフォルトの単価はBytePlusの公式価格と同等です。[チャージボーナス](/ja/faq/recharge-promotions)と組み合わせることで、実質価格は定価の**80%にまで**下がります（5.0 Flashの場合、公式レートを約9%〜17%下回ります）。
  </Card>

  <Card title="グローバルでフリクションレスなアクセス" icon="globe">
    **海外サーバーやプロキシは不要です**。中国本土のデータセンター、家庭用ネットワーク、海外ノードから`api.apiyi.com`へ直接接続できます。BytePlusの`ap-southeast-1` / `eu-west-1`リージョン向けにルーティングを設定する必要はありません。
  </Card>

  <Card title="OpenAI互換・コード変更不要" icon="plug">
    パス`/v1/images/generations`はOpenAIと同一です。OpenAI SDKの`base_url`をAPIYIに向けるだけで、そのままAPIを呼び出せます。拡張パラメータ（`image` / `sequential_image_generation`など）は`extra_body`経由で渡します。なお、OpenAIの`n`パラメータはアップストリームでサポートされていません（暗黙的に無視され、画像は1枚のみ出力されます）。複数画像を出力する場合は`sequential_image_generation`を使用してください。
  </Card>

  <Card title="プロフェッショナルサポート・エンタープライズコンシェルジュ" icon="handshake">
    複数画像合成、テキストレンダリング、アセットの一括バッチ生成など、画像生成ユースケースにおける深い専門知識を備えています。PoCから本番運用へのロールアウトまでエンドツーエンドでサポートします。
  </Card>
</CardGroup>

## 生成時間の比較

バージョンごとの単一リクエストのレイテンシ測定値（2026-07測定、5.0 Flashは2026-09-24測定、UTC+8。リクエストから完全なレスポンスまでの実測時間 — リクエストごとの通常の変動が見込まれます）：

| シナリオ | seedream-4-0 | seedream-4-5 | seedream-5-0 | seedream-5-0-pro | seedream-5-0-flash |
| - | - | - | - | - | - |
| テキストから画像生成 (1K/2K) | 7-11s | 8-13s | 29-34s | **110-130s** | 14-20s |
| テキストから画像生成（最高解像度） | \~15s (4K) | \~18s (4K) | \~37s (3K) | \~134s（WxH 2720×1530、最大サイズ） | \~19s（WxH 2688×1712、最大サイズ） |
| 編集 / 複数画像合成 | \~11s | 17-21s | 38-40s | **115-132s** | \~16s（1〜3画像） / \~28s（10画像） |
| バッチシーケンス（2画像、編集 + 自動） | — | \~36s | — | —（非対応） | —（非対応） |
| **推奨クライアントタイムアウト** | ≥ 60s | ≥ 60s | ≥ 120s | **≥ 240s** | ≥ 60s |

<Warning>
  **`seedream-5-0-pro` は一貫して1画像あたり約2分かかります**（例外なくすべての実行で110〜132sを測定）。これは深い推論を行う画像モデルとしての想定された挙動であり、不具合ではありません。pro を採用する前に、プロダクト側でこのレイテンシを許容できるかご確認ください。インタラクティブなフロー（ユーザーが画面の前で待機する処理）には適していません。代わりに 5.0-lite（約30s）をご利用ください。pro は、画質と指示への追従性が最も重視されるオフラインのバッチ生成に適しています。
</Warning>

## 主要パラメーターの詳細

### `size`（出力サイズ）

2つの値系統があります — いずれかを選択してください：

**プリセットティア**（モデルがアスペクト比を決定）：

| ティア | 概算ピクセル数 | 対応モデル |
| - | - | - |
| `1K` | \~1024×1024 | 4.0 / 5.0-pro / 5.0-flash |
| `1.5K` | \~1536×1536 | 5.0-flash のみ |
| `2K` | \~2048×2048（デフォルト） | 全バージョン |
| `3K` | \~3072×3072 | 5.0 のみ |
| `4K` | \~4096×4096 | 4.5 / 4.0 |

**正確なピクセル数**（カスタム）：

* 総ピクセル数 ∈ \[1280×720, 4096×4096]
* アスペクト比 ∈ \[1/16, 16]
* デフォルト：`2048x2048`

**有効な例**：`1920x1080`（FullHD）、`3840x2160`（横向き4K）、`1080x1920`（スマートフォンの縦向き）、`2560x1440`（横向き2K）
**無効な例**：`5000x5000`（上限超過）、`100x1600`（アスペクト比が1/16未満）

<Warning>
  総ピクセル数が 4096×4096 を超えるサイズは 400 を返します。極端なアスペクト比（1/16 または 16 に近い値）は不自然に引き伸ばされる可能性があるため、プリセットまたは一般的な 16:9 / 9:16 / 1:1 の使用をおすすめします。

  **5.0 シリーズのモデルは、4.x とは異なる正確なピクセル数の範囲を使用します**（下限が高く、上限が低くなります）。範囲外のサイズは 400 を返し、エラーメッセージに有効な範囲が含まれます。実測の参考値：5.0-lite の下限は約 2560×1440 です。**5.0-pro は総ピクセル数の上限が 4.19M です（最大 2048×2048。16:9 では長辺が 2720×1530 ≈ 2.7K に達し、動作確認済み）— 3K/4K プリセットはありません**。**5.0-flash は 921,600〜4,624,220 の総ピクセル数（約 0.92M〜4.62M）、最大 16:1 の辺比に対応しており、こちらも 3K/4K プリセットはありません**。プリセットを使用するとモデルがコンテンツからアスペクト比を選択するため、固定の比率が必要な場合は正確なピクセル数を指定してください。
</Warning>

### `image` および `sequential_image_generation`（モード切り替え）

`/v1/images/generations` エンドポイントは、テキストからの画像生成と編集／融合の両方をカバーしています。2つのパラメーターを組み合わせてモードを選択します：

| モード | `image` | `sequential_image_generation` | 備考 |
| - | - | - | - |
| 純粋なテキストからの画像生成 | 省略 | 省略または `"disabled"` | 出力1件 |
| 単一画像の編集 | `["url1"]` | `"disabled"` | 1枚の参照画像に基づく編集 |
| 複数画像の融合 | `["url1", "url2", ...]` | `"disabled"` | 最大10枚の参照画像。「image 1 / image 2」のように参照 |
| バッチシーケンス | 任意 | `"auto"` + `sequential_image_generation_options.max_images` | N件の一貫した出力、**N ≤ max\_images** かつ **入力 + 出力 ≤ 15** |

<Warning>
  **`seedream-5-0-pro` および `seedream-5-0-flash` は `sequential_image_generation` パラメーターを受け付けません** — いずれの値（`"disabled"` を含む）を渡しても 400 が返されます。これら2つのモデルで編集／融合を行う場合は、`image` のみを渡し、このパラメーターは完全に省略してください。`stream` についても同様です。
</Warning>

完全なコード例については、[テキストからの画像生成](/ja/api-capabilities/seedream-image/text-to-image) および [画像編集](/ja/api-capabilities/seedream-image/image-edit) を参照してください。

## エラーコードと再試行

| ステータス | 意味 | 推奨対応 |
| - | - | - |
| `400` | 無効なパラメータ（サイズが範囲外、`image` array > 10、未対応の tier） | 使用中のバージョンでサポートされている tier を確認してください |
| `401` | 無効な token | Bearer Token を確認してください |
| `403` | コンテンツモデレーションによりブロックされました | prompt を調整するか、参照画像を差し替えてください |
| `429` | rate limit（デフォルト 500 RPM）または残高不足 | 指数バックオフを適用してください。より高い RPM が必要な場合は営業にお問い合わせください |
| `5xx` | ゲートウェイ / upstream エラー | 1〜2回再試行してください |
| Timeout | 長い応答時間のリクエスト | クライアントタイムアウトは ≥ **60s**（バッチシーケンスまたは 4K + hd では 60s に達する場合があります） |

<Info>
  **クライアント向けの推奨事項**:

  * **60秒**のリクエストタイムアウトから始めてください（バッチシーケンスまたは 4K + hd では 1分かかる場合があります）
  * 5xx とタイムアウトには **指数バックオフ** を適用してください（推奨再試行回数は 2回です）
  * サポートチケット用に `x-request-id` レスポンスヘッダーを記録してください
</Info>

  <Accordion title="5.0 Flash / 5.0 Pro / 5.0 / 4.5 / 4.0 — どれを選ぶべきですか？">

    完全な比較については[過去のバージョン](/ja/api-capabilities/seedream-image/historical-versions)をご覧ください。
  </Accordion>

  <Accordion title="なぜ画像編集でも generations エンドポイントを使用するのですか？">
    Seedream は生成と編集の統合アーキテクチャを採用しており、**個別の `/v1/images/edits` エンドポイントはありません**。OpenAI の gpt-image-2（`/v1/images/edits` へのマルチパートアップロード）とは異なり、Seedream は `application/json` を使用し、`image` フィールドに画像 **URL を配列として** 渡します。

    メリット：プロトコルの一貫性、パラメータの再利用、容易なモード切り替え。詳細は[画像編集](/ja/api-capabilities/seedream-image/image-edit)をご覧ください。
  </Accordion>

  <Accordion title="image フィールドは base64 を受け入れますか？">
    **はい**（テストにより検証済みです）。データ URI を使用します：`data:image/<format>;base64,<base64 string>`（`<format>` は小文字、例：`data:image/jpeg;base64,...`）。URL と base64 のエントリは同じ配列内で混在させることができます。**可能な限り公開 URL を優先してください**：URL は APIYI ゲートウェイを経由せずに BytePlus がシンガポールから直接ダウンロードしますが、base64 のボディは国境を越えて全体をアップロードする必要があります。回線が遅い場合、20 MB を超えるボディはプロバイダーの 600 秒のリクエストボディタイムアウトに達する可能性があり、ゲートウェイが base64 を URL に変換することはありません。画像編集ページの上部にある警告をご覧ください。
  </Accordion>

  <Accordion title="複数画像の融合の制限は？バッチシーケンスの制限は？">
    * **複数画像の融合**（`image` 配列）：4.5 / 5.0-pro / 5.0-flash は明示的に最大 10 個までサポートしています（当社のテストでは 5.0-flash で 11 個目を指定すると 400 が返されました）。5.0 / 4.0 も複数画像をサポートしていますが、明示的な上限はドキュメントに記載されていません。
    * **バッチシーケンス**（`max_images`）：グローバルルールである **入力参照 + 出力 ≤ 15** に制限されます。融合とシーケンスを組み合わせる場合は、合計をカウントしてください。なお、**5.0-pro および 5.0-flash はバッチシーケンスをサポートしていません**（`sequential_image_generation` を渡すと 400 が返されます）。
  </Accordion>

  <Accordion title="b64_json には data:image プレフィックスが必要ですか？">
    `response_format` によって異なります：

    * `response_format: "url"`（デフォルト）→ `data[0].url` は一時的な署名付き URL であり、`<img src=...>` で直接レンダリングできます
    * `response_format: "b64_json"` → `data[0].b64_json` は**プレーンな base64 文字列**です（`data:image/...;base64,` プレフィックスなし）。デコードしてディスクに書き込むか、ブラウザでレンダリングするために手動でプレフィックスを先頭に付加してください。
  </Accordion>

  <Accordion title="ストリーミング出力はサポートされていますか？">
    `stream: true` 経由で 5.0 / 4.5 / 4.0 でサポートされています。ストリーミングは、長い prompt や高解像度画像に特に有用であり、フロントエンドで部分的な結果を段階的にレンダリングできます。**`seedream-5-0-pro` および `seedream-5-0-flash` はストリーミングをサポートしていません** — `stream` を渡すと 400 が返されます。
  </Accordion>

  <Accordion title="レート制限は？">
    **デフォルトは毎分 500 画像**（Max Images per Minute）で、バージョン共通です。より高いクォータが必要な場合は営業担当までお問い合わせください。
  </Accordion>

  <Accordion title="失敗したリクエストは課金されますか？">
    **いいえ**。BytePlus にはモデレーション機能が組み込まれています。モデレーションによる拒否やパラメータエラーは `400` / `403` を返し、**課金されません**。課金が発生しないその他のエラー：`401`（無効な token）、`429`（レート制限）。**生成が成功した場合（有効なレスポンスを伴う `200`）のみ課金されます**。
  </Accordion>

  <Accordion title="公式の OpenAI SDK を使用できますか？">
    はい、コードを変更することなく使用できます。`base_url` を `https://api.apiyi.com/v1` に向け、`extra_body` 経由で拡張パラメータ（`image` / `sequential_image_generation` / `watermark` など）を渡します：

    ```python theme={null}
    from openai import OpenAI

    client = OpenAI(api_key="sk-your-key", base_url="https://api.apiyi.com/v1")
    resp = client.images.generate(
        model="seedream-5-0-260128",
        prompt="...",
        size="2K",
        extra_body={
            "image": ["https://.../ref.png"],
            "sequential_image_generation": "disabled",
            "watermark": False,
        }
    )
    ```
  </Accordion>

  <Accordion title="生成された画像の所有権は誰に帰属しますか？">
    生成された画像は商用および非商用で利用できます。詳細は BytePlus の利用規約をご覧ください。
  </Accordion>

  <Accordion title="透明な背景はサポートされていますか？">
    `seedream-5-0` / `seedream-5-0-pro` は `png` 出力をサポートしており、prompt で指示した場合（「transparent background, alpha channel」）に透明な背景を生成できます。`seedream-5-0-flash` は透明な背景を要求してもアルファチャンネルを返しません。背景ベースと複数の透明レイヤーを取得するには `layer_decomposition: true` を使用してください（出力画像ごとに課金）。詳細は[画像編集](/ja/api-capabilities/seedream-image/image-edit)をご覧ください。`seedream-4-5` / `4-0` は `jpeg` のみを出力し、**透過をサポートしていません** — ご自身で背景を削除する後処理を行ってください。
  </Accordion>

  <Accordion title="実行中の生成をキャンセルできますか？">
    **いいえ**。`/v1/images/generations` は同期処理です。リクエストは一度送信されると、完了するまで実行されます。クライアントの接続が切断されても、サーバー側では処理が完了し、課金されます。クライアント側のタイムアウトを設定し、切断によってコストを抑えられるとは想定しないようにしてください。
  </Accordion>
</AccordionGroup>
