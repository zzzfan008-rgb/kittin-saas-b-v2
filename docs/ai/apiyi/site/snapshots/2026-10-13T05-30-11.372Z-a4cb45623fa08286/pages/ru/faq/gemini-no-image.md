# Почему API Gemini для генерации изображений возвращает NO_IMAGE?

> Узнайте, почему Gemini возвращает NO_IMAGE, а также как улучшить промпты для изображений и устранить неполадки в запросе.

## Краткий ответ

Когда API возвращает `finishReason: NO_IMAGE`, а `parts` имеет значение `null`, модель обычно обрабатывает запрос, но не возвращает содержимое изображения.

Это не обязательно означает, что prompt вызвал срабатывание блокировки безопасности контента. Такие prompt, как «Что такое GEO?» или «Объясни эту концепцию», больше похожи на текстовые вопросы. Модель может не определить однозначно, что пользователю действительно нужно изображение, поэтому возвращает `NO_IMAGE`.

Явно укажите намерение сгенерировать изображение в начале prompt, а затем опишите объект, композицию, стиль и требования к результату.

Еще одна частая причина — **prompt, в котором содержится просьба написать текст**, например «подготовь предложение по дизайну» или «сделай анализ подробным». Когда вызов допускает только вывод изображений, подобный запрос время от времени возвращает `NO_IMAGE`, поэтому один и тот же запрос может завершиться ошибкой, а затем выполниться успешно. См. раздел «Prompt запрашивает текстовый ответ» ниже.

<Note>
  Если в ответе отсутствует `candidates`, но содержится `promptFeedback.blockReason` (например, `OTHER`), это другая проблема: входные данные были заблокированы провайдером до начала генерации. См. [Почему Gemini Image возвращает blockReason: OTHER?](/ru/faq/gemini-image-input-blocked)
</Note>

## Почему возникает NO\_IMAGE?

### 1. prompt выглядит как текстовый вопрос

Например:

```text theme={null}
What is GEO?

GEO helps a company gain visibility in large-model AI systems...
```

Это объясняет концепцию, но явно не указывает:

* какой тип изображения требуется сгенерировать;
* какие элементы должны присутствовать на изображении;
* как должна быть скомпонована информация;
* должен ли ответ содержать только изображение.

Даже когда запрос содержит слова «generate an image», модель все равно может интерпретировать запрос целиком как текстовое объяснение.

### 2. Намерение сгенерировать изображение выражено недостаточно конкретно

Некоторые инструменты платформ автоматически добавляют в начало инструкции вроде «Generate an image:». Однако при прямом вызове API запрос может пересылаться напрямую без автоматического добавления полной инструкции по генерации изображений.

Вместо того чтобы писать только:

```text theme={null}
Generate an image: What is GEO?
```

Укажите тип изображения и визуальную цель напрямую:

```text theme={null}
Generate a Chinese technology-style infographic poster about “What is GEO”.
```

### 3. В prompt отсутствует визуальное описание

Если prompt лишь объясняет концепцию, модель не знает, как превратить ее в визуальную композицию. Рекомендуется указать:

* тип изображения: инфографика, плакат, блок-схема или промо-графика;
* компоновка: три колонки, временная шкала или радиальная структура;
* визуальный стиль: технологичный, деловой, минималистичный или фирменный;
* иерархия текста: заголовок, нумерованные разделы, основной текст и верстка;
* инструкция по выводу: сгенерировать только изображение, без текстовых объяснений.

### 4. prompt запрашивает текстовый вывод

Модели генерации изображений Gemini также могут распознавать изображения и писать текст. Если prompt содержит фразы, запрашивающие текстовый вывод, модель иногда сначала «пишет предложение», вместо того чтобы сгенерировать изображение:

```text theme={null}
...Based on the outsole in image 1, design a marathon running shoe...
Produce a professional, precise, and actionable design proposal for the shoe.
Make sure the analysis is thorough and accurate, and that the design and color scheme can be used directly in product development.
```

Подобные предложения подходят для текстовой модели. Когда они отправляются в модель генерации изображений с выводом только изображений (`responseModalities: ["IMAGE"]`), предложение, которое модель хочет написать, не может быть возвращено, поэтому ответом становятся `finishReason: NO_IMAGE`, `parts: null` и ноль выходных tokens.

Мы повторно запустили реальный запрос на дизайн обуви (3 референсных изображения плюс prompt, аналогичный приведенному выше) в сентябре 2026 года (UTC+8) на gemini-3.1-flash-image с `responseModalities: ["IMAGE"]`:

| Вариант prompt | Запросы, вернувшие NO\_IMAGE |
| - | - |
| Исходный prompt | 10/48 (около 21%, варьируется от 1/12 до 5/12 между запусками) |
| Удалены предложения «design proposal» и «thorough analysis» | 0/36 |
| Исходный prompt с добавленной в конец одной фразой: «output the final image only» | 0/24 |
| Из prompt удалены названия брендов | 1/12 (названия брендов не являются триггером) |

Именно поэтому один и тот же запрос может завершаться ошибкой несколько раз подряд, а затем успешно выполняться, даже если маршрут не менялся. Самое простое решение — добавить в конец prompt подобную фразу:

```text theme={null}
Important: output only one final image. Do not output any written proposal, analysis, or prompt.
```

<Tip>
  Если референсное изображение содержит четко читаемый текст или стороннюю маркировку (например, надпись бренда на подошве обуви), модель с большей вероятностью сначала начнет анализировать этот материал. В том же тесте размытие этой надписи также привело к результату 0/36.
</Tip>

## Разные настройки responseModalities — разные симптомы

Один и тот же запрос с неясным намерением генерации изображения завершается с ошибкой по-разному в зависимости от `responseModalities`:

| Настройка | Что отображается, если изображение не возвращено |
| - | - |
| `["IMAGE"]` | `finishReason: NO_IMAGE`, `parts: null`, ноль выходных tokens |
| Не указана или `["TEXT", "IMAGE"]` | `finishReason: STOP`, но `parts` содержит только текст без изображения |

**Совет по устранению неполадок**: отправьте сбойный запрос повторно несколько раз без `responseModalities` и прочитайте, что пишет модель, когда она не возвращает изображение:

* Предложение, анализ или prompt для изображения → намерение генерации изображения неясно; исправьте prompt, как описано на этой странице
* Отказ вроде «Я не могу это сгенерировать» → сработала политика безопасности контента; см. [сбои генерации изображений Nano Banana](/ru/faq/nano-banana-image-failure)

## Пример GEO-промпта

Вы можете переписать исходный промпт следующим образом:

```text theme={null}
Generate a Chinese technology-style infographic poster titled “What is GEO”.

The image must contain one main title and three numbered sections:

1. Help companies gain visibility in large-model AI search and recommendations;
2. Make a company the answer to a user's question;
3. Build AI trust in and recommendations for a company's information.

Design requirements:

- Use a blue and purple technology style;
- Use a clear three-column layout;
- Emphasize “visibility,” “answer,” and “trusted recommendation”;
- Use clean, readable Chinese typography;
- Make it suitable as a corporate promotional poster;
- Generate an image only, without a text explanation.
```

<Tip>
  «Сгенерировать изображение» — это лишь подсказка о действии. Она не заменяет описание визуального результата. Чем яснее вы опишете тип изображения, объект, композицию и стиль, тем легче модели определить, что запрос относится к генерации изображений.
</Tip>

## Как устранить ошибку NO\_IMAGE

<Steps>
  <Step title="Шаг 1: Определите, в каком поле содержится ошибка">
    Если `candidates[0].finishReason` имеет значение `NO_IMAGE`, данная страница вам подходит. Если `candidates` отсутствуют и `promptFeedback.blockReason` имеет значение, входные данные были заблокированы до генерации; см. [Устранение неполадок с blockReason: OTHER](/ru/faq/gemini-image-input-blocked).
  </Step>

  <Step title="Шаг 2: Проверьте, содержит ли ответ данные изображения">
    Проверьте `parts`, `inlineData`, `image` или аналогичное поле изображения в ответе. Если `parts` имеет значение `null`, ответ обычно не содержит данных изображения.
  </Step>

  <Step title="Шаг 3: Убедитесь, что prompt явно запрашивает изображение">
    Убедитесь, что prompt содержит четкую инструкцию, например «сгенерируй изображение», «создай постер» или «создай изображение». Не отправляйте только текстовый вопрос, например «Что такое...» или «Объясни...». Также проверьте наличие предложений, требующих текстового ответа, например «подготовь предложение», «проанализируй подробно» или «объясни свой замысел». Удалите их или добавьте «выведи только изображение» в конец prompt.
  </Step>

  <Step title="Шаг 4: Затем проверьте факторы безопасности контента">
    Если prompt явно запрашивает изображение, но все равно возвращается `NO_IMAGE`, проверьте запрос на наличие NSFW-контента, тем с несовершеннолетними, известных объектов интеллектуальной собственности, удаления водяных знаков, портретов реальных людей или других ограничений вышестоящих политик безопасности.
  </Step>

  <Step title="Шаг 5: Проверьте логи вызовов">
    Проверьте полный ответ, название модели, ID запроса и запись о тарификации в логах вызовов. `usageMetadata` показывает, что модель обработала запрос, но это не доказывает, что изображение было сгенерировано или произошла блокировка системой безопасности.
  </Step>
</Steps>

## Чем NO\_IMAGE отличается от блокировки безопасности?

| Симптом | Возможная причина | Рекомендуемое действие |
| - | - | - |
| `NO_IMAGE` с `parts: null` и абстрактным prompt | Намерение сгенерировать изображение неясно | Добавьте тип изображения, визуальный объект и требования к композиции |
| Возвращается ошибка политики безопасности | Сработала вышестоящая политика безопасности контента | Измените или удалите контент, который может вызывать срабатывание политики |
| `NO_IMAGE` появляется периодически, а повтор того же запроса завершается успешно | В prompt запрашивается текстовый ответ, поэтому модель иногда сначала пишет вводное описание | Удалите предложения с описанием или анализом либо добавьте в конец «выводите только итоговое изображение» |
| Отсутствует `candidates`, а `promptFeedback.blockReason` имеет значение `OTHER` | Входные данные были заблокированы провайдером до начала генерации | См. [Устранение неполадок: blockReason: OTHER](/ru/faq/gemini-image-input-blocked) |
| Намерение сгенерировать изображение выражено явно, но изображение не возвращено | Модель, группа, token или вышестоящий маршрут могут быть недоступны | Обратитесь в службу поддержки, предоставив полный текст ошибки, название модели, ID запроса и время |

<Info>
  `finishReason: NO_IMAGE` означает лишь то, что изображение не было возвращено. Само по себе это не доказывает, что prompt нарушил политику. Анализируйте полный текст ошибки, prompt и журналы вызовов в совокупности.
</Info>

## Часто задаваемые вопросы

<AccordionGroup>
  <Accordion title="Всегда ли добавление «сгенерировать изображение» решает проблему?">
    Нет. Это лишь делает базовое намерение более понятным. Опишите также тип изображения, объект, композицию, стиль и требования к результату. Для абстрактных понятий явно запрашивайте инфографику, плакат или блок-схему.
  </Accordion>

  <Accordion title="Была ли тема GEO заблокирована системой безопасности контента?">
    Сама по себе концепция GEO, судя по всему, не содержит явных рисков для безопасности. Однако одно лишь `NO_IMAGE` не позволяет полностью исключить решение политик вышестоящего провайдера. В этом случае prompt больше похож на объяснение информации, поэтому в первую очередь целесообразно проверить неясность намерения сгенерировать изображение.
  </Accordion>

  <Accordion title="Почему один и тот же запрос иногда выполняется успешно, а иногда завершается ошибкой? Изменился ли маршрут?">
    В большинстве случаев маршрут не менялся. `NO_IMAGE` из-за неясного намерения носит вероятностный характер: при каждом запросе модель выбирает между генерацией изображения и предварительным написанием текста. В наших тестах один и тот же запрос завершался ошибкой примерно в 21% случаев, часто несколько раз подряд. Настройте в своем клиенте автоматический повтор 1–2 раза для ответов `NO_IMAGE` и скорректируйте prompt, чтобы устранить первопричину.
  </Accordion>

  <Accordion title="Почему в usageMetadata отображаются tokens, если изображение не было возвращено?">
    `usageMetadata` лишь показывает, что модель обработала входные данные и сгенерировала tokens рассуждения или текста. Это не означает, что ответ содержит изображение. Проверьте поля данных изображения в ответе.
  </Accordion>

  <Accordion title="Будет ли тарифицироваться NO_IMAGE?">
    Не определяйте тарификацию только по `NO_IMAGE`. Проверьте логи вызовов APIYI, чтобы подтвердить, создана ли запись о списании за этот запрос.
  </Accordion>
</AccordionGroup>

## Всё ещё не удаётся решить проблему? Обратитесь в поддержку

Если после явного указания назначения изображения запрос по-прежнему возвращает `NO_IMAGE`, обратитесь в поддержку APIYI и укажите:

* Название модели и группу token;
* Полное сообщение об ошибке и `request ID`;
* Промпт с удалёнными конфиденциальными данными;
* Время возникновения;
* Запись тарификации из журналов вызовов.

<Warning>
  Никогда не отправляйте полный API-ключ. Удалите ключ перед отправкой скриншотов или журналов.
</Warning>
