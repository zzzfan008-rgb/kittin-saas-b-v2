# Генерация и редактирование изображений Seedream

> Полное руководство по моделям генерации изображений ByteDance BytePlus ModelArk Seedream — 5.0 Flash / 5.0 Pro / 5.0 / 4.5 / 4.0 в рамках одной интеграции, 5.0 Flash по цене $0.018 за запрос примерно за 15–20 секунд, вывод в 4K, объединение нескольких изображений, пакетная генерация последовательностей, редактирование по референсному изображению — и всё на едином эндпоинте.

## Обзор

**Seedream** — это флагманская серия моделей генерации изображений от ByteDance BytePlus ModelArk с **единой архитектурой генерации и редактирования**: генерация по тексту, редактирование одного изображения, объединение нескольких изображений и пакетная генерация серий изображений выполняются через один эндпоинт `/v1/images/generations` — различаются только параметры. APIYI поддерживает стратегическое партнерство с BytePlus и интегрирует каждую активную версию в день релиза.

<Note>
  **🎨 Главные особенности**: новая модель **5.0 Flash** стоит **\$0.018 за запрос** и возвращает результат примерно за 15–20 секунд, обеспечивая качественную композицию и отрисовку текста для масштабной генерации материалов; вся серия поддерживает единую интеграцию + разрешение 4K на выходе + до 10 референсных изображений для объединения + пакетный режим (вход + выход ≤ 15) + передовую отрисовку текста. **Идеально подходит для главных изображений в e-commerce, рекламных постеров, предметной фотосъемки и создания контента** — везде, где важны высокое качество и читаемый текст.
</Note>

<Info>
  Все API для работы с изображениями являются **синхронными** — здесь нет task ID для периодического опроса, и в случае разрыва соединения со стороны клиента результат будет утерян, тогда как за запрос всё равно будет произведена тарификация. Установите достаточно большой таймаут для этой модели; см. [Основы и лучшие практики API генерации изображений](/ru/api-capabilities/image-api-best-practices).
</Info>

<Note>
  **Какая именно это версия Seedream?** APIYI предоставляет Seedream на базе **официальных зарубежных (международных) ресурсов BytePlus**, а не версии Doubao / Volcengine для материкового Китая. В международной редакции действует сравнительно более мягкая политика модерации контента по сравнению с версией для внутреннего рынка, что обеспечивает большую творческую свободу — реальное преимущество данной платформы. Однако **это не означает полное отсутствие модерации**: BytePlus по-прежнему выполняет встроенные проверки безопасности контента, и нарушающие правила prompt или референсные изображения отклоняются с кодом ошибки 400/403 (отклоненные запросы не тарифицируются). Соблюдайте правила использования сервиса.
</Note>

<Prompt description="Поручите агенту для написания кода выполнить интеграцию или отладку генерации изображений по тексту и редактирования изображений Seedream. Скопируйте и вставьте в Codex, Claude Code, Cursor и аналогичные инструменты." icon="bot" actions={["copy"]}>
  Интегрируйте / выполните отладку генерации изображений по тексту и редактирования изображений Seedream в этом проекте.

  Ознакомьтесь с документацией, прежде чем трогать код: запросите [https://docs.apiyi.com/en/api-capabilities/seedream-image/overview.md](https://docs.apiyi.com/en/api-capabilities/seedream-image/overview.md) для получения текстовой версии этой страницы. Для более подробной информации о параметрах точно так же добавьте `.md` к страницам генерации изображений по тексту и редактирования изображений.

  Требования:

  1. Таймаут: дифференцируйте клиентский таймаут по моделям — начните с 60 секунд для серии 4.x и `seedream-5-0-flash` (flash занимает около 30 секунд при 10 референсных изображениях), увеличьте его до 120 секунд для `seedream-5-0` и **увеличьте до 240 секунд для `seedream-5-0-pro`, время работы которой составляет около 2 минут на изображение**. API изображений являются синхронными — task ID отсутствует, поэтому при отключении клиента результат теряется, тогда как тарификация за запрос всё равно происходит. Ограничения обратных прокси, шлюзов и лимиты времени выполнения в бессерверных средах также необходимо расширить.

  2. Обработка ответа: по умолчанию возвращается `url` — временная подписанная ссылка BytePlus TOS, срок действия которой истекает примерно через 24 часа, — также вы можете передать `response_format` со значением `b64_json` для получения чистого base64 (без префикса `data:`). Если вы используете URL, **немедленно скачайте и разместите его в собственном объектном хранилище**; никогда не сохраняйте ссылку апстрима в базе данных в качестве постоянного адреса. Если вы используете base64, отобразите его и предусмотрите действие сохранения на диск. Передавайте `response_format` явно, а не полагайтесь на значение по умолчанию.

  3. Загрузка референсных изображений (**главное отличие от других моделей изображений**): Seedream использует единую архитектуру генерации и редактирования, поэтому **эндпоинт `/v1/images/edits` отсутствует** — как генерация, так и редактирование обращаются к `/v1/images/generations` как `application/json`. Референсные изображения передаются в поле `image`, которое представляет собой **массив URL** — это не multipart-загрузка файлов и не повторяющееся поле `image[]`. Элементами массива могут быть URL изображений или data URL в формате `data:image/jpeg;base64,...`, причём их можно смешивать. Допускается до 10 референсных изображений, при этом **сумма входных и выходных изображений не должна превышать 15**. Поля `mask` нет. Для больших локальных файлов сначала загрузите их в собственное объектное хранилище и передайте URL; если вы используете data URL, сначала сжимайте их — обрабатывайте только файлы размером более 1.5MB, масштабируйте длинную сторону до 2048px с сохранением соотношения сторон (никогда не увеличивайте маленькое изображение), пережимайте с качеством 0.9 и сохраняйте общий размер менее 6MB для запросов с несколькими изображениями. Если сжатие какого-либо изображения завершилось ошибкой, вернитесь к оригиналу и продолжите работу.

  4. Критические ограничения по параметрам: у этой модели **нет параметра `quality`** — точность определяется версией модели и `size`. `size` принимает либо уровень (`1K` / `2K` / `3K` / `4K`, по умолчанию `2K`), либо точное количество пикселей; обратите внимание, что `seedream-5-0-pro` ограничена примерно 4.19 млн пикселей при 2048 на 2048, а `seedream-5-0-flash` предлагает только `1K` / `1.5K` / `2K` с ограничением по точным пикселям около 4.62 млн; **ни в одной из них нет уровней 3K или 4K**. Параметр `n` **молча игнорируется** (вы всё равно получаете одно изображение и оплачиваете одно), поэтому используйте `sequential_image_generation` для нескольких результатов; `seed` не оказывает никакого эффекта на 4.x или 5.x. Для коммерческого использования **всегда передавайте `watermark` со значением false**, поскольку значение по умолчанию зависит от версии (`seedream-5-0-flash` добавляет водяной знак «AI generated», если поле опущено). `output_format` поддерживает png только в серии 5.0; 4.5 и 4.0 выдают только jpeg без альфа-канала. `seedream-5-0-flash` возвращает png без альфа-канала при прямой генерации; для материалов с прозрачностью используйте `layer_decomposition: true` (тарифицируется за каждое выходное изображение, часто десяток и более).

  5. Два строгих ограничения для `seedream-5-0-pro` и `seedream-5-0-flash`: **вообще не передавайте `sequential_image_generation` — любое значение, включая `"disabled"`, возвращает 400** — и **не передавайте `stream`** (также 400). Если вы переносите код с 5.0 или 4.x, полностью удалите оба поля.

  6. Считывайте ключ из переменной окружения `APIYI_API_KEY` и используйте [https://api.apiyi.com/v1](https://api.apiyi.com/v1) в качестве базового URL. Никогда не прописывайте его жёстко в коде и не коммитьте в git. При вызове через OpenAI SDK параметры `image`, `sequential_image_generation`, `watermark` и `output_format` должны передаваться внутри `extra_body` для проброса.

  7. Завершив настройку, выполните один реальный вызов генерации изображения по тексту и один вызов редактирования изображения, затем покажите мне результаты и стоимость этих двух вызовов.
</Prompt>

Официально модель использует два ценовых уровня в зависимости от выходного разрешения (одна цена для ≤2.36M px, другая для >2.36M px), а также дополнительную плату за каждое референсное изображение сверх первого; APIYI упрощает это до единой фиксированной цены за запрос — **без уровней, плата за входные изображения включена**. Для этой модели **не предусмотрено никаких официальных скидок**; APIYI устанавливает цену исходя из гарантии доступности ресурсов — фактически с нулевой маржой с учётом бонусов за пополнение и налоговых расходов — и о любых изменениях цен будет объявлено заранее
  * В режиме `sequential_image_generation: "auto"` тарификация осуществляется по фактическому количеству результатов (например, если `max_images: 4` возвращает 4 → тарифицируются 4)
  * Неудачные запросы (ошибки 4xx / блокировка модерацией) **не тарифицируются**
  * Пробный период: 200 бесплатных изображений при первом подключении (предоставляются BytePlus)
  * Подробнее о бонусах за пополнение: см. [Акции по пополнению](/ru/faq/recharge-promotions)
</Info>

## Подробный обзор ключевых параметров

### `size` (размер вывода)

Два семейства значений — выберите одно:

**Предустановленные уровни** (модель определяет соотношение сторон):

| Уровень | Прибл. пикселей | Поддерживается в |
| - | - | - |
| `1K` | \~1024×1024 | 4.0 / 5.0-pro / 5.0-flash |
| `1.5K` | \~1536×1536 | только 5.0-flash |
| `2K` | \~2048×2048 (по умолчанию) | все версии |
| `3K` | \~3072×3072 | только 5.0 |
| `4K` | \~4096×4096 | 4.5 / 4.0 |

**Точные пиксели** (пользовательские):

* Общее количество пикселей ∈ \[1280×720, 4096×4096]
* Соотношение сторон ∈ \[1/16, 16]
* По умолчанию: `2048x2048`

**Допустимые примеры**: `1920x1080` (FullHD), `3840x2160` (альбомная 4K), `1080x1920` (портретная для телефона), `2560x1440` (альбомная 2K)
**Недопустимые примеры**: `5000x5000` (превышение лимита), `100x1600` (соотношение меньше 1/16)

<Warning>
  Размеры с общим числом пикселей свыше 4096×4096 возвращают 400. Экстремальные соотношения сторон (близкие к 1/16 или 16) могут растягиваться неестественно — отдавайте предпочтение предустановкам или стандартным 16:9 / 9:16 / 1:1.

  **Модели серии 5.0 используют другой диапазон точных пикселей, чем 4.x** (более высокий нижний предел, более низкий верхний предел). Размеры вне допустимого диапазона возвращают 400 с указанием допустимого диапазона в сообщении об ошибке. Измеренные ориентиры: нижний порог 5.0-lite составляет около 2560×1440; **5.0-pro ограничен 4,19 млн пикселей в сумме (максимум 2048×2048; при 16:9 длинная сторона достигает 2720×1530 ≈ 2,7K, работоспособность проверена) — предустановок 3K/4K нет**. **5.0-flash принимает 921 600–4 624 220 пикселей в сумме (около 0,92 млн–4,62 млн) с соотношением сторон до 16:1, также без предустановок 3K/4K**; при использовании предустановок модель выбирает соотношение сторон на основе контента, поэтому передавайте точные пиксели, если вам требуется фиксированное соотношение.
</Warning>

### `image` и `sequential_image_generation` (переключатели режимов)

Эндпоинт `/v1/images/generations` охватывает как генерацию изображений по тексту, так и редактирование/объединение. Два параметра вместе определяют режим:

| Режим | `image` | `sequential_image_generation` | Примечания |
| - | - | - | - |
| Генерация только по тексту | не указан | не указан или `"disabled"` | 1 результат |
| Редактирование одного изображения | `["url1"]` | `"disabled"` | Редактирование на основе 1 референса |
| Объединение нескольких изображений | `["url1", "url2", ...]` | `"disabled"` | До 10 референсов; обращение как «image 1 / image 2» |
| Пакетная последовательность | опционально | `"auto"` + `sequential_image_generation_options.max_images` | N согласованных результатов, **N ≤ max\_images** и **input + output ≤ 15** |

<Warning>
  **`seedream-5-0-pro` и `seedream-5-0-flash` не принимают параметр `sequential_image_generation`** — передача любого значения (включая `"disabled"`) возвращает 400. Для редактирования / объединения с этими двумя моделями передавайте только `image` и полностью опускайте этот параметр; то же самое относится к `stream`.
</Warning>

Полные примеры кода см. в разделах [Генерация изображений по тексту](/ru/api-capabilities/seedream-image/text-to-image) и [Редактирование изображений](/ru/api-capabilities/seedream-image/image-edit).

    * **Большие объемы / постерная верстка / скорость и стоимость** → `seedream-5-0-flash-260915` (\$0.018/запрос, \~15–20 с, примерно до 2K)
    * **Лучший универсальный вариант** → `seedream-5-0-260128` (максимум возможностей, но ограничение до 3K)
    * **4K + качественный рендеринг текста** → `seedream-4-5-251128` (4K + прорыв в работе с текстом)

    * **Максимальное качество изображения / сложные инструкции (профессиональная работа)** → `seedream-5-0-pro-260628` (\$0.12/запрос, \~2 мин на изображение, только 1K/2K — не рекомендуется для повседневного использования)
  </Step>

  <Step title="Отдавайте предпочтение предустановленным размерам">
    `1K`/`2K`/`3K`/`4K` оптимизированы BytePlus для стабильной скорости и качества. Задавайте точные размеры в пикселях только при наличии строгих требований к соотношению сторон. Обратите внимание на различия поддерживаемых уровней разрешения в зависимости от версии.
  </Step>

  <Step title="Явно ссылайтесь на изображения">
    При использовании нескольких URL `image` составляйте prompt с явными указаниями — «Помести человека с изображения 1 в сцену с изображения 2, используя цветовую палитру изображения 3» — вместо того чтобы позволять модели строить догадки.
  </Step>

  <Step title="Контролируйте расходы на пакетные серии">
    `sequential_image_generation: "auto"` + `max_images: 4` генерирует 4 изображения — тарификация × 4. Сначала выполните проверку с `max_images: 1`, а затем увеличивайте объем.
  </Step>

  <Step title="Выбирайте выходной формат в зависимости от задачи">
    Серия 5.0 поддерживает `png` и `jpeg`; 4.5 / 4.0 — только `jpeg`. Используйте png, когда требуется детализация без потерь (у 5.0-flash в png нет альфа-канала при прямой генерации; используйте разделение слоев для прозрачности), и jpeg — для сценариев, чувствительных к размеру файла.
  </Step>

  <Step title="Устанавливайте таймаут клиента ≥ 60 секунд">
    Генерация одного изображения занимает \~15 с, но пакетная серия (4 изображения) или 4K + hd может занять 30–60 с. **Начните с таймаута клиента в 60 с** и отображайте ход выполнения в интерфейсе. **`seedream-5-0-pro` занимает \~2 минуты на изображение — используйте таймаут от 240 с и выше**.
  </Step>

  <Step title="Отключайте водяной знак при необходимости">
    Установите `watermark: false`, чтобы удалить водяной знак BytePlus (значения по умолчанию различаются в зависимости от версии, поэтому задавайте его явно). Это необходимо для коммерческих материалов.
  </Step>
</Steps>

## Коды ошибок и повторные попытки

| Статус | Значение | Рекомендуемое действие |
| - | - | - |
| `400` | Недопустимые параметры (размер вне допустимых границ, массив `image` > 10, неподдерживаемый tier) | Проверьте соответствие поддерживаемому tier используемой версии |
| `401` | Недопустимый token | Проверьте Bearer Token |
| `403` | Заблокировано модерацией контента | Скорректируйте prompt или замените референсные изображения |
| `429` | Лимит запросов (по умолчанию 500 RPM) или недостаточный баланс | Экспоненциальная задержка; обратитесь в отдел продаж для более высокого RPM |
| `5xx` | Ошибка шлюза / вышестоящего сервиса | Повторите 1-2 раза |
| Timeout | Долгий запрос | Таймаут клиента ≥ **60s** (batch sequence или 4K + hd могут достигать 60s) |

<Info>
  **Рекомендации для клиента**:

  * Начните с таймаута запроса **60 секунд** (batch sequence или 4K + hd могут занимать до минуты)
  * Применяйте **экспоненциальную задержку** для 5xx и таймаутов (рекомендуется 2 повторные попытки)
  * Логируйте заголовок ответа `x-request-id` для обращений в поддержку
</Info>

  <Accordion title="Почему для редактирования изображений также используется эндпоинт генерации?">
    Seedream использует единую архитектуру генерации и редактирования — здесь **нет отдельного эндпоинта `/v1/images/edits`**. В отличие от gpt-image-2 от OpenAI (загрузка multipart на `/v1/images/edits`), Seedream использует `application/json` и передает **URL изображений в виде массива** в поле `image`.

    Преимущества: согласованность протокола, повторное использование параметров, простое переключение режимов. Подробности см. в разделе [Редактирование изображений](/ru/api-capabilities/seedream-image/image-edit).
  </Accordion>

  <Accordion title="Принимает ли поле image формат base64?">
    **Да** (проверено тестированием). Используйте data URI: `data:image/<format>;base64,<base64 string>` с `<format>` в нижнем регистре (например, `data:image/jpeg;base64,...`). URL и записи base64 можно совмещать в одном массиве. **По возможности отдавайте предпочтение публичным URL**: URL загружаются сервисом BytePlus напрямую из Сингапура, минуя шлюз APIYI, тогда как тело запроса с base64 должно быть сначала полностью загружено через границу. При низкой скорости соединения тела запросов размером более 20 МБ могут превысить установленный провайдером 600-секундный таймаут на передачу тела запроса, а шлюз не преобразует base64 в URL за вас. См. предупреждение в верхней части страницы редактирования изображений.
  </Accordion>

  <Accordion title="Лимит объединения нескольких изображений? Лимит пакетной последовательности?">
    * **Объединение нескольких изображений** (массив `image`): 4.5 / 5.0-pro / 5.0-flash явно поддерживают до 10 (в наших тестах 11-е изображение возвращает 400 на 5.0-flash). 5.0 / 4.0 также поддерживают объединение нескольких изображений, хотя явное ограничение не задокументировано.
    * **Пакетная последовательность** (`max_images`): ограничена глобальным правилом **входные референсы + выходные изображения ≤ 15**. При совмещении объединения и последовательности учитывайте общее количество. Обратите внимание: **5.0-pro и 5.0-flash не поддерживают пакетную последовательность** (передача `sequential_image_generation` возвращает 400).
  </Accordion>

  <Accordion title="Нужен ли префикс data:image для b64_json?">
    Зависит от `response_format`:

    * `response_format: "url"` (по умолчанию) → `data[0].url` — временный подписанный URL, отображайте напрямую с помощью `<img src=...>`
    * `response_format: "b64_json"` → `data[0].b64_json` — **обычная строка base64** (без префикса `data:image/...;base64,`). Декодируйте и запишите на диск либо добавьте префикс вручную для отображения в браузере.
  </Accordion>

  <Accordion title="Поддерживается ли потоковая передача вывода?">
    Поддерживается в 5.0 / 4.5 / 4.0 через `stream: true`. Потоковая передача особенно полезна для длинных prompt и изображений высокого разрешения — фронтенд может отображать промежуточные результаты по мере поступления. **`seedream-5-0-pro` и `seedream-5-0-flash` не поддерживают потоковую передачу** — передача `stream` возвращает 400.
  </Accordion>

  <Accordion title="Лимит запросов?">
    **По умолчанию 500 изображений в минуту** (Max Images per Minute), единый для всех версий. Для увеличения квоты свяжитесь с отделом продаж.
  </Accordion>

  <Accordion title="Тарифицируются ли неудачные запросы?">
    **Нет**. В BytePlus встроена модерация. Отклонения модерацией и ошибки параметров возвращают `400` / `403` и **не тарифицируются**. Другие нетарифицируемые ошибки: `401` (недействительный token), `429` (превышен лимит запросов). **Тарифицируется только успешная генерация (`200` с валидным ответом)**.
  </Accordion>

  <Accordion title="Можно ли использовать официальный SDK OpenAI?">
    Да, без каких-либо изменений в коде. Направьте `base_url` на `https://api.apiyi.com/v1` и передавайте параметры расширения (`image` / `sequential_image_generation` / `watermark` и т. д.) через `extra_body`:

    ```python theme={null}
    from openai import OpenAI

    client = OpenAI(api_key="sk-your-key", base_url="https://api.apiyi.com/v1")
    resp = client.images.generate(
        model="seedream-5-0-260128",
        prompt="...",
        size="2K",
        extra_body={
            "image": ["https://.../ref.png"],
            "sequential_image_generation": "disabled",
            "watermark": False,
        }
    )
    ```
  </Accordion>

  <Accordion title="Кому принадлежат сгенерированные изображения?">
    Сгенерированные изображения можно использовать в коммерческих и некоммерческих целях. Подробности см. в условиях обслуживания BytePlus.
  </Accordion>

  <Accordion title="Поддерживается ли прозрачный фон?">
    `seedream-5-0` / `seedream-5-0-pro` поддерживают вывод `png` и могут формировать прозрачный фон при указании в prompt («transparent background, alpha channel»). `seedream-5-0-flash` не возвращает альфа-канал даже при запросе прозрачного фона; используйте `layer_decomposition: true`, чтобы получить базовый фон плюс несколько прозрачных слоев (тарифицируется за каждое выходное изображение), см. [Редактирование изображений](/ru/api-capabilities/seedream-image/image-edit). `seedream-4-5` / `4-0` выводят только `jpeg` и **не поддерживают прозрачность** — удаляйте фон самостоятельно на этапе постобработки.
  </Accordion>

  <Accordion title="Можно ли отменить генерацию в процессе выполнения?">
    **Нет**. `/v1/images/generations` является синхронным. После отправки запрос выполняется до завершения. Сервер всё равно завершит обработку и тарифицирует запрос, даже если клиент отключится. Настройте таймауты на стороне клиента и избегайте предположения, что отключение сэкономит средства.
  </Accordion>
</AccordionGroup>
