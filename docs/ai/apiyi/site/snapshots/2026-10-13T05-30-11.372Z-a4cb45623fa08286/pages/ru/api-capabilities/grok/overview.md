# Руководство по серии моделей Grok

> Серия xAI Grok 4.x (grok-4.7 / grok-4.6 / grok-4.5 / grok-4.3 / grok-4.20 / grok-build-0.1) на APIYI: два эндпоинта (совместимый с OpenAI + Responses API), подтверждена работа серверных tools: веб-поиск / поиск в X / выполнение кода / MCP. Цены соответствуют официальным тарифам xAI, а группа по умолчанию — линия официального релея.

Grok — флагманское семейство моделей xAI. Текущее поколение (Grok 4.x) охватывает пять продуктовых линеек — флагманские модели общего назначения, стандартные с длинным контекстом, варианты с рассуждением и без него, ориентированные на код и для мультиагентного взаимодействия — все они доступны на APIYI. **Официальный API xAI сам по себе совместим с OpenAI** (Chat Completions + Responses API) и не имеет отдельного проприетарного протокола, поэтому вызов Grok через APIYI с помощью OpenAI SDK дает вам полный набор возможностей, включая официальные серверные инструменты (веб-поиск, поиск в X, выполнение кода, Remote MCP).

Эта группа документации основана на полном практическом тестировании через шлюз APIYI от 13 июля 2026 года (UTC+8) — 56 логов запросов/ответов, — поэтому каждая указанная здесь граница возможностей проверена.

<Note>
  **🚀 Главное**: `grok-4.7` — новейший флагман SpaceXAI (xAI), выпущенный 21 сентября 2026 года. В нем осуществлен переход на новую базовую модель с 2.1T параметров с наибольшим приростом эффективности в кодинг-агентах, а его **цена идентична grok-4.6**; grok-4.3 и серия grok-4.20 предлагают **контекстное окно на 1M tokens**; инструменты Responses API **web\_search / x\_search / code\_interpreter / MCP проверены и работают на APIYI**, а поиск в X — это уникальная возможность Grok; нативная поддержка responses также означает, что Grok может [напрямую подключаться к OpenAI Codex](/ru/scenarios/programming/codex-cli). Вся серия Grok работает на линии официального релея xAI в группе по умолчанию с тарификацией, аналогичной xAI; см. «Группы и скидки» ниже.
</Note>

### Уровни тарификации и стоимость кэша

Для всей серии Grok тарификация разделена на два уровня в зависимости от **длины контекста отдельного запроса** с порогом на 200K tokens (200Ki = 204,800). Выше этого значения ставки на ввод и вывод удваиваются:

| Модель | Уровень | Вход | Выход | Чтение из кэша |
| - | - | - | - | - |
| `grok-4.7` | 0 – 200K | \$2.00 | \$6.00 | \$0.50 |
| `grok-4.7` | 200K – 500K | \$4.00 | \$12.00 | \$1.00 |
| `grok-4.6` | 0 – 200K | \$2.00 | \$6.00 | \$0.50 |
| `grok-4.6` | 200K – 512K | \$4.00 | \$12.00 | \$1.00 |
| `grok-4.5` | 0 – 200K | \$2.00 | \$6.00 | \$0.30 |
| `grok-4.5` | 200K – 512K | \$4.00 | \$12.00 | \$0.60 |
| Серия `grok-4.3` / `grok-4.20` | 0 – 200K | \$1.25 | \$2.50 | \$0.20 |
| Серия `grok-4.3` / `grok-4.20` | 200K – 1M | \$2.50 | \$5.00 | \$0.40 |
| `grok-build-0.1` | 0 – 200K | \$1.00 | \$2.00 | \$0.20 |
| `grok-build-0.1` | 200K – 256K | \$2.00 | \$4.00 | \$0.40 |

Все цены указаны за 1M tokens. Модели `grok-4.7` и `grok-4.6` полностью идентичны по всем четырем статьям тарификации; **единственное ценовое различие между `grok-4.6` и `grok-4.5` — ставка чтения из кэша** (\$0.50 против \$0.30), стоимость ввода и вывода одинакова.

Оба уровня для `grok-4.7` и `grok-4.6` были попунктно проверены по ставкам ввода, вывода и чтения из кэша (порог уровня `grok-4.7` составляет 200,000 tokens); тарифы второго уровня на чтение из кэша для остальных моделей рассчитаны на основе правила xAI «удвоение для второго уровня», поэтому эталонными следует считать актуальные цены на [странице информации о моделях](/ru/api-capabilities/model-info).

<Info>
  * Псевдонимы `grok-code-fast` / `grok-code-fast-1` также доступны для вызова (доступность проверена); их цены см. на [странице информации о моделях](/ru/api-capabilities/model-info).
  * Кэшированные входящие tokens тарифицируются по ставке чтения из кэша, приведенной в таблице выше. Префиксное кэширование Grok работает **автоматически — настройка не требуется**, функциональность подтверждена для обоих эндпоинтов как с потоковой передачей, так и без нее; см. [руководство по тарификации кэша Grok](/ru/api-capabilities/grok/prompt-caching).
  * Обратите внимание на порог уровней при работе с длинным контекстом: единичный запрос на 210K tokens тарифицируется целиком по второму уровню, а не только 10K сверх порога. Разделение запросов помогает избежать скачка цены.
</Info>

## Группы и скидки

| Группа | Коэффициент тарифа | Примечания |
| - | - | - |
| `default` | 1.0x | Группа по умолчанию, представляющая собой линию официального релея xAI, с ценами как у xAI |
| `CodexResponses` | 1.0x | Для Codex и других клиентов Responses; те же модели и цены, что и в группе по умолчанию |

Серия Grok использует линию официального релея xAI в группе по умолчанию, поэтому отдельной группы официального релея больше нет. Прежняя группа `GrokOfficial` больше не отображается в списке, также работает с коэффициентом 1x, и для Tokens, которые уже используют её, никаких изменений не требуется.

Чтобы еще больше снизить затраты, используйте [бонус за пополнение](/ru/faq/recharge-promotions), зависящий от суммы каждого пополнения.

## Эндпоинты

| Эндпоинт | Метод | Назначение |
| - | - | - |
| `/v1/chat/completions` | `POST` | Чат / reasoning / вызов функций / структурированные выходные данные / vision (общий для всех моделей; выбирайте через `model`) |
| `/v1/responses` | `POST` | Responses API: поиск в Web, поиск в X, выполнение кода, Remote MCP и другие серверные инструменты |

### Используйте напрямую в Codex

Поскольку Grok изначально поддерживает `/v1/responses`, это одна из немногих моделей не от OpenAI, которая работает в **OpenAI Codex** (настольное приложение / расширение IDE / CLI) по нативному протоколу responses — задайте `model = "grok-4.6"` и `wire_api = "responses"` в `config.toml`, и вы подключитесь за 5 минут, при этом все агентные возможности Codex (вызовы инструментов, элементы reasoning и т. д.) работают через нативный протокол. Напротив, Claude / Gemini в APIYI работают только в совместимом с OpenAI режиме chat (резервный вариант `wire_api = "chat"`), что приводит к несовместимости протоколов в сценариях Codex / agent. Полные шаги настройки: [Руководство по интеграции с Codex](/ru/scenarios/programming/codex-cli).

<Warning>
  **Следующее НЕ поддерживается на APIYI** (подтверждено — избегайте этих ловушек):

  * **Legacy Completions (`/v1/completions`)**: отклонено на стороне upstream — вся линейка Grok 4.x представляет собой reasoning-архитектуру и не поддерживает raw text completion на официальном уровне
  * **Устаревший параметр live-search `search_parameters`**: удалён xAI (подтверждён 410). Весь live search проходит через инструменты Responses API — см. [Поиск в Web и X](/ru/api-capabilities/grok/web-search)
  * **Batch API / Files**: не маршрутизируется через шлюз; не применимо к режиму key-pool
  * **Deferred Completions (`deferred: true`)**: параметр **молча игнорируется** — запрос выполняется синхронно и тарифицируется как обычно. Не полагайтесь на него
  * **Collections Search (RAG / file\_search)**: требует заранее созданных collections в консоли xAI; не применимо к режиму key-pool
  * **Context Compaction (`/v1/responses/compact`)**, **Priority Processing (`service_tier: "priority"` — в тестировании откатывается к значениям по умолчанию)**, **режим WebSocket**, **аутентификация mTLS**: все не поддерживается
</Warning>

## Быстрый старт

<CodeGroup>
  ```bash cURL theme={null}
  curl -X POST "https://api.apiyi.com/v1/chat/completions" \
    -H "Authorization: Bearer sk-your-api-key" \
    -H "Content-Type: application/json" \
    -d '{
      "model": "grok-4.6",
      "messages": [
        {"role": "user", "content": "Introduce yourself in one sentence"}
      ]
    }'
  ```

  ```python Python theme={null}
  from openai import OpenAI

  client = OpenAI(
      api_key="sk-your-api-key",
      base_url="https://api.apiyi.com/v1"
  )

  resp = client.chat.completions.create(
      model="grok-4.6",
      messages=[{"role": "user", "content": "Introduce yourself in one sentence"}]
  )
  print(resp.choices[0].message.content)
  ```

  ```javascript Node.js theme={null}
  import OpenAI from 'openai';

  const client = new OpenAI({
    apiKey: 'sk-your-api-key',
    baseURL: 'https://api.apiyi.com/v1',
  });

  const resp = await client.chat.completions.create({
    model: 'grok-4.6',
    messages: [{ role: 'user', content: 'Introduce yourself in one sentence' }],
  });
  console.log(resp.choices[0].message.content);
  ```
</CodeGroup>

Чтобы дополнительно снизить расходы, воспользуйтесь бонусом за пополнение.

## Примечание о тарификации: tokens рассуждения

`grok-4.7` / `grok-4.6` / `grok-4.5` / `grok-4.3` / `grok-build-0.1` **по умолчанию выполняют внутреннее рассуждение**: ответы содержат `reasoning_content`, а tokens рассуждения учитываются при тарификации исходящих tokens. В ходе тестирования короткий ответ содержал всего 30 видимых tokens, но тарифицировался как 586 исходящих tokens (556 из них — tokens рассуждения). Для коротких вопросов и ответов, чувствительных к стоимости, переключитесь на `grok-4.20-0309-non-reasoning`. Подробности — в разделе [Чат и рассуждение](/ru/api-capabilities/grok/chat).

## Часто задаваемые вопросы

<AccordionGroup>
  <Accordion title="Есть ли у Grok собственный нативный формат API?">
    Отдельного проприетарного протокола нет. Официальный REST API от xAI совместим с OpenAI: `/v1/chat/completions` (чат) плюс `/v1/responses` (Responses API и серверные инструменты). Направьте OpenAI SDK на `https://api.apiyi.com/v1`, и вы получите полный набор возможностей — никакого «урезания возможностей в режиме совместимости» нет.
  </Accordion>

  <Accordion title="Как включить веб-поиск?">
    Используйте Responses API: `tools: [{"type": "web_search"}]` (или `x_search`). Устаревшее поле `search_parameters` в Chat Completions было удалено xAI (подтверждено кодом 410) — не используйте его. См. [Поиск в вебе и X](/ru/api-capabilities/grok/web-search).
  </Accordion>

  <Accordion title="Модель представляется как Grok 4 — мой запрос попадает не в ту модель?">
    Это нормально. Все модели Grok 4.x представляются просто как «Grok 4» (мультиагентная модель называет себя Oppie) и не сообщают точные номера версий, такие как 4.6 / 4.5 / 4.3. Проверяйте идентификатор через поле `model` в вашем запросе и ответе, а не по самопрезентации модели.
  </Accordion>

  <Accordion title="Требуется ли настройка кэширования?">
    Нет. Кэширование префиксов в Grok работает автоматически; проверяйте попадания в кэш с помощью `usage.prompt_tokens_details.cached_tokens` (в `/v1/responses` считывайте `usage.input_tokens_details.cached_tokens`). Попадания в кэш округляются в меньшую сторону до 128 tokens, что подтверждают оба раунда тестирования: для префикса из 8802 tokens попадание составило 8704, для префикса из 2735 tokens — 2688. xAI заявляет, что записи кэша могут вытесняться, а попадания в кэш не гарантируются, поэтому **закладывайте в бюджет стоимость без учета кэша**. Подробная информация — в [руководстве по тарификации кэша Grok](/ru/api-capabilities/grok/prompt-caching).
  </Accordion>

  <Accordion title="Что произойдет при превышении контекстного окна?">
    Ошибка 400. Лимиты зависят от модели: для grok-4.7, grok-4.6 и grok-4.5 это 500K, для grok-4.3 и серии 4.20 — 1M, для grok-build-0.1 — 256K. Для более длинного контента используйте суммаризацию, разбиение на фрагменты или RAG-поиск.
  </Accordion>

  <Accordion title="Тарифицируются ли неуспешные запросы?">
    Ошибки клиента 4xx (некорректные параметры / сбои авторизации) не тарифицируются; запросы, которые успешно возвращают tokens, тарифицируются по фактическому использованию. Обратите внимание, что `deferred: true` молча игнорируется — запрос фактически выполняется синхронно и тарифицируется в обычном порядке.
  </Accordion>
</AccordionGroup>
