## 🔧 Устранение неполадок по симптомам

Найдите строку, соответствующую тому, что вы наблюдаете. Один симптом часто охватывает несколько тем, поэтому эта таблица группирует статьи по устранению неполадок по наблюдаемому поведению.

| Что вы наблюдаете | Вероятная причина | Где искать |
| - | - | - |
| Недействительный API Key / 401 | Base URL и KEY не совпадают, либо KEY введен с ошибкой | [Недействительный API Key](/ru/faq/invalid-api-key) · [Настройка Base URL](/ru/faq/base-url-config) |
| API баланса, логов или управления token возвращает 401 `ACCESS_TOKEN_LEGACY_RETIRED` или 403 `ACCESS_TOKEN_SCOPE_DENIED` | Устаревший системный token выведен из эксплуатации, либо у персонального access token нет нужного разрешения | [Персональные access token](/ru/faq/personal-access-token) |
| Текст ошибки неясен, непонятно с чего начать | Последовательно проверьте типы ошибок по порядку | [Устранение ошибок API моделей](/ru/faq/model-error-troubleshooting) |
| Баланс положительный, но запросы завершаются сбоем | Механизм предварительного списания, либо max\_tokens задан слишком большим | [Недостаточно средств на балансе](/ru/faq/balance-insufficient) · [Предварительное списание](/ru/faq/pre-deduction-quota) |
| Таймаут запроса или обрыв посреди потоковой передачи | Слишком короткий таймаут на стороне клиента; reasoning-модели работают медленно | [Предотвращение таймаутов API](/ru/faq/timeout-configuration) |
| В логе показан успех и тарификация, но клиент ничего не получил | Длительность в логе фиксируется, когда шлюз завершает работу; задержка возникает дальше по цепочке или в сигнале завершения | [Лог завершен, но ответа нет](/ru/faq/log-duration-vs-client-wait) |
| Сайт или API возвращает 502 | Кратковременный автоматический перезапуск контейнера службы; восстанавливается примерно за 1 минуту | [Что делать при ошибке 502](/ru/faq/website-502-error) |
| Скрипт периодически получает 502 с пустым телом, а в логах ничего нет | Пустая ошибка 502 генерируется локальным прокси-клиентом (Clash / v2rayN) | [Пустая ошибка 502 от прокси](/ru/faq/proxy-empty-502) |
| Запросы к генерации изображений через VPN пакетами обрываются через 90–180 с, но тарификация списывается | Локальный прокси закрывает соединения, по которым слишком долго не передаются данные | [Отключения прокси по неактивности](/ru/faq/proxy-idle-timeout-disconnect) |
| Python выдает SSLEOFError, но curl работает | Постквантовые рукопожатия OpenSSL 3.5+ блокируются промежуточными узлами (middlebox) | [Устранение ошибки SSLEOFError](/ru/faq/openssl-pq-handshake-eof) |
| Ошибки 429 из-за параллельных запросов | Достигнута квота на параллельные запросы | [Лимиты на параллельные запросы к API](/ru/faq/api-concurrency) |
| Вывод обрывается на полуслове | Параметр max\_tokens не задан или слишком мал | [Что такое max\_tokens](/ru/faq/max-tokens) |
| Возвращается 200, но в ответе отказ, и разбор JSON завершается сбоем | Модели GPT отклоняют контент, нарушающий политики, без кода ошибки или категории | [Как выглядит отказ OpenAI](/ru/faq/openai-content-safety-refusal) |
| Claude возвращает 200 с пустым контентом, и `content[0]` вызывает исключение | Запрос нарушил политику безопасности провайдера; `stop_reason` имеет значение `refusal` | [Почему отказ Claude возвращает пустой контент](/ru/faq/claude-content-safety-refusal) |
| Claude Code / Claude Agent сообщает о 429 `Invalid signature in thinking block`, и все 10 повторных попыток завершаются сбоем | Дело не в лимите запросов: блок thinking в истории потерял свою подпись | [Недействительная подпись thinking в Claude](/ru/faq/claude-thinking-signature-invalid) |
| Конкретная модель не запускается | Разрешения аккаунта заблокированы или действует белый список моделей для token | [Почему недоступны некоторые модели](/ru/faq/model-availability) · [Белый список моделей для token](/ru/faq/token-model-whitelist) |
| Сбой генерации изображений / пустой ответ | Сработал фильтр безопасности контента Google | [Сбои Nano Banana](/ru/faq/nano-banana-image-failure) |
| API изображений Gemini возвращает NO\_IMAGE | Причина отличается от блокировок безопасности | [Почему возникает NO\_IMAGE](/ru/faq/gemini-no-image) |
| API изображений Gemini за секунды возвращает blockReason: OTHER без вариантов candidates | Входные данные заблокированы до генерации, обычно из-за одного из референсных изображений | [Устранение ошибки blockReason: OTHER](/ru/faq/gemini-image-input-blocked) |
| API изображений Gemini периодически возвращает IMAGE\_OTHER | Изображение было сгенерировано, но отфильтровано на выводе, часто из-за упоминания реального человека в prompt | [Устранение ошибки IMAGE\_OTHER](/ru/faq/gemini-image-other) |
| Результат сильно отличается от референсного изображения | Референсные изображения необходимо загружать в формате base64 | [Изображение отличается от референса](/ru/faq/image-result-differs-from-reference) |
| Сбой загрузки с ошибкой does not match MIME type | URL изображения содержит параметры обработки CDN | [Несоответствие MIME-типа](/ru/faq/image-mime-type-mismatch-with-query) |
| На изображении с белым фоном появляются черные точки | Известная особенность маршрута AI Studio | [Артефакты на белом фоне](/ru/faq/white-background-image-artifacts) |
| Нужно опрашивать результат генерации изображения по ID задачи | Генерация изображений работает только синхронно | [Существует ли асинхронный API изображений](/ru/faq/image-async-api) |
| Счет за изображения оказался намного выше ожидаемого | Разрешение, качество, соотношение сторон и количество масштабируют исходящие tokens | [Почему у GPT Image большой расход выходных tokens](/ru/faq/gpt-image-output-token-calculation) |
| Seedance блокирует референсное изображение с лицом | Для реальных лиц требуется загрузка ассета и подтверждение личности | [Почему блокируются ассеты с лицами](/ru/faq/seedance2-face-asset-whitelist) |
| Ссылка на изображение для Seedance открывается в браузере, но отправка завершается с ошибкой invalid image format | Ссылка отклоняет запросы Range, ограничивает скачивание или истекает слишком быстро, поэтому провайдер не может ее загрузить | [Ссылка на изображение открывается, но запрос падает](/ru/faq/seedance-image-url-invalid-format) |
| Seedance 2.5 возвращает 400 `TaskTypeConstraint`, несмотря на заданные соотношение сторон и длительность | Задача была распознана как редактирование видео; `ratio` должно быть `adaptive`, а `duration` — `-1` | [Генерация видео по референсу или редактирование видео](/ru/faq/seedance2-reference-vs-edit) |
| Seedance возвращает `first/last frame content cannot be mixed with reference media content` без режима первого кадра | У изображения нет `role`, и оно воспринимается как первый кадр; используйте нативный эндпоинт и явно задайте `reference_image` | [Смешение первого кадра и референса](/ru/faq/seedance-first-frame-mixed-with-reference) |
| Модель заявляет, что принадлежит другому поставщику / не может указать свою версию | Собственные знания модели о себе ненадежны | [Claude утверждает, что является Qwen](/ru/faq/claude-identity-confusion) · [Модели не знают свою версию](/ru/faq/model-version-identity) |
| Веб-приложение отвечает умнее, чем API | Веб-приложение включает системные prompt и инструменты; API предоставляет только чистую модель | [Веб-приложение против API](/ru/faq/webapp-vs-api-difference) |
| Незнакомые вызовы по вашему KEY | KEY мог быть скомпрометирован — отследите его и отключите | [Анализ неожиданного использования KEY](/ru/faq/troubleshoot-key-usage) · [Безопасное управление ключами](/ru/faq/key-security-management) |
| Данные тарификации не сходятся | Тарификация по объему использования и за вызов отображаются по-разному | [Просмотр тарификации в логах](/ru/faq/log-billing-explained) · [Коэффициент тарифа для модели](/ru/faq/model-multiplier) |
| Скачивание изображений или видео идет медленно либо возникает ошибка Read timed out | Генерация прошла успешно; проведите самодиагностику и отправьте нам результаты | [Медленная загрузка или таймаут CDN](/ru/faq/cdn-download-slow) |
| Нужен ли прокси? | Прямое подключение работает; прокси не требуется | [Нужен ли прокси](/ru/faq/network-proxy) |
| При входе через GitHub появляется сообщение «Account already bound» | Этот аккаунт GitHub привязан к другому адресу эл. почты | [Ошибка привязки GitHub](/ru/faq/github-bindng-bindng-error) |
| Забыли пароль | Сбросьте по эл. почте или обратитесь в службу поддержки | [Забыли пароль](/ru/faq/forgot-password) |
