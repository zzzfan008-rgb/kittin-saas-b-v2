# GPT-Image-2.5-All: генерация/редактирование изображений

> Реверс-инжиниринговая модель генерации изображений GPT gpt-image-2-all (веб-линейка ChatGPT). Фиксированная тарификация $0.025 за изображение за вызов, генерация за ~30–60 с. Поддерживает text-to-image, объединение и редактирование нескольких изображений, редактирование на естественном языке, высокую точность отрисовки текста и отлично подходит для prompt на китайском языке.

<Info>
  Все API изображений являются **синхронными** — здесь нет ID задачи для опроса, и если ваш клиент отключится, результат будет потерян, при этом запрос всё равно тарифицируется. Установите для этой модели достаточно большой таймаут; см. [Основы и лучшие практики API изображений](/ru/api-capabilities/image-api-best-practices).
</Info>

## Обзор

**gpt-image-2.5-all** и **gpt-image-2-all** — это **реверс-инжиниринговые модели генерации изображений GPT** от APIYI (веб-линейка ChatGPT). Веб-приложение ChatGPT полностью перешло на Images 2.5, поэтому `gpt-image-2-all` уже создает изображения версии 2.5; новое название `gpt-image-2.5-all` лишь делает это обновление явным — **оба названия имеют одинаковую цену и поведение и взаимозаменяемы**; для новых проектов следует использовать `gpt-image-2.5-all`. Благодаря исключительно выгодной цене **\$0.025 за изображение** за вызов (снижена с \$0.03 от 2026-10-10), модель генерирует изображения **примерно за 30–60 секунд** и поддерживает **генерацию изображений по тексту / редактирование одного изображения / объединение нескольких изображений / редактирование на естественном языке** — с высокой точностью рендеринга текста и нативной поддержкой prompt на китайском языке.

<Note>
  **🎨 Главное**: Надежный реверс-инжиниринговый канал с фиксированной ценой \$0.025 за изображение. Не нужно беспокоиться о параметрах size/quality/n — просто укажите размер и стиль в prompt. Использует стандартные эндпоинты OpenAI Images API: `/v1/images/generations` (генерация изображений по тексту) и `/v1/images/edits` (редактирование изображений).

  **Нужно зафиксировать выходной размер или получить 4K?** Переключитесь на родственную модель [`gpt-image-2-vip`](/ru/api-capabilities/gpt-image-2-vip/overview) — тот же формат вызова, только с дополнительным полем `size`.
</Note>

## Доверьте интеграцию ИИ-агенту

<Note>
  Если вы разрабатываете с помощью Codex / Claude Code / Cursor, скопируйте prompt ниже и передайте его вашему агенту. Сначала он загрузит текстовую версию этой страницы (добавьте `.md` к любому URL документации), а затем напишет код для стека вашего проекта — таймаут, рендеринг base64, сжатие при загрузке и параметры, которые эта модель отклоняет, уже включены в требования.
</Note>

<Prompt description="Поручите ИИ-агенту интеграцию или диагностику генерации и редактирования изображений gpt-image-2-all. Скопируйте и вставьте в Codex, Claude Code, Cursor и аналогичные инструменты." icon="bot" actions={["copy"]}>
  Выполните интеграцию / диагностику генерации и редактирования изображений с помощью gpt-image-2-all в этом проекте.

  Прежде чем приступать к коду, ознакомьтесь с документацией: загрузите [https://docs.apiyi.com/en/api-capabilities/gpt-image-2-all/overview.md](https://docs.apiyi.com/en/api-capabilities/gpt-image-2-all/overview.md) для получения текстовой версии этой страницы. Для более подробной информации о параметрах аналогичным образом добавьте `.md` к страницам генерации (text-to-image) и редактирования изображений (image-edit).

  Требования:

  1. Таймаут: увеличьте клиентский таймаут до 360 секунд. API изображений работают синхронно — идентификатор задачи (task ID) отсутствует, поэтому при отключении клиента результат будет потерян, а запрос все равно будет тарифицирован. Лучше подождать, чем прерывать по таймауту раньше времени. Обратные прокси, шлюзы и лимиты времени выполнения в бессерверных средах также необходимо увеличить: любой уровень с лимитом меньше времени генерации прервет запрос.

  2. Рендеринг ответа: по умолчанию возвращается base64 (`b64_json`, без префикса `data:`); вы также можете передать `response_format` со значением url, чтобы вместо этого получить ссылку на CDN. **Всегда явно отправляйте `response_format`, а не полагайтесь на поведение по умолчанию** — ранее оно уже менялось в зависимости от группы и нагрузки. Если вы получаете base64, отобразите его и предусмотрите сохранение на диск; если получаете URL, учтите, что срок его действия истекает примерно через 24 часа, поэтому немедленно скачайте и разместите его на своем сервере. Каждая запись в `data[]` содержит только одно из двух полей, поэтому выполняйте парсинг с защитой для обоих вариантов.

  3. Сжатие перед загрузкой: перед вызовом `/v1/images/edits` (multipart) сжимайте каждое референсное изображение — обрабатывайте только файлы размером более 1.5MB, уменьшайте длинную сторону до 2048px с сохранением пропорций (никогда не увеличивайте маленькие изображения), перекодируйте с качеством 0.9 и сохраняйте исходный формат. Для запросов с несколькими изображениями общий размер должен быть менее 6MB, и ни одно отдельное изображение не должно превышать 10MB. Если сжать изображение не удалось, используйте оригинал и продолжайте — никогда не прерывайте весь запрос из-за ошибки сжатия.

  4. Критические ограничения по параметрам: эта модель **не** принимает `size`, `quality`, `n` или `aspect_ratio`. Не отправляйте ни один из них. В частности, есть две ловушки: отправка `n` со значением 3 тарифицируется как 3 изображения, но возвращается все равно только 1; а метод `client.images.generate()` в OpenAI SDK по умолчанию отправляет `size` и `n`, поэтому **здесь безопаснее отправлять прямой HTTP-запрос**. Размеры выходного изображения вместо этого задаются префиксом prompt (например, начиная prompt с указания формата landscape 16:9). На этой странице приведена проверенная таблица соответствия prompt и разрешения — следуйте ей.

  5. Считывайте ключ из переменной окружения `APIYI_API_KEY` и используйте [https://api.apiyi.com/v1](https://api.apiyi.com/v1) в качестве базового URL. Никогда не прописывайте его в коде и не коммитьте в git.

  6. По завершении выполните один реальный вызов text-to-image и один вызов image-edit, после чего покажите мне результаты и стоимость этих двух вызовов.
</Prompt>

<Tip>
  **Снижение цены с 2026-10-10: \$0.03 → \$0.025/изображение** (применяется как к `gpt-image-2-all`, так и к `gpt-image-2.5-all`).

  * **Причина**: серия -all сама по себе обеспечивает высокое качество изображений и работает стабильнее серии -vip — серия -vip сильнее подвержена контролю рисков на стороне провайдера (мы продолжаем поддерживать её и наращивать мощности, и -vip остаётся доступной). Снижение призвано сделать -all простым выбором по умолчанию для повседневной генерации изображений.
  * **Единственный компромисс**: разрешение на выходе составляет 1K–1.5K; 2K / 4K недоступны. Этого достаточно для повседневной генерации; выбирайте -vip или официальный релей, когда вам требуются фиксированные размеры или 4K.
  * **На практике ещё дешевле**: \$0.025 — это цена до скидок; объедините её с бонусом за пополнение (10%–20% дополнительных средств), и фактическая стоимость станет ещё ниже.
</Tip>

<Tip>
  **Аналогичная модель**: [`gpt-image-2-vip`](/ru/api-capabilities/gpt-image-2-vip/overview) (Adobe reverse line (Firefly)) — \$0.03/изображение, поддерживает 30 фиксированных размеров (включая 4K), тот же формат вызова. Переключайтесь на неё, когда вам нужны точные размеры на выходе или 4K.
</Tip>

## Настройка групп

`gpt-image-2-all` находится в группе `Default` — **дополнительная группа не требуется**. Обратный канал в настоящее время стабилен, поэтому сценарий переключения на корпоративную группу, как у официального релея `gpt-image-2`, здесь отсутствует.

| Модель | Группа | Примечания |
| - | - | - |
| `gpt-image-2-all` | `Default` | Обратный канал ChatGPT-web, фиксированно \$0.025/избр., \~30–60 с |
| `gpt-image-2.5-all` | `Default` | Версия GPT-Image 2.5 той же линейки, фиксированно \$0.025/избр., те же группы, что и у -all |
| `gpt-image-2-all` | `image2_OSS` | **Коэффициент тарифа 1x (без наценки)**, детерминированный вывод URL — никогда не переключается на base64 при нагрузке на группу по умолчанию |

### Нужен детерминированный вывод URL → переключитесь на группу `image2_OSS`

По замерам за июль 2026 года в группе по умолчанию `gpt-image-2-all` (и `gpt-image-2-vip`) возвращают `b64_json`, если `response_format` не указан; передайте `response_format: "url"` явно, чтобы получить URL изображения. Формат вывода в группе по умолчанию **не гарантируется** — исторически по умолчанию возвращался `url` с переключением на `b64_json` под нагрузкой, а также менялся в разных версиях канала.

Если ваши сценарии **зависят от вывода в формате URL** (прямая запись URL в базу данных, рендеринг на фронтенде по URL, base64 не подходит), переключите группу вашего token на **`image2_OSS`** — группу, специально созданную для **детерминированного вывода URL**, с **коэффициентом тарифа 1x (без наценки)**, действующую для обеих реверс-моделей `gpt-image-2-all` и `gpt-image-2-vip`. Она гарантирует, что ответ всегда содержит URL изображения и никогда не переключается на base64.

| Атрибут | Значение |
| - | - |
| **Название модели** | `gpt-image-2-all` |

| **Тарификация** | \$0.025 / изображение, за вызов |
| **Время генерации** | \~30–60 секунд |
| **Разрешение на выходе** | Нет явного параметра размера; адаптивное (описывается в prompt) |

| **Дополнительный формат** | `url` (ссылка с ускорением через R2 CDN, **срок действия \~1 день**, требуется явно указать `response_format: "url"`) |
| **Промпты на китайском языке** | ✅ Нативная поддержка |
| **Возможности** | Генерация по тексту (text-to-image), редактирование одного изображения, объединение нескольких изображений, редактирование на естественном языке |

<Warning>
  Эта модель имеет **адаптивные размеры на выходе** и не эквивалентна официальному API `gpt-image-2`. Для строго фиксированных размеров вывода или разрешения 4K используйте [`gpt-image-2-vip`](/ru/api-capabilities/gpt-image-2-vip/overview) (линейка реверс-инжиниринга Adobe (Firefly), 30 явных размеров, включая 4K). Для полной совместимости с официальным API используйте [`gpt-image-2`](/ru/api-capabilities/gpt-image-2/overview).
</Warning>

<Warning>
  **⏰ Срок действия URL изображения: \~1 день (по умолчанию)**

  Поле `url` ответа в режиме `url` представляет собой ссылку R2 CDN, **срок действия которой истекает примерно через 24 часа** — последующие запросы вернут ошибку 404. Если изображения требуют длительного хранения (карточки товаров, пользовательские работы, история и т. д.), **скачайте и сохраните их в собственное хранилище как можно скорее** после генерации.

  Два распространенных подхода:

  * **Загрузка на стороне сервера**: как только вы получите ответ, используйте `requests` / `fetch`, чтобы скачать изображение и сохранить его в S3 / OSS / R2 / на локальный диск
  * **Использование формата ответа `b64_json`**: вы получаете изображение напрямую в виде данных base64, минуя дополнительное кросс-доменное скачивание — идеально подходит для отрисовки на фронтенде или прямой записи в файл
</Warning>

  </Accordion>

  </Accordion>

  <Accordion title="Если контент отклонен или модель отвечает «I can't do that», списывается ли оплата?">
    Это реверс-инжиниринговый канал, использующий **синхронные ответы в формате чата**. Возможны два сценария с **разными правилами тарификации**:

    **1) Возвращен код HTTP 5xx → НЕ тарифицируется**

    Когда политика фильтрации контента вышестоящего провайдера жестко блокирует запрос, вы увидите примерно следующее:

    ```json theme={null}
    {
      "error": {
        "message": "Image was not generated as expected. Please adjust the prompt and retry (traceid: 0672821c6951af183dbf847130caaf16)",
        "localized_message": "Unknown error",
        "type": "invalid_request_error",
        "param": "",
        "code": null
      }
    }
    ```

    Такие критические ошибки **не тарифицируются**. Попросите пользователя скорректировать prompt и повторить попытку.

    **2) HTTP 200 с текстовым «мягким отказом» → ТАРИФИЦИРУЕТСЯ**

    Когда модель выдает мягкий отказ в рамках диалога (например, «I can't do that», «Sorry, this request involves…»), на уровне протокола это выглядит как обычный ответ чата, поэтому **вызов тарифицируется**. Реверс-канал не может надежно отличить «текст отказа» от «вывода изображения» на уровне протокола.

    **Почему мы не можем просто отменять плату за мягкие отказы**

    Автоматическая отмена платы за каждый мягкий отказ означала бы, что платформа берет на себя расходы за каждый неудачный вызов вышестоящего провайдера. Что еще важнее, **частые срабатывания систем безопасности контента вышестоящего провайдера повышают риск блокировки аккаунта поставщика** — это реальные издержки на стороне инфраструктуры, которые невозможно полностью устранить.

    **Рекомендации для интеграторов**

    * ✅ **Предварительно фильтруйте и предупреждайте пользователей**: настройте фильтрацию по ключевым словам и сценариям на фронтенде или шлюзе (имена реальных людей, защищенные авторским правом персонажи, деликатные темы) и показывайте в интерфейсе подсказку вроде: «Запросы об известных личностях и объектах авторского права могут завершиться ошибкой, но все равно будут протарифицированы согласно правилам вышестоящего провайдера». Это значительно сократит лишние списания.
    * ✅ **Ежемесячная компенсация для b2c-продуктов**: мы понимаем, что в продуктах для конечных пользователей невозможно полностью ограничить пользовательский ввод. Если ваши ежемесячные расходы достаточно высоки (**от \$1000+/month**), вы можете **собирать логи раз в месяц** (запросы с малой задержкой обычно являются мягкими отказами) и обращаться в поддержку за разовой ручной компенсацией — подавать заявку по каждому вызову отдельно не требуется.

    **Добавление `4K` / `8K` в prompt на самом деле не приводит к генерации изображения высокого разрешения** — эти слова служат лишь украшением, и модель не увеличивает разрешение из-за них. Для надежного получения изображений большего размера используйте проверенные формулировки из таблицы «Проверенные формулировки prompt → фактическое разрешение» выше (например, `cinematic`, `phone poster`, `square composition`). Если требуется строго зафиксировать размер или получить 4K, переключитесь на [`gpt-image-2-vip`](/ru/api-capabilities/gpt-image-2-vip/overview) (30 фиксированных размеров, включая 4K, фиксированная цена \$0.03 за изображение).
  </Accordion>

  <Accordion title="Каков максимальный размер эталонного изображения и какие форматы поддерживаются?">
    Рекомендуется **≤ 10MB на изображение**, форматы `png` / `jpg` / `webp`. Слишком большие изображения могут упереться в лимиты шлюза. Этому ограничению должно соответствовать каждое изображение при объединении нескольких файлов.
  </Accordion>

  <Accordion title="Сколько времени действительны возвращаемые URL изображений? Нужно ли их скачивать?">
    Поле `url` в ответе режима `url` представляет собой **ссылку R2 CDN, срок действия которой истекает примерно через 1 день (24 часа)** — последующие запросы к ней вернут ошибку 404.

    **Настоятельно рекомендуется**: скачивайте и сохраняйте сгенерированные изображения в **собственное объектное хранилище (S3 / OSS / R2), CDN или базу данных** сразу после генерации. Не используйте полученный URL для постоянных прямых ссылок (hotlinking).

    **Два рекомендуемых подхода**:

    * **Проксирование на стороне сервера**: сразу после получения ответа выполните `requests.get(url)`, сохраните в собственное хранилище и верните на фронтенд собственный URL;
    * **Использование `b64_json`**: добавьте `"response_format": "b64_json"` в запрос, чтобы получить данные изображения напрямую в формате base64 — это избавит от лишнего кросс-доменного скачивания и идеально подходит для отображения на фронтенде или прямой записи в файл.

    Для кратковременного предпросмотра (отображение в рамках одной сессии) URL R2 можно использовать как есть, без сохранения.
  </Accordion>

  <Accordion title="Поддерживается ли потоковая передача?">
    Нет. Эта модель возвращает изображение целиком за один раз; потоковая передача не поддерживается. Если важна задержка, отображайте индикатор выполнения «генерация...» на стороне клиента и настройте таймаут **300 с** (с запасом).
  </Accordion>

  <Accordion title="Можно ли использовать официальный SDK OpenAI?">
    Да. Укажите `base_url` на `https://api.apiyi.com/v1` и задайте свой token APIYI в `api_key`. Однако `client.images.generate()` по умолчанию отправляет `size`/`n` — эта модель отклоняет оба параметра, поэтому мы рекомендуем выполнять прямые HTTP-запросы с помощью `requests` / `fetch` к `/v1/images/generations` и `/v1/images/edits`.
  </Accordion>

  <Accordion title="Есть ли существенная разница между prompt на китайском и английском языках?">
    Эта модель нативно поддерживает китайский язык, и результаты сопоставимы. Для специфических китайских сценариев (каллиграфия, элементы традиционных праздников) формулировки на китайском языке выглядят более естественно.
  </Accordion>

  <Accordion title="Можно ли по-прежнему генерировать изображения через /v1/chat/completions?">
    Да, этот эндпоинт по-прежнему работает, но он **больше не рекомендуется** — используйте вместо него `/v1/images/generations` и `/v1/images/edits` (это стабильнее, и тот же код будет работать с официальным релеем `gpt-image-2`).

    Формат чата имеет смысл только в двух сценариях: многоэтапное пошаговое редактирование или прямая передача URL онлайн-изображений. Обратите внимание: если намерение сгенерировать изображение неочевидно, модель может вернуть обычный текст вместо изображения (добавьте в начало вашего prompt фиксированный префикс, например «Generate an image:», чтобы подчеркнуть цель).

    Полный список параметров см. в [справочнике по API на базе чата](/en/api-capabilities/gpt-image-2-all/chat-completions).
  </Accordion>
</AccordionGroup>
