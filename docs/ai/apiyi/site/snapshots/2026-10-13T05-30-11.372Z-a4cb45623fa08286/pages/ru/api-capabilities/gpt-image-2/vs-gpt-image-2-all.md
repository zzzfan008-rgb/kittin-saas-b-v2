# GPT-image-2.5 / 2: официальные модели против reverse-версий

> Сравните официальные модели gpt-image-2.5-flare / gpt-image-2.5-sunburst / gpt-image-2 и созданные с помощью reverse-инжиниринга сестринские модели gpt-image-2.5-all, gpt-image-2-all, gpt-image-2.5-vip и gpt-image-2-vip: особенности каналов, цены, эндпоинты, форматы загрузки/вывода, баланс скорости и качества, следование prompt — выберите подходящий вариант.

## TL;DR

| Если вам требуется | Выберите |
| - | - |
| **Регулировка `quality` / inpainting по маске / произвольные пользовательские размеры (помимо 30 пресетов) / строгое соответствие полям OpenAI-API** | Официальные с тарификацией по token: `gpt-image-2.5-flare` (приоритет скорости) / `gpt-image-2.5-sunburst` (приоритет точности редактирования) / `gpt-image-2` (предыдущее поколение) |
| **Предсказуемый фиксированный тариф \$0.025/изображение + быстрый, стабильный результат (преимущество в скорости)** | `gpt-image-2-all` / `gpt-image-2.5-all` (Reverse, линейка ChatGPT-web, \~90 с; в основе 2.5-all лежит Images 2.5) |
| **Предсказуемый фиксированный тариф \$0.03/изображение + фиксированные размеры (30 пресетов, включая 4K)** | `gpt-image-2-vip` / `gpt-image-2.5-flare-vip` / `gpt-image-2.5-sunburst-vip` (Reverse, линейка Adobe; две модели 2.5 принимают все шесть уровней `quality`, `gpt-image-2-vip` до `high`) |

Все восемь моделей **в основе построены на базе серий GPT-Image 2.5 / 2 от OpenAI**. Различия заключаются в типе канала (официальный прямой доступ против реверс-инжиниринга), модели тарификации и детализации параметров. Три официальные модели имеют одинаковую цену и параметры; пять reverse-моделей имеют одинаковый формат вызова (две модели `-all` по \$0.025/изображение, трио `-vip` по \$0.03/изображение).

<Note>
  **Три reverse-линейки (-all / 2.5-all / трио -vip)**: В столбце «Reverse» на этой странице представлены **`gpt-image-2-all`**, **`gpt-image-2.5-all`** и **`gpt-image-2-vip` / `gpt-image-2.5-flare-vip` / `gpt-image-2.5-sunburst-vip`** (алиас `gpt-image-2.5-vip` = sunburst-vip). Все они используют одинаковый формат вызова (три модели `-vip` дополнительно поддерживают `size`) и тарифицируются за каждый вызов: \$0.025/изображение для двух моделей `-all`, \$0.03/изображение для трио `-vip`:

  * `gpt-image-2-all` / `gpt-image-2.5-all`: линейка ChatGPT web, генерация **\~90 с** — **преимущество в скорости**; в основе 2.5-all лежит Images 2.5
  * `gpt-image-2-vip` и две модели 2.5 -vip: линейка Adobe (Firefly), **блокировка `size` (30 пресетов, включая 4K)**; все три принимают `quality` (поведение канала, не обязательство): две модели 2.5 открыли `xhigh` / `max` при повторном тестировании 2026-09-10 и теперь принимают все шесть уровней, `gpt-image-2-vip` доходит до `high`; все три возвращают прозрачный фон; flare-vip — самый быстрый с более мягким стилем, sunburst-vip визуально близок к `gpt-image-2-vip`
  * Общие черты: ни одна из них не поддерживает `n`; `mask` на всех них выполняет повторную генерацию всего изображения без гарантии изменения только замаскированной области

  Для точного inpainting по маске, произвольных пользовательских размеров за пределами 30 пресетов или `n` > 1 используйте официальные модели (`gpt-image-2.5-flare` / `gpt-image-2.5-sunburst` / `gpt-image-2`).
</Note>

<Tip>
  **О текущей скорости**: генерация в `-all` / `-vip` происходит **медленнее, чем на момент запуска**, из-за **колебаний вычислительных мощностей на стороне OpenAI** — это затрагивает всех пользователей reverse-каналов, а не только APIYI; наш пул аккаунтов и инфраструктура работают в штатном режиме. Устанавливайте тайм-ауты на клиенте от 300 с и закладывайте больший запас времени для сложных prompt.
</Tip>

## Когда и какую модель выбирать

### Выбирайте `gpt-image-2-all` / `gpt-image-2.5-all` (Reverse), если:

<CardGroup cols={2}>
  <Card title="💰 Предсказуемая стоимость" icon="dollar-sign">

  </Card>

  <Card title="⚡ Более быстрая генерация" icon="bolt">
    Генерация за \~90 с — **немного быстрее**, чем у `-vip` и официальной версии. **Лучший UX при работе в реальном времени.**
  </Card>

  <Card title="🔁 Единая кодовая база, переключение в любой момент" icon="repeat">
    Стандартный формат Images API — **тот же код**, что и для трех моделей `-vip` и трех официальных моделей; переключайтесь или настраивайте фолбэк простой сменой имени `model`. `gpt-image-2-all` и `gpt-image-2.5-all` имеют одинаковую цену и поведение; новое имя лишь отражает переход веб-версии ChatGPT на Images 2.5.

  <Card title="🌏 Китайский язык + маркетинговый текст" icon="type">

  </Card>

### Выбирайте три модели `-vip` (Reverse, фиксированный размер), если:

<CardGroup cols={2}>
  <Card title="🎚️ Работает quality (все шесть уровней на 2.5)" icon="sliders-horizontal">
    В ходе тестирования `gpt-image-2.5-flare-vip` / `gpt-image-2.5-sunburst-vip` принимают все шесть уровней от `auto` до `max` (уровни `xhigh` / `max` открыты с 2026-09-10); `gpt-image-2-vip` поддерживает до `high`. Все это — особенности канала, а не обязательство сервиса. Сопоставление уровней: 2.5 `high` соответствует только `gpt-image-2-vip` `medium`, а 2.5 `max` — `gpt-image-2-vip` `high`; фиксированная стоимость \$0.03 не зависит от уровня.
  </Card>

  <Card title="⏱️ Выбор среди трех моделей" icon="hourglass">
    flare-vip — самая быстрая модель с более мягким визуальным стилем; sunburst-vip обеспечивает более высокое качество и точность редактирования, приближаясь по виду к `gpt-image-2-vip`; все три достигают одного и того же максимального уровня token (`max` на 2.5, `high` на `gpt-image-2-vip`). Все они работают медленнее, чем `-all` — для `max` на разрешении 1024² замеренное время составило 80–160 с — поэтому выбирайте их, когда допустимо более длительное ожидание.
  </Card>

  <Card title="🖼️ Фиксированные размеры / 4K" icon="expand">
    Параметр `size` **восстановлен** (с 2026-07-22): 30 предустановленных размеров (10 соотношений сторон × 1K/2K/4K). Главные баннеры для e-commerce, шаблоны плакатов и обои 4K генерируются в точных размерах — фиксированные \$0.03 за изображение без наценки за 4K.
  </Card>

  <Card title="🔁 Общий код с версиями -all" icon="copy">
    Та же структура запроса, что и у `-all` (всего одно дополнительное поле `size`) — **единая кодовая база позволяет переключаться между всеми пятью reverse-моделями**, меняя лишь имя `model` в зависимости от ваших предпочтений по скорости или качеству.
  </Card>
</CardGroup>

<Note>
  Параметр `size` модели `-vip` работает только на эндпоинтах `/v1/images/generations` и `/v1/images/edits` — **чат-эндпоинт `/v1/chat/completions` не поддерживает `size`**. Для произвольных пользовательских размеров за рамками 30 пресетов или точного inpainting по маске используйте официальные модели (`gpt-image-2.5-flare` / `sunburst`). </Note>

### Выбирайте официальные модели (`gpt-image-2.5-flare` / `sunburst` / `gpt-image-2`), если:

<CardGroup cols={2}>
  <Card title="🎚️ Уровни качества" icon="sliders-horizontal">
    Доступны все шесть уровней `quality` **с официальной гарантией**: уровни и количество token стабильны согласно официальной спецификации. В reverse-моделях 2.5 -vip также открыты все шесть уровней (зафиксировано 2026-09-10), но это поведение канала без обязательств, а `gpt-image-2-vip` по-прежнему ограничивается `high`.
  </Card>

  <Card title="🎯 Inpainting по маске" icon="paintbrush">
    Поддерживается маска с альфа-каналом — **точное изменение нужной области с сохранением остальной части изображения**. Reverse-модели лишь перегенерируют изображение целиком и не гарантируют изменение исключительно замаскированной области.
  </Card>

  <Card title="🖼️ Произвольные пользовательские размеры" icon="expand">
    `size` принимает **любое допустимое разрешение** (включая 4K) без привязки к пресетам. Тройка моделей `-vip` гарантирует только 30 пресетов и перезаписывает любые другие значения — **если требуются строго заданные пользовательские размеры, выбирайте официальные модели**.

## Подробные ключевые различия

### 1. Нюансы формата b64\_json (ловушка при миграции!)

По состоянию на июль 2026 года и официальные, и reverse-модели возвращают **чистый base64 (без префикса `data:`)** — однако ранее `gpt-image-2-all` включал этот префикс, поэтому наиболее безопасный универсальный код сначала проверяет его наличие:

```python theme={null}
# Universal pattern: detect the prefix before processing — works for all official and reverse models
b64 = resp["data"][0]["b64_json"]
if b64.startswith("data:"):          # handles historical prefixed responses
    b64 = b64.split(",", 1)[1]
with open("out.png", "wb") as f:
    f.write(base64.b64decode(b64))   # ✅ write file
img_tag = f'<img src="data:image/png;base64,{b64}">'  # ✅ browser render
```

<Warning>
  При переключении между официальными и reverse-моделями **код обработки `b64_json` необходимо изменить**, иначе вы получите поврежденный data URL или ошибку декодирования.
</Warning>

### 2. Управление разрешением

**`gpt-image-2-all` / `gpt-image-2.5-all`** (поля `size` нет — композиция задается в prompt; оба названия работают одинаково):

```
"Landscape 16:9 cinematic, old lighthouse at sunset"   → ~1672×941
"Portrait 9:16 phone wallpaper, cyberpunk city"        → ~941×1672
"1024×1024 square logo, minimalist cat line art"        → ~1254×1254
```

**Три модели `-vip`** (`gpt-image-2.5-vip` / `gpt-image-2.5-flare-vip` / `gpt-image-2-vip`; `size` восстановлена с 22.07.2026):

Принимают **30 предустановленных размеров** (10 соотношений сторон × 1K/2K/4K) — передавайте `size: "WIDTHxHEIGHT"` напрямую (должен быть одним из 30 пресетов; полный список в [таблице 30 размеров](/ru/api-capabilities/gpt-image-2-vip/overview#supported-sizes-full-30-size-table)). При тестировании все три модели также принимают `quality` (поведение канала, а не обязательство): две модели 2.5 принимают все шесть уровней (`xhigh` / `max` открыты 10.09.2026), `gpt-image-2-vip` — до `high`; выходные tokens `high` моделей 2.5 равны только `gpt-image-2-vip` `medium`, а их `max` равен его `high`:

```python theme={null}
client.images.generate(
    model="gpt-image-2.5-vip",   # alias = gpt-image-2.5-sunburst-vip; swap in gpt-image-2.5-flare-vip / gpt-image-2-vip on this line only
    prompt="...",
    size="3840x2160",   # ✅ one of the 30 presets; images endpoints only (not chat)
    quality="max"       # optional; all six tiers on the 2.5 models, gpt-image-2-vip stops at high; flat $0.03 regardless of tier
)
```

**Официальные модели** (строго учитывается `size` + уровни `quality`; в примере используется `gpt-image-2.5-flare`, для переключения на `sunburst` / `gpt-image-2` достаточно изменить только название модели):

```python theme={null}
client.images.generate(
    model="gpt-image-2.5-flare",
    prompt="...",
    size="2048x1152",   # ✅ output exactly this
    quality="max"       # all six tiers; xhigh / max on the two 2.5 models only; 2.5 high only equals gpt-image-2 medium
)
```

### 3. Различия в форматах загрузки и вывода

| Операция | Пять reverse-моделей (`-all` / `2.5-all` / трио `-vip`) | Три официальные модели (`2.5-flare` / `2.5-sunburst` / `gpt-image-2`) |
| - | - | - |
| **Загрузка референса** | файловое поле multipart `image` (эндпоинт edits) | файловое поле multipart `image[]` |
| **Скачивание результата** | По умолчанию `b64_json` (чистый base64, проверено в июле 2026 г.); явное указание `response_format: "url"` возвращает ссылку на R2 CDN (**срок действия 24 часа**) | `b64_json` (**чистый base64**, требуется декодирование) |
| **Объединение нескольких изображений** | Повторение поля `image` в эндпоинте edits | массив `image[]`, **не более 16** |

<Tip>
  **Общее для всех восьми моделей: при редактировании изображений / объединении нескольких изображений сжимайте каждое входное изображение до размера менее 1,5 МБ** (качество JPEG 80–90 / уменьшенное разрешение). Периодические ответы `shell_api_error` / `Unknown error` чаще всего вызваны слишком большим размером входных данных — сжатие ощутимо повышает процент успешных запросов и снижает задержку. **Выходное разрешение не зависит от размера входных данных** — качество задается на стороне вывода (`size` + `quality` для официальных моделей; уровень `size` плюс `quality` для трио `-vip`; формулировка prompt для `-all` / `2.5-all`), а не размером входного файла.
</Tip>

## FAQ

<AccordionGroup>
  <Accordion title="Нужно ли сжимать входные изображения? Помогает ли указание 4K / 8K в prompt?">
    **Да, настоятельно рекомендуется.** Для всех восьми моделей сжимайте каждое входное изображение до размера **менее 1,5 МБ** (качество JPEG 80–90 / уменьшенное разрешение): спорадические ответы `shell_api_error` / `Unknown error` чаще всего вызваны слишком большим размером входных данных, а сжатие ощутимо повышает процент успешных запросов и снижает задержку.

    **Не беспокойтесь о том, что сжатие ухудшит качество** — разрешение на выходе не зависит от размера входного файла. Элементы управления «на стороне вывода» различаются для трех семейств:

    * `gpt-image-2-all` / `gpt-image-2.5-all`: управляется формулировками композиции в prompt (см. таблицу проверенных формулировок на [странице обзора -all](/ru/api-capabilities/gpt-image-2-all/overview)) — `4K` / `8K` в prompt не учитываются
    * Три модели `-vip` (`gpt-image-2.5-vip` / `gpt-image-2.5-flare-vip` / `gpt-image-2-vip`): управляются полем `size` (30 предустановленных размеров, включая 4K), опционально с `quality` (шесть уровней на моделях 2.5, до `high` на `gpt-image-2-vip`) — `4K` / `8K` в prompt также не учитываются
    * Официальные модели (`gpt-image-2.5-flare` / `sunburst` / `gpt-image-2`): управляются `size` + `quality` (любой допустимый размер)

    Итог: уменьшение входных файлов лишь ускоряет работу — качество задается конфигурацией на стороне вывода, а не размером входного файла.
  </Accordion>

  <Accordion title="Можно ли вызывать все восемь моделей с помощью одного и того же API Key?">
    Да. Все восемь моделей работают в группе Default — один и тот же API Key вызывает их без дополнительной настройки. Обратите внимание: для вызова официальных моделей требуется token типа «Token-priority»; `-all` / `-vip` принимают любой тип token.
  </Accordion>

  <Accordion title="Какие эндпоинты следует использовать на реверс-канале?">
    **Используйте OpenAI Images API** (`/v1/images/generations` для text-to-image + `/v1/images/edits` для редактирования) по двум причинам:

    1. **Более стабильно**: апстрим-ресурсы для канала Images API более доступны, поэтому процент успешных вызовов выше
    2. **Совместимость с официальным релеем для удобного переключения**: метод вызова и формат параметров полностью совместимы с тремя официальными моделями (`gpt-image-2.5-flare` / `sunburst` / `gpt-image-2`) — если реверс-канал столкнется с ограничениями риск-контроля, **просто измените имя `model` для переключения на официальный релей** без каких-либо изменений в коде

    Также существует эндпоинт на базе чата (`/v1/chat/completions`, **больше не рекомендуется**), который полезен только для многоэтапного итеративного редактирования или прямой передачи URL онлайн-изображений. Обратите внимание: если намерение сгенерировать изображение не очевидно, он может вернуть обычный текст вместо изображения (добавьте фиксированный префикс, например «Generate an image:», чтобы зафиксировать намерение). Полный список параметров см. в [справочнике по API на базе чата для -all](/en/api-capabilities/gpt-image-2-all/chat-completions) / [справочнике по API на базе чата для -vip](/en/api-capabilities/gpt-image-2-vip/chat-completions).
  </Accordion>

  <Accordion title="Что выбрать среди реверс-каналов: -all или -vip?">
    Обе линейки представляют собой реверс-каналы (-all \$0.025 за изображение, -vip \$0.03 за изображение) с одинаковым форматом вызова (трио `-vip` дополнительно поддерживает фиксацию `size` и `quality`, все шесть уровней на моделях 2.5). Разница заключается в выборе между **скоростью и качеством с фиксацией размера**:

    * **Время генерации**: `-all` / `2.5-all` \~90 с — **преимущество в скорости**; трио `-vip` \~120–200 с. В настоящее время медленнее, чем на старте, из-за колебаний вычислительных мощностей на стороне OpenAI
    * **Качество**: детализация у `-vip` (линейка Adobe) **иногда выше** — подходит для демонстрационных изображений, когда вы не спешите; внутри трио sunburst-vip выглядит близко к `gpt-image-2-vip`, а flare-vip — мягче
    * **Фиксация размера**: трио `-vip` поддерживает 30 предустановленных значений `size` (включая 4K); `-all` / `2.5-all` отклоняют `size` — композиция задается в prompt

    Решение: нужен быстрый вывод → `-all` / `2.5-all`; требуются фиксированные размеры / 4K → трио `-vip`; нужны произвольные размеры за рамками 30 пресетов или точная маска → официальные модели. Подробности см. в [обзоре GPT-Image-2.5-VIP](/ru/api-capabilities/gpt-image-2-vip/overview).
  </Accordion>

Все три достигают одинакового максимального уровня token
    * **Качество и скорость**: flare-vip — самая быстрая модель с более мягким стилем и меньшим количеством декоративных деталей; sunburst-vip визуально близка к `gpt-image-2-vip`
    * **Размер по умолчанию**: у flare-vip он фиксирован как 1024×1536, у двух других — 2048×2048; всегда передавайте `size` для его фиксации
