# VEO 3.1 Официальная генерация видео

> Полное руководство по официальному релей-каналу Google Veo 3.1: прозрачная передача запросов в Google AI Studio, тарификация за каждый запрос по $0.3 / $1.2, гибкая длительность 4 / 6 / 8 секунд, уровни 720p / 1080p / 4k и подключение без лишних действий — не требуется переключать группу или режим тарификации.

## Обзор

**VEO 3.1 Official** — это канал **официального релея** APIYI для Google Veo 3.1, обеспечивающий прозрачную пересылку запросов к асинхронным эндпоинтам `veo-3.1-generate-preview` / `veo-3.1-fast-generate-preview` в Google AI Studio с идентификаторами моделей, полями ответов и ограничениями, полностью идентичными вышестоящему сервису. **Тарификация за каждый запрос**, **доступность для вызова в группе `Default`** — самый удобный и доступный канал Veo 3.1 официального качества на сегодняшний день.

<Note>
  **🎬 Главное**: прозрачная пересылка в Google AI Studio + нативный синхронизированный звук + гибкая длительность 4 / 6 / 8 секунд + три варианта разрешения (720p / 1080p / 4k) + тарификация за запрос от \$0.3 + **группа `Default` + Pay-per-request или Pay-as-you-go Priority tokens** (выделенная группа не требуется; чистый Pay-as-you-go не поддерживается). **Подходит для коротких рекламных роликов, материалов для e-commerce, контента для социальных сетей и демонстраций продуктов**, где требуется официальное качество при максимально простом подключении.
</Note>

<Warning>
  **⚠️ Скачивайте через `/content` и сохраняйте у себя**: как только `status: "completed"`, **вызовите `GET /v1/videos/{task_id}/content` для получения бинарных данных MP4** и сохраните их в собственном OSS / CDN перед отдачей конечным пользователям. Завершенный ответ **может** также содержать `video_url` (прямая ссылка без авторизации) — срок ее действия **истекает примерно через 24 часа** (см. `expires_at`), и она **не гарантируется для каждой задачи**, поэтому используйте ее только для временного предпросмотра и никогда не используйте как постоянный адрес. См. раздел [Эндпоинты API](#api-endpoints) ниже.
</Warning>

<Prompt description="Поручите ИИ-агенту интеграцию или отладку официального VEO 3.1 text-to-video и image-to-video. Скопируйте и вставьте в Codex, Claude Code, Cursor и аналогичные инструменты." icon="bot" actions={["copy"]}>
  Выполните интеграцию / устранение неполадок VEO 3.1 Official text-to-video и image-to-video в этом проекте.

  Ознакомьтесь с документацией перед написанием кода: загрузите [https://docs.apiyi.com/en/api-capabilities/veo-3-1-official/overview.md](https://docs.apiyi.com/en/api-capabilities/veo-3-1-official/overview.md), чтобы получить текстовую версию этой страницы. Для более подробной информации о параметрах точно так же добавьте `.md` к страницам text-to-video и image-to-video.

  Требования:

  1. Используйте трехэтапный асинхронный процесс вместо синхронного ожидания. Этот канал работает **только асинхронно**: `POST /v1/videos` отправляет задачу и возвращает `task_id`, затем опрашивайте `GET /v1/videos/{task_id}` каждые **8–10 секунд**, пока `status` не примет значение `completed`, после чего скачайте MP4 из `GET /v1/videos/{task_id}/content`. **webhook не поддерживается, только polling** — не ищите настройки callback.

  2. Получение видео (**самый важный пункт для этой модели**): считайте эндпоинт `/content` единственным источником истины для бинарного потока MP4; этот запрос **обязательно должен содержать заголовок `Authorization`**, поэтому фронтенд **не может** использовать его напрямую в теге video `src` — запрос из браузера без заголовка авторизации вернет ошибку 401. Ответ об успешном завершении **может** содержать прямую ссылку `video_url`, не требующую авторизации, однако срок ее действия истекает примерно через 24 часа (см. `expires_at`), и она **не гарантируется для каждой задачи** — не полагайтесь на нее в коде; используйте ее для быстрого предпросмотра при наличии, в противном случае работайте через `/content`. Корректный подход: **как только статус станет `completed`, скачайте MP4 на стороне сервера и повторно разместите его в собственном объектном хранилище или CDN**, после чего отдавайте пользователям собственный URL. **Удаленное видео хранится всего около 24 часов, поэтому никогда не используйте `task_id` в качестве постоянного адреса**. Если `/content` возвращает 400, повторяйте попытки каждые 4 секунды в течение примерно 30 секунд — сразу после того, как `status` переходит в `completed`, возникает окно длительностью около 20 секунд, когда возвращается 400 (текст ошибки: `task status is IN_PROGRESS`). При скачивании с помощью curl обязательно добавьте `-f --retry-all-errors`; иначе ошибка 400 не будет обработана повторно, а JSON с ошибкой запишется в видеофайл. **С `502` ситуация иная**: провайдер не может получить файл, и повторные попытки не помогут, поэтому прекратите попытки после 2 раз, отметьте задачу как завершившуюся сбоем и сохраните `task_id` — никогда не создавайте бесконечный цикл повторов.

  3. Многоуровневые тайм-ауты: заложите 30 секунд на отправку POST-запроса (загрузка multipart-изображения для референса может занять больше времени). Ограничьте время ожидания при опросе в зависимости от разрешения: **3 минуты** для 720p и 1080p, **10 минут** для 4K. Вынесите эти значения в конфигурацию, а не прописывайте единое жестко закодированное значение.

  4. Модель и параметры: имя модели — либо `veo-3.1-fast-generate-preview` (более дешевая, подходит для повседневных задач), либо `veo-3.1-generate-preview` (стандартный тариф). Поле длительности называется **`seconds`, а не `duration`**, и оно **обязательно должно быть строкой** (`"4"` / `"6"` / `"8"`) — числовое значение отклоняется сервером. **Использование имени поля `duration` не вызывает ошибки: оно просто молча игнорируется, а длительность сбрасывается на 4 секунды** — именно из-за этого возникает ситуация «я запросил 8 секунд, а получил 4». **Длительность и разрешение связаны**: и `1080p`, и `4k` принимают **только `seconds` из `"8"`**, а передача `"4"` или `"6"` приводит к ошибке; только `720p` поддерживает все три варианта длительности. Поэтому, если ваш интерфейс позволяет выбирать разрешение и длительность одновременно, ограничьте доступные пары, чтобы исключить недопустимые комбинации. Для 4K дополнительно требуется модель `veo-3.1-generate-preview` и 10-минутный тайм-аут. Учтите, что 4K рендерится в 4–6 раз медленнее, чем 1080p, и создает файлы примерно в 10 раз больше, при этом **тарификация за вызов не зависит ни от длительности, ни от разрешения (4K стоит столько же и ничего не экономит)** — поэтому используйте 1080p по умолчанию и сделайте выбор 4K явным решением пользователя.

  5. Три жестких ограничения для image-to-video: запрос должен отправляться как **`multipart/form-data`**, а не JSON; поле изображения должно называться **строго `input_reference`** (`image`, `reference` и `input_image` игнорируются); и **принимается только одно изображение** — лишние изображения автоматически отбрасываются. Удаленные URL **не принимаются**, поэтому передавайте файл или Base64. Поддерживаемые форматы: `image/jpeg`, `image/png` и `image/webp`. Обратите внимание, что этот канал также **не поддерживает первый/последний кадр (first/last-frame) и несколько референсов (multi-reference)**, поэтому не ориентируйтесь на документацию самого Google для Veo 3.1 в этих аспектах. В режиме multipart поля `metadata.*` преобразуются в обычные поля формы с именами `resolution`, `aspectRatio` и `seed`.

  6. **Не передавайте `generateAudio`.** Veo 3.1 генерирует аудио нативно, но передача этого параметра приводит к ошибке `INVALID_ARGUMENT` от апстрима. Чтобы управлять звуковыми эффектами, речью или атмосферой, опишите пожелания в prompt — на этом канале поля audio нет вовсе.

  7. Тарификация и ошибки: **тарификация осуществляется за вызов, по имени модели**, независимо от длительности, разрешения и передачи референсного изображения. В асинхронном режиме **сбои генерации, блокировки модерации и ошибки перегрузки не тарифицируются — списание происходит только при статусе `completed`**, поэтому автоматические повторы не несут риска повторного списания средств. Обработка ошибок: ошибка с префиксом `PUBLIC_` указывает на блокировку модерацией на стороне апстрима, она не тарифицируется, и запрос можно повторить сразу после корректировки prompt; `5xx` или `INTERNAL` — это временные ошибки апстрима, для которых имеет смысл выполнить 1–2 повторные попытки с тем же seed; задача со статусом `failed` обычно связана с модерацией, нехваткой мощностей у апстрима или недоступностью видеофайла и также не тарифицируется (любые списания возвращаются автоматически); причина указывается в `error.message`, поэтому логируйте ее.

  8. Важная настройка token: для этой модели требуется, чтобы token был настроен на **тарификацию за вызов** или **приоритет pay-as-you-go**; **обычный pay-as-you-go не поддерживается**. Если вызов завершается с ошибкой о режиме тарификации, переключите режим token в консоли.

  9. Считывайте ключ из переменной окружения `APIYI_API_KEY` и используйте [https://api.apiyi.com/v1](https://api.apiyi.com/v1) в качестве базового URL. Никогда не прописывайте его жестко в коде и не коммитьте в git.

  10. По завершении выполните реальный вызов text-to-video и вызов image-to-video, затем покажите мне полученные видео и стоимость этих двух вызовов.
</Prompt>

## Цены

APIYI использует тарификацию **pay-per-request** — фиксированная цена в пределах поддерживаемых комбинаций длительности/разрешения, **без доплаты за более длинный вывод или более высокое разрешение**. По публичным тарифам `ai.google.dev/gemini-api/docs/pricing`, официальный Veo 3.1 от Google тарифицируется за секунду; указанные ниже скидки рассчитаны для **8-секундных видео**.

| - | - | - | - |
| `veo-3.1-fast-generate-preview` | **\$0.3 / req** | \$0.96<br />**68.8% off** | \$2.40<br />**87.5% off** |

<Info>
  **Примечания по тарификации**:

  * Взимается **за запрос по названию модели**, независимо от длительности (4/6/8 сек), разрешения (720p/1080p/4k) или наличия `input_reference` — **выбор 4K стоит столько же, сколько 720p**
  * В асинхронном режиме неудачные генерации / отклонения по политике контента / ошибки емкости **не тарифицируются**

  * Рендеринг 4K работает в 4–6 раз медленнее и создает файлы примерно в 10 раз больше — **для ежедневного использования по умолчанию выбирайте 1080p**
  * Официальный тариф Google для 4K составляет \$0.30/сек (fast) / \$0.60/сек (standard), то есть \$2.40 / \$4.80 за 8 сек (источник: `ai.google.dev/gemini-api/docs/pricing`)
</Info>

## Настройка группы

VEO 3.1 Official **работает в группе `Default`** (1x), **отдельное переключение группы не требуется**. Режим тарификации Token должен быть **Pay-per-request** или **Pay-as-you-go Priority** — **чистый Pay-as-you-go не поддерживается** (при необходимости переключите режим Token в [консоли](https://api.apiyi.com/token)).

<Tip>

</Tip>

## Эндпоинты API

| Эндпоинт | Метод | Назначение | Content-Type |
| - | - | - | - |
| `/v1/videos` | POST | Отправка задачи на генерацию видео (text-to-video / image-to-video, единый эндпоинт) | `application/json` или `multipart/form-data` |
| `/v1/videos/{task_id}` | GET | Запрос статуса и прогресса задачи | — |
| `/v1/videos/{task_id}/content` | GET | **Скачивание созданного MP4 (бинарный поток)** | — |

<Warning>
  **⚠️ Скачивайте через `/content`; `video_url` предназначен только для временного предпросмотра**

  Стандартный способ получения видео — **`GET /v1/videos/{task_id}/content`, который возвращает бинарный поток MP4** (требуется заголовок `Authorization: Bearer`).

  Что следует учитывать:

  * Ответ о завершении задачи **может** содержать `video_url` (прямая ссылка без авторизации) и `expires_at` (примерно через 24 часа); это **не гарантируется для каждой задачи**, поэтому ваш код должен обрабатывать его отсутствие
  * Фронтенд **не может** использовать эндпоинт `/content` напрямую в теге `<video>` — запросы браузера без заголовка авторизации вернут ошибку 401; `video_url` можно использовать для временного предпросмотра до истечения срока действия
  * **Как только `status: "completed"`, скачайте MP4 и сохраните его в собственном хранилище OSS / CDN**, а затем отдавайте свой URL конечным пользователям
  * Удаленная копия хранится около 24 часов — **не полагайтесь в долгосрочной перспективе на удаленные `task_id` или `video_url`** для получения видео
</Warning>

<Tip>
  **Выбор эндпоинта**: основной — `api.apiyi.com`; резервный шлюз `b.apiyi.com` работает аналогично.
</Tip>

### `seconds` (длительность видео)

Поле длительности называется **`seconds`** (а не `duration`) и **должно быть строкой** (`"4"` / `"6"` / `"8"`). Если передать число, возвращается:

```
parse_request_failed: cannot unmarshal number into Go struct field ... duration of type string
```

| Value | 720p | 1080p | 4k |
| - | - | - | - |
| `"4"` | ✅ | ❌ | ❌ |
| `"6"` | ✅ | ❌ | ❌ |
| `"8"` | ✅ (по умолчанию) | ✅ (обязательно) | ✅ (обязательно) |

<Warning>
  **Распространенная ошибка: поле с именем `duration` тихо игнорируется.** `duration` не распознается этим каналом → оно отбрасывается → длительность откатывается к значению по умолчанию **4 сек.**:

  * В 720p (и на других уровнях, где разрешены 4 сек.): **ошибки нет, но вы получаете только 4 сек.** (это именно тот случай «отправили 8s, получили 4s»)
  * В 1080p / 4k: 4 сек. недопустимы, поэтому возникает ошибка `Resolution 1080p requires duration seconds to be 8 seconds, but got 4`

  **Правильное использование: отправляйте поле `seconds` со значением `"8"` (строка).**
</Warning>

Приоритет параметров: `metadata.durationSeconds > seconds > 8`

### `metadata.resolution` (уровень разрешения)

| Value | Pixels (landscape) | Pixels (portrait) | Примечания |
| - | - | - | - |
| `720p` (по умолчанию) | `1280x720` | `720x1280` | Все три длительности |
| `1080p` | `1920x1080` | `1080x1920` | Только **`seconds="8"`** |
| `4k` | `3840x2160` | `2160x3840` | Только **`seconds="8"`**, рендер в 4–6 раз медленнее |

Приоритет параметров: `metadata.resolution > size > 720p`

### ⚠️ Не передавайте `generateAudio`

Veo 3 / 3.1 **изначально поддерживает звук**, но параметр `generateAudio` **передавать нельзя** — вышестоящий сервис отклонит запрос с `INVALID_ARGUMENT`. Чтобы управлять звуком, **запишите намерение в свой prompt**:

> "Морской маяк в сумерках; волны, далекие морские птицы, тихий ветер, кинематографическая атмосфера"

  <Step title="Используйте асинхронный поллинг, а не синхронное ожидание">

  </Step>

  <Step title="Задавайте клиентские таймауты по категориям">
    * 720p / 1080p: жесткий таймаут 3 мин
    * 4K: жесткий таймаут 10 мин
    * Отправка POST (multipart): минимум 30 сек
  </Step>

Эндпоинт `/content` **иногда возвращает 400** сразу после смены `status`; повторите попытку через 4 секунды (в примерах клиентов это уже предусмотрено). Ответ `502` от этого же эндпоинта означает, что провайдер не может получить файл — повторные попытки не помогут.
  </Step>

  <Step title="Описывайте требования к звуку в prompt">

  </Step>
</Steps>

## Коды ошибок и повторные попытки

| Статус / Симптом | Значение | Рекомендуемое действие |
| - | - | - |
| `400` + `parse_request_failed` | Параметр `seconds` был числом | Используйте строку `"4"` / `"6"` / `"8"` |
| Только 4 сек / `... but got 4` | Поле называлось `duration` (молча игнорируется, с откатом к 4 сек) | Используйте `seconds` со значением `"8"` (строка) |
| `INVALID_ARGUMENT` | Передано `generateAudio` или длительность, отличная от 8 сек при 1080p/4k | Удалите `generateAudio`; установите `seconds="8"` для HD/4K |
| `401` | Недействительный token | Проверьте `Authorization: Bearer <key>` (без лишних пробелов), действителен ли ключ |
| `429` | Превышен лимит запросов / недостаточно средств на балансе | Повторите запрос с экспоненциальной задержкой; выполните пополнение и повторите попытку |
| `5xx` / `INTERNAL` | Временная ошибка на стороне вышестоящего сервиса | Повторите попытку 1–2 раза с тем же seed (тарификация не производится) |
| `GET /content` возвращает 400 (`task status is IN_PROGRESS`) | `status` только что переключился на `completed` (в течение примерно до 20 секунд) | Повторяйте запрос каждые 4 сек в течение примерно до 30 сек; для curl требуется `-f --retry-all-errors` |
| `GET /content` возвращает `502` | Провайдер не может получить этот видеофайл (сейчас встречается редко, см. FAQ ниже) | **Повторные попытки не помогут** (ошибка 502 останется даже спустя часы). Сохраните `task_id` и свяжитесь с нами для проверки списания; повторная отправка в виде новой задачи обычно срабатывает |
| Задача `failed` | Сбой генерации (обычно модерация контента, нехватка мощностей вышестоящего сервиса или невозможность получить созданный файл) | См. `error.message`; скорректируйте prompt и повторите попытку; **задача не тарифицируется, любые списания возвращаются автоматически** |

<Info>
  **Рекомендуемые настройки клиента**:

  * Таймаут отправки POST-запроса: **30 сек** (для multipart-загрузок может потребоваться больше)
  * Интервал опроса (polling): **8–10 сек**; максимальное время ожидания для 720p/1080p — **3 мин**, для 4K — **10 мин**
  * Повтор с экспоненциальной задержкой для ошибок 5xx и `failed` (рекомендуется 1–2 попытки)
  * При ошибке 400 от `/content` повторяйте запрос каждые 4 секунды в течение примерно до 30 секунд
  * **Обрабатывайте `400` и `502` от `/content` по-разному**: ошибка `400` исчезает при повторной попытке; `502` — нет: прекратите попытки после 2 раз, пометьте задачу как завершившуюся с ошибкой и сохраните `task_id`
</Info>

<AccordionGroup>
  <Accordion title="Официальный канал против Reverse-канала — в чем разница? Можно ли по-прежнему использовать Reverse-канал?">
    **Официальный (эта страница)**: прозрачный проброс к апстрим-эндпоинтам Google AI Studio. Идентификаторы моделей совпадают с апстримом Google (`veo-3.1-generate-preview` / `veo-3.1-fast-generate-preview`), стоимость — \$0.3 / \$1.2 за запрос, только асинхронный эндпоинт.

    **Reverse** (существующий [VEO 3.1](/en/api-capabilities/veo/overview)): доступ через реверс-инжиниринг к Google Flow. Идентификаторы моделей — серии `veo-3.1-fast` / `veo-3.1` / `-fl`, стоимость от \$0.15 за запрос — дешевле, поддерживаются как **потоковый синхронный (streaming sync)**, так и асинхронный режимы, плюс **frame-to-video** (первый/последний кадр).

    Полную информацию см. в [Матрице выбора: Official или Reverse](/ru/api-capabilities/veo-3-1-official/vs-veo-reverse). Оба канала сосуществуют; выбирайте в зависимости от задач бизнеса.
  </Accordion>

  <Accordion title="Поле length — это секунды или длительность? И почему оно обязательно должно быть строкой?">
    **Поле запроса — `seconds`** (строка `"4"` / `"6"` / `"8"`). Название `duration` не распознается — оно просто игнорируется, и длительность откатывается к значению по умолчанию в 4 секунды, что и является первопричиной проблемы «отправили 8s, а получили только 4s».

    Что касается того, почему это должна быть строка: структура Go на бэкенде объявляет это поле (внутреннее имя `duration`) как `string`, поэтому число отклоняется на уровне декодера с ошибкой `parse_request_failed: cannot unmarshal number into Go struct field ... duration of type string` (`duration` в этой ошибке — внутреннее имя поля на бэкенде, в вашем же запросе по-прежнему передается `seconds`). **Запомните: передавайте `seconds` и берите значение в кавычки: `"4"` / `"6"` / `"8"`**.
  </Accordion>

  <Accordion title="Как добавить диалог / звуки окружения / фоновую музыку? Можно ли передавать generateAudio?">
    Veo 3 / 3.1 — это модель генерации видео с **нативной поддержкой звука**, но параметр `generateAudio` **передавать нельзя** (апстрим возвращает `INVALID_ARGUMENT`). Чтобы управлять звуком, **опишите желаемое в вашем prompt**:

    > «Прибрежный маяк в сумерках; волны, далекие чайки, негромкий шум ветра, кинематографичная атмосфера»
  </Accordion>

  <Accordion title="fast против standard — что выбрать? Действительно ли fast работает быстрее?">
    * При одинаковых параметрах **время рендеринга примерно одинаково** (замеры для 720p 8 сек: fast 83 с, standard 78 с). **fast не быстрее — он дешевле** (\$0.3 против \$1.2)
    * По умолчанию используйте `veo-3.1-fast-generate-preview`
    * Переключайтесь на `veo-3.1-generate-preview` для финальной сдачи работы или когда критически важны детализация и физическая согласованность
    * A/B-тестирование в продакшене: запустите оба варианта с одинаковым prompt + seed и выберите визуально
  </Accordion>

  <Accordion title="Стоит ли использовать 4K?">
    **В большинстве случаев не рекомендуется**:

    * Одинаковая цена за запрос выглядит привлекательно
    * Но рендеринг происходит в **4–6 раз медленнее** (720p 80 с → 4K 350 с)
    * Файлы примерно в 10 раз больше (720p 4 МБ → 4K 40 МБ) — расходы на трафик и хранилище удваиваются
    * 1080p визуально достаточно для большинства сценариев воспроизведения

    **Если вам действительно нужен 4K**: используйте `veo-3.1-generate-preview`, укажите `seconds="8"` (обязательно), таймаут на клиенте ≥ 10 мин, запускайте как фоновую асинхронную задачу.
  </Accordion>

  <Accordion title="Когда задача считается завершенной? Есть ли webhook?">
    * **webhook отсутствуют**; выполняйте только опрос `GET /v1/videos/{task_id}`
    * Рекомендуемый интервал опроса: **8 сек** (по замерам этого достаточно, и это не приведет к превышению лимита запросов)
    * Замеренное время: 720p / 1080p — 60–115 сек, 4K — 5–6 мин
    * Таймауты на стороне клиента: 3 мин для 720p/1080p, 10 мин для 4K
  </Accordion>

  <Accordion title="GET /content возвращает 400 или 502 — эти ошибки требуют совершенно разной обработки">
    **`400`: просто подождите.** Сразу после того, как `status` переключается в `completed`, вызов `/v1/videos/{task_id}/content` иногда возвращает 400, так как видеофайл еще не завершил синхронизацию. Это окно длится примерно до 20 секунд, поэтому **повторяйте запрос каждые 4 секунды в течение максимум 30 секунд** (в примерах клиентов это уже реализовано). При использовании curl обратите внимание, что `--retry` по умолчанию не повторяет запрос при 400 — добавьте `-f --retry-all-errors`.

    **`502`: повторные попытки не помогут.** Тело ответа выглядит как `{"error":{"message":"Upstream service returned status 502"}}`. Сама генерация прошла успешно — `GET /v1/videos/{task_id}` по-прежнему возвращает `status: "completed"` со статусом `progress: 100`, — но **провайдер не может получить этот видеофайл**. По нашим замерам, ошибка 502 сохраняется и спустя часы, поэтому **сама по себе ситуация не исправится**. Никогда не делайте бесконечный цикл повторов для этой ошибки.

    Что делать:

    1. Повторите запрос максимум дважды; если по-прежнему возвращается 502, пометьте задачу как завершившуюся сбоем
    2. **Сохраните `task_id` и свяжитесь с нами** — тарификация за эту генерацию уже произошла, мы проверим данные и решим вопрос
    3. Повторная отправка в виде новой задачи обычно успешно создает видео; менять prompt не требуется

    **Сейчас такое случается редко**: большинство задач перед отправкой ответа `completed` проверяются на наличие доступного для загрузки видеофайла; если файл получить невозможно, задача переходит в статус `status: "failed"` (с указанием причины в `error.message`), а **списанные средства автоматически возвращаются**, поэтому вы больше не платите за видео, которое не можете забрать. Однако полностью исключить это нельзя — **возврат `GET /v1/videos/{task_id}` со значением `completed` не означает, что видео гарантированно доступно для скачивания.** Относитесь к этому как к двум отдельным проверкам успешности.
  </Accordion>

  <Accordion title="Можно ли получить прямую ссылку (URL) на видео? Может ли фронтенд обращаться к эндпоинту напрямую?">
    **Иногда, но только временно**. Ответ о завершении задачи **может** содержать `video_url` (прямая ссылка без авторизации) и `expires_at` (временная метка примерно через 24 часа после завершения). Это **не гарантируется для каждой задачи**, и ссылка перестает работать после истечения срока действия, поэтому не распространяйте ее в качестве постоянного адреса.

    **Стандартный способ получения видео**: после `status: "completed"` вызовите `GET /v1/videos/{task_id}/content` для получения **бинарного потока MP4** (требуется заголовок `Authorization: Bearer`). Это работает для каждой задачи.

    **Стандартный паттерн для продакшена**:

    1. Бэкенд скачивает MP4 сразу после завершения задачи → отправляет в ваше собственное хранилище OSS / CDN
    2. Конечным пользователям отдается ваш CDN URL
    3. **Тег `<video>` на фронтенде НЕ должен указывать напрямую на `/content`** — браузеры не могут прикрепить заголовок авторизации, и запросы завершатся с ошибкой 401; при наличии `video_url` вы можете использовать его для мгновенного предпросмотра
  </Accordion>

  <Accordion title="Как долго видео хранятся на сервере? Нужно ли скачивать их сразу?">
    **Около 24 часов**, согласно полю `expires_at` в ответе (если поле отсутствует, считайте срок равным 24 часам). **Настоятельно рекомендуется скачивать файл сразу после завершения** и сохранять локально — не полагайтесь в долгосрочной перспективе на удаленные `task_id` или `video_url`; ни один из них не работает после истечения срока.
  </Accordion>

  <Accordion title="Почему прогресс изменяется скачками?">
    Поле `progress` имеет низкую степень детализации — **оно переключается только между несколькими фиксированными шагами** (такими как 0 / 10 / 30 / 50 / 100). Не используйте его для процентного индикатора прогресса (progress bar). Используйте спиннер или рассчитывайте соотношение «прошедшее время / ожидаемое время» самостоятельно.
  </Accordion>

  <Accordion title="Взимается ли плата за неудачные генерации?">
    **Нет**. **Плата взимается только за задачи в статусе `status=completed`**. Задачи со статусом `failed`, отмененные, отклоненные политикой контента или завершившиеся ошибкой параметров — бесплатны. **Нет готового видео — нет списания**.
  </Accordion>

  <Accordion title="Позволяет ли seed воспроизводить идентичные видео?">
    **Не байт-в-байт**. Замеры показали: одинаковый prompt + одинаковый seed (`88888`) + одинаковые параметры при двух запусках fast дают размеры файлов 9.81 МБ и 9.25 МБ, md5 полностью различаются, время рендеринга также разное.

    **Однако seed — это не просто декорация**: результаты с одинаковым seed **группируются близко друг к другу** (тест из 5 запусков показал разброс размера файлов внутри группы всего 6%), тогда как при смене seed происходит **систематический сдвиг** (межгрупповой разброс +36.8%). Выводы:

    * Нужен «стабильный стиль/вид» → зафиксируйте seed
    * Хотите «исследовать вариации» → меняйте seed вместо бесконечной правки prompt
    * Нужен «точный повтор» → забудьте об этом, просто сохраняйте mp4
  </Accordion>

  <Accordion title="Можно ли передавать несколько референсных изображений? Первый и последний кадры?">
    **На данный момент ничего из этого не поддерживается**. Режим Image-to-video принимает только 1 изображение с фиксированным именем поля `input_reference`, и **только в виде файла или base64, удаленные URL не поддерживаются**.

    Апстрим Google Veo 3.1 поддерживает несколько референсов, первый/последний кадры и расширение видео, но данный канал этого не умеет. **Для работы с первым/последним кадром используйте серию `-fl` в [VEO 3.1 (Reverse)](/en/api-capabilities/veo/overview)**.
  </Accordion>

  <Accordion title="Лимиты на параллельные запросы? Ограничения QPS?">
    При тестировании 10 одновременных отправок все задачи успешно встали в очередь без отклонений. Точный верхний лимит публично не разглашается. **Для продакшена рекомендуется ограничение: количество активных запросов в обработке (in-flight) ≤ 10**, с экспоненциальной задержкой при ошибках 429 / 5xx.
  </Accordion>

  <Accordion title="Есть ли на видео водяные знаки или метаданные о происхождении?">
    * Видимых водяных знаков нет
    * Но видео содержат метаданные **Google C2PA Content Credentials** (выданные Google C2PA Media Services, формат `urn:c2pa:...`), встроенные в структуру MP4. Конечные пользователи их не видят; **инструменты C2PA (например, Adobe Content Authenticity) могут подтвердить факт «сгенерировано с помощью Veo»**
    * Учитывайте это при сценариях дистрибуции; на обычное воспроизведение это никак не влияет
  </Accordion>

  <Accordion title="Можно ли использовать официальный SDK OpenAI напрямую?">
    Частично. Интерфейс соответствует соглашениям OpenAI (авторизация через `Bearer` + `/v1/...`), но официальный SDK OpenAI **не предоставляет метод `videos.create`** (`/v1/videos` — это кастомный путь). Используйте низкоуровневый метод `client.post()` из SDK OpenAI или обычные HTTP-запросы. **Обычный HTTP проще всего** — см. примеры кода в [Интерактивной песочнице Text-to-Video](/ru/api-capabilities/veo-3-1-official/text-to-video).
  </Accordion>
</AccordionGroup>
