# MAI-Image 2.6: генерация и редактирование изображений

> Полное руководство по Microsoft MAI-Image 2.6 (MAI-Image-2.6 / MAI-Image-2.6-Flash): генерация по тексту и редактирование по референсным изображениям (объединение от 1 до 5 изображений), настраиваемые ширина и высота с площадью до 1536×1536, качественный рендеринг китайского текста, фиксированная цена за изображение $0.12 / $0.06 независимо от размера.

## Обзор

**MAI-Image 2.6** — это собственная модель генерации изображений от Microsoft AI, выпущенная 2026-09-04 и доступная в режиме public preview на Microsoft Foundry. На момент запуска она занимала **2-е место как по генерации изображений по тексту, так и по редактированию изображений на Arena**, а также **1-е место по редактированию изображений на Artificial Analysis** (по состоянию на 2026-09-04, согласно анонсу Microsoft).

APIYI предоставляет два варианта через официальный канал Microsoft. Оба используют одинаковые эндпоинты и параметры:

* **`MAI-Image-2.6`**: флагманская версия, настроенная на максимальное качество и точность
* **`MAI-Image-2.6-Flash`**: быстрая версия. По заявлению Microsoft, она генерирует изображения в 2,8 раза быстрее, чем GPT-Image-2-Medium, и подходит для высоконагруженных рабочих процессов в production

<Note>
  **Главные особенности**: **превосходный рендеринг китайского текста** (вывески магазинов, вертикальные парные надписи и рукописный текст передаются с точностью до иероглифа), **высокоточное редактирование** (изменяется только запрошенная часть, остальное остается попиксельно идентичным), произвольный холст с помощью `width` + `height` (с площадью до 1536×1536), а также **фиксированная цена за изображение независимо от размера**. Генерация изображения размером 1024×1024 занимает около 17 с на Flash и около 30 с на 2.6.
</Note>

<Warning>
  **📌 Три вещи, которые нужно знать перед началом работы**

  1. **Поддерживаются только два эндпоинта**: `/v1/images/generations` (генерация по тексту, JSON) и `/v1/images/edits` (редактирование, `multipart/form-data`). **`/v1/chat/completions` и `/v1/responses` не поддерживаются** и возвращают 404.
  2. **Не передавайте `response_format`, `seed` или `negative_prompt`**. Все три параметра сразу возвращают 400. Ответ всегда приходит в формате `data[0].b64_json` (PNG).
  3. **Задавайте размер с помощью `width` + `height`, а не `size`**. На эндпоинте генерации по тексту `size` игнорируется без предупреждения, и вы всегда получаете 1024×1024.
</Warning>

<Info>
  Все API изображений являются **синхронными**: идентификатор асинхронной задачи (async task ID) отсутствует. При отключении клиента результат будет потерян, но запрос все равно тарифицируется. Установите для этой модели увеличенный таймаут. См. раздел [Главное об API изображений и лучшие практики](/ru/api-capabilities/image-api-best-practices).
</Info>

## Поручите интеграцию AI-агенту

<Note>
  Если вы ведете разработку с помощью Codex / Claude Code / Cursor, скопируйте приведенный ниже prompt в агент. Сначала агент загрузит текстовую версию этой страницы (добавьте `.md` к любому URL документации), а затем напишет код под ваш стек. Здесь прямо указаны типичные ошибки: таймауты, **три параметра, возвращающие 400**, `width`/`height` вместо `size` и редактирование исключительно через загрузку файлов.
</Note>

<Prompt description="Поручите агенту-программисту выполнить интеграцию или отладку генерации и редактирования изображений с помощью MAI-Image 2.6. Скопируйте и вставьте это в Codex, Claude Code, Cursor и т. д." icon="bot" actions={["copy"]}>
  Интегрируйте (или отладьте) генерацию изображений по тексту и редактирование изображений с помощью Microsoft MAI-Image 2.6 в этом проекте.

  Ознакомьтесь с документацией перед написанием кода: загрузите [https://docs.apiyi.com/en/api-capabilities/mai-image/overview.md](https://docs.apiyi.com/en/api-capabilities/mai-image/overview.md), чтобы получить текстовую версию этой страницы. Для просмотра подробных параметров аналогичным образом добавьте `.md` к URL страниц text-to-image и редактирования изображений.

  Требования:

  1. Названия моделей: флагманская `MAI-Image-2.6`, быстрая версия `MAI-Image-2.6-Flash`. **Названия моделей чувствительны к регистру**. Название, написанное строчными буквами, возвращает 503, что выглядит как сбой сервиса, но на самом деле вызвано неверным именем модели.

  2. Эндпоинты: только `/v1/images/generations` (JSON) и `/v1/images/edits` (`multipart/form-data`). **Не вызывайте `/v1/chat/completions` или `/v1/responses`**. Они возвращают 404.

  3. Таймауты: установите клиентский таймаут на 120 с для Flash и 180 с для 2.6. Генерация изображения 1024×1024 занимает около 17 с / 30 с соответственно, однако при пиковых нагрузках и больших размерах времени требуется больше. API изображений является синхронным и не возвращает task ID: если клиент отключится, результат будет потерян, а запрос все равно будет протарифицирован. Также увеличьте лимиты на обратных прокси-серверах, шлюзах и ограничения времени выполнения в serverless-средах.

  4. Запрещенные параметры: **никогда не отправляйте `response_format`, `seed` или `negative_prompt`**. Любой из них возвращает 400 `Invalid parameters`. В коде, перенесенном с gpt-image / DALL·E, часто явно задается `response_format="b64_json"` — удалите его. Параметры `quality`, `output_format`, `background` и `style` молча игнорируются, поэтому их также следует удалить.

  5. Обработка ответа: ответ всегда возвращается как `data[0].b64_json` — чистый base64 без префикса `data:`, декодируемый в формат PNG (около 1,5–1,7 МБ для размера 1024×1024). Режим `url` отсутствует. `usage` содержит фиктивные значения и не может использоваться для сверки; окончательными являются данные о тарификации в консоли.

  6. Размер: используйте `width` + `height` (целые числа, всегда вместе). Длина каждой стороны должна быть не менее 768, а произведение ширина × высота не должно превышать 2 359 296 (площадь 1536×1536). Значения, не кратные 16, округляются в меньшую сторону до ближайшего кратного 16. Если не передан ни один из параметров, по умолчанию используется 1024×1024. **Параметр `size` молча игнорируется на эндпоинте генерации изображений по тексту.**

  7. Количество: генерация по тексту всегда возвращает 1 изображение, и `n` не оказывает никакого эффекта; отправляйте параллельные запросы, если требуется больше. На эндпоинте редактирования параметр `n` работает и тарифицируется за каждое изображение.

  8. Редактирование: референсные изображения должны быть **загружены как файлы** в multipart, имя поля — `image`. **Передача через URL и base64 в JSON не поддерживается** (400). **Объединение нескольких изображений принимает от 1 до 5 референсных изображений**: для нескольких изображений повторите поле `image[]` (при использовании OpenAI SDK передайте список `image=[f1, f2]`). Изображения нумеруются как image 1, image 2, … в порядке загрузки; ссылайтесь на них как «image N» в prompt. Передача более 5 изображений возвращает 400. **Не используйте нумерованные имена полей, такие как `image` + `image2`**: второе изображение будет проигнорировано (статус 200, но будет использовано только первое). Количество референсных изображений не влияет на стоимость. Поддерживаются только форматы JPEG / PNG / WebP. Маски не поддерживаются. Сжимайте изображения перед загрузкой: обрабатывайте только файлы размером более 1,5 МБ, уменьшайте длинную сторону до 2048 пикселей или менее, выполняйте перекодирование с качеством 0.9 и возвращайтесь к исходному файлу в случае сбоя сжатия.

  9. Ошибки: модерация контента возвращает 400 `content_safety_violation` (блокируются реальные знаменитости, жестокость, известные персонажи с авторскими правами и нагота). Измените prompt; повторные попытки с тем же запросом бессмысленны. Размеры вне допустимого диапазона возвращают 400 `unsupported_request_value` с указанием точного ограничения в сообщении.

  10. Считывайте ключ из переменной окружения `APIYI_API_KEY` и используйте base\_url [https://api.apiyi.com/v1](https://api.apiyi.com/v1). Никогда не прописывайте ключ в коде напрямую и не фиксируйте его в git.

  11. По завершении выполните один реальный вызов генерации изображения по тексту и один вызов редактирования, затем покажите мне результаты и стоимость обоих вызовов.
</Prompt>

<Accordion title="От чего защищает этот prompt">

  | - | - |

<Info>
  **Примечания по тарификации**

  * **За изображение, независимо от размера**: разрешения 768×768 и 1536×1536 стоят одинаково, а длина prompt не влияет на стоимость.
  * **Редактирование стоит столько же, сколько генерация по тексту**: тарифицируются итоговые изображения, при этом **1 или 5 референсных изображений стоят одинаково**; `n=2` на эндпоинте редактирования тарифицируется как 2 изображения.
  * **Запросы, завершившиеся ошибкой 400** (модерация или неверные параметры), не создают изображений.
  * **Не сверяйте с полем `usage` в ответе**: `prompt_tokens` всегда равно 1000 × количество изображений и является заполнителем. Официальные данные отображаются в счете в консоли.
  * Суммируется с [акцией бонусов при пополнении](/ru/faq/recharge-promotions).
</Info>

## Группы и tokens

Эта серия входит в **группу `Default`**. Её может вызывать любой вновь созданный token; подавать заявку не требуется.

<Info>
  **Режим тарификации token**: для этой серии подходят как `Pay-as-you-go Priority`, так и `Per-request`. Мы рекомендуем `Pay-as-you-go Priority`, чтобы один и тот же token работал и с моделями платформы, тарифицируемыми по tokens.

  **Частота запросов**: держите нагрузку на один ключ в пределах **50 RPM**. При больших пакетных нагрузках заранее обратитесь в службу поддержки.
</Info>

## Технические характеристики

| Параметр | Спецификация |
| - | - |

| Редактирование изображений | `POST` | `/v1/images/edits` | **`multipart/form-data`** |

<Warning>
  **❌ Чат-эндпоинты не поддерживаются**

  `/v1/chat/completions` и `/v1/responses` возвращают **404 `Requested path is not found`** для этой серии. Чат-клиенты, такие как Cherry Studio и LobeChat, отправляют чат-запросы ко всем моделям из списка, поэтому **не выбирайте MAI-Image в этих клиентах**. Используйте инструмент с поддержкой Images API или вызывайте его из собственного кода.
</Warning>

<Warning>
  **✅ Эндпоинт редактирования принимает только загрузку файлов через multipart**

  Отправка JSON (с `image` в виде URL, data URI или необработанного base64) на `/v1/images/edits` возвращает 400:

  ```text theme={null}
  request Content-Type isn't multipart/form-data
  ```

  Загружайте локальный файл напрямую с помощью `-F "image=@photo.jpg"`. **Хостинг изображений не требуется.** Полные примеры см. в разделе [API редактирования изображений](/ru/api-capabilities/mai-image/image-edit).
</Warning>

<Tip>
  Основной домен — `https://api.apiyi.com`, резервный домен — `https://b.apiyi.com`.
</Tip>

## Ключевые параметры

### `width` и `height` (размер вывода)

| Правило | Подробности |
| - | - |
| Всегда вместе | Передача только одного возвращает 400 |
| Минимум | Каждая сторона не менее 768; 767 возвращает 400 `'width' must be at least 768 pixels` |
| Ограничение площади | ширина × высота ≤ 2,359,296; 1600×1600 возвращает 400 `exceeds the maximum of 2359296` |
| Округление | Значения, не кратные 16, округляются в меньшую сторону: 1000×1000 → 992×992, 1024×1023 → 1024×1008 |
| Соотношение сторон | Без ограничений; 3072×768 (баннер 4:1) работает |

**Распространенные размеры холста** (все в пределах ограничения площади):

| Назначение | `width` × `height` |
| - | - |
| Квадрат | 1024×1024 / 1536×1536 |
| Альбомная ориентация 3:2 | 1536×1024 |
| Портретная ориентация 2:3 | 1024×1536 |
| Альбомная ориентация 16:9 | 1792×1008 |
| Портретная ориентация 9:16 | 1008×1792 |
| Баннер 4:1 | 3072×768 |

<Warning>
  **`size` ведет себя по-разному на двух эндпоинтах**: в text-to-image он **молча игнорируется** (всегда 1024×1024), тогда как на эндпоинте редактирования он применяется. Чтобы избежать путаницы, **используйте `width` + `height` на обоих эндпоинтах**.
</Warning>

### `n` (количество изображений)

* **Text-to-image**: `n` не действует. Передача 2, 4 или 10 по-прежнему возвращает 1 изображение (и тарифицируется как 1). Для получения большего количества отправляйте параллельные запросы.
* **Редактирование**: `n` работает. `n=2` возвращает 2 изображения, которые тарифицируются как 2.

## Рекомендации

<Steps>
  <Step title="Выбирайте вариант под конкретную задачу">
    Пакетная генерация или чувствительные к задержке задачи → `MAI-Image-2.6-Flash`. Главные постеры, сложные композиции или строгие требования к качеству → `MAI-Image-2.6`. Параметры идентичны, поэтому переключение требует лишь изменения имени модели.
  </Step>

  <Step title="Заключайте в кавычки текст, который нужно отобразить">
    Поместите любой текст, который должен появиться на изображении, в кавычки и укажите, где он должен располагаться, например вывеска с надписью «Grand Opening». Модель очень точно воспроизводит текст в кавычках.
  </Step>

  <Step title="Указывайте «оставьте всё остальное без изменений» при редактировании">
    Формулируйте инструкции наподобие «Сделай чайник кобальтово-синим, всё остальное оставь точно таким же», чтобы сохранить как можно больше деталей оригинала.
  </Step>

  <Step title="Изменение холста меняет композицию изображения">
    Если вы передадите `width` / `height` с соотношением сторон, отличным от оригинала, модель **перестраивает композицию сцены**, а не обрезает её и не добавляет поля. Для точечного редактирования не указывайте размер: тогда соотношение сторон результата будет соответствовать оригиналу с округлением до кратных 16 (например, входное изображение 1344×756 → результат 1360×768).
  </Step>

  <Step title="Нужно несколько изображений? Отправляйте параллельные запросы">
    Генерация «текст в изображение» возвращает одно изображение за вызов, поэтому для 4 изображений отправьте 4 параллельных запроса. В наших тестах при 10 параллельных запросах задержка соответствовала одиночным запросам.
  </Step>
</Steps>

## Коды ошибок и повторные попытки

| HTTP | Код / сообщение | Значение | Что делать |
| - | - | - | - |
| `400` | `unsupported_request_value` | Размер вне допустимого диапазона, неверный тип или `width`/`height` отправлены не вместе | Исправьте в соответствии с ограничением в сообщении; не повторяйте запрос |
| `400` | `invalid_request`: `Invalid parameters: xxx` | Отправлено `response_format` / `seed` / `negative_prompt` | Удалите поле |
| `400` | `invalid_request`: `Prompt must be …` | `prompt` пуст или отсутствует | Добавьте prompt |
| `400` | `invalid_request_error`: `at most 5 reference images are accepted for <model>` | Более 5 референсных изображений на эндпоинте редактирования | Отправьте не более 5 |
| `400` | `invalid_request_error`: `reference image xxx is image/gif; only JPEG, PNG and WebP are accepted` | Неподдерживаемый формат референсного изображения | Преобразуйте в JPEG / PNG / WebP перед загрузкой |
| `400` | `invalid_request_error`: `<model> does not support mask edits` | `mask` на эндпоинте редактирования | Удалите маску и опишите область в prompt |
| `400` | `content_safety_violation` | Заблокировано модерацией контента | Измените prompt; повторная попытка не поможет |
| `400` | `request Content-Type isn't multipart/form-data` | JSON отправлен на эндпоинт редактирования | Переключитесь на загрузку файлов через multipart |
| `404` | `Requested path is not found` | Отправлено в chat / responses | Используйте Images API |
| `500` | `image is required` | В запросе на редактирование отсутствует поле файла изображения или используются нумерованные имена полей, такие как `image1` + `image2` | Используйте `image` для одного изображения; дублируйте `image[]` для нескольких |
| `503` | `no available channels` | Неверный регистр имени модели (например, только строчные буквы) | Используйте `MAI-Image-2.6` / `MAI-Image-2.6-Flash` |

<Info>
  **Совет клиенту**: перечисленные выше ошибки 4xx / 500 детерминированы, поэтому повторять запросы бессмысленно — вместо этого настройте оповещения о них. Повторять попытки стоит только при сетевых таймаутах и `429`, используя экспоненциальную задержку и максимум 3 попытки. Помните, что **запросы, прерванные по клиентскому таймауту, все равно тарифицируются**, поэтому сначала увеличьте таймаут.
</Info>

## Часто задаваемые вопросы

<AccordionGroup>
  <Accordion title="Почему при передаче response_format возвращается ошибка 400?">
    Эта серия возвращает только `b64_json` и **не принимает параметр `response_format`**. Даже `"b64_json"` возвращает 400 `Invalid parameters: response_format`.

    Код, перенесенный с gpt-image / DALL·E, часто задает его явно. Удалите его; изображение по-прежнему будет в `data[0].b64_json`. То же самое относится к `seed` и `negative_prompt`.
  </Accordion>

  <Accordion title="Я передал size: 1536x1024, почему результат всё равно квадратный?">
    Эндпоинт text-to-image **не считывает `size`**. Он просто игнорирует его и генерирует стандартное разрешение 1024×1024. Используйте вместо этого `"width": 1536, "height": 1024`.

    На эндпоинте редактирования `size` работает, но для единообразия используйте `width` + `height` в обоих случаях.
  </Accordion>

  <Accordion title="Можно ли редактировать с помощью URL изображения?">
    **Нет.** Эндпоинт редактирования принимает только загрузку файлов `multipart/form-data`. Передача URL, data URI или строки base64 в качестве `image` вернет ошибку 400.

    Если у вас есть только URL, сначала скачайте его на свой сервер, а затем загрузите:

    ```python theme={null}
    import requests
    img = requests.get("https://example.com/photo.jpg", timeout=30).content
    files = {"image": ("photo.jpg", img, "image/jpeg")}
    ```
  </Accordion>

  <Accordion title="Можно ли отправить несколько референсных изображений для объединения?">
    **Да, от 1 до 5 изображений** (с 2026-10-07) по той же цене, что и одно изображение.

    * **Как**: повторяйте поле `image[]`, `curl -F "image[]=@a.jpg" -F "image[]=@b.jpg"`; в OpenAI SDK передайте список `client.images.edit(image=[f1, f2])`
    * **Ссылки на изображения**: они нумеруются как image 1, image 2, … в порядке загрузки, например: «Помести лису из image 2 в сцену из image 1, всё остальное в image 1 оставь без изменений»
    * **Не используйте `image` + `image2`**: возвращается 200, но второе изображение отбрасывается и используется только первое
    * **Более 5 изображений** вернет 400 `at most 5 reference images are accepted for <model>`

    Полные примеры см. в [API редактирования изображений](/ru/api-capabilities/mai-image/image-edit).
  </Accordion>

  <Accordion title="Поддерживается ли инпейнтинг по маске?">
    **Нет.** Поле `mask` возвращает 400 `<model> does not support mask edits`. Для локальных изменений опишите область в prompt, например: «Сделай только чайник синим, всё остальное оставь точно таким же». По результатам наших тестов модель точно следует подобным ограничениям.
  </Accordion>

  <Accordion title="Можно ли использовать его в Cherry Studio / LobeChat?">
    **Не рекомендуется.** Эти чат-клиенты используют `/v1/chat/completions`, который возвращает 404 для этой серии. Используйте инструмент с поддержкой OpenAI Images API или вызывайте его напрямую с помощью примеров кода из этой документации.
  </Accordion>

  <Accordion title="Сколько изображений можно получить за один запрос?">
    Text-to-image **всегда возвращает 1**. Какое бы значение `n` вы ни передали, вы получите и оплатите 1 изображение. Для получения большего количества отправляйте параллельные запросы.

    На эндпоинте редактирования `n` работает: `n=2` возвращает 2 изображения и тарифицируется как 2.
  </Accordion>

  <Accordion title="Можно ли сверять тарификацию с количеством token в usage?">
    **Нет.** `usage.prompt_tokens` всегда равен 1000 × количество изображений, а `output_tokens` всегда равен 0; это плейсхолдеры. Эта серия тарифицируется за изображение, и данные о списаниях в консоли APIYI являются определяющими.
  </Accordion>

  <Accordion title="Насколько строга модерация? Как выглядит блокировка?">
    В этой серии используется официальная политика безопасности контента Microsoft, которая **довольно строгая**: блокируются реальные знаменитости, сцены насилия и жестокости, известные персонажи с авторскими правами (например, Disney) и нагота.

    При блокировке возвращается `400 content_safety_violation` с указанием конкретной причины в сообщении. Блокировки на уровне prompt обычно возвращаются в течение 5–8 с; некоторые применяются уже после генерации и занимают примерно столько же времени, сколько обычное изображение. Повторная отправка того же prompt не поможет; перефразируйте его.
  </Accordion>

  <Accordion title="Поддерживается ли потоковая передача?">
    **Нет.** Выполняйте обычный синхронный запрос и ожидайте полного ответа.
  </Accordion>

  <Accordion title="Получаете ошибку 503 no available channels?">
    Наиболее частая причина — **неверный регистр в имени модели**. Имя должно быть строго `MAI-Image-2.6` или `MAI-Image-2.6-Flash`; `mai-image-2.6-flash` возвращает 503.
  </Accordion>
</AccordionGroup>
