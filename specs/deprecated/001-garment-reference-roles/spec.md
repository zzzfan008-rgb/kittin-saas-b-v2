## User Scenarios & Testing *(mandatory)*

### User Story 1 - 明确每张参考图的用途后再生成 (Priority: P1)

服装设计师为一次生成任务添加多张参考图时，可以逐张确认其用途，并在开始生成前看清完整的角色分工。系统不会把尚未确认用途的图片带入生成，也不会自行猜测它代表人物、服装或其他内容。

**Why this priority**: 多参考图的核心风险是输入语义不明确；先确认角色才能避免人物身份、服装、姿势和风格被错误混用。

**Independent Test**: 添加三张用途不同的参考图，分别确认角色，再尝试生成；可以独立验证待确认拦截、角色可见性和生成就绪状态。

**Acceptance Scenarios**:

1. **AS-001** — **Given** 一次生成包含一张或多张新添加但未确认角色的参考图，**When** 设计师尝试开始生成，**Then** 生成被阻止，并明确指出哪些参考图仍需确认角色。
2. **AS-002** — **Given** 所有参考图均已选择受支持的角色，**When** 设计师复核本次生成，**Then** 每张图的角色和顺序均清晰可见，且任务可以进入生成。
3. **AS-003** — **Given** 同一任务包含人物身份、姿势与构图、服装和背景参考，**When** 任务进入生成，**Then** 每张图只承担已确认的职责，角色说明不允许相互替换或跨角色借用。
4. **AS-004** — **Given** 同一任务同时包含“人物身份 / 模特”和“造型方式（不借用身份）”参考，**When** 任务进入生成，**Then** 造型参考只影响造型方式，不被用于复制人物身份或面部特征。

---

### User Story 2 - 调整参考图后保持角色关系一致 (Priority: P2)

服装设计师可以在生成前修改角色、调整参考图顺序或移除参考图，并始终看到图片、角色和顺序之间的一致关系。已经开始的任务保留启动时的角色快照，后续修改只影响下一次生成。

**Why this priority**: 设计工作会频繁换图和调整优先级；角色关系若随编辑漂移，会导致难以复现的生成结果。

**Independent Test**: 对一组已确认参考图依次改角色、重排、删除并保存，验证当前任务与下一次任务各自采用预期的角色关系。

**Acceptance Scenarios**:

1. **AS-005** — **Given** 多张参考图已有角色和顺序，**When** 设计师重排或移除其中的图片，**Then** 保留图片的角色不变，显示顺序与实际使用顺序一致，且不存在遗漏或重复位置。
2. **AS-006** — **Given** 一次生成已经开始，**When** 设计师随后修改某张参考图的角色，**Then** 已开始任务仍保留启动时的角色关系，修改后的角色仅用于后续生成。
3. **AS-007** — **Given** 设计师保存并重新打开项目，**When** 查看参考图，**Then** 图片、已确认角色、待确认状态和顺序均与保存前一致。

---

### User Story 3 - 安全打开旧项目并补齐角色 (Priority: P3)

服装设计师打开包含旧版或含糊参考图角色的项目时，原有图片不会丢失。系统将这类图片标记为待确认，并要求设计师在下一次生成前补齐明确角色。

**Why this priority**: 旧项目数据必须可继续使用，同时不能因迁移时的猜测而引入新的错误生成。

**Independent Test**: 打开含旧版角色的项目，确认图片完整保留、保守映射清晰可见，并验证未确认前不能生成、确认后可以继续。

**Acceptance Scenarios**:

1. **AS-008** — **Given** 旧项目包含旧版或无法明确判断的图片角色，**When** 设计师打开项目，**Then** 所有图片均被保留，并以保守角色和“待确认”状态呈现。
2. **AS-009** — **Given** 一张旧图被保守映射为“通用参考”，**When** 设计师明确确认该角色，**Then** 它只能提供任务明确需要的通用视觉参考，不得覆盖已经指定的人物、服装、姿势或背景角色。

### Edge Cases

- 多张参考图选择同一角色时，每张图仍保持独立身份和明确顺序；系统不自动合并或改写角色。
- 同一张素材被多次加入任务时，每个参考图条目独立确认一个角色，不从另一个条目继承角色。
- 参考图已被删除、失效或无法读取时，任务不得以缺失图片继续生成，并应指出受影响的条目。
- 角色修改与生成启动同时发生时，用户必须能辨认本次任务最终采用的是哪一份角色快照。
- “通用参考”与更具体角色同时存在时，具体角色优先定义相应内容边界，通用参考不得覆盖它们。
- 项目包含无法识别的旧角色值时，图片继续保留并标记待确认，而不是静默丢弃或自动确认为通用参考。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 为每个参考图条目显示当前角色或清晰的“待确认”状态。
- **FR-002**: 系统 MUST 支持以下明确角色：人物身份 / 模特、姿势 / 构图、上装、下装、整套服装、面料 / 材质、配饰、造型方式（不借用身份）、背景、通用参考。
- **FR-003**: 每个新添加、旧版迁移或角色含糊的参考图 MUST 保持待确认状态，直到用户通过角色选择控件，或主动连接到清晰标注固定角色的专用输入句柄，明确选择一个受支持角色。
- **FR-004**: 只要本次任务存在待确认、缺失或不可读取的参考图，系统 MUST 阻止生成，并给出能够定位到具体参考图的原因。
- **FR-005**: 用户 MUST 能为每个参考图条目确认且仅确认一个角色；多个条目 MAY 使用同一角色。
- **FR-006**: 系统 MUST 在生成前向用户展示实际使用的参考图顺序，并保持图片、角色与顺序的一一对应。
- **FR-007**: 系统 MUST 将每个已确认角色转化为明确的使用边界，禁止在人物身份、服装、姿势与构图、材质、配饰、造型方式和背景之间交换职责。
- **FR-008**: “造型方式（不借用身份）”参考 MUST 只提供造型表达，不得被用于复制人物身份或面部特征。
- **FR-009**: “通用参考” MUST 由用户显式确认，并且不得覆盖同一任务中更具体角色已经定义的内容边界。
- **FR-010**: 用户 MUST 能在下一次生成开始前修改参考图角色；修改不得追溯改变已经开始或已经完成任务的角色快照。
- **FR-011**: 系统 MUST 在保存和重新打开项目后保留参考图、角色、待确认状态及其顺序。
- **FR-012**: 系统 MUST 保留旧项目中的参考图，对旧版或无法明确判断的角色进行保守映射，并继续要求用户确认。
- **FR-013**: 每个已开始或已完成的生成任务 MUST 提供可复核的参考图角色与顺序记录，使用户能够解释该任务实际采用了哪些输入职责。
- **FR-014**: 用户重排或移除参考图时，系统 MUST 保持剩余条目的角色不变，并形成连续、无遗漏、无重复的使用顺序。

### Key Entities

- **参考图条目**: 一次生成所使用的一张图片；包含用户可辨认的图片、唯一角色、顺序和确认状态。
- **参考图角色**: 用户声明的图片职责及其内容边界；决定图片可以影响哪些内容、不得影响哪些内容。
- **角色快照**: 某次生成启动时冻结的参考图、角色和顺序集合；用于复核与重现该次任务。
- **生成任务**: 使用角色快照执行的一次生成；与后续对画布参考图的修改相互独立。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在全部验收场景中，含待确认、缺失或不可读取参考图的生成尝试有 100% 被阻止，并能定位到具体问题图片。
- **SC-002**: 进入生成的任务中，100% 的参考图条目都具有一个已确认的受支持角色，且展示顺序与实际使用顺序一致。
- **SC-003**: 在人物身份、造型、服装、姿势和背景混合的验收样例中，100% 的任务角色说明都明确限定每张图的职责，并明确禁止跨角色借用。
- **SC-004**: 在重排、移除、修改、保存和重新打开的全部验收场景中，剩余参考图的角色和顺序保持正确，无角色漂移或图片丢失。
- **SC-005**: 在旧项目迁移验收样例中，100% 的原有参考图得到保留，所有含糊角色均保持待确认，未发生静默自动确认。
- **SC-006**: 在至少 10 名符合目标用户假设、且未参与本功能设计或实现的服装设计师中，至少 9 人能在 90 秒内为三张参考图完成角色确认并达到可生成状态，无需查阅外部说明。
- **SC-007**: 对 100% 已开始或已完成的验收任务，复核者都能从任务记录还原当时使用的参考图角色与顺序。

## Assumptions

- 目标用户是已能使用现有画布、素材选择和生成流程的服装设计师。
- 每个参考图条目只承担一个角色；需要同一素材承担不同职责时，用户将其作为独立条目分别确认。
- 多张参考图可以使用相同角色，顺序用于保持用户的明确选择和结果可复核性，不代表系统自动推断角色权重。
- “通用参考”是有边界的补充角色，不是跳过角色确认的默认选项。
- 角色确认针对每个参考图条目；系统不依赖自动图像识别来代替用户决定。
- 用户主动连接到清晰标注固定角色的专用输入句柄，属于对该角色的显式选择；普通输入句柄、自动迁移和系统推断均不属于显式确认。

## Dependencies

- 依赖现有画布中的图片上传、素材选择、节点连接、项目保存和重新打开能力。
- 依赖现有生成流程能够接收多张有序参考图，并保留每次任务的输入记录。
- 依赖各可用生成模型已有的输入契约能够表达角色分工；不兼容的组合需在生成前给出清晰状态。

## Out of Scope

- 自动识别或推荐参考图角色。
- 新增生成模型、供应商、计费方式或模型参数。
- 评价生成图片的审美质量，或执行真实付费生成验收。
- 改变现有登录、成员权限或项目共享方式。
- 重新设计与参考图角色确认无关的画布交互。
